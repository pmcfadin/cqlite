1//! Push-time columnar row accumulator: ONE cell resolution per row, feeding both
2//! the Arrow build pass and the payload-byte accounting (issue #3552).
3//!
4//! # What was duplicated
5//!
6//! The `cqlite-flight` `do_get` row routes resolved every projected cell of every
7//! row TWICE:
8//!
9//! 1. at PUSH time, [`estimate_arrow_row_bytes`](super::estimate_arrow_row_bytes)
10//!    walked the projected columns and probed `row.values.get(col.name)` — one
11//!    sip-hash string lookup into the row's own value map per column per row
12//!    (`N·M` probes, including absent cells: the exact pattern issue #1495
13//!    removed from the build pass);
14//! 2. at FLUSH time, `arrow_columnar::transpose_columns` walked the buffered rows
15//!    again to build the column-major cell slices the builders consume.
16//!
17//! Issue #3248 priced that first walk at 592 cyc/row (`Estimator::charge_slot`
18//! 163 + `charge_child` 93 on top).
19//!
20//! # The fold
21//!
22//! [`ArrowRowAccumulator`] moves the build pass's FIRST STAGE — the transpose —
23//! to push time and charges the estimator from the cells it has just resolved, so
24//! a cell is resolved exactly once:
25//!
26//! * [`stage`](ArrowRowAccumulator::stage) consumes one row, routes each of its
27//!   OWN entries into that column's staging slot through a small
28//!   `name → column indices` map built once per column set (no probe against the
29//!   large per-row map), and returns the row's payload width charged from those
30//!   slots;
31//! * [`commit`](ArrowRowAccumulator::commit) moves the staged cells into the
32//!   column-major store — into ONE store per distinct projected NAME, so a value
33//!   named by several output columns (`SELECT a, a`) is stored once and read twice
34//!   through the `canonical` index, never cloned (issue #3552 review B3), and
35//!   storing only PRESENT cells, so an absent cell costs no slot (review B4);
36//! * [`to_record_batch`](ArrowRowAccumulator::to_record_batch) hands each column's
37//!   already-transposed cells straight to its builder — `transpose_columns` is not
38//!   run at all on this path.
39//!
40//! The store is reused across batches — [`clear`](ArrowRowAccumulator::clear)
41//! keeps allocations up to a BOUND and releases the excess above it, so a store
42//! that grew far past what any batch since has used may shrink and later
43//! reallocate — so the per-batch `n_cols × vec![None; n_rows]` allocation is gone
44//! too. The bound is what stops per-column capacity accumulating across batches
45//! whose density moves between columns (issue #3552, roborev rounds 6-7).
46//!
47//! # Memory profile — sparse persistent, dense transient
48//!
49//! What is RETAINED between batches is one `(row index, value)` pair per PRESENT
50//! cell, per distinct projected name. Nothing retained scales with
51//! `n_cols × rows`: an absent cell costs no slot, and a duplicate output column
52//! costs one `usize` in `canonical`, not a copy. What is DENSE is built only
53//! inside [`to_record_batch`](ArrowRowAccumulator::to_record_batch), into ONE
54//! reused `Vec<Option<&Value>>` of `rows` borrowed slots, and dropped with the
55//! batch.
56//!
57//! This matters because of what the byte-cap does NOT bound (issue #3552 reviews
58//! B1/B3/B4, three instances of one family): the cap is denominated in PAYLOAD
59//! bytes, so a wide SPARSE projection has small payload, does not trip the cap
60//! early, and fills the buffer to the ROW cap. Any per-row cost proportional to
61//! projection WIDTH rather than to payload is therefore effectively unbounded by
62//! the governor, and must not be retained. The rule this module is built to: ask
63//! of every allocation not just "is it bounded", but "bounded by what, in the
64//! worst case over BOTH projection width AND sparsity?" — and "the caps bound it"
65//! is a valid answer only for a quantity proportional to PAYLOAD.
66//!
67//! # Why stage/commit, and not push (the byte-budget contract — AC2)
68//!
69//! The width has two consumers that MUST run before any batch materializes:
70//! `BatchByteCap::cut_before(width)` decides the batch boundary before the row
71//! joins the buffer (test-then-push — building a batch to discover it is oversized
72//! "is a report, not a cap"), and issue #2821's reserve-before-materialize turns
73//! the accumulated payload into an egress credit reservation before the build runs.
74//! So the width is still produced BEFORE the row joins the batch, and the caller's
75//! sequence — `stage` → `cut_before` → (flush) → `commit` → `accumulate` — is
76//! byte-for-byte the sequence it replaces (`estimate` → `cut_before` → (flush) →
77//! `push` → `accumulate`). Thresholds, timing and batch boundaries are unchanged;
78//! only the duplicated resolution is gone.
79//!
80//! A staged row deliberately SURVIVES a flush: `clear` empties the committed
81//! store and leaves the staging slot alone, exactly as the old code pushed the
82//! crossing row into the freshly emptied buffer.
83//!
84//! # Conservatism is preserved, including for ABSENT columns
85//!
86//! `Σ width(columns, row) >= arrow_payload_bytes(batch)` still holds. The one
87//! place a fold like this can silently under-charge is an ABSENT cell:
88//! `transpose_columns` never enumerates the projected columns per row, so it never
89//! *sees* an absent cell, while the estimator charges one (its validity byte, its
90//! shape's structural overhead and `column_slack_bytes`). This accumulator
91//! therefore keeps the estimator's enumeration, not the transpose's: the staging
92//! slot is a vector of ARITY `columns.len()` reset to `None` per row, and the
93//! charge walks all of it — so an absent column arrives at the charging core as
94//! `None`, which is exactly what a failed `row.values.get(name)` produces in
95//! `estimate_arrow_row_bytes`. Nothing about the absent-column charge is
96//! re-derived or approximated here.
97//!
98//! # What deliberately still uses the standalone estimator
99//!
100//! The AGGREGATE route (`cqlite_flight::producer`'s `split_rows_into_batches`)
101//! folds rows into accumulator state and materializes one PARTIAL row per
102//! `GROUP BY` group in one go, then applies the batch boundary AFTER THE FACT to
103//! an already-materialized row slice. It has no incremental push loop, so this
104//! seam does not reach it and it keeps calling
105//! [`estimate_arrow_row_bytes`](super::estimate_arrow_row_bytes) per row. Nothing
106//! there is duplicated work of the kind this module removes: that route resolves
107//! the cells once for the estimate and once for the build, but its rows are
108//! already in hand and are a per-GROUP count, not a per-ROW-of-the-scan one.
109//!
110//! Both accountings share ONE charging core (`arrow_size::charge_row`) and differ
111//! only in resolution, and their equivalence over the shared shape corpus —
112//! including absent columns, saturating fan-out and duplicate column names — is
113//! pinned by `arrow_row_accumulator_tests`.

127/// Total retained cell slots tolerated after a batch, as a multiple of the largest
128/// batch's own present-cell count. Slack, not a hard equality, so an ordinary
129/// batch-to-batch density wobble does not reallocate.
130const RETAINED_SLOT_SLACK: usize = 2;
131
132/// Floor below which retained slots are never trimmed, so a small-batch workload
133/// never pays repeated reallocation to reclaim a few hundred slots.
134const RETAINED_SLOT_FLOOR: usize = 1024;

136/// Reusable column-major row accumulator for one projected column set.
137///
138/// Borrows the column set (it is stable for the whole scan) and owns the cells it
139/// has taken out of the rows. See the module documentation for the stage/commit
140/// contract and why it is shaped that way.
141pub struct ArrowRowAccumulator<'a> {
142    /// The projected output columns, in output order.
143    columns: &'a [ColumnInfo],
144    /// Per-column Arrow slot shapes, resolved once (never per row).
145    prepared: PreparedColumns<'a>,
146    /// `column name → its CANONICAL output index` — the FIRST column with that
147    /// name. Duplicate output columns for one name (`SELECT a, a`) resolve to the
148    /// same canonical index, which is how one stored value serves all of them.
149    name_to_canonical: HashMap<&'a str, usize>,
150    /// `output column index → the index whose store holds its cells`.
151    /// `canonical[i] == i` for a unique name; for a duplicate it points at the
152    /// first column of that name. Every read of a cell — the width charge, the
153    /// re-derivation, and the batch build — goes through this, so a value is
154    /// stored ONCE however many output columns name it (issue #3552 review B3).
155    canonical: Vec<usize>,
156    /// Committed cells, column-major and **SPARSE**: `cells[c]` holds one
157    /// `(row index, value)` pair per PRESENT cell of canonical column `c`, in
158    /// ascending row order (appended as rows commit, so it is sorted for free).
159    ///
160    /// An ABSENT cell occupies NO slot. That is the whole point of the
161    /// representation (issue #3552 review B4): a DENSE
162    /// `Vec<Vec<Option<Value>>>` costs `n_canonical_cols × rows` slots of
163    /// `size_of::<Option<Value>>()` whatever fraction of them is present, and
164    /// `clear` retains that capacity — so a WIDE SPARSE projection (ordinary in
165    /// Cassandra) retained tens of MB that NEITHER cap bounds: the byte cap bounds
166    /// PAYLOAD, and sparse rows have little payload, so it does not cut early and
167    /// the buffer fills to the row cap. Sparse storage makes the persistent cost
168    /// proportional to present cells, which is what the payload cap is
169    /// proportional to as well. The builders' dense row-aligned slice is
170    /// materialized TRANSIENTLY at flush, into one reused view — the same
171    /// sparse-persistent / dense-transient shape `main` had when it buffered
172    /// `Vec<QueryRow>` (maps hold only present cells) and transposed at flush.
173    ///
174    /// Only a CANONICAL `c` is ever stored or read: a non-canonical
175    /// (duplicate-name) column's store stays EMPTY for the whole scan, and its
176    /// cells come from `cells[canonical[c]]` (review B3). Cleared per batch,
177    /// retaining capacity up to [`ArrowRowAccumulator::clear`]'s bound — a store
178    /// over that bound is shrunk and may reallocate on a later batch.
179    cells: Vec<Vec<(usize, Value)>>,
180    /// The row under test: one slot per column, all `None` between rows.
181    staged: Vec<Option<Value>>,
182    /// Whether [`Self::staged`] currently holds a staged, uncommitted row.
183    has_staged: bool,
184    /// Committed row count, tracked explicitly rather than read off a column's
185    /// length — so it is available for a ZERO-column projection, where there is no
186    /// column to read.
187    ///
188    /// Which surface reports it, precisely: [`Self::len`] reports THIS count for
189    /// every projection, including a zero-column one. [`Self::to_record_batch`]
190    /// does NOT — with no columns there is no array to carry a length, so the batch
191    /// cannot report these rows (it reports 0, or refuses; the terminal behaviour is
192    /// `RecordBatch::try_new`'s). That divergence is PRE-EXISTING — pre-fold
193    /// `rows_to_record_batch` ends in the same `try_new` over an empty array list —
194    /// and is deliberately not changed here, since doing so would change Arrow
195    /// output inside a behaviour-preserving refactor. Whether a zero-column
196    /// projection is reachable on the `do_get`/streaming path is unresolved; issue
197    /// #3742 owns both questions.
198    rows: usize,
199    /// Largest total PRESENT-cell count any single batch has held — the basis for
200    /// how much capacity may stay resident between batches. A batch's own present
201    /// cells are what the byte cap bounds, so they are the only sound basis.
202    peak_cells: usize,
203    /// Canonical indices the CURRENT staged row filled, in fill order.
204    ///
205    /// `commit` walks THIS instead of every projected column: only present canonical
206    /// cells need work, so an all-columns pass was an extra O(projection_width) per
207    /// row on the hot path — penalising exactly the wide sparse projections this
208    /// accumulator exists to optimise (issue #3552, roborev round 14). `stage` fills
209    /// only canonical slots, so this set is EXACT, not an optimisation hint.
210    ///
211    /// NOTE the charge is a different matter: `prepared.row_bytes` must still visit
212    /// every projected column, because an ABSENT cell contributes to the width. That
213    /// O(width) pass is required by the byte-cap semantics and is NOT removable.
214    staged_idx: Vec<usize>,
215    /// Per-column present-cell count at the LAST `clear` — what each store actually
216    /// needed most recently, so the trim can keep an active store warm and reclaim
217    /// from the ones that went quiet.
218    last_used: Vec<usize>,
219}

221impl<'a> ArrowRowAccumulator<'a> {
222    /// Prepare an accumulator for `columns`.
223    ///
224    /// Column shapes and the `name → indices` map are resolved HERE, once, and
225    /// reused for every row and every batch. The per-column cell stores start
226    /// EMPTY — see [`Self::with_capacity`] for why they are never pre-sized.
227    pub fn new(columns: &'a [ColumnInfo]) -> Self {
228        // FIRST occurrence of a name wins (`or_insert`), so the canonical slot of
229        // a duplicated name is its first output column. One `usize` per NAME, not
230        // a `Vec<usize>` per name — the fan-out lives in `canonical` below.
231        let mut name_to_canonical: HashMap<&'a str, usize> = HashMap::with_capacity(columns.len());
232        for (idx, col) in columns.iter().enumerate() {
233            name_to_canonical.entry(col.name.as_str()).or_insert(idx);
234        }
235        // `unwrap_or(idx)` is unreachable — every column's name was just inserted —
236        // and its fallback is the correct answer anyway (a column is its own
237        // canonical slot), so it cannot silently mis-resolve.
238        let canonical: Vec<usize> = columns
239            .iter()
240            .enumerate()
241            .map(|(idx, col)| {
242                name_to_canonical
243                    .get(col.name.as_str())
244                    .copied()
245                    .unwrap_or(idx)
246            })
247            .collect();
248        Self {
249            columns,
250            prepared: PreparedColumns::new(columns),
251            name_to_canonical,
252            canonical,
253            // Do NOT pre-size per column: `n_cols × capacity ×
254            // size_of::<Option<Value>>()` is the `batch_size × width` product
255            // issue #2825's byte-cap exists to BOUND, and pre-sizing pays it
256            // eagerly, before a single row arrives, on every per-request drive
257            // loop (so a `SELECT … LIMIT 1` point read pays a full batch's
258            // reservation). With `size_of::<Value>() <= 40` and an 8192-row
259            // batch that is ~65 MB at 200 columns and ~131 MB at 400 — over the
260            // <128 MB target, on ONE stream, times `--max-concurrent-scans`, and
261            // `batch_size` is operator-settable with no upper clamp. Because
262            // `clear` RETAINS capacity, pre-sizing only ever bought the FIRST
263            // batch's amortized growth (issue #3552 review B1).
264            //
265            // An earlier revision added "the store reaches the same steady state after
266            // one batch either way" here. That is FALSE for a density pattern that MOVES
267            // between columns, and `clear` now BOUNDS what survives rather than resting
268            // on that argument — see the trim there.
269            cells: (0..columns.len()).map(|_| Vec::new()).collect(),
270            staged: vec![None; columns.len()],
271            has_staged: false,
272            rows: 0,
273            peak_cells: 0,
274            staged_idx: Vec::new(),
275            last_used: vec![0; columns.len()],
276        }
277    }
278
279    /// Prepare an accumulator for `columns` whose batches hold up to `capacity`
280    /// rows.
281    ///
282    /// `capacity` is accepted for call-site clarity — the caller knows the row cap
283    /// its batches are bounded by — and is DELIBERATELY not used to pre-allocate
284    /// the per-column cell stores: that product is exactly the eager
285    /// `n_cols × batch_size` residency [`Self::new`] documents (issue #3552
286    /// review B1).
287    ///
288    /// This doc previously argued the store "reaches its steady state after one
289    /// batch regardless" because `clear` retains capacity. True only for a STABLE
290    /// density pattern; see [`Self::clear`], which bounds the resident total.
291    pub fn with_capacity(columns: &'a [ColumnInfo], capacity: usize) -> Self {
292        let _ = capacity;
293        Self::new(columns)
294    }
295
296    /// Committed rows in the current batch (a staged-but-uncommitted row is NOT
297    /// counted — it has not joined the batch).
298    pub fn len(&self) -> usize {
299        self.rows
300    }
301
302    /// Whether the current batch holds no committed row.
303    pub fn is_empty(&self) -> bool {
304        self.rows == 0
305    }

307    /// Resolve `row`'s projected cells ONCE into the staging slot and return the
308    /// row's Arrow payload width — the same number
309    /// [`estimate_arrow_row_bytes`](super::estimate_arrow_row_bytes) reports for
310    /// the same `(columns, row)`, charged through the same core from the cells the
311    /// build pass will consume.
312    ///
313    /// The row does NOT join the batch here: the caller may flush the committed
314    /// rows first (test-then-push) and must then call [`Self::commit`].
315    ///
316    /// # Precondition — one `stage` per `commit`
317    ///
318    /// The caller MUST call [`Self::commit`] (or abandon the accumulator) before
319    /// the next `stage`; both `do_get` row routes do exactly that, in straight-line
320    /// code. There is deliberately NO recovery for staging twice, and debug and
321    /// release behave the SAME WAY (issue #3552 review B2): a debug build fails the
322    /// assertion below, and a release build resets the staging slot, so the earlier
323    /// row's cells are dropped and it never joins a batch.
324    ///
325    /// That is a lost row in a hypothetical mis-sequenced caller — but it is NOT a
326    /// byte-budget violation, which is the property AC2 forbids moving: the width
327    /// is `accumulate`d by the caller only AFTER `commit`, so a row that never
328    /// commits is never charged either, and `byte_cap.accumulated()` still
329    /// describes exactly the committed rows (the invariant `flush_credited`
330    /// asserts). An earlier version *recovered* by committing the pending row here,
331    /// which was the unsafe direction: that row would have joined the batch with
332    /// its width never accumulated, under-counting the accumulator and so
333    /// UNDER-RESERVING issue #2821's pre-materialization egress credit — silently,
334    /// and only in release, since the `debug_assert` made the recovery branch
335    /// unreachable in every debug build and untestable.
336    pub fn stage(&mut self, row: QueryRow) -> usize {
337        debug_assert!(
338            !self.has_staged,
339            "ArrowRowAccumulator::stage called with a row still staged — the \
340             contract is stage -> (flush) -> commit per row (issue #3552)"
341        );
342        // Both are built from `columns` in `new` and neither is ever resized, so
343        // every index in `name_to_canonical` is in range for `staged` — asserted
344        // rather than left to a permissive `get_mut` below (issue #3552 review N3).
345        debug_assert_eq!(
346            self.staged.len(),
347            self.columns.len(),
348            "staging arity must equal the projected column count"
349        );
350        // An ABSENT column must arrive at the charging core as `None`, exactly as a
351        // failed `row.values.get(name)` does — so every slot must be `None` here.
352        //
353        // It already IS, on every path that reaches this line after a `commit`:
354        // `commit` TAKES every slot IT FILLED (`staged_idx`, which is exact because
355        // `stage` fills only canonical slots), and the initial `staged` is all-`None`.
356        // An unconditional reset was therefore a
357        // redundant PROJECTION-WIDTH pass on the hot path, per row — which is work
358        // this issue exists to REMOVE, not add (issue #3552, roborev round 12).
359        //
360        // The one path that genuinely needs the reset is a re-`stage` with no
361        // intervening `commit` (`has_staged` still true), where the previous row's
362        // values are still resident. That case pays for itself; the common one does
363        // not. The `debug_assert` makes the skipped invariant CHECKED in debug builds
364        // rather than merely argued for here.
365        if self.has_staged {
366            // Only the slots the previous (uncommitted) row actually filled — the same
367            // exactness that lets `commit` skip the all-columns pass.
368            for &idx in &self.staged_idx {
369                if let Some(slot) = self.staged.get_mut(idx) {
370                    *slot = None;
371                }
372            }
373        } else {
374            debug_assert!(
375                self.staged.iter().all(Option::is_none),
376                "staging slots must be empty when no row is staged — `commit` takes \
377                 every slot, so a non-empty slot here means that contract broke"
378            );
379        }
380        // Resolve by iterating the ROW's own entries — the large per-row value map
381        // is never probed by column name (issue #1495 / parser epic J1). An entry
382        // whose name is not projected is dropped, as the transpose dropped it.
383        self.staged_idx.clear();
384        let staged = &mut self.staged;
385        let staged_idx = &mut self.staged_idx;
386        let name_to_canonical = &self.name_to_canonical;
387        for (name, value) in row.values {
388            if let Some(&canonical_idx) = name_to_canonical.get(name.as_ref()) {
389                // MEMORY: each row value is MOVED into exactly one slot and is
390                // never cloned — including when several output columns name it
391                // (`SELECT a, a`). The duplicate columns read this same canonical
392                // slot at charge time and at build time, so the fan-out costs
393                // nothing beyond a second `usize` index, exactly as
394                // `transpose_columns` fanned out a `&Value` for free.
395                //
396                // Cloning here instead would deep-copy the payload once per
397                // duplicate column — recursively for a collection, tuple, UDT,
398                // JSON or decimal — at STAGE time, i.e. BEFORE `cut_before`
399                // decides the batch boundary and before the egress reservation
400                // exists: unbounded memory taken outside the governed window and
401                // ahead of the admission decision (issue #3552 review B3, the same
402                // family as review B1's eager reservation). The output would be
403                // byte-identical either way, which is precisely why saying only
404                // that is not enough.
405                //
406                // Direct indexing, not a `get_mut` whose `None` arm would SKIP a
407                // column the row carries: the index came from `name_to_canonical`,
408                // built from the same `columns` that sized `staged`, so it is in
409                // range by construction (review N3).
410                staged[canonical_idx] = Some(value);
411                staged_idx.push(canonical_idx);
412            }
413        }
414        self.has_staged = true;
415        self.prepared.row_bytes(&self.staged, &self.canonical)
416    }

418    /// Move the staged row's cells into the batch. A no-op when nothing is staged.
419    ///
420    /// Only CANONICAL columns are appended to: a duplicate-name column has no
421    /// store of its own and reads its canonical column's, so a duplicated value is
422    /// held once rather than once per output column (issue #3552 review B3). Its
423    /// store therefore stays empty for the whole scan — every reader goes through
424    /// `canonical`, so nothing ever indexes it directly.
425    ///
426    /// Only PRESENT cells are appended: an absent cell costs NO slot, so the
427    /// store's size tracks present cells rather than `n_cols × rows` (review B4).
428    /// An explicit `Value::Null` IS present and IS stored — the absent/null
429    /// distinction the builders rely on is preserved exactly, since a row missing
430    /// from a column's store reads back as `None` and a stored `Value::Null` reads
431    /// back as `Some(&Value::Null)`, which is what `transpose_columns` produced.
432    pub fn commit(&mut self) {
433        if !self.has_staged {
434            return;
435        }
436        let row_idx = self.rows;
437        let Self {
438            cells,
439            staged,
440            canonical,
441            staged_idx,
442            ..
443        } = self;
444        // Walk ONLY the canonical slots this row filled. An all-columns pass was an
445        // extra O(projection_width) per row (roborev round 14); `stage` fills only
446        // canonical slots, so this set is exact and nothing can be missed.
447        //
448        // Still TAKE rather than read: a value must never survive into the next row.
449        // A repeated index (a row carrying the same name twice) takes `None` on the
450        // second visit and stores nothing, so duplicates are harmless.
451        for &idx in staged_idx.iter() {
452            let Some(slot) = staged.get_mut(idx) else {
453                continue;
454            };
455            let value = slot.take();
456            match (canonical.get(idx), cells.get_mut(idx)) {
457                // The canonical column for this name owns the storage — and stores
458                // the cell ONLY if the row carries one.
459                (Some(&c), Some(store)) if c == idx => {
460                    if let Some(value) = value {
461                        store.push((row_idx, value));
462                    }
463                }
464                // A duplicate-name column, or an arity mismatch: nothing to store.
465                _ => {}
466            }
467        }
468        self.staged_idx.clear();
469        // Saturating for hygiene: a batch is bounded by the row cap long before
470        // this could matter, but a wrapping row count would corrupt the arity
471        // checks that guard the charge.
472        self.rows = self.rows.saturating_add(1);
473        self.has_staged = false;
474    }

476    /// Drop every COMMITTED row, keeping allocations for the next batch up to a
477    /// BOUND — a store whose retained capacity exceeds its share of that bound is
478    /// shrunk here and may reallocate on a later batch. Retention is bounded, not
479    /// unconditional; see the trim below for why unconditional retention is unsafe.
480    ///
481    /// A staged-but-uncommitted row is deliberately left staged: it belongs to the
482    /// NEXT batch, which is what makes the test-then-push boundary work.
483    pub fn clear(&mut self) {
484        // A batch's OWN present-cell count is what the byte cap bounds, so it is the
485        // only sound basis for what may stay resident. Measured BEFORE the clear.
486        let mut used = 0usize;
487        for (idx, column) in self.cells.iter().enumerate() {
488            let n = column.len();
489            used = used.saturating_add(n);
490            if let Some(slot) = self.last_used.get_mut(idx) {
491                *slot = n;
492            }
493        }
494        self.peak_cells = self.peak_cells.max(used);
495
496        for column in &mut self.cells {
497            column.clear();
498        }
499
500        // WHY A TRIM IS NEEDED AT ALL. `Vec::clear` retains capacity, and capacity is
501        // retained PER COLUMN — so across batches whose density MOVES BETWEEN COLUMNS
502        // the resident total converges on the SUM of per-column high-water marks, not
503        // the high-water mark of the sum. One dense column per batch, rotating,
504        // reaches the full dense `n_cols × batch_size` residency this sparse
505        // representation exists to avoid, and NEITHER cap bounds it: the byte cap
506        // bounds a batch's PAYLOAD and says nothing about what survives BETWEEN
507        // batches. Two comments in this file asserted the opposite until issue #3552
508        // roborev round 6; pinned by
509        // `rotating_density_does_not_accumulate_per_column_capacity`.
510        let allowance = self
511            .peak_cells
512            .saturating_mul(RETAINED_SLOT_SLACK)
513            .max(RETAINED_SLOT_FLOOR);
514        let retained: usize = self.cells.iter().map(Vec::capacity).sum();
515        if retained > allowance {
516            // Trim each store toward ITS OWN recent usage, not an equal share of the
517            // allowance. An equal share bounds the total correctly but churns
518            // permanently: once the inactive stores hold their shares, a column that
519            // is stably dense exceeds its own share every batch and is shrunk every
520            // batch, reallocating on the next one (issue #3552, roborev round 12).
521            //
522            // Usage-proportional keeps an actively populated store warm and takes the
523            // space back from the ones that went quiet. The total bound still holds:
524            // the kept slots sum to `Σ last_used[c] × SLACK` = `used × SLACK`, and
525            // `used <= peak_cells`, so the sum cannot exceed the allowance.
526            let Self {
527                cells, last_used, ..
528            } = self;
529            for (idx, column) in cells.iter_mut().enumerate() {
530                let keep = last_used
531                    .get(idx)
532                    .copied()
533                    .unwrap_or(0)
534                    .saturating_mul(RETAINED_SLOT_SLACK);
535                if column.capacity() > keep {
536                    column.shrink_to(keep);
537                }
538            }
539        }
540        self.rows = 0;
541    }
542
543    /// Total retained cell slots across every column store — the quantity
544    /// [`Self::clear`]'s trim bounds. Exposed so that bound is TESTED rather than
545    /// merely asserted in a comment.
546    #[cfg(test)]
547    pub(crate) fn retained_cell_slots(&self) -> usize {
548        self.cells.iter().map(Vec::capacity).sum()
549    }
550
551    /// Retained slots of ONE column's store.
552    ///
553    /// Separate from [`Self::retained_cell_slots`] because the two answer different
554    /// questions and the total cannot stand in for the per-column value: an
555    /// equal-share trim keeps the TOTAL at its allowance while shrinking whichever
556    /// column is actually being used, so a test asserting on the total passes for an
557    /// implementation that churns (issue #3552, roborev round 12 — caught by a mutant
558    /// run, not by the test itself).
559    #[cfg(test)]
560    pub(crate) fn retained_cell_slots_for(&self, column: usize) -> usize {
561        self.cells.get(column).map_or(0, Vec::capacity)
562    }
563
564    /// Re-derive the payload estimate of exactly the COMMITTED rows, charged from
565    /// the stored cells (not from a remembered running total).
566    ///
567    /// This is the O(rows) recomputation an incremental accumulator exists to
568    /// avoid; it exists so a consumer can keep an "accumulator describes exactly
569    /// the buffered rows" invariant enforced rather than merely documented.
570    pub fn recomputed_payload(&self) -> usize {
571        (0..self.rows).fold(0usize, |acc, row| {
572            acc.saturating_add(
573                self.prepared
574                    .row_bytes_columnar(&self.cells, &self.canonical, row),
575            )
576        })
577    }
578
579    /// Build the Arrow batch for the committed rows from the ALREADY-transposed
580    /// column-major cells.
581    ///
582    /// Identical output to `rows_to_record_batch(columns, rows)` over the same
583    /// rows: the same schema, the same per-column builder dispatch, and the same
584    /// cell slices — only the transpose has moved to push time.
585    ///
586    /// # Errors
587    ///
588    /// [`ArrowConvertError`] if a value cannot be represented in the target Arrow
589    /// type, or if schema/array construction fails.
590    pub fn to_record_batch(&self) -> Result<RecordBatch, ArrowConvertError> {
591        let schema = Arc::new(build_arrow_schema(self.columns)?);
592        // Fail closed rather than build a short array list `RecordBatch::try_new`
593        // would have to reject: the three must be the same arity by construction.
594        if self.cells.len() != self.columns.len()
595            || self.canonical.len() != self.columns.len()
596            || self.prepared.len() != self.columns.len()
597        {
598            return Err(ArrowConvertError::InvalidValue(format!(
599                "columnar accumulator arity {} does not match the {} projected columns",
600                self.cells.len(),
601                self.columns.len()
602            )));
603        }
604        // ONE dense borrowed view, reused across columns: the builders need a
605        // row-aligned `&[Option<&Value>]`, but only TRANSIENTLY, so the dense
606        // structure is materialized here rather than retained (issue #3552 review
607        // B4). It costs `rows × size_of::<Option<&Value>>()` once per BATCH —
608        // `transpose_columns` allocated that PER COLUMN, so this term is smaller
609        // than `main`'s by a factor of the projection width.
610        let mut view: Vec<Option<&Value>> = Vec::with_capacity(self.rows);
611        let mut arrays: Vec<ArrayRef> = Vec::with_capacity(self.columns.len());
612        for (idx, col) in self.columns.iter().enumerate() {
613            // Read through `canonical`: a duplicate-name column builds its array
614            // from the SAME stored cells as the first column of that name, so the
615            // value is BORROWED a second time rather than stored a second time —
616            // byte-identical output, one copy in memory (issue #3552 review B3).
617            let store = match self.canonical.get(idx).and_then(|&c| self.cells.get(c)) {
618                Some(store) => store,
619                None => {
620                    return Err(ArrowConvertError::InvalidValue(format!(
621                        "column {idx} has no canonical cell store"
622                    )))
623                }
624            };
625            // Fail closed on a stored row index outside the committed range rather
626            // than panic on the indexed write below. The store is sorted ascending
627            // (appended as rows commit), so its LAST entry bounds every entry — an
628            // O(1) check, not a scan.
629            if let Some(&(last_row, _)) = store.last() {
630                if last_row >= self.rows {
631                    return Err(ArrowConvertError::InvalidValue(format!(
632                        "column {idx} holds row index {last_row} outside the {} \
633                         committed rows",
634                        self.rows
635                    )));
636                }
637            }
638            // Dense fill: absent rows stay `None`, present rows are BORROWED from
639            // the sparse store. O(present cells), walking in row order — no search,
640            // and no reallocation after the first column.
641            view.clear();
642            view.resize(self.rows, None);
643            for (row_idx, value) in store {
644                // In range by the guard above, so this cannot panic.
645                view[*row_idx] = Some(value);
646            }
647            arrays.push(convert_column_to_array(col, &view)?);
648        }
649        Ok(RecordBatch::try_new(schema, arrays)?)
650    }
651}
