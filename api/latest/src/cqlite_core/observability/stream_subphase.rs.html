1//! In-`stream` sub-phase wall-time accumulator for the Flight `do_get` data plane
2//! (issue #2819).
3//!
4//! The Flight `do_get` `stream` phase (`cqlite-flight`) is a CONCURRENT pipeline:
5//! the merge consumer runs on one `spawn_blocking` thread and each input SSTable
6//! is scanned on its own producer thread, where the cold body-chunk page-in + LZ4
7//! decompress physically happen (synchronously, on that producer thread — NOT a
8//! separate `spawn_blocking` feed thread). To attribute WHERE the in-`stream` time
9//! goes (cold-IO vs decompress vs merge vs encode vs gRPC-write) WITHOUT a
10//! profiler, the flight side installs a per-request accumulator and each pipeline
11//! thread adds its own elapsed wall time into the right bucket.
12//!
13//! Thread-locals are NOT inherited across a thread spawn, so the per-request sink
14//! is propagated EXPLICITLY at each spawn site: the merge closure installs it on
15//! the merge consumer thread, and [`current`] captures it there so the per-SSTable
16//! producer thread can re-[`install`] the SAME `Arc`. A deeper `spawn_blocking`
17//! feed thread (the windowed-scan page-in path) is NOT reached by this
18//! propagation and is therefore NOT covered — the instrumented Summary-guided /
19//! full-ring compaction read paths run their page-in on the producer thread, which
20//! IS covered.
21//!
22//! This module owns the crate-side half of that seam so the `cqlite-core` scan
23//! path (which is where cold-fault + decompress physically happen) can push into
24//! it WITHOUT taking a new parameter on every hot reader signature:
25//!
26//! * [`StreamSubPhaseTimings`] — five `AtomicU64` nanosecond counters shared via an
27//!   `Arc`, so scopes on the concurrent pipeline threads accumulate lock-free.
28//! * A thread-local `Option<Arc<StreamSubPhaseTimings>>` sink installed for the
29//!   duration of one RPC's work on a thread, via the panic-safe RAII
30//!   [`StreamSubPhaseGuard`]. [`current`] reads it (so a spawn site can propagate
31//!   the SAME `Arc` onto a child scan thread); [`timed`] times a closure and
32//!   attributes it to a sub-phase on the installed sink.
33//! * A thread-local recv-wait accumulator ([`add_pull_wait_nanos`] /
34//!   [`pull_wait_nanos`]) the merge consumer thread uses to EXCLUDE the blocking
35//!   merge-input channel wait from `stream_merge` (issue #2819 B2 — that wait is
36//!   producer starvation / cold-IO, not merge CPU).
37//!
38//! # Zero-cost when absent
39//!
40//! Every non-flight caller (compaction, CLI, point reads) never installs a sink,
41//! so [`current`] returns `None`, [`timed`] runs the closure with a single
42//! thread-local peek and NO `Instant::now()` and NO atomic write, and
43//! [`record_nanos`] is a no-op. The instrumentation is paid for only on the flight
44//! streaming path that opted in.
45//!
46//! # Isolation
47//!
48//! The sink is scoped to the request's scan threads only: it is installed with an
49//! RAII guard that restores the previous thread-local value on drop (including on
50//! panic / unwind), so a reused blocking-pool thread never leaks one RPC's `Arc`
51//! into another RPC or an unrelated thread.
52

58/// One of the six in-`stream` data-plane sub-phases (issue #2819; `EncodeFraming`
59/// added by issue #3096). Which thread records each is fixed by the pipeline
60/// architecture: `ColdFault`/`Decompress` on the per-SSTable PRODUCER thread(s)
61/// (where the page-in + decompress run synchronously), `Merge`/`Encode`/`GrpcWrite`
62/// all on the MERGE-CONSUMER `spawn_blocking` thread (`GrpcWrite` is
63/// `ChannelSink::emit`, which runs on that thread, NOT a separate egress thread),
64/// and `EncodeFraming` on the ASYNC gRPC task that polls the response stream. The
65/// flight side maps these to the bounded `cqlite.rpc.phase` values
66/// `stream_cold_fault` / `stream_decompress` / `stream_merge` / `stream_encode` /
67/// `stream_encode_framing` / `stream_grpc_write`.
68#[derive(Debug, Clone, Copy, PartialEq, Eq)]
69pub enum StreamSubPhase {
70    /// Synchronous SSTable body-chunk page-in (cold-IO latency).
71    ColdFault,
72    /// LZ4 chunk decompression of a read body chunk.
73    Decompress,
74    /// k-way merge + LWW/tombstone/TTL reconcile + per-row materialize.
75    Merge,
76    /// Arrow `RecordBatch` conversion (encode): the projected cells' RESOLUTION
77    /// plus the ARRAY BUILD, on the merge-consumer thread.
78    ///
79    /// # Scope, and how it CHANGED at issue #3552 — read before comparing across
80    /// that commit
81    ///
82    /// Until #3552 this bucket was recorded in exactly one place, around
83    /// `cqlite-flight`'s `flush_buffer`, and covered the row→column transpose plus
84    /// the Arrow array build. #3552 folded the transpose into the byte-cap's
85    /// push-time cell resolution AND column-major commit (`ArrowRowAccumulator::stage`
86    /// then `::commit` — BOTH are inside the timed window; naming only `stage` is what
87    /// made this bucket under-report wide projections until roborev round 7), so the bucket is
88    /// now recorded from TWO places that sum into it: the push-time resolution
89    /// (`cqlite_flight::egress_flush::StageEncodeAccum`, folded in once per merge)
90    /// and the flush-time build (still `flush_buffer`).
91    ///
92    /// Recording both is what keeps the bucket from silently SHRINKING while the
93    /// work merely moved out of the measured window. But the two are not the same
94    /// SPAN of work, and the difference matters in ONE direction: the fused
95    /// resolution also performs the per-row width CHARGE, which before #3552 was a
96    /// separate `estimate_arrow_row_bytes` call at push time that sat in NO
97    /// sub-phase at all. So across #3552 this counter LOSES nothing and GAINS the
98    /// charge — it can read higher on identical work, and a naive before/after diff
99    /// of `stream_encode` alone across that commit is not a like-for-like
100    /// comparison. What IS comparable: rows/s.
101    ///
102    /// `merge + encode` is NOT, and an earlier revision of this comment said it was —
103    /// citing the very fact that refutes it. The charge sat outside BOTH buckets
104    /// before and is inside `encode` now, so the SUM gains it exactly as `encode`
105    /// does; summing two buckets cannot cancel work that was in neither
106    /// (issue #3552, roborev round 11). Use throughput, or normalise per row. The fold's whole point is that the
107    /// resolution and the charge are no longer separable, so no honest split of the
108    /// fused region into two buckets exists.
109    Encode,
110    /// Arrow-flight IPC FRAMING of an already-built `RecordBatch`: everything
111    /// `FlightDataEncoderBuilder`'s stream does — dictionary hydration, splitting
112    /// a batch that exceeds the encoder's `GRPC_TARGET_MAX_FLIGHT_SIZE_BYTES`, and
113    /// the IPC serialization into `FlightData` messages (issue #3096).
114    ///
115    /// # Why this is a SEPARATE bucket from [`Self::Encode`]
116    ///
117    /// [`Self::Encode`] wraps only the projected cells' resolution and the Arrow
118    /// array build, on the merge-consumer thread (before issue #3552, the
119    /// transpose plus `rows_to_record_batch` inside `flush_buffer`; since then,
120    /// the push-time resolution as well — see that variant's scope note). It has never covered
121    /// the encoder stage, which runs LATER and on a DIFFERENT thread (the async
122    /// gRPC task). Any change aimed at the framing stage — the batch-size/encoder
123    /// target alignment, or the dictionary-hydration rebuild — was therefore
124    /// UNFALSIFIABLE from in-process timings alone: the only bucket that could
125    /// have moved does not span the code being changed. This variant closes that
126    /// blind spot.
127    ///
128    /// It measures the framing stage's POLL time, so it also contains the (cheap,
129    /// non-blocking) downstream channel poll that returns `Pending` when the merge
130    /// has not yet produced a batch. It is a server-side CPU bucket in the same
131    /// sense as [`Self::Encode`], not a client-paced one like [`Self::GrpcWrite`].
132    EncodeFraming,
133    /// Egress channel `reserve()`/send, including backpressure park/wake.
134    GrpcWrite,
135}

137/// Per-request accumulator of in-`stream` sub-phase wall time, in nanoseconds.
138///
139/// Six `AtomicU64` counters so RAII scopes running on the CONCURRENT pipeline
140/// threads (the per-SSTable producer thread(s), the merge-consumer thread, and —
141/// for [`StreamSubPhase::EncodeFraming`] — the async gRPC task) all `fetch_add`
142/// into the same shared instance lock-free. The sub-phases OVERLAP in
143/// wall-clock (the pipeline is concurrent), so the counters are NOT expected to
144/// sum to the `stream` phase's duration — the load-bearing signal is the
145/// cold−warm delta on the cold-fault counter (issue #2819, amended accounting
146/// model).
147#[derive(Debug, Default)]
148pub struct StreamSubPhaseTimings {
149    cold_fault_nanos: AtomicU64,
150    decompress_nanos: AtomicU64,
151    merge_nanos: AtomicU64,
152    encode_nanos: AtomicU64,
153    encode_framing_nanos: AtomicU64,
154    grpc_write_nanos: AtomicU64,
155}
156
157impl StreamSubPhaseTimings {
158    fn counter(&self, phase: StreamSubPhase) -> &AtomicU64 {
159        match phase {
160            StreamSubPhase::ColdFault => &self.cold_fault_nanos,
161            StreamSubPhase::Decompress => &self.decompress_nanos,
162            StreamSubPhase::Merge => &self.merge_nanos,
163            StreamSubPhase::Encode => &self.encode_nanos,
164            StreamSubPhase::EncodeFraming => &self.encode_framing_nanos,
165            StreamSubPhase::GrpcWrite => &self.grpc_write_nanos,
166        }
167    }
168
169    /// Add `nanos` to `phase`'s counter (SATURATING, `Relaxed` — the counters are
170    /// independent per-sub-phase totals with no ordering dependency). A plain
171    /// `fetch_add` would already be atomic and correct under the several concurrent
172    /// producer threads that share one `Arc` and write `cold_fault`/`decompress`;
173    /// the CAS loop (`fetch_update`) is used SOLELY so the add SATURATES instead of
174    /// wrapping on the (practically unreachable) `u64` nanosecond overflow.
175    pub fn add_nanos(&self, phase: StreamSubPhase, nanos: u64) {
176        let _ = self
177            .counter(phase)
178            .fetch_update(Ordering::Relaxed, Ordering::Relaxed, |v| {
179                Some(v.saturating_add(nanos))
180            });
181    }
182
183    /// Read `phase`'s accumulated nanoseconds (a snapshot; a concurrently-running
184    /// producer thread may add more after this read — acceptable, the emission is a
185    /// best-effort per-RPC snapshot at teardown).
186    pub fn nanos(&self, phase: StreamSubPhase) -> u64 {
187        self.counter(phase).load(Ordering::Relaxed)
188    }
189}

191thread_local! {
192    /// The current thread's installed sub-phase sink, or `None` for every
193    /// non-flight caller. `const`-initialised so the common (unset) path is a
194    /// cheap thread-local read with no lazy init.
195    static CURRENT_SINK: RefCell<Option<Arc<StreamSubPhaseTimings>>> =
196        const { RefCell::new(None) };
197
198    /// Fast `Cell<bool>` mirror of "a sink is installed on this thread", kept in
199    /// lock-step with `CURRENT_SINK` by [`install`] + the guard's `Drop`. A hot
200    /// caller (the merge-input recv-wait site) gates its `Instant::now()` on this
201    /// single `Cell` load instead of a `RefCell` borrow + `Arc` clone (issue #2819
202    /// B3) — so a non-flight scan pays effectively nothing.
203    static SINK_ACTIVE: Cell<bool> = const { Cell::new(false) };
204
205    /// Running merge-input channel recv-wait accrued on THIS (merge consumer)
206    /// thread, in nanoseconds (issue #2819 B2). The row-drive loop snapshots it
207    /// around each `step_row` and subtracts the delta from that step's wall time,
208    /// so the blocking wait for a producer to deliver the next entry (producer
209    /// starvation / cold-IO) is EXCLUDED from `stream_merge` — leaving merge CPU.
210    static PULL_WAIT_NANOS: Cell<u64> = const { Cell::new(0) };
211}
212
213/// RAII guard restoring the previous sub-phase sink on drop — panic-safe, so a
214/// reused blocking-pool thread never leaks one RPC's sink into another.
215#[must_use = "the sink is uninstalled when the guard is dropped"]
216pub struct StreamSubPhaseGuard {
217    prev: Option<Arc<StreamSubPhaseTimings>>,
218    prev_active: bool,
219}
220
221impl Drop for StreamSubPhaseGuard {
222    fn drop(&mut self) {
223        let prev = self.prev.take();
224        CURRENT_SINK.with(|c| *c.borrow_mut() = prev);
225        SINK_ACTIVE.with(|c| c.set(self.prev_active));
226    }
227}
228
229/// Install `sink` as the current thread's sub-phase sink for the lifetime of the
230/// returned guard, restoring the previous value on drop. Passing `None` installs
231/// "no sink" (used when a scan-thread spawn captured `None` from a non-flight
232/// caller) — still restoring the prior value on drop.
233pub fn install(sink: Option<Arc<StreamSubPhaseTimings>>) -> StreamSubPhaseGuard {
234    let active = sink.is_some();
235    let prev = CURRENT_SINK.with(|c| std::mem::replace(&mut *c.borrow_mut(), sink));
236    let prev_active = SINK_ACTIVE.with(|c| c.replace(active));
237    StreamSubPhaseGuard { prev, prev_active }
238}
239
240/// Whether a flight sub-phase sink is installed on this thread — a cheap
241/// `Cell<bool>` load (no `RefCell` borrow, no `Arc` clone). A hot caller uses it
242/// to skip `Instant::now()` entirely on the non-flight path (issue #2819 B3).
243pub fn sink_active() -> bool {
244    SINK_ACTIVE.with(|c| c.get())
245}
246
247/// Add merge-input channel recv-wait (`nanos`) to this thread's running pull-wait
248/// total (issue #2819 B2). Recorded only by the merge consumer thread, at the
249/// blocking `SSTableRowIterator::next` recv site, so the row-drive loop can
250/// subtract it from `stream_merge`. A plain thread-local `Cell` add — cheap, and
251/// never touched on the non-flight path (the caller gates on [`sink_active`]).
252pub fn add_pull_wait_nanos(nanos: u64) {
253    PULL_WAIT_NANOS.with(|c| c.set(c.get().saturating_add(nanos)));
254}
255
256/// This thread's running merge-input recv-wait total, in nanoseconds (issue #2819
257/// B2). The drive loop reads it before/after each `step_row` and uses the delta.
258pub fn pull_wait_nanos() -> u64 {
259    PULL_WAIT_NANOS.with(|c| c.get())
260}

262/// The current thread's installed sub-phase sink, if any. A scan-thread spawn
263/// site calls this on the PARENT thread and re-[`install`]s the captured value on
264/// the CHILD thread, so the per-SSTable producer thread's page-in/decompress reach
265/// the request's accumulator.
266pub fn current() -> Option<Arc<StreamSubPhaseTimings>> {
267    CURRENT_SINK.with(|c| c.borrow().clone())
268}
269
270/// Clamped nanoseconds elapsed since `start` — the ONE place the `Instant`→`u64`
271/// clamp lives (issue #2819 L3), reused by every sub-phase timing site. A scan
272/// long enough to overflow `u64` nanoseconds (~584 years) is unreachable.
273pub fn elapsed_nanos(start: Instant) -> u64 {
274    start.elapsed().as_nanos().min(u64::MAX as u128) as u64
275}
276
277/// Time `f` and, IF a sink is installed on this thread, attribute its elapsed
278/// wall time to `phase`. When no sink is installed (every non-flight caller) this
279/// is a single thread-local peek plus the bare closure — no `Instant::now()`, no
280/// atomic write — so the hot scan path pays effectively nothing.
281pub fn timed<T>(phase: StreamSubPhase, f: impl FnOnce() -> T) -> T {
282    // Clone the Arc only when a sink is actually installed, so the unset path
283    // never touches a refcount.
284    let sink = current();
285    match sink {
286        None => f(),
287        Some(sink) => {
288            let start = Instant::now();
289            let out = f();
290            sink.add_nanos(phase, elapsed_nanos(start));
291            out
292        }
293    }
294}

296/// Add `nanos` directly to `phase` on the current thread's sink, if installed
297/// (no-op otherwise). For a caller that measured elapsed time itself rather than
298/// wrapping a closure via [`timed`].
299pub fn record_nanos(phase: StreamSubPhase, nanos: u64) {
300    CURRENT_SINK.with(|c| {
301        if let Some(sink) = c.borrow().as_ref() {
302            sink.add_nanos(phase, nanos);
303        }
304    });
305}

307/// RAII timer that records the elapsed wall time into `phase` when dropped. The
308/// tight-scope counterpart of [`timed`] for an ASYNC region that a sync closure
309/// cannot wrap (e.g. an `.await`ed page-in): bind it in a `{ let _t = …; expr }`
310/// block so it drops the instant the region ends.
311///
312/// It CAPTURES the sink `Arc` at construction (like [`timed`]), NOT via the
313/// thread-local at drop time — so it stays correct even if the guard is held
314/// across an `.await` that resumes the future on a DIFFERENT executor thread
315/// (issue #2819 L1). A `None` sink means "not installed" — a no-op on drop.
316pub struct SubPhaseTimer {
317    phase: StreamSubPhase,
318    start: Instant,
319    sink: Arc<StreamSubPhaseTimings>,
320}
321
322impl Drop for SubPhaseTimer {
323    fn drop(&mut self) {
324        self.sink.add_nanos(self.phase, elapsed_nanos(self.start));
325    }
326}
327
328/// A [`SubPhaseTimer`] for `phase`, or `None` (zero `Instant::now`) when no sink
329/// is installed — so a non-flight caller pays nothing. The sink `Arc` is captured
330/// here (correct-by-construction across an `.await`), never re-resolved at drop.
331pub fn scoped(phase: StreamSubPhase) -> Option<SubPhaseTimer> {
332    scoped_captured(&current(), phase)
333}
334
335/// A [`SubPhaseTimer`] for `phase` built from an ALREADY-CAPTURED sink (from a
336/// prior [`current`] call), so NO thread-local read happens here (issue #2819
337/// L1). Use when the timer must be constructed AFTER an `.await` that may resume
338/// on a different executor thread — capture the sink ONCE before the await, then
339/// build each timer from that captured `Option`.
340pub fn scoped_captured(
341    sink: &Option<Arc<StreamSubPhaseTimings>>,
342    phase: StreamSubPhase,
343) -> Option<SubPhaseTimer> {
344    sink.clone().map(|sink| SubPhaseTimer {
345        phase,
346        start: Instant::now(),
347        sink,
348    })
349}

351/// Time `f` (a BLOCKING merge-input recv) and add its elapsed to this thread's
352/// pull-wait accumulator IF a sink is installed, so the row-drive loop can
353/// EXCLUDE it from `stream_merge` (issue #2819 B2). Zero `Instant::now` when
354/// inert, so the non-flight compaction merge pays nothing.
355pub fn time_recv<T>(f: impl FnOnce() -> T) -> T {
356    // Also armed by an installed READ-phase sink (issue #1707): `read.phase.merge`
357    // subtracts this SAME per-thread accumulator's delta from each merge step, so
358    // producer starvation is not charged to merge CPU. ONE accumulator and ONE call
359    // site serve both accountings — duplicating a second thread-local and a second
360    // recv-site call is the "two statements of one fact can disagree" shape.
361    if sink_active() || super::read_phase::sink_active() {
362        let start = Instant::now();
363        let out = f();
364        add_pull_wait_nanos(elapsed_nanos(start));
365        out
366    } else {
367        f()
368    }
369}

376    #[test]
377    fn timed_is_noop_when_no_sink_installed() {
378        // No sink on this thread: `timed` must still run the closure and record
379        // nothing anywhere (there is nowhere to record).
380        assert!(current().is_none());
381        let ran = AtomicBool::new(false);
382        let out = timed(StreamSubPhase::ColdFault, || {
383            ran.store(true, Ordering::Relaxed);
384            42
385        });
386        assert_eq!(out, 42);
387        assert!(ran.load(Ordering::Relaxed));
388        assert!(current().is_none(), "no sink leaked onto the thread");
389    }
390
391    #[test]
392    fn timed_accumulates_into_the_installed_sink() {
393        let sink = Arc::new(StreamSubPhaseTimings::default());
394        let _g = install(Some(sink.clone()));
395        timed(StreamSubPhase::Decompress, || {
396            std::thread::sleep(std::time::Duration::from_millis(2));
397        });
398        assert!(
399            sink.nanos(StreamSubPhase::Decompress) > 0,
400            "a wrapped op accumulates into its bucket"
401        );
402        assert_eq!(
403            sink.nanos(StreamSubPhase::ColdFault),
404            0,
405            "an unentered bucket stays zero"
406        );
407    }
408
409    #[test]
410    fn guard_restores_previous_sink_on_drop() {
411        assert!(current().is_none());
412        {
413            let sink = Arc::new(StreamSubPhaseTimings::default());
414            let _g = install(Some(sink));
415            assert!(current().is_some());
416        }
417        assert!(
418            current().is_none(),
419            "dropping the guard uninstalls the sink (no leak across RPCs)"
420        );
421    }
422
423    #[test]
424    fn sink_propagates_across_a_spawned_thread() {
425        // Mirrors the scan-thread propagation: capture `current()` on the parent,
426        // re-install on the child, and the child's recording lands in the SAME Arc.
427        let sink = Arc::new(StreamSubPhaseTimings::default());
428        let _g = install(Some(sink.clone()));
429        let captured = current();
430        std::thread::spawn(move || {
431            let _child = install(captured);
432            record_nanos(StreamSubPhase::ColdFault, 1234);
433        })
434        .join()
435        .expect("child thread joins");
436        assert_eq!(
437            sink.nanos(StreamSubPhase::ColdFault),
438            1234,
439            "the child thread accumulated into the propagated per-request sink"
440        );
441    }
442
443    #[test]
444    fn record_nanos_is_noop_without_a_sink() {
445        assert!(current().is_none());
446        record_nanos(StreamSubPhase::Merge, 999); // must not panic
447        assert!(current().is_none());
448    }

450    #[test]
451    fn sink_active_mirrors_install_and_restores_on_drop() {
452        assert!(!sink_active(), "no sink installed at start");
453        {
454            let sink = Arc::new(StreamSubPhaseTimings::default());
455            let _g = install(Some(sink));
456            assert!(sink_active(), "sink_active tracks an installed sink");
457            {
458                // A nested `None` install (a non-flight child capture) flips the
459                // fast bool off, then restores the outer `true` on drop.
460                let _none = install(None);
461                assert!(!sink_active(), "nested None install deactivates");
462            }
463            assert!(sink_active(), "outer sink restored after nested drop");
464        }
465        assert!(!sink_active(), "sink_active cleared once the guard drops");
466    }

468    #[test]
469    fn pull_wait_accumulates_on_this_thread() {
470        // A fresh thread starts at zero (thread-locals do not leak across
471        // threads); the accumulator is a plain running total.
472        std::thread::spawn(|| {
473            assert_eq!(pull_wait_nanos(), 0);
474            add_pull_wait_nanos(100);
475            add_pull_wait_nanos(50);
476            assert_eq!(
477                pull_wait_nanos(),
478                150,
479                "recv-wait accumulates monotonically"
480            );
481        })
482        .join()
483        .expect("thread joins");
484    }

486    #[test]
487    fn add_nanos_saturates_rather_than_wrapping() {
488        let sink = StreamSubPhaseTimings::default();
489        sink.add_nanos(StreamSubPhase::Merge, u64::MAX);
490        sink.add_nanos(StreamSubPhase::Merge, 10);
491        assert_eq!(
492            sink.nanos(StreamSubPhase::Merge),
493            u64::MAX,
494            "a second add saturates at u64::MAX instead of wrapping to a tiny value"
495        );
