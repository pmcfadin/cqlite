1//! Arrow Flight gRPC metric names — the `cqlite.rpc.*`, `cqlite.warm.cache.*` and
2//! `cqlite.flight.admission.*` constants of [`super`] (issue #1041 / #2310 / #2420).
3//!
4//! Split out of `catalog.rs` mechanically (issue #1707, campsite rule #1116): the
5//! Arrow Flight RPC surface is one responsibility and it is the only family in the
6//! catalog emitted entirely from ANOTHER crate (`cqlite-flight`), so it reads as a
7//! unit. Every constant is re-exported from [`super`], so the public paths
8//! (`observability::catalog::RPC_DURATION`, …) are unchanged and no caller moves.
9//!
10//! Declaration-parsing note: the catalog guards recover `pub const IDENT: &str =
11//! "…";` declarations from SOURCE, and they scan `catalog.rs` AND this file (see
12//! `catalog_tests::catalog_sources`). A future split must be added there too, or the
13//! guards go blind to the constants it moves.

19/// `cqlite.rpc.requests` — counter `1`.
20///
21/// Total Arrow Flight RPC requests served, one increment per completed RPC.
22/// Bounded attributes: [`super::attr::RPC_METHOD`] (fixed `FlightService` method set)
23/// and [`super::attr::RPC_STATUS`] (`ok`/`error`) so a dashboard computes per-method
24/// error rate from one series. NEVER carries request payloads or ticket data.
25pub const RPC_REQUESTS: &str = "cqlite.rpc.requests";
26
27/// `cqlite.rpc.duration` — histogram `s`.
28///
29/// Distribution of Arrow Flight RPC handler durations in seconds (handler entry
30/// to response/stream construction). Bounded attributes: [`super::attr::RPC_METHOD`],
31/// [`super::attr::RPC_STATUS`].
32pub const RPC_DURATION: &str = "cqlite.rpc.duration";
33
34/// `cqlite.rpc.in_flight` — gauge `1`.
35///
36/// Number of Arrow Flight RPCs currently being handled (incremented on entry,
37/// decremented on completion). Bounded attributes: [`super::attr::RPC_METHOD`].
38pub const RPC_IN_FLIGHT: &str = "cqlite.rpc.in_flight";
39
40/// `cqlite.rpc.rows` — counter `{row}`.
41///
42/// Total rows returned to clients by `do_get` (summed across emitted record
43/// batches). Emitted incrementally during a long-running scan (issue #2162): a
44/// monotonic counter delta per record batch as it passes toward the client, so a
45/// climbing value reads as a healthy long scan and a flat one (while
46/// [`RPC_IN_FLIGHT`] > 0) as a stall. The counter total over a fully-drained
47/// stream is unchanged — only the emission cadence moved from stream-end to
48/// per-batch. Bounded attributes: [`super::attr::RPC_METHOD`].
49pub const RPC_ROWS: &str = "cqlite.rpc.rows";
50
51/// `cqlite.rpc.bytes` — counter `By`.
52///
53/// Total record-batch payload bytes streamed to clients by `do_get` (in-memory
54/// Arrow batch size, pre-IPC-framing). Emitted incrementally during a
55/// long-running scan (issue #2162): a monotonic counter delta per record batch;
56/// the total over a fully-drained stream is byte-identical to the pre-#2162
57/// single end-of-stream emission. Bounded attributes: [`super::attr::RPC_METHOD`].
58pub const RPC_BYTES: &str = "cqlite.rpc.bytes";
59
60/// `cqlite.rpc.phase.duration` — histogram `s` (issue #2162; `admission` phase
61/// added #2420 roborev-1700; `validate` phase added #2420 roborev-1702).
62///
63/// Wall time a `do_get` spends in each of a bounded, closed set of execution
64/// phases — `validate` (parsing the ticket bytes, BEFORE any admission-permit
65/// acquire — a syntactically malformed ticket records ONLY this phase),
66/// `admission` (queued waiting for, or immediately granted, an admission permit
67/// — see #2420 — AFTER validation but BEFORE any producer/schema construction
68/// or filesystem access), `resolve` (producer/schema construction + path
69/// discovery/token prune), `merge_setup` (opening input SSTables + building the
70/// k-way merger, the #2157 stall suspect), and `stream` (partitions stepping +
71/// batches flowing to the client). Recorded once per phase transition, so a
72/// `do_get` dominated by opening SSTables shows its wall time accumulating in
73/// `merge_setup` BEFORE the first batch, and a `do_get` queued behind a
74/// saturated admission ceiling shows it accumulating in `admission` BEFORE
75/// `resolve` even starts — a stall (or queueing delay, or a flood of malformed
76/// tickets) that emits zero rows still localizes to a phase. `cqlite.rpc.duration`
77/// already includes admission wait time in the RPC total; this is the per-phase
78/// breakdown field triage uses to localize WHERE that time went (e.g. #2398).
79/// Bounded attributes: [`super::attr::RPC_METHOD`], [`super::attr::RPC_PHASE`] (the closed
80/// five-value set). NEVER carries a ticket, key, token range, or query-text
81/// attribute.
82pub const RPC_PHASE_DURATION: &str = "cqlite.rpc.phase.duration";
83
84/// `cqlite.rpc.phase.active` — gauge `1` (issue #2361; `admission` phase added
85/// #2420 roborev-1700; `validate` phase added #2420 roborev-1702).
86///
87/// In-flight visibility of the phase a `do_get` is CURRENTLY executing, set to 1
88/// on phase entry and back to 0 on exit (via [`super::super`]'s `PhaseTimer`
89/// transition/`Drop`). [`RPC_PHASE_DURATION`] only records a sample once a phase
90/// COMPLETES, so a `do_get` wedged forever in `stream` (the #2361 hang: a merge
91/// that never returns a batch) recorded NOTHING — this gauge shows `stream = 1`
92/// for the entire hang, so a stall is observable BEFORE completion; likewise a
93/// `do_get` queued behind a saturated admission ceiling shows `admission = 1`
94/// for the whole wait. Bounded attributes: [`super::attr::RPC_METHOD`],
95/// [`super::attr::RPC_PHASE`] (the closed five-value set) — low cardinality (methods ×
96/// 5 phases). NEVER a ticket/key/query value.
97pub const RPC_PHASE_ACTIVE: &str = "cqlite.rpc.phase.active";

99/// `cqlite.warm.cache.hits` — counter `{1}` (issue #2310).
100///
101/// Flight warm-handle cache hits: a request whose probed SSTable generation set
102/// matched the cached set, served from warm parsed state with ZERO reader-open
103/// and zero Index/Summary/Statistics/bloom parse. No attributes (bounded).
104pub const WARM_CACHE_HITS: &str = "cqlite.warm.cache.hits";
105
106/// `cqlite.warm.cache.misses` — counter `{1}` (issue #2310).
107///
108/// Flight warm-handle cache misses: no cached entry, or the generation set
109/// changed so a (delta) rebuild was required. No attributes (bounded).
110pub const WARM_CACHE_MISSES: &str = "cqlite.warm.cache.misses";
111
112/// `cqlite.warm.cache.evicts` — counter `{1}` (issue #2310).
113///
114/// Warm generations evicted, whether by LRU (byte-budget pressure) or because a
115/// rebuild found them removed on disk. No attributes (bounded).
116pub const WARM_CACHE_EVICTS: &str = "cqlite.warm.cache.evicts";
117
118/// `cqlite.warm.cache.refresh` — counter `{1}` (issue #2310).
119///
120/// Warm-handle refresh outcomes, tagged by [`super::attr::WARM_REFRESH_OUTCOME`]
121/// (`unchanged` / `rebuilt_delta` / `fail_closed_retained`) — the single bounded
122/// dimension. Distinguishes a warm hit from a delta rebuild from a fail-closed
123/// retention in metrics alone (spec Requirement 6).
124pub const WARM_CACHE_REFRESH: &str = "cqlite.warm.cache.refresh";
125
126/// `cqlite.flight.admission.limit` — gauge `1` (issue #2420, WS4).
127///
128/// The configured `do_get` admission ceiling `K` (the `--max-concurrent-scans`
129/// value). A constant level while the server runs; recorded on startup so a
130/// dashboard can chart `in_use` against the limit. No attributes (bounded).
131/// DISTINCT from [`RPC_IN_FLIGHT`]: this is the CONFIGURED ceiling, not a live
132/// count.
133pub const FLIGHT_ADMISSION_LIMIT: &str = "cqlite.flight.admission.limit";
134
135/// `cqlite.flight.admission.in_use` — gauge `1` (issue #2420, WS4).
136///
137/// `do_get` admission permits currently held — the number of scans ADMITTED and
138/// in-flight (an up/down level like [`RPC_IN_FLIGHT`], but counting only admitted
139/// scans, not every accepted RPC incl. the ones parked waiting for a permit).
140/// Returns to zero when every admitted scan completes/cancels/disconnects (the
141/// RAII permit release). No attributes (bounded). DISTINCT from [`RPC_IN_FLIGHT`].
142pub const FLIGHT_ADMISSION_IN_USE: &str = "cqlite.flight.admission.in_use";
143
144/// `cqlite.flight.admission.waiting` — gauge `1` (issue #2420, WS4).
145///
146/// `do_get` requests currently parked on `acquire`, waiting for an admission
147/// permit to free within the permit-wait timeout. A non-zero value is the
148/// backpressure signal: offered concurrency has exceeded the ceiling and requests
149/// are queuing rather than degrading together. No attributes (bounded).
150pub const FLIGHT_ADMISSION_WAITING: &str = "cqlite.flight.admission.waiting";
151
152/// `cqlite.flight.admission.rejected_total` — counter `{1}` (issue #2420, WS4).
153///
154/// `do_get` requests rejected because no admission permit freed within the
155/// permit-wait timeout — each returned to the client as gRPC `UNAVAILABLE` (so the
156/// connector's #2241 replica-failover treats it as retry-safe), before any record
157/// batch was delivered. A monotonic total; scale-free. No attributes (bounded).
158pub const FLIGHT_ADMISSION_REJECTED_TOTAL: &str = "cqlite.flight.admission.rejected_total";
159
160/// `cqlite.flight.admission.wait_seconds` — histogram `s` (issue #2420, WS4).
161///
162/// Distribution of how long a `do_get` waited on `acquire` before it was admitted
163/// (a permit freed) OR rejected (the wait timeout elapsed). Localizes admission
164/// pressure: a rising tail means requests are increasingly queuing for permits.
165/// No attributes (bounded).
166pub const FLIGHT_ADMISSION_WAIT_SECONDS: &str = "cqlite.flight.admission.wait_seconds";
