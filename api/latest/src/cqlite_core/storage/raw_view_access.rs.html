1//! The raw SSTable view's storage-side access seam (issue #4222).
2//!
3//! ONE responsibility: hand the raw view's row producers the per-generation
4//! [`SSTableReader`](super::sstable::reader::SSTableReader) set for a table, WITHOUT
5//! going through any of [`StorageEngine`](super::StorageEngine)'s reconciling
6//! read paths.
7//!
8//! Split out of `storage/mod.rs` under the campsite rule (epic #1116): that
9//! file sat 2 lines under the 800-line threshold on `origin/main` and this
10//! accessor is what pushed it over. Since the accessor is #4222's own code and
11//! is a self-contained responsibility, extracting it returns `storage/mod.rs`
12//! to its pre-PR size instead of spending a `CQLITE_ALLOW_FILE_GROWTH=1`
13//! opt-out on a file this change is solely responsible for crossing.
14//!
15//! ## Why the gate is on the `impl`, not on the module
16//!
17//! The accessor is reachable only under `state_machine` (its sole consumer,
18//! `query::select_executor::raw_view`, lives under `query::select_executor`,
19//! which is itself `#[cfg(feature = "state_machine")]` — `query/mod.rs:39`).
20//! Ungated it is genuinely dead code in any feature set omitting
21//! `state_machine`: the gate's `feature-iso-delta-scan` component builds
22//! exactly such a set with `-D warnings` and FAILed on it.
23//!
24//! The `#[cfg]` therefore sits on the `impl` block below rather than on the
25//! `mod` declaration in `storage/mod.rs`. Two reasons, in order:
26//!
27//! 1. `storage/mod.rs` had **2 lines of headroom** under the 800-line campsite
28//!    threshold on `origin/main` (798). A gated declaration costs three lines
29//!    (`#[cfg]` + `mod` + separator) and re-crosses it; a bare one costs one
30//!    and does not. The ratchet exists to stop NEW threshold crossings, and
31//!    this is the difference between causing one and not.
32//! 2. It does not weaken #1712, whose rule is that a top-level `pub mod NAME;`
33//!    in `lib.rs` must not be silently switched off by an inner `#![cfg(...)]`
34//!    in `NAME`'s own file. This is a PRIVATE module, not a `lib.rs` public
35//!    declaration, and the gate here is an ITEM-level `#[cfg]` on the `impl`,
36//!    not a module-level `#![cfg]` — so nothing about the crate's public
37//!    surface is misrepresented. Under a non-`state_machine` build this module
38//!    compiles to nothing, which is exactly what it should do.
39
40// Types are named by FULLY-QUALIFIED path below rather than imported: a `use`
41// here would be an unused import — a `-D warnings` ERROR — in every build that
42// cfg's the `impl` out, which is precisely the `feature-iso-delta-scan` lane
43// this module's gate exists to satisfy. Gating the imports too would work but
44// costs three more `#[cfg]` lines to say the same thing.
45#[cfg(feature = "state_machine")]
46impl super::StorageEngine {
47    /// Snapshot the resolved [`SSTableReader`](super::sstable::reader::SSTableReader) set
48    /// for `table_id`, plus the authoritative `fully_qualified_match` signal
49    /// (issue #4222, raw SSTable view).
50    ///
51    /// A thin passthrough to `SSTableManager::resolve_reader_snapshot` — the
52    /// raw view's point-key and full-scan row producers need the per-generation
53    /// readers DIRECTLY (never through
54    /// [`scan`](super::StorageEngine::scan)/[`scan_partition`](super::StorageEngine::scan_partition),
55    /// which RECONCILE across generations) so they can emit one row per
56    /// physical row per generation. `pub(crate)`: this bypasses every
57    /// reconciliation guarantee `StorageEngine`'s other methods provide, so it
58    /// is deliberately not part of the public API — only the query engine's
59    /// raw-view producer (`query::select_executor::raw_view`) calls it.
60    ///
61    /// The bool mirrors `SSTableManager::resolve_reader_snapshot`'s own
62    /// `fully_qualified_match`: `false` means a fully-qualified `table_id` (one
63    /// carrying a keyspace) resolved ONLY via the bare-table-name fallback —
64    /// the same signal the point-read path (`manager_point_read.rs`) threads
65    /// into `get_with_resolution_unmetered` to keep strict keyspace matching
66    /// on a fallback resolution (#1321), so a qualified raw-view name never
67    /// silently reads another keyspace's same-named table's rows.
68    ///
69    /// Reachable only under `state_machine` (see the module doc and the gated
70    /// declaration in `storage/mod.rs`): its sole consumer,
71    /// `query::select_executor::raw_view`, lives under
72    /// `query::select_executor`, which is itself
73    /// `#[cfg(feature = "state_machine")]` (`query/mod.rs:39`). Ungated it is
74    /// genuinely dead code in any feature set omitting `state_machine` — the
75    /// gate's `feature-iso-delta-scan` component builds exactly such a set with
76    /// `-D warnings` and FAILed on it. Gated to match the consumer rather than
77    /// silenced with `allow(dead_code)`, because this is a real "unreachable in
78    /// this configuration", not a false positive.
79    pub(crate) async fn raw_view_reader_snapshot(
80        &self,
81        table_id: &crate::TableId,
82    ) -> (
83        Vec<std::sync::Arc<super::sstable::reader::SSTableReader>>,
84        bool,
85    ) {
86        self.sstables.resolve_reader_snapshot(table_id).await
87    }
88}
