1//! Per-CALL cancellation for the detached `spawn_blocking` merges (issue #1695).
2//!
3//! # Why future-drop is not enough here
4//!
5//! The query budget (`query.max_execution_time`) is enforced by ONE
6//! `tokio::time::timeout` at the engine chokepoint (`query::engine::deadline`),
7//! and its whole cancellation mechanism is DROPPING the inner future. That is
8//! correct for async cooperative code — a dropped future stops being polled — but
9//! tokio CANNOT cancel a `spawn_blocking` closure by dropping its `JoinHandle`:
10//! the closure runs to completion on its blocking thread regardless.
11//!
12//! The materializing cross-generation merges build a `Vec` inside such a closure
13//! with no intermediate channel send that could fail, so a dropped handle left the
14//! ENTIRE multi-generation merge running after `Error::QueryTimeout` had already
15//! been returned to the caller — the timed-out query kept burning a blocking
16//! thread (and its scan-admission permit) to produce rows nobody would read.
17//! (The STREAMING driver has no such gap: its `blocking_send` fails as soon as the
18//! consumer is gone, which ends its loop within one merge step.)
19//!
20//! # Two granularities, and why the token also goes INTO the merger
21//!
22//! [`check`] is called once per partition, which is the merge's own unit of work
23//! — but a single `KWayMerger::step()` can itself be long, because the merger's
24//! producer threads are doing the actual SSTable decode. So the token is ALSO
25//! handed to the merger's input readers via `KWayMerger::new_cancellable` /
26//! `build_single_partition_merger_from_readers` (#2264's cooperative reader
27//! cancellation), letting an abandoned merge stop MID-step instead of finishing
28//! the partition it is decoding. This costs nothing and removes nothing: the
29//! tokens it displaces were `ScanCancel::default()` (what plain `KWayMerger::new`
30//! installs) and one literal `ScanCancel::new()` — neither reachable by any
31//! caller, so neither could ever be tripped. It must stay the PER-CALL token for
32//! the same reason as below; the shared reader token would cancel other queries.
33//! Producer TEARDOWN was already safe without this (#2361: dropping a
34//! `KWayMerger` closes the channel, trips the readers' token and joins the
35//! threads) — this is about promptness, not leaks.
36//!
37//! # Why the streaming producer needs its own check (roborev round 8)
38//!
39//! `stream_generations_for_read` was excluded from the guard above on the grounds
40//! that its `out_tx.blocking_send(..).is_err()` already retires it when the consumer
41//! drops. That reasoning was INCOMPLETE: a send-failure check is only reached when a
42//! partition actually yields a row, and three paths in that loop `continue` without
43//! sending — a partition below `start_key`, one above `end_key`, and one whose rows
44//! are all tombstoned or TTL-expired (`live` empty). A range scan matching nothing,
45//! or a no-match full scan, therefore performed not one send and so not one check,
46//! and walked the whole remaining table after `QueryTimeout` had already been handed
47//! back to the caller.
48//!
49//! It uses `Sender::is_closed()` at the top of its loop rather than this module's
50//! token: closure is already observable through the channel it owns, so nothing has
51//! to be plumbed in and no `Drop` impl is needed on the stream, and it strictly
52//! dominates the send-failure check. The token machinery here remains the right tool
53//! for the MATERIALIZING merges, which have no channel to consult at all.
54//!
55//! RESIDUAL: neither mechanism can abort a single long `KWayMerger::step()` on the
56//! streaming path, because that merger's readers still hold an inert
57//! `ScanCancel::default()`. Fixing that means a drop-tripped guard living inside
58//! `JoinedStream` so the readers can be cancelled too — the deferred "carry
59//! cancellation into the core streaming producer" work, which also covers the
60//! per-batch bound and lets core RECORD the elapse.
61//!
62//! # The shape: a guard in the async scope, a flag in the closure
63//!
64//! [`per_call`] mints a FRESH token per call and returns it paired with a guard
65//! that [`ScanCancel::cancel`]s it on `Drop`. The guard lives in the async fn's
66//! own scope, so whatever destroys that future — a timeout elapse, a client
67//! disconnect, a caller's `drop` — trips the flag, and the blocking merge loop
68//! observes it at its next per-partition check and abandons the merge.
69//!
70//! It is per-call BY CONSTRUCTION, which is the load-bearing property: the token
71//! on a shared [`crate::storage::sstable::reader::SSTableReader`]
72//! (`SSTableReader::scan_cancel`) is reachable from every query using that reader,
73//! so tripping THAT one would cancel other queries' in-flight scans. Nothing but a
74//! freshly-minted token is safe here.
75//!
76//! No deadline knowledge crosses this boundary: the merge never reads a clock and
77//! never learns the budget (issue #1695's mandate is one wrapper at the
78//! chokepoint, never ad-hoc clock checks in a scan loop). It only makes the
79//! blocking walk ABANDONABLE, at the same coarse per-partition cadence at which
80//! the async paths are already cancellable.

84/// Trips its token when dropped. Held in the async scope of a merge helper; the
85/// clone of the token it cancels lives inside that helper's blocking closure.
86pub(super) struct CancelOnDrop(ScanCancel);
87
88impl Drop for CancelOnDrop {
89    fn drop(&mut self) {
90        self.0.cancel();
91    }
92}
93
94/// A fresh per-call token plus the guard that cancels it when the calling future
95/// is dropped. Bind the guard (`let (_guard, cancel) = per_call();`) so it lives
96/// as long as the async fn's scope, and move `cancel` into the blocking closure.
97pub(super) fn per_call() -> (CancelOnDrop, ScanCancel) {
98    probe::record_armed();
99    let token = ScanCancel::new();
100    (CancelOnDrop(token.clone()), token)
101}
102
103/// The blocking merge loop's per-partition poll: `Err(Error::Cancelled)` once the
104/// caller's future is gone, else `Ok(())`.
105///
106/// Call it at the TOP of the loop, BEFORE `step()`, so an abandoned merge does no
107/// further work at all — that ordering is what makes "abandoned" mean "zero
108/// partitions merged since the flag was tripped", which is what the probe's
109/// [`probe::abandoned`] count lets a test assert without any timing.
110pub(super) fn check(cancel: &ScanCancel) -> crate::Result<()> {
111    if cancel.is_cancelled() {
112        probe::record_abandoned();
113        return Err(crate::Error::Cancelled);
114    }
115    Ok(())
116}

118/// Observability for the abandonment mechanism, on the `stream_merge_probe`
119/// pattern: the RECORD calls are unconditional `#[inline(always)]` functions whose
120/// BODIES are cfg-gated, so a default/release build links no atomic and pays
121/// nothing. Without them "the merge abandoned instead of running to completion" is
122/// unobservable from outside, and any test of it would have to time something.
123///
124/// Gated on `cfg(test)` ALONE — deliberately narrower than `stream_merge_probe`'s
125/// `any(test, feature = "work-counters")`. The only consumer is the in-crate
126/// [`super::abandon_tests`], which needs a `max_blocking_threads(1)` runtime it
127/// builds itself, so nothing in `tests/` can use these; adding the feature arm
128/// would only make the getters dead code in a `--all-features` build. A future
129/// integration consumer adds `feature = "work-counters"` back to all of the cfgs
130/// below, together. The READERS carry `not(feature = "tombstones")` as well,
131/// because their one caller does: that build has no `multi_gen_fixture` (its
132/// `scan_stream` routes through the materializing `scan`), so under
133/// `--all-features` the getters would be dead code.
134pub(super) mod probe {
135    #[cfg(test)]
136    use std::sync::atomic::{AtomicU64, Ordering};
137
138    /// Merges that ARMED a per-call guard (i.e. reached the spawn point).
139    #[cfg(test)]
140    static ARMED: AtomicU64 = AtomicU64::new(0);
141    /// Merge loops that exited via the cancel check rather than completing.
142    #[cfg(test)]
143    static ABANDONED: AtomicU64 = AtomicU64::new(0);
144
145    #[inline(always)]
146    pub(super) fn record_armed() {
147        #[cfg(test)]
148        ARMED.fetch_add(1, Ordering::Relaxed);
149    }
150
151    #[inline(always)]
152    pub(super) fn record_abandoned() {
153        #[cfg(test)]
154        ABANDONED.fetch_add(1, Ordering::Relaxed);
155    }
156
157    /// Merges that armed a guard since the last [`reset`].
158    #[cfg(all(test, not(feature = "tombstones")))]
159    pub(super) fn armed() -> u64 {
160        ARMED.load(Ordering::Relaxed)
161    }
162
163    /// Merge loops ABANDONED since the last [`reset`] — each one is a blocking
164    /// merge that stopped instead of building a `Vec` nobody could receive.
165    #[cfg(all(test, not(feature = "tombstones")))]
166    pub(super) fn abandoned() -> u64 {
167        ABANDONED.load(Ordering::Relaxed)
168    }
169
170    /// Zero both counters. The statics are process-global, so callers serialize on
171    /// the shared test mutex (the counter-test convention).
172    #[cfg(all(test, not(feature = "tombstones")))]
173    pub(super) fn reset() {
174        ARMED.store(0, Ordering::Relaxed);
175        ABANDONED.store(0, Ordering::Relaxed);
176    }
177}

186    /// Structural pin (#1695 roborev round 8): the STREAMING producer must observe
187    /// consumer closure BEFORE it does a merge step, not only when it sends.
188    ///
189    /// Behavioural coverage cannot reach this without being vacuous. To show the
190    /// difference you need a producer that is still alive, has work left, and has
191    /// nothing to send — and on any fixture small enough for the suite, a no-match
192    /// scan runs to completion and the producer exits ON ITS OWN, so the case passes
193    /// with the check deleted. Making it discriminating needs a fixture large enough
194    /// that "walks the rest of the table" is observably slower than "stops now",
195    /// which is a wall-clock threshold in the correctness path — forbidden. So the
196    /// invariant is asserted on the source, and ORDER is the substance of it: a check
197    /// placed after `step()` would still pay for a full step per iteration after the
198    /// consumer is gone.
199    #[test]
200    fn the_streaming_producer_checks_closure_before_stepping() {
201        let src = include_str!("../generation_merge.rs");
202
203        // Scope the pin to the STREAMING producer (issue #1707). Two corrections to
204        // the earlier form, both found by it breaking on a change that PRESERVED the
205        // invariant: it searched the WHOLE file, where the three MATERIALIZING merges
206        // also call `merger.step()` (and do so earlier), and it matched the statement
207        // prefix `let step = match merger.step()`, i.e. an incidental SPELLING —
208        // wrapping the call in the read-phase timing helper broke the pin while the
209        // ORDER it protects was untouched. The subject is this function's step CALL.
210        let region_start = src
211            .find("async fn stream_generations_for_read")
212            .expect("the streaming cross-generation merge must still be there");
213        let region = &src[region_start..];
214        let region = &region[..region
215            .find("\n}\n")
216            .expect("the streaming producer must end at a column-0 closing brace")];
217
218        let check = region.find("if out_tx.is_closed()").expect(
219            "the streaming producer must consult `is_closed()`; without it the \
220                     only stop signal is a failing send, which the three `continue` \
221                     paths never reach",
222        );
223        let step = region
224            .find("merger.step()")
225            .expect("the streaming producer's merge step must still be there");
226        assert!(
227            check < step,
228            "the closure check must come BEFORE the merge step, else an abandoned \
229             stream still pays for one full step per iteration"
230        );
231        assert_eq!(
232            region.matches("if out_tx.is_closed()").count(),
233            1,
234            "exactly one closure check is expected in the streaming producer"
235        );
236    }

238    /// Structural pin (#1695 roborev round 2): the three MATERIALIZING merges must
239    /// hand their per-call token to the merger's own input readers, not the inert
240    /// default. Behavioural coverage cannot reach this — "a reader stops mid-step"
241    /// is only observable as a latency difference, and a wall-clock assert in the
242    /// correctness path is forbidden — so the invariant is asserted on the source.
243    ///
244    /// It is deliberately NOT "no `KWayMerger::new` anywhere": the STREAMING driver
245    /// (`stream_generations_for_read`) keeps the plain constructor on purpose, since
246    /// its `blocking_send` already fails the instant the consumer is dropped.
247    #[test]
248    fn the_materializing_merges_pass_their_token_into_the_merger() {
249        let src = include_str!("../generation_merge.rs");
250
251        assert_eq!(
252            src.matches("KWayMerger::new_cancellable(").count(),
253            2,
254            "`merge_generations_for_read` and `merge_generations_for_read_with_metadata` \
255             must each build a CANCELLABLE merger; a plain `KWayMerger::new` there installs \
256             `ScanCancel::default()`, which no caller can ever trip"
257        );
258
259        // AFFIRMATIVE, not "no inert constructor survives": an absence assert over
260        // source is defeated by any COMMENT that names the thing it forbids (the
261        // first draft of this test was, by a comment two lines from the call site).
262        // Counting the tokens actually handed out cannot be satisfied by prose.
263        assert_eq!(
264            src.matches("cancel.clone()").count(),
265            3,
266            "each of the 3 per-call tokens must be handed to a merger — the two \
267             cancellable `KWayMerger`s and `build_single_partition_merger_from_readers`, \
268             whose token was a discarded `ScanCancel` that no caller could ever trip"
269        );
270
271        assert_eq!(
272            src.matches("merge_cancel::per_call()").count(),
273            3,
274            "one fresh token per materializing merge — a token shared across calls \
275             would let one query's timeout cancel another query's merge"
276        );
277    }

279    /// The guard trips its token on drop — the mechanism the timed-out query
280    /// relies on — and does not trip it before.
281    // #[serial] with the abandonment test (roborev round 4): `per_call()` arms the
282    // probe and `check()` on a cancelled token records an abandonment, so this test
283    // increments the SAME process-global counters `abandon_tests` resets and then
284    // asserts on. `#[serial]` does not exclude UNANNOTATED tests, so without this
285    // annotation a concurrent run of this test could satisfy that test's
286    // `armed() > 0` anti-vacuity guard AND its `abandoned() >= 1` assertion while
287    // the merge under test did neither — a vacuous pass in the one test whose whole
288    // job is proving the abandonment really happened.
289    #[test]
290    #[serial_test::serial]
291    fn guard_cancels_its_token_on_drop() {
292        let (guard, cancel) = per_call();
293        assert!(
294            check(&cancel).is_ok(),
295            "an un-cancelled token must not stop a merge"
296        );
297        assert!(!cancel.is_cancelled(), "must start un-cancelled");
298        drop(guard);
299        assert!(
300            cancel.is_cancelled(),
301            "dropping the async-scope guard must trip the blocking closure's flag"
302        );
303        assert!(
304            matches!(check(&cancel), Err(crate::Error::Cancelled)),
305            "the merge loop's poll must abandon once the guard has dropped"
306        );
307    }

309    /// Each call mints an INDEPENDENT token, so one query's cancellation can never
310    /// reach another's in-flight merge (the reason a shared reader token must not
311    /// be reused here).
312    // #[serial] for the same reason as above: `per_call()` arms the probe.
313    #[test]
314    #[serial_test::serial]
315    fn tokens_are_independent_per_call() {
316        let (guard_a, cancel_a) = per_call();
317        let (_guard_b, cancel_b) = per_call();
318        drop(guard_a);
319        assert!(cancel_a.is_cancelled());
320        assert!(
321            !cancel_b.is_cancelled(),
322            "a per-call token must be private to its own call"
323        );
324    }
