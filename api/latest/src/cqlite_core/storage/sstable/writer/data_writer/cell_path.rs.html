1//! CELL-PATH serialization for a MULTICELL collection — a map's KEY and a set's
2//! ELEMENT (issues #3805, #4106).
3//!
4//! # Why the cell path is the one write position that may emit the SENTINEL
5//! [`crate::types::Value::Empty`]'s zero-byte form is legal here and nowhere
6//! else, because this is the only position supplying BOTH halves of the
7//! admission:
8//!
9//!  * the **FRAMING** half — the length is carried by the ENCLOSING framing, so a
10//!    zero-length buffer is expressible and MEANS "empty". One
11//!    `CollectionType.cellPathSerializer` serializes every collection's cell path
12//!    (`db/marshal/CollectionType.java:55`, `:361-382` at `cassandra-5.0.8`) and
13//!    its whole body is `ByteBufferUtil.writeWithVIntLength(path.get(0))`. This
14//!    half is supplied by the POSITION and by nothing else, which is why
15//!    [`super::serialize_value_into`] — type-blind, and reached from every generic
16//!    write context — refuses the sentinel outright, and why the type-AWARE
17//!    `storage/serialization/types.rs` refuses it too: it has the type and not the
18//!    framing (roborev job 452);
19//!  * the **TYPE** half — the DECLARED component type is known, so the sentinel's
20//!    tag can be validated against it. That check is
21//!    [`crate::types::EmptyValueType::check_admits`], which lives beside the tag
22//!    table it is derived from, which is derived from Cassandra's `validate()`. It
23//!    is NOT written here: a copy would be a second opinion able to drift from
24//!    that table (roborev job 449 finding D asked for exactly this reuse).
25//!
26//! Cassandra decides both collection kinds with ONE rule: `validateCellPath`
27//! (`schema/ColumnMetadata.java:457-467`) validates
28//! `((CollectionType)type).nameComparator().validate(path.get(0))`, and
29//! `nameComparator()` is the KEYS type of a `MapType` and the ELEMENTS type of a
30//! `SetType` (`db/marshal/SetType.java:101-104`). So the two functions below are
31//! the same shape by construction, and the READ side mirrors them from one shared
32//! gate (`row_decoder::complex_column::cell_path_empty`).
33//!
34//! Both dispositions are pinned by the write-surface census in
35//! `crate::types::empty_value`'s `write_surface_census_tests`, which requires
36//! every admitting position in the crate to be enumerated there.
37//!
38//! # BOTH declared SPELLINGS are recognised; an UNRESOLVABLE one is a REFUSAL,
39//! # never a guess (#28)
40//! A column's declared type reaches the writer as a CQL `map<K,V>` / `set<T>`
41//! when it came from a CQL schema, and as Cassandra's MARSHAL form
42//! (`org.apache.cassandra.db.marshal.MapType(Int32Type,Int32Type)`,
43//! `SetType(Int32Type)`) when it came from a `SerializationHeader` — which is why
44//! `write_complex_column` dispatches on both forms and why the READ path decodes
45//! both. A gate that understood only the CQL spelling refused a sentinel that a
46//! schema-less read had legitimately DECODED, on a rewrite (compaction) of the
47//! very SSTable it came from (roborev job 453). Recognising the second spelling
48//! widens what the gate can SEE; the admission itself is unchanged.
49//!
50//! Where the declared type resolves to no collection type at all, the sentinel is
51//! REFUSED — there is then no declared component type to validate the tag
52//! against, and refusing beats writing bytes that read back as something else.
53//! Every NON-sentinel component is unaffected and goes straight to the ordinary
54//! serializer, so an unresolved declared type costs nothing on any path that does
55//! not carry a sentinel.
56

63// THE COMPONENT RESOLVER IS SHARED WITH THE READ SIDE and lives in
64// `crate::storage::sstable::cell_path_component` — see that module's header, and
65// in particular `resolve_declared_cell_path_type`'s "THE SEAM" section.
66//
67// It used to be private HERE, and that is precisely what #4106 roborev job 449
68// finding B1 found: the writer resolved the component from the COMPLETE declared
69// type (so `org.apache.cassandra.db.marshal.SetType(Int32Type)` — package on the
70// outer name, BARE inner element name — worked), while the reader split the
71// component name out first and then asked a classifier that requires the package
72// on the name it is HANDED, so the same declaration decoded the empty cell path
73// as an opaque blob. One resolver, one opinion.
74
75/// The ADMISSION, shared by the two entry points below.
76///
77/// Takes no [`Value`] and writes no bytes — deliberately, and not only for
78/// tidiness: the write-surface census (`crate::types::empty_value`'s
79/// `write_surface_census_tests`) derives its subject set from any function
80/// taking `&Value` AND producing bytes, and its rule is that a function whose
81/// disposition is a claim about the SENTINEL must carry its own `Value::Empty`
82/// arm. Factoring the arm itself out would leave both entry points looking
83/// arm-free while their delegate admitted, i.e. the census would report a
84/// refusal where there is an admission. So the arm stays at each entry point and
85/// only what happens AFTER it is shared.
86///
87/// Two refusals, both a caller bug rather than something to paper over
88/// (no-heuristics, #28): a declared type that resolves to no collection of this
89/// kind (nothing to validate the tag against), and — inside
90/// [`EmptyValueType::check_admits`] — a declared component type that does not
91/// admit an empty buffer, or one that admits a DIFFERENT family than the tag
92/// names.
93fn admit_empty_cell_path(
94    tag: EmptyValueType,
95    declared: &str,
96    component: CellPathComponent,
97) -> Result<()> {
98    let Some(component_type) = resolve_declared_cell_path_type(declared, component) else {
99        return Err(Error::InvalidInput(format!(
100            "an empty-buffer sentinel (`{}`, issue #3805) needs the DECLARED component \
101             type to be validated against, and `{declared}` resolves to neither {}; \
102             refusing rather than guessing (issue #28)",
103            tag.cql_name(),
104            component.declared_shapes()
105        )));
106    };
107    tag.check_admits(&component_type, declared)
108    // The whole encoding: NOTHING. The caller's `out` is deliberately left
109    // untouched — the length lives in its unsigned VInt, so a zero-length cell
110    // path IS the empty component.
111}

113/// Serialize a MULTICELL map's CELL PATH (its serialized KEY) into `out`.
114///
115/// `map_data_type` is the COLUMN's declared type, in either spelling. See the
116/// module header for the admission's two halves, why the check is not written
117/// twice, and why an unresolvable declaration is a refusal.
118pub(crate) fn serialize_map_cell_path_key_into(
119    key: &Value,
120    map_data_type: &str,
121    out: &mut Vec<u8>,
122) -> Result<()> {
123    let Value::Empty(tag) = key else {
124        return serialize_value_into(key, out);
125    };
126    admit_empty_cell_path(*tag, map_data_type, CellPathComponent::MapKey)
127}

129/// Serialize a MULTICELL set's CELL PATH (its serialized ELEMENT) into `out`.
130///
131/// ISSUE #4106. A non-frozen set stores its element IN the cell path and writes
132/// the EMPTY buffer as the cell value (`cql3/Sets.java:407`:
133/// `params.addCell(column, CellPath.create(bb), ByteBufferUtil.EMPTY_BYTE_BUFFER)`),
134/// exactly as a map stores its key there — so the sentinel is legal here for the
135/// same two reasons, decided by the same `validateCellPath` line (module header).
136///
137/// Before this existed, `write_set_complex_cells` routed every element through
138/// the type-blind [`super::serialize_value_into`], whose sentinel refusal is
139/// CORRECT and deliberate (it has no declared type, so it cannot tell a legal
140/// empty `text` from the corruption Cassandra's `validate` throws on for
141/// `tinyint`). The consequence was that a set CQLite had legitimately DECODED
142/// from Cassandra-written bytes could not be written back — a compaction of that
143/// SSTable failed. The refusal is untouched; this adds the schema-aware position
144/// that has what it lacks.
145///
146/// A NON-sentinel element still goes through
147/// [`super::serialize_collection_element_into`], so its bytes and its
148/// "SET elements cannot be null" refusal are unchanged.
149pub(crate) fn serialize_set_cell_path_element_into(
150    element: &Value,
151    set_data_type: &str,
152    out: &mut Vec<u8>,
153) -> Result<()> {
154    let Value::Empty(tag) = element else {
155        return serialize_collection_element_into(element, "SET", out);
156    };
157    admit_empty_cell_path(*tag, set_data_type, CellPathComponent::SetElement)
158}
