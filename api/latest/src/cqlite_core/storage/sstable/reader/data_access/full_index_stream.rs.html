1//! Streaming partition enumeration for the non-stitching read path (issue #2361).
2//!
3//! [`SSTableReader::iterate_all_partitions_via_full_index`](super::full_index_scan)
4//! (issue #2302) resolves every partition of a BIG SSTable through the full
5//! `Index.db` offset table, but MATERIALISES the whole result into one sorted
6//! `Vec` before returning. The compaction/Flight `do_get` streaming producer then
7//! forwards that Vec one entry at a time — so for a huge SSTable (the #2361 field
8//! case: 1.13M partitions, uncompressed BIG, which routes to the non-stitching
9//! branch of
10//! [`stream_all_partitions_for_compaction`](super::super::SSTableReader::stream_all_partitions_for_compaction))
11//! the producer builds the ENTIRE table in memory before the first `emit`, the
12//! consumer's `LIMIT` early-break and cancellation cannot take effect until that
13//! completes, and peak memory grows unbounded.
14//!
15//! This module adds a TRUE-streaming variant that emits each partition as the
16//! index walk resolves it — the same index-ordered (== token-ordered) walk, but
17//! without the whole-file `Vec`. The compressed-nb chunk-stitching path already
18//! streams through a bounded window; this brings the non-stitching path to
19//! parity.
20//!
21//! ## Fallback safety (why some bails move up-front)
22//!
23//! The materialising [`iterate_all_partitions_via_full_index`] can bail to a
24//! `sequential_scan` fallback on ANY structural inconsistency because it has
25//! emitted nothing yet (it only drops a local `Vec`). A STREAMING walk that has
26//! already emitted partition `k` into the k-way merge CANNOT then fall back — a
27//! re-scan would double-emit and corrupt the merge. So every gate computable from
28//! the `Index.db` offset table ALONE (entries present, data section non-empty,
29//! index fully parsed, all keys non-empty, offsets strictly ascending, spans fit
30//! `u32`) is checked UP-FRONT: a failure returns [`FullIndexStreamOutcome::FellBack`]
31//! with nothing emitted, so the caller's `sequential_scan` fallback is still
32//! safe. The remaining per-partition check (a partition slice that does not fully
33//! consume) requires reading the partition body, so it can only surface mid-walk
34//! — and there it is a hard `Error` (fail-closed), never a silent fallback. For a
35//! well-formed BIG SSTable it never fires.
36//!
37//! ## Sequential read window (issue #2366)
38//!
39//! The uncompressed walk resolves each partition's `data_offset` DIRECTLY from
40//! the `Index.db` offset table (no per-partition random `Index.db` probe) and
41//! serves its bytes from a bounded, forward-only sequential read window over
42//! Data.db rather than one positioned `seek`+`read_exact`+CRC per partition —
43//! turning ~O(partitions) random reads into O(data_section_len / window)
44//! sequential reads with bounded peak memory. See
45//! [`SEQUENTIAL_WINDOW_TARGET_BYTES`].
46

55/// Target size (bytes) of the sequential Data.db read window used by the
56/// uncompressed non-stitching streaming walk (issue #2366).
57///
58/// The walk visits partitions in ascending `data_offset` order (== token order
59/// == Data.db physical order), so instead of one positioned `seek`+`read_exact`
60/// +CRC per partition (~1.13M small random reads at field scale) it fills a
61/// bounded in-memory window covering many consecutive partitions with ONE
62/// sequential `read_uncompressed_verified` call, then serves each partition's
63/// slice from that window. A partition larger than the target still reads in a
64/// single window sized to exactly its span (never smaller than one partition),
65/// so peak memory is bounded by `max(TARGET, largest_partition_span)`. 4 MiB is
66/// large enough to amortise the per-read + CRC overhead across ~hundreds of
67/// typical partitions yet small enough to keep the memory target (<128 MiB).
68const SEQUENTIAL_WINDOW_TARGET_BYTES: u64 = 4 * 1024 * 1024;

70/// Hardening B (issue #2361, roborev rounds 2/3): the streaming walk EMITS each
71/// partition to the k-way merger as it resolves it, unlike the materialising
72/// sibling ([`SSTableReader::iterate_all_partitions_via_full_index`]), which
73/// defensively re-sorts its whole result via `sort_by_token_order` before
74/// returning — a post-hoc corrective the streaming path cannot apply (it has
75/// already emitted). This is the O(1)-per-partition guard that stands in for
76/// that sort: `Index.db` entries are ASSUMED to be in the same total order the
77/// materialising sibling produces (matching Data.db's physical layout), but that
78/// assumption is never re-verified anywhere else on this path. A violation would
79/// silently hand the merger inputs it requires to be sorted, corrupting
80/// cross-SSTable reconciliation — so this fails CLOSED (`Error::corruption`)
81/// rather than emit out of order (issue #28: authoritative structure only, never
82/// a silent best-effort).
83///
84/// The order compared is EXACTLY `sort_by_token_order`'s: Murmur3 `token`, then
85/// (on a token TIE) the raw partition-key bytes, unsigned-lexicographic —
86/// `RowKey`/`&[u8]` `cmp` matches Cassandra's on-disk `DecoratedKey`
87/// (`ByteBuffer.compareTo`) order. Checking token alone (roborev round 2) missed
88/// the tie-break: two distinct keys colliding on one token could be emitted in
89/// the wrong relative order — legal per a token-only check but NOT what the
90/// materialising sibling (or the merger) requires. A genuine token collision
91/// with keys still in ascending byte order is NOT a violation; only a STRICT
92/// decrease of the `(token, key)` pair is. Factored out as a pure function
93/// (`prev`/`token`/`key`/`index` in, `Result<()>` out) so it is unit-testable
94/// without a full `SSTableReader` fixture.
95pub(in crate::storage::sstable::reader) fn check_token_order(
96    prev: Option<(i64, &[u8])>,
97    token: i64,
98    key: &[u8],
99    index: usize,
100) -> Result<()> {
101    if let Some((prev_token, prev_key)) = prev {
102        // Same total order as the materialising sibling's `sort_by_token_order`.
103        if prev_token.cmp(&token).then_with(|| prev_key.cmp(key)) == std::cmp::Ordering::Greater {
104            return Err(Error::corruption(format!(
105                "stream_all_partitions_via_full_index: partition {index} (token {token}) is out \
106                 of order (< previous token {prev_token}) — Index.db entries are not in \
107                 (token, key) order (issue #2361)"
108            )));
109        }
110    }
111    Ok(())
112}

114/// Outcome of [`SSTableReader::stream_all_partitions_via_full_index`].
115pub(in crate::storage::sstable::reader) enum FullIndexStreamOutcome {
116    /// Every partition was streamed (the walk ran to completion, or the
117    /// consumer returned `ControlFlow::Break`).
118    Streamed,
119    /// An up-front structural gate failed BEFORE any partition was emitted. The
120    /// caller must fall back to a (materialising) `sequential_scan`; nothing was
121    /// emitted, so the fallback cannot double-emit.
122    FellBack,
123}
124
125impl SSTableReader {
126    /// Streaming sibling of
127    /// [`iterate_all_partitions_via_full_index`](Self::iterate_all_partitions_via_full_index):
128    /// walk the full `Index.db` offset table and `emit` each partition's rows as
129    /// they are resolved, never building a whole-file `Vec`.
130    ///
131    /// `emit` receives `(row_key, value)` per surviving (tombstone-filtered) row,
132    /// in index (token) order, and returns `ControlFlow::Break` to stop early
133    /// (consumer dropped / satisfied).
134    ///
135    /// No `limit`/budget parameter (issue #2361, roborev round 2): a per-producer
136    /// PARTITION count is not a safe proxy for a row-level `LIMIT` — a producer
137    /// cannot know how many of its partitions the k-way merger will keep (a
138    /// predicate filter runs at the consumer, and shadowed/tombstoned partitions
139    /// contribute zero surviving rows), so any producer-side cap risks
140    /// under-returning. `LIMIT` is enforced purely downstream: the consumer's
141    /// post-reconciliation early break (`drive_merge`) plus this crate's
142    /// cancel-aware Drop teardown (cancel → drop receiver → join) stopping the
143    /// producer promptly once the consumer stops pulling — see
144    /// [`stream_all_partitions_cancellable`](Self::stream_all_partitions_cancellable).
145    pub(in crate::storage::sstable::reader) async fn stream_all_partitions_via_full_index<F>(
146        &self,
147        scan_cancel: &ScanCancel,
148        emit: &mut F,
149    ) -> Result<FullIndexStreamOutcome>
150    where
151        F: FnMut((RowKey, ScanRow)) -> Result<ControlFlow<()>>,
152    {
153        let Some(index_reader) = &self.index_reader else {
154            return Ok(FullIndexStreamOutcome::FellBack);
155        };
156        // Issue #2412 Stage 2: a lazily-opened reader defers the full parse to
157        // first use — a full streaming enumeration IS that first use (Stage 4
158        // replaces the SOURCE of entries with a true Summary-guided streaming
159        // walk that never materializes the whole map; the walk CONTRACT below is
160        // unchanged either way). No-op for an eagerly-opened reader.
161        index_reader.ensure_materialized(scan_cancel).await?;
162        let entries = index_reader.get_partition_entries();
163
164        // Exclusive end of the last partition (uncompressed data-section domain).
165        let data_section_end = match self.compression_info.as_deref() {
166            Some(ci) => ci.data_length,
167            None => self
168                .stats
169                .file_size
170                .saturating_sub(self.actual_header_size as u64),
171        };
172
173        // Up-front structural gates (no per-partition I/O): any failure => FellBack
174        // (nothing emitted; the caller's sequential fallback stays safe). These
175        // mirror the same-named checks in the materialising variant, but hoisted
176        // BEFORE the first emit so the streaming path never bails mid-walk on a
177        // signal it could have seen from the offset table alone.
178        if entries.is_empty() || data_section_end == 0 || !index_reader.is_fully_parsed() {
179            return Ok(FullIndexStreamOutcome::FellBack);
180        }
181        for i in 0..entries.len() {
182            // Empty partition keys are rejected fail-safe (issue #2302/#2325 — an
183            // empty PK round-trips corrupt through BOTH read paths).
184            let key = entries[i].raw_key.as_deref().unwrap_or(&[]);
185            if key.is_empty() {
186                return Ok(FullIndexStreamOutcome::FellBack);
187            }
188            let start = entries[i].data_offset;
189            let end = if i + 1 < entries.len() {
190                entries[i + 1].data_offset
191            } else {
192                data_section_end
193            };
194            if end <= start || u32::try_from(end - start).is_err() {
195                return Ok(FullIndexStreamOutcome::FellBack);
196            }
197        }
198
199        // All gates passed: stream. Read-shadowing parser (matches sequential_scan
200        // + the materialising variant).
201        let parser = self.build_v5_parser(true);
202        let reader_schema = self.get_table_schema(None);
203        let schema = reader_schema.as_ref();
204        // Hardening B (issue #2361): O(1)-per-partition (token, key)-order guard —
205        // see `check_token_order`'s doc for why this stands in for the
206        // materialising sibling's defensive `sort_by_token_order`.
207        let mut prev_key: Option<(i64, &[u8])> = None;
208
209        // Sequential read window over the UNCOMPRESSED data section (issue #2366):
210        // instead of one positioned read + CRC per partition, `window` holds the
211        // bytes of `[window_start, window_start + window.len())` (data-section
212        // domain, i.e. the `data_offset` domain) and each partition's slice is
213        // served from it. Because entries are ascending, `window_start` only ever
214        // advances forward — the read pattern is O(data_section_len / TARGET)
215        // sequential reads, not O(partitions) random reads. Unused (never filled)
216        // on the compressed-offset branch.
217        let mut window: Vec<u8> = Vec::new();
218        let mut window_start: u64 = 0;
219        let mut window_filled = false;
220
221        for i in 0..entries.len() {
222            // Cooperative cancellation: poll every entry so a cancelled scan
223            // abandons the walk promptly (issue #2264, PER-CALL token issue #2346).
224            scan_cancel.check()?;
225
226            let partition_key = entries[i].raw_key.as_deref().unwrap_or(&[]);
227            let token = cassandra_murmur3_token(partition_key);
228            check_token_order(prev_key, token, partition_key, i)?;
229            prev_key = Some((token, partition_key));
230
231            // The partition's data offset comes DIRECTLY from the offset table
232            // entry already validated up-front (issue #2366): the former
233            // `lookup_partition_with_index` probe returned this identical value via
234            // a HashMap lookup that also incremented `INDEX_PROBES` — dropping it
235            // removes O(partitions) index probes without weakening any check (the
236            // up-front gate already proved every offset present, ascending, and
237            // span-representable). This intentionally also skips the
238            // `READ_PARTITION_LOOKUP` observability counter and the B4
239            // `key_offset_cache` population that `lookup_partition_with_index`
240            // performs on the point-read path: a full scan is not a point lookup,
241            // so it must not inflate point-read lookup metrics, nor thrash/evict
242            // the bounded B4 cache by pushing ~1M entries through it. This is a
243            // deliberate divergence from the materialising sibling's
244            // `lookup_partition_with_index` call, not an oversight.
245            let data_offset = entries[i].data_offset;
246            let next_offset = if i + 1 < entries.len() {
247                entries[i + 1].data_offset
248            } else {
249                data_section_end
250            };
251            if next_offset <= data_offset {
252                return Err(Error::corruption(format!(
253                    "stream_all_partitions_via_full_index: non-ascending offset at entry {i} \
254                     (offset {data_offset} >= successor {next_offset}, issue #2361)"
255                )));
256            }
257            let span = next_offset - data_offset;
258            let Ok(size) = u32::try_from(span) else {
259                return Err(Error::corruption(format!(
260                    "stream_all_partitions_via_full_index: partition {i} span {span} \
261                     overflows u32 (issue #2361)"
262                )));
263            };
264
265            let control = if let Some(ci) = self.compression_info.as_deref() {
266                // Rare non-nb compressed non-stitching branch: unchanged per-partition
267                // windowed read (issue #2366 targets the uncompressed field case only).
268                let raw = self
269                    .read_compressed_offset_window(ci, data_offset, size)
270                    .await?;
271                self.emit_partition_slice(i, &raw, &parser, schema, emit)?
272            } else {
273                // Uncompressed sequential window (issue #2366). Refill when the
274                // partition's slice is not fully covered by the current window.
275                if !window_filled
276                    || data_offset < window_start
277                    || next_offset > window_start + window.len() as u64
278                {
279                    window_start = data_offset;
280                    // One read per window: at least this partition's whole span,
281                    // at most the target, clamped to the data section end so we
282                    // never read past the last partition.
283                    let remaining = data_section_end - window_start;
284                    let want = span.max(SEQUENTIAL_WINDOW_TARGET_BYTES).min(remaining);
285                    let absolute_offset = window_start + self.actual_header_size as u64;
286                    // Count the window refill as one production read-path seek
287                    // (`SEEK_CALLS`) — the single positioned read stands in for the
288                    // per-partition seeks it replaces, matching the windowed-read
289                    // convention in `scan_stream_windowed_read.rs`. This is the
290                    // O(N/window) read-pattern evidence for issue #2366.
291                    crate::storage::sstable::read_work_counters::record_seek();
292                    window = self
293                        .read_uncompressed_verified(&self.file, absolute_offset, want as usize)
294                        .await?;
295                    window_filled = true;
296                }
297                let lo = (data_offset - window_start) as usize;
298                let hi = (next_offset - window_start) as usize;
299                let raw = &window[lo..hi];
300                self.emit_partition_slice(i, raw, &parser, schema, emit)?
301            };
302
303            if control.is_break() {
304                return Ok(FullIndexStreamOutcome::Streamed);
305            }
306        }
307
308        Ok(FullIndexStreamOutcome::Streamed)
309    }
310
311    /// Per-partition body of the streaming full-index walk (issue #2361/#2366):
312    /// verify the slice decodes as exactly one complete partition, record the
313    /// work-probe, parse it, and `emit` each surviving (tombstone-filtered) row.
314    /// Returns `ControlFlow::Break` if the consumer asked to stop.
315    ///
316    /// Factored out of [`Self::stream_all_partitions_via_full_index`] so the
317    /// compressed-offset branch and the uncompressed sequential-window branch
318    /// share identical decode/emit semantics — only how the `raw` bytes are
319    /// obtained differs (issue #2366).
320    fn emit_partition_slice<F>(
321        &self,
322        index: usize,
323        raw: &[u8],
324        parser: &crate::storage::sstable::reader::parsing::V5CompressedLegacyParser,
325        schema: Option<&TableSchema>,
326        emit: &mut F,
327    ) -> Result<ControlFlow<()>>
328    where
329        F: FnMut((RowKey, ScanRow)) -> Result<ControlFlow<()>>,
330    {
331        // Structural coverage: the slice must decode as exactly one complete
332        // partition (issue #2302 Signal B). Mid-walk failure = fail-closed.
333        if !self.partition_slice_fully_consumed(parser, raw, schema)? {
334            return Err(Error::corruption(format!(
335                "stream_all_partitions_via_full_index: partition {index} slice not fully \
336                 consumed (truncated/corrupt body, issue #2361)"
337            )));
338        }
339
340        // Work-probe (issue #2398): one partition body read + parsed. A
341        // token-range split must keep this bounded to its in-range slice, not
342        // the SSTable's whole partition count.
343        crate::storage::sstable::work_counters::add_stream_walk_partition_parsed();
344        let parsed = parser.parse_block(raw, schema, self)?;
345        for (_table_id, row_key, value) in parsed {
346            if self.filter_tombstone(&value) {
347                match emit((row_key, value))? {
348                    ControlFlow::Continue(()) => {}
349                    ControlFlow::Break(()) => return Ok(ControlFlow::Break(())),
350                }
351            }
352        }
353        Ok(ControlFlow::Continue(()))
354    }

356    /// Streaming sibling of
357    /// [`iterate_all_partitions_cancellable`](Self::iterate_all_partitions_cancellable):
358    /// enumerate every partition, emitting each surviving row via `emit` as it is
359    /// resolved instead of returning a whole-file `Vec` (issue #2361).
360    ///
361    /// Routing mirrors the materialising method: a BIG SSTable with a usable
362    /// `Index.db` streams through
363    /// [`stream_all_partitions_via_full_index`](Self::stream_all_partitions_via_full_index)
364    /// (bounded memory, index/token order). Only when that up-front-bails (no
365    /// usable/complete index) does it fall back to the MATERIALISING
366    /// `sequential_scan` — which cannot stream in token order without collecting +
367    /// sorting first. The #2361 field table has a valid `Index.db`, so it takes
368    /// the streaming branch; the sequential fallback is the rare degenerate path
369    /// (missing/malformed index) and is documented, not fixed, here.
370    ///
371    /// ## No producer-side `LIMIT` budget (issue #2361, roborev round 2)
372    ///
373    /// Earlier revisions threaded an optional per-producer PARTITION budget here.
374    /// It was REMOVED: `LIMIT` counts surviving, post-reconciliation ROWS, not
375    /// partitions scanned, and a producer cannot know that count in advance — a
376    /// consumer-side predicate filter can thin a partition's rows to zero, and a
377    /// tombstoned/cross-generation-shadowed partition contributes zero surviving
378    /// rows while still consuming a "budget" slot. Either case makes a
379    /// partition-granular producer cap risk returning FEWER rows than exist,
380    /// which no `limitGuaranteed = false` contract permits (it only permits
381    /// MORE). `LIMIT` is therefore enforced purely downstream: the consumer's
382    /// post-reconciliation early break (`drive_merge`) stops pulling, and the
383    /// cancel-aware Drop teardown (cancel → drop receiver → join) then stops the
384    /// producer promptly — bounding work WITHOUT any risk of under-return.
385    pub(in crate::storage::sstable::reader) async fn stream_all_partitions_cancellable<F>(
386        &self,
387        scan_cancel: &ScanCancel,
388        mut emit: F,
389    ) -> Result<()>
390    where
391        F: FnMut((RowKey, ScanRow)) -> Result<ControlFlow<()>>,
392    {
393        if self.index_reader.is_some() && self.bti_partitions_db.is_none() {
394            match self
395                .stream_all_partitions_via_full_index(scan_cancel, &mut emit)
396                .await?
397            {
398                FullIndexStreamOutcome::Streamed => return Ok(()),
399                FullIndexStreamOutcome::FellBack => {
400                    tracing::warn!(
401                        "SSTable Index.db is present but the streaming index-random-read path \
402                         could not prove every partition resolvable; falling back to a \
403                         MATERIALISING sequential scan of Data.db (issues #2361/#2302). This \
404                         should not happen for a well-formed BIG SSTable."
405                    );
406                }
407            }
408        }
409
410        // Fallback: materialising sequential scan (rare degenerate path). No
411        // producer-side limit (see this method's doc) — the consumer's
412        // post-reconciliation LIMIT break bounds it downstream instead.
413        //
414        // Work-probe (issue #2398, roborev 1693): `sequential_scan` itself owns
415        // the `stream_walk_partitions_parsed` accounting for this path (added at
416        // its per-partition decode boundary, roborev 1692) — do NOT increment
417        // again here. This loop only re-emits `sequential_scan`'s already-decoded
418        // results, one call per RETURNED ROW; a second increment here would
419        // double-count every partition body relative to what was actually decoded.
420        let table_id = self.scan_table_id();
421        let schema = self.schema.as_deref();
422        let entries = self
423            .sequential_scan(&table_id, None, None, None, schema, scan_cancel)
424            .await?;
425        for (key, value) in entries {
426            match emit((key, value))? {
427                ControlFlow::Continue(()) => {}
428                ControlFlow::Break(()) => return Ok(()),
429            }
430        }
431        Ok(())
432    }

434    /// Authoritative structural coverage check for ONE index entry's Data.db slice
435    /// (issue #2302, roborev jobs 1606/1609/1610): physically decode `raw` as
436    /// exactly one partition and require the decode to consume the slice in FULL
437    /// AND terminate via a CONFIRMED end-of-partition marker, never a bare "ran out
438    /// of bytes" collapse. Shared by the materialising
439    /// ([`iterate_all_partitions_via_full_index`](Self::iterate_all_partitions_via_full_index))
440    /// and streaming full-index walks (issue #2361).
441    ///
442    /// Drives with `at_final_chunk = false` DELIBERATELY: that is LENIENT-off, so
443    /// every ambiguous "consumed every byte but saw no explicit END_OF_PARTITION
444    /// marker" / row-parse-failure / unrepresentable-range case reports
445    /// `ParseStep::NeedMore` (never `Emitted`). `Emitted(consumed)` is then
446    /// reachable ONLY via the driver's unconditional `is_end_of_partition`
447    /// marker-consumption branch — so `consumed == raw.len()` PROVES the terminator
448    /// was structurally confirmed as the slice's last byte (Cassandra's own
449    /// on-disk completion signal, which CQLite's writer always appends). No
450    /// heuristics (issue #28).
451    pub(in crate::storage::sstable::reader) fn partition_slice_fully_consumed(
452        &self,
453        parser: &crate::storage::sstable::reader::parsing::V5CompressedLegacyParser,
454        raw: &[u8],
455        schema: Option<&TableSchema>,
456    ) -> Result<bool> {
457        use crate::storage::sstable::reader::parsing::ParseStep;
458        let mut noop = |_row| Ok(std::ops::ControlFlow::Continue(()));
459        let step =
460            parser.parse_one_partition_for_compaction(raw, schema, self, false, &mut noop)?;
461        Ok(matches!(step, ParseStep::Emitted(consumed) if consumed == raw.len()))
462    }
463}

465#[cfg(test)]
466mod check_token_order_tests {
467    use super::check_token_order;

469    /// The FIRST partition (`prev = None`) never fails, regardless of its token.
470    #[test]
471    fn first_partition_always_passes() {
472        assert!(check_token_order(None, i64::MIN, b"a", 0).is_ok());
473        assert!(check_token_order(None, 0, b"a", 0).is_ok());
474        assert!(check_token_order(None, i64::MAX, b"a", 0).is_ok());
475    }
476
477    /// Ascending tokens (the well-formed case) pass at every step, whatever the
478    /// key bytes are (token strictly dominates the order).
479    #[test]
480    fn ascending_tokens_pass() {
481        assert!(check_token_order(Some((-100, b"z")), -50, b"a", 1).is_ok());
482        assert!(check_token_order(Some((-50, b"z")), 0, b"a", 2).is_ok());
483        assert!(check_token_order(Some((0, b"z")), 50, b"a", 3).is_ok());
484    }
485
486    /// Equal tokens with ASCENDING (or equal) key bytes — a genuine Murmur3
487    /// collision between distinct keys stored in the correct on-disk order — are
488    /// NOT a violation.
489    #[test]
490    fn equal_tokens_ascending_keys_pass() {
491        assert!(check_token_order(Some((42, b"aaa")), 42, b"aab", 1).is_ok());
492        assert!(check_token_order(Some((42, b"aaa")), 42, b"aaa", 1).is_ok());
493        // Unsigned-lexicographic: a high byte is GREATER than a low byte.
494        assert!(check_token_order(Some((42, &[0x01])), 42, &[0xff], 1).is_ok());
495    }
