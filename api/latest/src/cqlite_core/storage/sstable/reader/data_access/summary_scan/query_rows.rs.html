1//! Single-generation, token-scoped, PULL-based query ROW stream (issue #3058).
2//!
3//! # Why this exists
4//!
5//! A `SELECT` served from exactly ONE SSTable generation needs no cross-generation
6//! reconciliation: read-time SELECT semantics (partition deletions, range
7//! tombstones, row/cell tombstones, TTL expiry, static-cell injection) are applied
8//! inside the decoder by `PartitionShadow` when the parser is built with
9//! `read_shadowing = true` (issue #1741). The k-way merge exists to reconcile
10//! ACROSS generations; with one generation it is pure overhead — it materialises
11//! full-fidelity `CompactionRow`s with per-cell write metadata that the read path
12//! then throws away.
13//!
14//! This module exposes the already-shipped single-generation walk as a **pull**
15//! surface a synchronous consumer can drive: the Flight `do_get` row loop
16//! (`cqlite-flight`) runs on a blocking thread with no async runtime of its own,
17//! and the underlying walks ([`SSTableReader::stream_partitions_summary_guided`],
18//! [`SSTableReader::stream_all_partitions_via_full_index`]) are async with a
19//! SYNCHRONOUS emit callback. So the walk is driven on a dedicated thread owning a
20//! `current_thread` runtime and hands BATCHES to the consumer over a bounded
21//! `sync_channel` — the same thread/bounded-channel shape the k-way merge's own
22//! per-input adapter uses (`write_engine/merge/from_readers.rs`), minus the merge:
23//! one thread instead of one-per-input, and one handoff per BATCH instead of one
24//! per row.
25//!
26//! # Guarantees this surface makes to its caller
27//!
28//! * **Read shadowing is ON.** Every source this module drives builds its parser
29//!   with `build_v5_parser(true)` — the Summary-guided walk
30//!   ([`SSTableReader::stream_partitions_summary_guided`]), the full-`Index.db`
31//!   walk ([`SSTableReader::stream_all_partitions_via_full_index`]) and the
32//!   windowed batched scan (`scan_stream_windowed`'s `drain_scan_window_blocking`).
33//!   That posture is asserted BEHAVIOURALLY, not by reading: the Flight
34//!   forced-path differential (`cqlite-flight/tests/issue_3058_forced_path_differential.rs`)
35//!   shows tombstoned/expired rows suppressed identically to the reconciling
36//!   merge arm, which is only possible with shadowing on.
37//! * **The TTL/expiry clock is the CALLER's.** `now_secs` is pinned onto the
38//!   parser ([`V5CompressedLegacyParser::with_now_secs`]), never re-sampled from
39//!   the wall clock, so a request that captured ONE reconciliation instant (and a
40//!   test that PINS `now`) is honored.
41//! * **Token pushdown is preserved.** `token_bound` is pushed into the
42//!   Summary-guided walk (#2412/#2413), so out-of-range partition bodies are never
43//!   decoded.
44//! * **Fail-closed on an unservable reader.** If neither walk can prove it can
45//!   stream this reader (no usable `Index.db`/`Summary.db`, a BTI reader, or a
46//!   coverage gap), the stream reports [`QueryRowBatch::Unsupported`] as its FIRST
47//!   and ONLY message — having emitted NOTHING — so the caller can fall back to
48//!   the k-way merge path with no partial output. The degenerate materialising
49//!   `sequential_scan` fallback is deliberately NOT taken here: it cannot honor a
50//!   caller-pinned `now`, and silently serving a scan against the wall clock would
51//!   break the pinned-`now` contract above.
52//! * **Cancellation and backpressure.** The walk polls this stream's CHILD
53//!   [`ScanCancel`] at its normal cadence, and the CALLER's flag is bridged into
54//!   that child at every batch boundary — on the full-ring arm in
55//!   [`drive_full_scan_rows`] and on the token-bounded arm in `BatchSink::flush`
56//!   — so a client disconnect stops either walk without waiting for the consumer
57//!   to drop the stream, and a cancelled scan terminates with `Cancelled` rather
58//!   than a silently short stream. Only the child is ever cancelled; the caller's
59//!   flag is left intact so a fallback to the merge arm still works. Every batch
60//!   send also observes the bounded channel, and a dropped consumer breaks the
61//!   walk at its next send.
62//! * **A dead producer is an ERROR, never a clean end of stream (issue #3106).**
63//!   Completion is EXPLICIT: the producer thread's last act is to send
64//!   [`QueryRowMsg::Done`], and the consumer reports end-of-stream ONLY on that
65//!   sentinel. A bare channel disconnect — which is what an UNWINDING producer
66//!   leaves behind, since a panic drops the `SyncSender` without sending anything
67//!   — is reported as a hard error instead of "the walk finished". Belt and
68//!   braces: the thread body also runs under `catch_unwind`, so a panic is
69//!   forwarded as an INFORMATIVE terminal error naming the panic message rather
70//!   than a generic "the producer died". Before this, such a panic completed the
71//!   request SUCCESSFULLY with a silently truncated result set.
72//!
73//!   The two halves cover different builds ON PURPOSE, which is why both are
74//!   here: `catch_unwind` only fires under `panic = "unwind"` (dev/test, and the
75//!   `release-unwind` profile the bindings ship — `[profile.release]` is
76//!   `panic = "abort"`, where a panicking producer takes the process down instead,
77//!   loudly). The `Done` sentinel needs no unwinding at all: it makes "the walk
78//!   finished" an OBSERVED fact in every profile, so any way THIS THREAD can stop
79//!   without reporting — a future exit path that forgets its terminator included —
80//!   fails closed rather than being read as a complete scan.
81//!
82//!   SCOPE, stated precisely (roborev, issue #3106): `Done` proves only that the
83//!   query-row THREAD ran to completion. It says nothing about that thread's own
84//!   upstream, and on the full-ring arm the rows come from an INNER `tokio` task
85//!   over a second channel — whose death this thread would report as a clean
86//!   walk. That boundary is closed separately and by the same principle, in
87//!   [`crate::storage::sstable::reader::BatchedScanStream`]: it owns the scan
88//!   task's `JoinHandle` and joins it when its channel closes, so a task that
89//!   died surfaces as an error there and reaches this thread as a normal `Err`
90//!   (hence a `Failed` terminator). Both boundaries are needed for the end-to-end
91//!   claim; neither alone suffices — and the claim is bounded to those two, NOT
92//!   universal: on the chunk-stitching branch there is a THIRD hop, the windowed
93//!   driver's batch forwarder, whose `JoinError` is deliberately discarded
94//!   (`scan_stream_windowed`'s `let _ = forwarder.await;`), so a panic there is
95//!   still invisible. Pre-existing and low-likelihood (the forwarder only moves
96//!   already-decoded batches), tracked as a follow-up rather than fixed here.

118/// One message from a [`QueryRowStream`].
119#[derive(Debug)]
120pub enum QueryRowBatch {
121    /// A batch of decoded, read-shadowed `(RowKey, ScanRow)` rows in
122    /// token/partition order.
123    Rows(Vec<(RowKey, ScanRow)>),
124    /// This reader cannot be served by the single-generation streaming query
125    /// walk. Guaranteed to arrive BEFORE any [`QueryRowBatch::Rows`] and to be
126    /// the stream's only message, so the caller may fall back to another read
127    /// path having emitted nothing.
128    Unsupported,
129}
130
131/// One message on the producer→consumer channel (issue #3106).
132///
133/// INTERNAL: the terminator is deliberately NOT a [`QueryRowBatch`] variant, so
134/// no consumer can observe (or forget to handle) it — the sentinel exists purely
135/// to disambiguate "the walk finished" from "the producer died", which a bare
136/// channel disconnect cannot do.
137#[derive(Debug)]
138enum QueryRowMsg {
139    /// A batch. Carries only `Ok` BY CONSTRUCTION (issue #3106, roborev): a
140    /// failure is [`QueryRowMsg::Failed`], so "this message ends the stream" is a
141    /// structural property of the variant rather than an unenforced invariant
142    /// about where an `Err` was built. Were a non-fatal mid-stream `Err` ever sent
143    /// as an `Item`, the consumer would mark the stream terminated and a LATER
144    /// genuine dead-producer disconnect would silently revert to a clean end of
145    /// stream — #3106 reintroduced with no test failing.
146    Item(QueryRowBatch),
147    /// The walk failed. TERMINAL: the producer sends exactly one of this or
148    /// [`QueryRowMsg::Done`], as its last act.
149    Failed(Error),
150    /// The producer finished its walk and is exiting normally. This is the ONLY
151    /// thing that makes [`QueryRowStream::next_batch`] report a clean end of
152    /// stream; a disconnect without it is a dead producer.
153    Done,
154}

156/// A pull-based, single-generation query row stream (issue #3058).
157///
158/// Dropping it requests cancellation of the underlying walk; the producer thread
159/// then observes the cancel (or a failed send into the dropped channel) and exits.
160pub struct QueryRowStream {
161    rx: Receiver<QueryRowMsg>,
162    /// This stream's OWN cancellation flag — a CHILD of the caller's, never the
163    /// caller's own clone (roborev, issue #3058).
164    ///
165    /// `ScanCancel` clones share one `Arc<AtomicBool>`, so cancelling the
166    /// caller's flag on drop would POISON the whole request: the designed clean
167    /// fallback (`QueryRowBatch::Unsupported` → drop the stream → build the
168    /// k-way merger instead) would hand the merger an already-cancelled flag and
169    /// yield `Cancelled`/zero rows instead of the full result set, and even a
170    /// successful stream would leave the request's `CancelFlag` single-use. The
171    /// caller's flag is bridged INTO this child (caller-cancel stops the walk)
172    /// but never the other way round.
173    child_cancel: ScanCancel,
174    /// Whether an EXPLICIT terminator has been observed (issue #3106): either the
175    /// [`QueryRowMsg::Done`] sentinel or a terminal `Err`.
176    ///
177    /// This is what makes a subsequent channel disconnect interpretable. Set →
178    /// the producer is known to have finished/failed on purpose, so the
179    /// disconnect is a clean end of stream. Unset → the sender was dropped
180    /// WITHOUT a terminator, which only an unwinding (or otherwise dead)
181    /// producer can do, so the stream fails closed rather than reporting a
182    /// silently truncated result set as success.
183    terminated: bool,
184}
185
186impl QueryRowStream {
187    /// Block until the next message is available. `None` = the walk finished
188    /// (clean end of stream), proven by the explicit [`QueryRowMsg::Done`]
189    /// sentinel — never inferred from a channel disconnect.
190    ///
191    /// A disconnect WITHOUT that sentinel means the producer thread died mid-walk
192    /// (issue #3106) and yields `Some(Err(..))`: the result set is truncated, and
193    /// truncation must never be reported as success. A producer PANIC normally
194    /// arrives as a terminal `Err` carrying the panic message (the thread body
195    /// runs under `catch_unwind`), so this arm is the backstop for a producer that
196    /// died in a way it could not report at all (e.g. an abort of the send itself).
197    ///
198    /// The blocking wait is timed into the per-request RECV-WAIT accumulator
199    /// (`stream_subphase::time_recv`), exactly as the k-way merge's own recv site
200    /// is (`write_engine/merge/mod.rs`). The drive loop SUBTRACTS that accumulator
201    /// from its `stream_merge` bucket, so producer starvation / cold I/O on this
202    /// arm is not billed as merge CPU — without this wrap the fast arm (now the
203    /// DEFAULT path) would silently break #2819's "`stream_merge` is merge CPU
204    /// only" contract and inflate the sub-phase profile that issue #3096 uses as
205    /// its evidence base. Inert (no clock read) when no sub-phase sink is
206    /// installed, and it never touches the value returned.
207    pub fn next_batch(&mut self) -> Option<Result<QueryRowBatch>> {
208        let received = crate::observability::stream_subphase::time_recv(|| self.rx.recv());
209        match received {
210            Ok(QueryRowMsg::Item(batch)) => Some(Ok(batch)),
211            Ok(QueryRowMsg::Failed(e)) => {
212                // Terminal by construction: a caller that keeps polling after it
213                // gets a clean `None`, not a spurious dead-producer error.
214                self.terminated = true;
215                Some(Err(e))
216            }
217            Ok(QueryRowMsg::Done) => {
218                self.terminated = true;
219                None
220            }
221            Err(_disconnected) if self.terminated => None,
222            Err(_disconnected) => {
223                self.terminated = true;
224                Some(Err(dead_producer_error()))
225            }
226        }
227    }
228}

230/// The fail-closed error for a producer that disconnected without a terminator
231/// (issue #3106).
232///
233/// [`Error::Internal`] — ONE variant for both halves of this event (here and
234/// [`panicked_producer_error`]), chosen deliberately (roborev, issue #3106):
235/// nothing suggests the `Data.db` is bad, so `Corruption` would send an operator
236/// hunting a nonexistent bad file, and `Storage` is `is_recoverable() == true`
237/// (surfaced to consumers, e.g. the Node bindings' error mapping) which would
238/// advertise a deterministic internal failure as RETRYABLE. `Internal` is
239/// `is_recoverable() == false` and is the honest variant for a violated internal
240/// invariant.
241fn dead_producer_error() -> Error {
242    Error::internal(
243        "query row stream: the producer thread disconnected WITHOUT its terminal \
244         Done sentinel — it died mid-walk, so the result set is TRUNCATED and \
245         cannot be reported as a complete scan (issue #3106)",
246    )
247}
248
249/// Turn a caught producer-thread panic into an INFORMATIVE terminal error
250/// (issue #3106).
251///
252/// The bare disconnect backstop can only say "the producer died"; catching the
253/// unwind lets the client see WHERE/WHY, which is the difference between a
254/// debuggable failure and a mystery. The panic payload is a `String`/`&str` for
255/// every `panic!`/assertion (the only other shapes are hand-rolled
256/// `panic_any`), so an unrecognized payload degrades to a named placeholder
257/// rather than being dropped.
258///
259/// Same [`Error::Internal`] variant as [`dead_producer_error`] — one event, one
260/// variant, and not the `is_recoverable() == true` `Storage` this first used.
261fn panicked_producer_error(payload: &(dyn std::any::Any + Send)) -> Error {
262    let message = payload
263        .downcast_ref::<String>()
264        .map(String::as_str)
265        .or_else(|| payload.downcast_ref::<&'static str>().copied())
266        .unwrap_or("<non-string panic payload>");
267    Error::internal(format!(
268        "query row stream: the producer thread PANICKED mid-walk ({message}) — the \
269         result set is TRUNCATED and cannot be reported as a complete scan \
270         (issue #3106)"
271    ))
272}

274impl Drop for QueryRowStream {
275    fn drop(&mut self) {
276        // Stop the walk promptly rather than letting it run to completion into a
277        // channel nobody reads (the producer would otherwise only notice at its
278        // next send). Cancels only THIS stream's child flag — the caller's flag
279        // is untouched, so a caller that falls back to another read path gets an
280        // un-cancelled one. The thread is deliberately NOT joined: it holds only
281        // an `Arc<SSTableReader>` + its own runtime and exits on the next cancel
282        // poll, so a dropped stream never blocks the consumer.
283        self.child_cancel.cancel();
284    }
285}

287impl SSTableReader {
288    /// Open a [`QueryRowStream`] over this ONE reader (issue #3058).
289    ///
290    /// `schema` is the authoritative table schema for decoding, `token_bound` the
291    /// split's `(start, end]` range to push into the Summary-guided walk (`None`
292    /// = full ring), `now_secs` the caller's request-scoped read-time TTL clock,
293    /// and `scan_cancel` the caller's cooperative cancellation flag.
294    ///
295    /// See the module docs for the guarantees (read shadowing on, pinned clock,
296    /// token pushdown, fail-closed [`QueryRowBatch::Unsupported`]).
297    pub fn open_query_row_stream(
298        self: Arc<Self>,
299        schema: crate::schema::TableSchema,
300        token_bound: Option<ScanTokenBound>,
301        now_secs: i64,
302        scan_cancel: ScanCancel,
303    ) -> Result<QueryRowStream> {
304        let (tx, rx) = sync_channel::<QueryRowMsg>(QUERY_ROWS_CHANNEL_BATCHES);
305        // This stream's own flag (see `QueryRowStream::child_cancel`): the walk
306        // polls the CHILD, the caller's flag is bridged into it, and nothing ever
307        // cancels the caller's.
308        let child_cancel = ScanCancel::new();
309        let bridge = CancelBridge {
310            caller: scan_cancel,
311            child: child_cancel.clone(),
312        };
313        // Issue #3106: whatever fault a test armed FOR THIS READER is captured
314        // HERE (never re-read mid-walk) and owned by the producer thread. Always
315        // empty — and a zero-sized no-op whose scope closure is never called — in
316        // a production build.
317        let mut fault =
318            crate::storage::producer_fault::ProducerFault::capture_for(|| self.file_path());
319        // One publisher per producer thread; see `CompletionOnce` (issue #3384).
320        let mut done = CompletionOnce::new();
321        std::thread::Builder::new()
322            .name("cqlite-query-rows".to_string())
323            .spawn(move || {
324                let sender = tx.clone();
325                // Issue #3106: an UNWINDING walk must not look like a finished
326                // one. `AssertUnwindSafe` is sound here because nothing the
327                // closure touched is observed after an unwind: the reader,
328                // schema, parser buffers and cancel bridge are dropped, and the
329                // only thing used afterwards is `sender` — an mpsc `SyncSender`,
330                // which has no poisoning/broken-invariant state — to report the
331                // failure. The walk's own output is already downstream.
332                let outcome =
333                    std::panic::catch_unwind(std::panic::AssertUnwindSafe(|| -> Result<()> {
334                        let rt = tokio::runtime::Builder::new_current_thread()
335                            .enable_all()
336                            .build()
337                            .map_err(|e| {
338                                Error::Storage(format!(
339                                    "query row stream: failed to create runtime: {e}"
340                                ))
341                            })?;
342                        rt.block_on(drive_query_rows(
343                            self,
344                            schema,
345                            token_bound,
346                            now_secs,
347                            &bridge,
348                            &tx,
349                            &mut fault,
350                            &mut done,
351                        ))
352                    }));
353                // EXACTLY ONE terminal message on every exit path, so the
354                // consumer never has to infer completion from a disconnect.
355                let terminal = match outcome {
356                    Ok(Ok(())) => QueryRowMsg::Done,
357                    Ok(Err(e)) => QueryRowMsg::Failed(e),
358                    Err(panic) => QueryRowMsg::Failed(panicked_producer_error(panic.as_ref())),
359                };
360                // CAUSAL completion signal (issue #3384), published BEFORE the
361                // terminal message and never after (roborev): a consumer holding
362                // the terminal message must be able to conclude this producer can
363                // no longer publish, or a PRIOR case's producer could increment
364                // into a LATER case's freshly-reset counter. Nothing below decodes.
365                done.publish();
366                // The consumer may already be gone; a failed send is fine.
367                let _ = sender.send(terminal);
368            })
369            .map_err(|e| {
370                Error::Storage(format!("query row stream: failed to spawn thread: {e}"))
371            })?;
372        Ok(QueryRowStream {
373            rx,
374            child_cancel,
375            terminated: false,
376        })
377    }
378
379    /// Whether this reader has the components the single-generation streaming
380    /// query walk needs (an `Index.db`, not a BTI `Partitions.db`).
381    ///
382    /// AUTHORITATIVE reader metadata (issue #28): the presence of parsed
383    /// components, never a guess from file names, sizes, or byte content. It is a
384    /// NECESSARY condition, not a sufficient one — a walk may still report
385    /// [`QueryRowBatch::Unsupported`] when it cannot prove partition coverage, which
386    /// is why that signal exists.
387    pub fn supports_streaming_query_scan(&self) -> bool {
388        self.index_reader.is_some() && self.bti_partitions_db.is_none()
389    }
390
391    /// The STATIC columns this SSTable's OWN serialization header declares
392    /// (`Statistics.db`'s `SerializationHeader.staticColumns`) — authoritative
393    /// ON-DISK metadata, independent of any caller-supplied schema.
394    ///
395    /// Exists because a caller schema is not a safe source for the static
396    /// question (roborev, issue #3058): the Flight producer's schema comes from
397    /// the ticket DDL, and an `nb` header carries no embedded schema to
398    /// cross-check it against (#3097), so a DDL that predates an
399    /// `ALTER TABLE ADD … STATIC` (or a hand-built ticket) would declare no
400    /// static column for an SSTable that actually contains one. The
401    /// single-generation read path emits NOTHING for a partition holding only a
402    /// static row, where the merge arm emits one row, so a routing decision made
403    /// on the stale DDL alone would change the row count.
404    ///
405    /// The serialization header enumerates EVERY static column the file can
406    /// contain, so this is at least as strong as inspecting each decoded row's
407    /// `EXTENDED_IS_STATIC` flag, and it is available BEFORE the first row (so a
408    /// caller can fall back cleanly instead of aborting mid-stream).
409    ///
410    /// An empty result means "this file declares no static column" when the
411    /// header was parsed. A file whose `Statistics.db` is absent/unparsed also
412    /// yields an empty list — see [`Self::static_columns_are_known`], which a
413    /// caller MUST consult to distinguish the two.
414    pub fn on_disk_static_columns(&self) -> Vec<String> {
415        let Some(stats) = self.statistics_reader.as_ref() else {
416            return Vec::new();
417        };
418        stats
419            .statistics()
420            .serialization_header_columns
421            .iter()
422            .filter(|c| c.is_static)
423            .map(|c| c.name.clone())
424            .collect()
425    }
426
427    /// Whether [`Self::on_disk_static_columns`] is an ANSWER rather than an
428    /// absence of information: `true` when the serialization header was parsed
429    /// (so "no static columns" is authoritative), `false` when there is nothing
430    /// to read (no `Statistics.db`, or a header with no columns at all), in which
431    /// case a caller that needs the static question settled MUST fail closed.
432    pub fn static_columns_are_known(&self) -> bool {
433        self.statistics_reader
434            .as_ref()
435            .is_some_and(|s| !s.statistics().serialization_header_columns.is_empty())
436    }
437}

439/// Drive the single-generation walk, batching rows into `tx`.
440///
441/// # Source selection (issue #3058)
442///
443/// Both sources are single-generation, read-shadowed and clock-pinned; they
444/// differ in which cost they avoid, and the choice is made from the request's
445/// own authoritative shape — the presence of a token bound — never from a guess:
446///
447/// * **No token bound (a full-ring scan).** The WINDOWED batched scan
448///   (`scan_stream_batched_admitted`) — the exact path the bare `SELECT`
449///   full scan uses. It walks the data section directly, so it pays NO
450///   `partition_slice_fully_consumed` structural re-decode per partition and
451///   builds ZERO per-row `CellWriteMetadata` maps.
452/// * **A token bound (a Trino split).** The Summary-guided walk, so the split's
453///   range is pushed INTO the per-SSTable walk (#2412/#2413) and out-of-range
454///   partition bodies are never read. Its per-partition coverage check
455///   (`partition_slice_fully_consumed`, Signal B) drives the framing in
456///   STRUCTURE-ONLY mode (`parse_one_partition_structure_only`), so it builds no
457///   `CompactionRow`, no per-row `CellWriteMetadata` map and no complex-element
458///   map — this arm allocates ZERO metadata maps, exactly like the full-ring one,
459///   and that is pinned by `cell_metadata_maps == 0` in
460///   `cqlite-flight/tests/issue_3058_bypass_path_taken.rs`
461///   (`token_pruning_to_one_source_still_selects_the_fast_path`) plus every
462///   `assert_arms_agree` case's bypass leg. (Before that fix the check decoded
463///   through the compaction parser and DID build one map per row; the merge arm's
464///   own coverage check got the same saving, since those rows were always
465///   discarded.)
466///
467/// On a pre-emit `FellBack` from the Summary-guided walk the full-`Index.db`
468/// streaming walk is tried (full ring; the caller's downstream token filter
469/// still bounds the result set); on a second pre-emit `FellBack`,
470/// [`QueryRowBatch::Unsupported`] is reported and NOTHING has been emitted.
471async fn drive_query_rows(
472    reader: Arc<SSTableReader>,
473    schema: crate::schema::TableSchema,
474    token_bound: Option<ScanTokenBound>,
475    now_secs: i64,
476    cancel: &CancelBridge,
477    tx: &SyncSender<QueryRowMsg>,
478    fault: &mut ProducerFault,
479    done: &mut CompletionOnce,
480) -> Result<()> {
481    if token_bound.is_none() {
482        return drive_full_scan_rows(reader, schema, now_secs, cancel, tx, fault).await;
483    }
484
485    let scan_cancel = cancel.child();
486    let mut sink = BatchSink::new(tx, cancel, fault);
487
488    // Each walk gets its OWN short-lived emit closure so the `&mut sink` borrow
489    // ends with the call — that is what lets the pre-emit guard below actually
490    // READ `sink.emitted` between the two walks (roborev, issue #3058).
491    let outcome = reader
492        .stream_partitions_summary_guided(
493            scan_cancel,
494            token_bound,
495            Some(now_secs),
496            Some(&schema),
497            &mut |row: (RowKey, ScanRow)| sink.push(row),
498        )
499        .await?;
500    if matches!(outcome, FullIndexStreamOutcome::Streamed) {
501        sink.finish()?;
502        // A caller cancellation that broke the walk must surface as `Cancelled`,
503        // never as a clean (silently short) end of stream.
504        return cancel.caller_result();
505    }
506
507    // No usable Summary.db: fall back to the full-`Index.db` streaming walk. Both
508    // walks CONTRACT to report `FellBack` only BEFORE their first emit — ENFORCED
509    // here, not assumed (roborev, issue #3058): re-driving a second walk into a
510    // sink that already holds rows (an under-full, still-buffered batch counts)
511    // would flush both walks' output and silently DUPLICATE rows. Fail closed.
512    assert_nothing_emitted(sink.emitted, "before the full-index fallback walk")?;
513    let outcome = reader
514        .stream_all_partitions_via_full_index(
515            scan_cancel,
516            Some(now_secs),
517            Some(&schema),
518            &mut |row: (RowKey, ScanRow)| sink.push(row),
519        )
520        .await?;
521    if matches!(outcome, FullIndexStreamOutcome::Streamed) {
522        sink.finish()?;
523        return cancel.caller_result();
524    }
525
526    // Neither walk can serve this reader. Report it as the FIRST and ONLY
527    // message, having emitted nothing — enforced, for the same reason.
528    assert_nothing_emitted(sink.emitted, "before reporting Unsupported")?;
529    // Publish BEFORE the send: the documented caller drops the stream the moment it
530    // sees `Unsupported`, so this message is terminal in practice even though the
531    // closure still sends `Done` behind it (roborev, issue #3384).
532    done.publish();
533    let _ = tx.send(QueryRowMsg::Item(QueryRowBatch::Unsupported));
534    Ok(())
535}
536
537/// Publishes producer completion EXACTLY ONCE, and always BEFORE any message a
538/// consumer can act on as terminal (issue #3384, roborev).
539///
540/// The invariant this exists to hold: **no consumer-observable terminal message may
541/// precede the completion publish.** If one does, the consumer can drop the stream,
542/// its test can finish and a LATER test can `reset` the counter, and only then does
543/// the paused producer increment — so the later test observes a completion that was
544/// never its own and reads a non-final work count. That is a false PASS in the exact
545/// test this issue exists to make trustworthy.
546///
547/// Two exit paths publish, hence the idempotence: the `Unsupported` report inside
548/// [`drive_query_rows`], and the producer closure's terminal `Done`/`Failed`. A
549/// producer that takes the first still reaches the second.
550struct CompletionOnce(bool);
551
552impl CompletionOnce {
553    const fn new() -> Self {
554        Self(false)
555    }
556
557    fn publish(&mut self) {
558        if !self.0 {
559            self.0 = true;
560            crate::storage::read_path_probe::mark_query_row_producer_finished();
561        }
562    }
563}
564
565/// Hand ONE batch of rows to the consumer, returning `false` when the consumer
566/// has dropped the channel.
567///
568/// The SINGLE batch-handoff funnel for BOTH walk arms — which is exactly why the
569/// test-only producer-fault hook is consulted here (issue #3106): a fault armed
570/// against this stream is observed identically on the full-ring and the
571/// token-bounded arm, so neither can be fixed while the other silently truncates.
572/// [`ProducerFault::before_batch_handoff`] is a no-op (and `fault` a ZST) in a
573/// production build.
574fn emit_rows(
575    tx: &SyncSender<QueryRowMsg>,
576    fault: &mut ProducerFault,
577    rows: Vec<(RowKey, ScanRow)>,
578) -> bool {
579    fault.before_batch_handoff();
580    tx.send(QueryRowMsg::Item(QueryRowBatch::Rows(rows)))
581        .is_ok()
582}
583
584/// Fail closed when a walk reported `FellBack` AFTER handing rows to the sink.
585///
586/// The fallback design rests on "`FellBack` is pre-emit only"; if that ever
587/// stopped holding, continuing would emit some rows twice (once from the walk
588/// that fell back, once from the fallback walk) with no error anywhere. A
589/// corruption error is the only safe outcome — a partially-served stream must
590/// never be silently topped up.
591fn assert_nothing_emitted(emitted: u64, stage: &str) -> Result<()> {
592    if emitted > 0 {
593        return Err(Error::corruption(format!(
594            "query row stream: a walk reported FellBack AFTER emitting {emitted} row(s) \
595             ({stage}) — continuing would duplicate rows (issue #3058)"
596        )));
597    }
598    Ok(())
599}

601/// The stream's cancellation pair: the caller's flag (observed, NEVER cancelled)
602/// and this stream's own child flag (what the walks poll and what `Drop`
603/// cancels). See [`QueryRowStream::child_cancel`].
604struct CancelBridge {
605    caller: ScanCancel,
606    child: ScanCancel,
607}
608
609impl CancelBridge {
610    /// The flag to hand the walks.
611    fn child(&self) -> &ScanCancel {
612        &self.child
613    }
614
615    /// Propagate a CALLER cancellation into the child (one-way), returning
616    /// whether the scan should stop. Polled at batch boundaries, so a cancelled
617    /// request stops the walk without waiting for the consumer to drop us.
618    fn poll_caller(&self) -> bool {
619        if self.caller.is_cancelled() {
620            self.child.cancel();
621            return true;
622        }
623        false
624    }
625
626    /// `Err(Cancelled)` when the CALLER cancelled, else `Ok(())` — so a walk that
627    /// was broken by a cancellation terminates the stream with a cancellation
628    /// rather than a clean, silently truncated end of stream.
629    fn caller_result(&self) -> Result<()> {
630        if self.caller.is_cancelled() {
631            return Err(Error::Cancelled);
632        }
633        Ok(())
634    }
635}

637/// Full-ring arm: forward the windowed batched scan's `(RowKey, ScanRow)` batches
638/// straight through, re-using the batching the scan already did.
639///
640/// # Admission (issue #1594 / #2420, roborev #3058)
641///
642/// Opened [`ScanAdmission::Exempt`] — this scan does NOT take a core admission
643/// permit. Three reasons, all load-bearing:
644/// * The CALLER is already admitted. The Flight `do_get` this serves holds a
645///   `--max-concurrent-scans` permit for its whole life (#2420), and the core
646///   semaphore's default cap is `available_parallelism()` (≈ncpu), which is
647///   SMALLER than that governor's default of 64 — acquiring here would silently
648///   throttle single-source `do_get`s below the operator's configured
649///   concurrency.
650/// * The arm it replaces takes none. The k-way merge arm drives its inputs on
651///   plain `std::thread`s and never admits, so admitting here would make the
652///   fast path *less* concurrent than the slow path it replaces.
653/// * The resource the core semaphore protects is not contended here. This scan's
654///   `spawn_blocking` parse/feed tasks run on the query-row thread's OWN
655///   `current_thread` runtime (and therefore its own blocking pool), not the
656///   shared runtime pool whose starvation #1594 exists to prevent.
657///
658/// `Exempt` never blocks, so it cannot introduce the #1594 hold-and-wait cycle.
659async fn drive_full_scan_rows(
660    reader: Arc<SSTableReader>,
661    schema: crate::schema::TableSchema,
662    now_secs: i64,
663    cancel: &CancelBridge,
664    tx: &SyncSender<QueryRowMsg>,
665    fault: &mut ProducerFault,
666) -> Result<()> {
667    let table_id = reader.scan_table_id();
668    let mut rx = reader.scan_stream_batched_admitted(
669        table_id,
670        None,
671        None,
672        Some(schema),
673        QUERY_ROWS_FULL_SCAN_BUFFER_ROWS,
674        ScanAdmission::Exempt,
675        Some(now_secs),
676        // Issue #1704: `Exempt` here is about the ADMISSION permit (the caller holds
677        // one for the whole operation), not about nesting — this stream is drained
678        // DIRECTLY below, so nothing else will ever see its failures.
679        crate::storage::sstable::reader::ScanErrorReporting::TopLevel,
680    );
681    while let Some(msg) = rx.recv().await {
682        // Cooperative cancellation: the caller dropping the stream also drops our
683        // receiver (so the send below fails), but polling here stops a cancelled
684        // scan without waiting for the next batch to be produced. A CALLER cancel
685        // is bridged into the child flag; the caller's own flag is never touched.
686        if cancel.poll_caller() {
687            return Err(Error::Cancelled);
688        }
689        cancel.child().check()?;
690        let rows = msg?;
691        if !emit_rows(tx, fault, rows) {
692            // Consumer dropped: stop pulling (not an error).
693            return Ok(());
694        }
695    }
696    Ok(())
697}

699/// Accumulates emitted rows into `QUERY_ROWS_PER_BATCH`-sized batches and pushes
700/// them through the bounded channel, translating a dropped consumer — or a
701/// CALLER cancellation — into `ControlFlow::Break` so the walk stops instead of
702/// running to completion.
703struct BatchSink<'a> {
704    tx: &'a SyncSender<QueryRowMsg>,
705    /// The caller/child cancellation pair. The token-bounded walk polls the CHILD
706    /// internally at its own cadence, but nothing there sees the CALLER's flag —
707    /// so a client disconnect would otherwise only stop this walk once the
708    /// consumer noticed and dropped the stream (a whole batch of a wide partition
709    /// later). Bridged here, at the batch boundary (roborev, issue #3058).
710    cancel: &'a CancelBridge,
711    batch: Vec<(RowKey, ScanRow)>,
712    emitted: u64,
713    /// Test-only producer-fault state for this stream (issue #3106); a ZST with
714    /// a no-op hook in a production build.
715    fault: &'a mut ProducerFault,
716}
717
718impl<'a> BatchSink<'a> {
719    fn new(
720        tx: &'a SyncSender<QueryRowMsg>,
721        cancel: &'a CancelBridge,
722        fault: &'a mut ProducerFault,
723    ) -> Self {
724        Self {
725            tx,
726            cancel,
727            batch: Vec::with_capacity(QUERY_ROWS_PER_BATCH),
728            emitted: 0,
729            fault,
730        }
731    }
732
733    fn push(&mut self, row: (RowKey, ScanRow)) -> Result<ControlFlow<()>> {
734        self.batch.push(row);
735        self.emitted += 1;
736        if self.batch.len() >= QUERY_ROWS_PER_BATCH {
737            return self.flush();
738        }
739        Ok(ControlFlow::Continue(()))
740    }
741
742    fn flush(&mut self) -> Result<ControlFlow<()>> {
743        // Bridge a CALLER cancellation into the child (one-way — the caller's own
744        // flag is never cancelled, which is what keeps the merge-arm fallback
745        // usable) and stop the walk here rather than a batch later.
746        if self.cancel.poll_caller() {
747            return Ok(ControlFlow::Break(()));
748        }
749        if self.batch.is_empty() {
750            return Ok(ControlFlow::Continue(()));
751        }
752        let batch = std::mem::take(&mut self.batch);
753        self.batch.reserve(QUERY_ROWS_PER_BATCH);
754        if emit_rows(self.tx, self.fault, batch) {
755            Ok(ControlFlow::Continue(()))
756        } else {
757            // Consumer dropped: stop the walk (not an error).
758            Ok(ControlFlow::Break(()))
759        }
760    }
761
762    fn finish(&mut self) -> Result<()> {
763        // A `Break` here means the consumer went away with a partial tail
764        // pending — a clean end of stream, not an error.
765        let _ = self.flush()?;
766        Ok(())
767    }
768}
