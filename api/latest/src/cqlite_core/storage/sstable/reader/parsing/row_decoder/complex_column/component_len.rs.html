1//! One guarded conversion for a COMPOSITE COMPONENT LENGTH read from untrusted
2//! on-disk bytes (issue #3612 review round 3, finding R3-F1).
3//!
4//! # The defect this closes
5//! A tuple/UDT component is framed `[i32 BE len][bytes]`, where `-1` means null.
6//! Three of the UDT field loops handled `-1` and `0` and then cast the remainder
7//! with a bare `as usize`, so a length BELOW `-1` — e.g. `-2`, which is
8//! representable in any hostile or corrupt cell path — became a ~1.8e19 `usize`.
9//! The following `current_offset + field_len > data.len()` bounds test then
10//! OVERFLOWED (a debug-build panic; a wrap in release, after which the test can
11//! pass and the slice index panics instead). CLAUDE.md forbids a reachable panic
12//! in a parser on untrusted bytes, so this is a hard failure, not a nit.
13//!
14//! The UDT field loops, ALL FIVE now routed through here:
15//! * `udt.rs` `parse_udt_value` — the one that already rejected `< 0`
16//!   explicitly, i.e. the control that this was an inconsistency and not a
17//!   design; routed anyway so its duplicated arm could go away.
18//! * `udt.rs` `parse_nested_udt_from_registry`
19//! * `udt.rs` `parse_inline_udt_value`
20//! * `raw_type_value.rs`'s two INLINE loops inside `parse_raw_type_value` — the
21//!   MARSHAL one (the branch the committed `cm` fixture key actually takes) and
22//!   the REGISTRY-BARE one. Neither is a call to `parse_udt_value`; an earlier
23//!   revision of this header and of the enumeration table said it was.
24//!
25//! # Why the guard lives HERE, of all places
26//! Not for elegance. Those three branches became reachable from a MULTICELL map's
27//! cell-path key only because #3612 delegated that key to the structural decoder
28//! (`decode_reporting_consumption` routes a registry-resolved bare UDT name and a
29//! marshal `UserType(..)` through `parse_raw_type_value`), so this module is the
30//! change that exposed them. Their own files — `udt.rs` (1777 lines) and
31//! `raw_type_value.rs` (1233) — are both far over the 800-line campsite threshold
32//! and cannot grow without tripping the gate's file-size ratchet, whereas routing
33//! each site through this helper REMOVES ~5 lines from each of them. Splitting
34//! either file properly is epic #1116's job, not a bounds fix's.
35//!
36//! # Why it also owns the bounds test
37//! Folding the conversion and the `offset + len <= end` test into one call is what
38//! makes the change line-negative at every site, and it means the two can never
39//! again be applied in the wrong order or one without the other — which is exactly
40//! how R3-F1 arose.
41
42use super::*;
43
44impl V5CompressedLegacyParser {
45    /// Convert a component/field length read from on-disk bytes into a `usize`
46    /// and prove it fits inside `end`, or return a corruption error.
47    ///
48    /// Callers handle the two SPECIAL lengths first — `-1` (null component) and
49    /// `0` (empty component) — so anything arriving here must be positive.
50    /// A negative value is corruption and is rejected BEFORE any conversion; the
51    /// bounds test then uses `checked_add`, so no arithmetic here can wrap or
52    /// panic for any `i32` input.
53    pub(in crate::storage::sstable::reader::parsing::row_decoder) fn checked_component_len(
54        raw: i32,
55        component: &str,
56        offset: usize,
57        end: usize,
58    ) -> Result<usize> {
59        if raw < 0 {
60            return Err(Error::corruption(format!(
61                "UDT/tuple component '{}': invalid negative length {} (only -1, meaning \
62                 null, is a legal negative)",
63                component, raw
64            )));
65        }
66        let len = raw as usize;
67        let past = offset.checked_add(len).ok_or_else(|| {
68            Error::corruption(format!(
69                "UDT/tuple component '{}': length {} overflows the offset {}",
70                component, len, offset
71            ))
72        })?;
73        if past > end {
74            return Err(Error::corruption(format!(
75                "UDT/tuple component '{}' extends beyond data (need {}, have {})",
76                component,
77                len,
78                end.saturating_sub(offset)
79            )));
80        }
81        Ok(len)
82    }
83}
