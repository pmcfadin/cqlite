1//! Issue #3928 — the ONE partition-HEADER arm of the two SLIDING drivers.
2//!
3//! `drive_partition_sliding` (buffered, one whole partition per call) and
4//! `stream_partition_body_incremental` (row-granular, one structure per call)
5//! had this arm spelled out twice, verbatim: the same
6//! [`PartitionHeaderReadiness`] classification, the same re-classification after
7//! a parse failure, and the same byte resync — each expressed in its own advance
8//! vocabulary (`ParseStep::Emitted(1)` / `PartitionStreamStep::Consumed(1)`,
9//! which are the SAME resync wearing two names).
10//!
11//! What must not diverge between them is the DECISION, so the decision lives
12//! here and each driver only translates the answer into its own vocabulary. The
13//! block-emit walk deliberately keeps its own arm
14//! (`block_emit_windowed/partition_header_arm.rs`): its discriminator is the
15//! caller-stated [`BufferExtent`], not `at_final_chunk`, and it has a partition
16//! index to report.
17//!
18//! # Why the tolerant answer was unsound at the final chunk
19//!
20//! Both arms tolerated unconditionally. At the final chunk no further bytes can
21//! arrive, so a header that does not classify or does not parse is truncation or
22//! corruption — and the one-byte resync then has two effects, the second worse
23//! than the first: the partition is silently DROPPED, and the resync can land on
24//! MISALIGNED bytes that parse as a plausible header, INVENTING a partition that
25//! does not exist.
26//!
27//! Measured on a real Cassandra 5.0 `da` fixture with ONE compressed byte
28//! flipped so the first partition's `DeletionTime` discriminator reads `0xFF` —
29//! a value Cassandra's own `DeletionTime.Serializer.deserialize` throws on
30//! (cassandra-5.0.8 `DeletionTime.java:222-230`) — both compaction surfaces
31//! answered `Ok` with **404 of 468** rows and both partition-key surfaces
32//! answered `Ok` with **5** keys where the fixture has **3**: 64 rows lost and 2
33//! partitions invented, reported as success. Compaction would write that back to
34//! disk. The count moves in BOTH directions, so no count-based check and no
35//! total-comparing parity oracle can see it.
36//!
37//! `at_final_chunk` is the authoritative discriminator, exactly as it is for the
38//! row arm #3782 fixed: it is a property of the sliding window, not a guess
39//! about the bytes. Mid-stream the SAME conditions stay tolerant, because a
40//! window the driver can still advance out of may legitimately be positioned
41//! mid-structure.

46/// Issue #3999 — every refusal derived from CQLite's partition-key-LENGTH model
47/// must carry this, because that model is known to differ from Cassandra's for
48/// keys of 256 bytes or more.
49///
50/// Cassandra writes the Data.db partition key as
51/// `ByteBufferUtil.writeWithShortLength(key.getKey(), writer)` inside
52/// `SortedTablePartitionWriter.start` (cassandra-5.0.8
53/// `SortedTablePartitionWriter.java:97-105`), i.e. `out.writeShort(length)` — an
54/// unsigned 16-bit BIG-ENDIAN length, with NO flags byte. CQLite reads byte 0 as
55/// "flags" and byte 1 as a one-byte length, so the two models coincide only
56/// while the high byte is `0x00`, i.e. for keys under 256 bytes. For a 256-byte
57/// key Cassandra writes `0x0100`, CQLite reads a length of `0`, and a refusal
58/// here would be CQLite's own model rather than corruption.
59///
60/// Correcting the model touches `partition_header_readiness`,
61/// `scan_partition_header`, `peek_is_partition_header`,
62/// `parse_partition_header_full` and `FORMAT_MAX_KEY_SIZE`, and needs a
63/// 256-byte-key fixture the corpus does not have — a different family, tracked
64/// as **#3999**. Until then the refusal STAYS (loud beats silent, and #3928's
65/// whole subject is that the silent answer both dropped and invented
66/// partitions) and it SAYS SO, so an operator who hits a long key is pointed at
67/// the right issue instead of at their disk.
68const KEY_LENGTH_MODEL_CAVEAT: &str = "NOTE (#3999): CQLite reads that length as ONE byte \
69     after a 'flags' byte, while Cassandra writes an unsigned 2-byte big-endian length and no \
70     flags byte (SortedTablePartitionWriter.start -> ByteBufferUtil.writeWithShortLength), so \
71     the two models agree only for keys under 256 bytes; for a longer key this refusal may be \
72     CQLite's model and not corruption.";

74/// What a sliding driver should do with the bytes at its window front.
75pub(in crate::storage::sstable::reader::parsing::row_decoder) enum DriverHeader {
76    /// A structurally-valid header: the partition key, the offset of the first
77    /// row/marker, and the partition-level deletion.
78    Parsed(RowKey, usize, Option<(i64, i32)>),
79    /// The header (or, for an `oa`/`da` deleted partition, its 12-byte
80    /// `DeletionTime`) is split across the chunk boundary. Unreachable at the
81    /// final chunk.
82    NeedMore,
83    /// The window front is not a decodable header and more bytes may still
84    /// arrive, so the driver consumes ONE byte and re-tries. Unreachable at the
85    /// final chunk.
86    Resync,
87    /// There is NOTHING here: an EMPTY buffer at the final chunk. The drivers
88    /// translate it to `ParseStep::Done` / `PartitionStreamStep::AllDone`, i.e.
89    /// clean completion of the walk.
90    ///
91    /// Reachable ONLY for an empty buffer since finding C1 — a non-empty
92    /// incomplete header at the final chunk is a truncated partition and is
93    /// refused. Both drivers early-return on `data.is_empty()` before calling
94    /// this arm, so no caller reaches this variant today; it exists so the arm
95    /// is total, because "there is nothing here" is not corruption.
96    Done,
97}
98
99/// What CQLite READ as the partition key length, when there were enough bytes to
100/// read one at all (issue #3928 / #3999).
101///
102/// With a single byte present NO length has been read, so the diagnostic must
103/// not name one — asserting a length nobody read is the same class of false
104/// statement #3999 is about, one field over.
105fn read_length_note(data: &[u8]) -> String {
106    match data.get(1) {
107        Some(&low) => format!(" (CQLite READ a key length of {low} from byte 1)"),
108        None => " (too short for CQLite to have read a key length at all)".to_string(),
109    }
110}

112impl V5CompressedLegacyParser {
113    /// Classify and (on success) parse the partition header at the front of
114    /// `data`.
115    ///
116    /// `at_final_chunk` is the driver's authoritative "no further bytes can
117    /// arrive" fact, and it is converted at this boundary into the same
118    /// [`HeaderTolerance`] the block-emit arm consults, so both arms ask ONE
119    /// question with one answer. A driver has no row-body bound, so its progress
120    /// is always attributable: every call starts at a partition boundary the
121    /// caller advanced to by a CONFIRMED consumed-byte count.
122    pub(in crate::storage::sstable::reader::parsing::row_decoder) fn driver_partition_header(
123        &self,
124        data: &[u8],
125        at_final_chunk: bool,
126    ) -> Result<DriverHeader> {
127        // #1741 (roborev HIGH): size the header need-more decision correctly for
128        // the oa/da DeletionTime form via the authoritative discriminator peek,
129        // so a deleted header split across a NON-FINAL chunk returns `NeedMore`
130        // instead of being mis-parsed and skipped (which desynced the scan and,
131        // on compaction, dropped a partition tombstone).
132        let tolerance = HeaderTolerance::for_final_chunk(at_final_chunk);
133        match self.partition_header_readiness(data) {
134            // `Malformed` is decidable from TWO bytes (a zero or over-long
135            // declared key length), so no additional byte can rescue it — and at
136            // the final chunk none can arrive at all.
137            PartitionHeaderReadiness::Malformed => {
138                if tolerance.refuses() {
139                    return Err(Error::corruption(format!(
140                        "V5CompressedLegacy: refusing an unreadable partition header at the \
141                         FINAL chunk (leading bytes {:02x?}, {} byte(s) in window): CQLite \
142                         READ a partition key length of {} and rejects it as zero or \
143                         over-long, and no further bytes can arrive to change what was read. \
144                         Skipping a byte to resynchronise would DROP this partition and can \
145                         land on misaligned bytes that parse as a plausible header, INVENTING \
146                         a partition that does not exist (issue #3928). \
147                         {KEY_LENGTH_MODEL_CAVEAT}",
148                        &data[..data.len().min(2)],
149                        data.len(),
150                        usize::from(data[1])
151                    )));
152                }
153                Ok(DriverHeader::Resync)
154            }
155            // `Incomplete` means the header could not be COMPLETED from the
156            // bytes present — the declared key runs past the buffer, its
157            // `DeletionTime` does, or there are fewer than the two bytes any
158            // header needs.
159            //
160            // Mid-stream that is the ordinary straddle: more bytes can arrive,
161            // so `NeedMore`. At the final chunk none can, and then EVERY
162            // non-empty case is a header Cassandra wrote whose bytes were
163            // truncated away. `DriverHeader::Done` is read by BOTH drivers as
164            // CLEAN COMPLETION (`ParseStep::Done` / `PartitionStreamStep::AllDone`),
165            // so it is truthful only where there is genuinely NOTHING here.
166            //
167            // Issue #3928 round 1 kept the one-byte case tolerant, reasoning that
168            // fewer than two bytes cannot be a partition. Finding C1: that byte
169            // can be the surviving FIRST byte of a truncated partition-key
170            // length, so the partition IS lost — and `block_emit`'s walk already
171            // refused the identical bytes, leaving the driver path and the
172            // block-emit path disagreeing about one file. Measured pre-fix: the
173            // driver answered `Done` over ONE byte of a header declaring a
174            // 16-byte key while both block walks answered `Err`.
175            //
176            // So the byte COUNT decides nothing (it never did — see
177            // `HeaderTolerance`); emptiness does. And an empty buffer cannot
178            // reach here from either driver today: both early-return on
179            // `data.is_empty()` before this call. The arm is kept total anyway,
180            // because a function that refuses "there is nothing here" as
181            // corruption would be wrong in isolation, and this one is
182            // `pub(in row_decoder)`.
183            //
184            // No caller legitimately leaves a non-empty stub at the final chunk:
185            // every `Emitted`/`PartitionDone` consumed-count includes the
186            // structural terminator and the callers advance by exactly it
187            // (`scan_stream_windowed.rs`'s `window.consume(take)`,
188            // `drain_compaction_window`), and the AC3 counters recorded ZERO
189            // arrivals here at the final chunk across 126 tables / 148 SSTables
190            // on four surfaces.
191            PartitionHeaderReadiness::Incomplete => {
192                if !tolerance.refuses() {
193                    return Ok(DriverHeader::NeedMore);
194                }
195                if data.is_empty() {
196                    return Ok(DriverHeader::Done);
197                }
198                Err(Error::corruption(format!(
199                    "V5CompressedLegacy: refusing a TRUNCATED partition header at the FINAL \
200                     chunk: {} byte(s) are present{}, too few to complete the header, and no \
201                     further bytes can arrive. The partition Cassandra wrote here was \
202                     truncated away, so reporting completion would DROP it and answer Ok \
203                     with one fewer partition than the file holds (issue #3928). \
204                     {KEY_LENGTH_MODEL_CAVEAT}",
205                    data.len(),
206                    read_length_note(data)
207                )))
208            }
209            PartitionHeaderReadiness::Ready => match self.parse_partition_header_full(data, 0) {
210                Ok((key, after_header, deletion)) => {
211                    Ok(DriverHeader::Parsed(key, after_header, deletion))
212                }
213                // Defense-in-depth: `Ready` guarantees the DeletionTime is fully
214                // present, so a parse failure here cannot be truncation. On a
215                // non-final chunk only re-request bytes if the header is somehow
216                // still incomplete (a `NeedMore` on a complete buffer would loop
217                // for ever).
218                //
219                // Issue #3928: the error is REPORTED, with its own kind
220                // preserved, exactly as the row arm reports its own (#3782) —
221                // and here it is reported REGARDLESS of `at_final_chunk`, which
222                // is the one place this issue's rule is STRONGER than #3782's.
223                //
224                // Why that is sound rather than over-eager: `Ready` is an
225                // AFFIRMATIVE guarantee from `partition_header_readiness` that
226                // every header byte — the key length, the key, and the full
227                // `DeletionTime` for its live/deleted form (the discriminator is
228                // PEEKED to size it, #1741) — is already present. So a failure
229                // here "is a genuine STRUCTURAL rejection ... never truncation"
230                // (that classifier's own contract, quoted from
231                // `row_framing.rs`), and no additional byte can change the
232                // verdict. AC1's tolerance carve-out is for a header that "can
233                // legitimately straddle" the window; a `Ready` header provably
234                // cannot.
235                //
236                // Measured: on a real `da` fixture whose FIRST partition's
237                // `DeletionTime` discriminator was flipped to a value
238                // Cassandra's own reader throws on, that header sits in chunk 0
239                // of 5 — so `at_final_chunk` is FALSE there —  and
240                // `stream_all_partitions_for_compaction` answered `Ok` with 404
241                // of 468 rows. An `at_final_chunk`-gated refusal would have left
242                // that silent loss in place on the surface compaction WRITES
243                // BACK.
244                //
245                // The `Incomplete` re-probe is kept as defence in depth: it can
246                // only fire if the classifier disagrees with itself between the
247                // two calls, and a `NeedMore` is the conservative answer there.
248                Err(e) => {
249                    if !at_final_chunk
250                        && self.partition_header_readiness(data)
251                            == PartitionHeaderReadiness::Incomplete
252                    {
253                        return Ok(DriverHeader::NeedMore);
254                    }
255                    Err(e)
256                }
257            },
258        }
259    }
