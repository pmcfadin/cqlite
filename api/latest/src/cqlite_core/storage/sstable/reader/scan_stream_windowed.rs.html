1//! Sliding-window stitch+parse driver for the user-facing streaming scan
2//! (issue #1143).
3//!
4//! # Design (issue #1143 regression fix)
5//!
6//! The V5CompressedLegacy full scan must reconcile two goals that PR #1156
7//! treated as mutually exclusive:
8//!
9//!   1. **Bounded heap.** Keep only a sliding `window: Vec<u8>` of decompressed
10//!      bytes (peak `max_partition_size + one_chunk`), not an O(file) stitched
11//!      buffer per scan. (PR #1156's contribution — KEPT.)
12//!   2. **CPU off the async worker pool.** Decompress +
13//!      `parse_one_partition_with_timestamps` are CPU-bound; running them inline
14//!      on the small async worker pool (as PR #1156 did, relying on
15//!      `yield_now()`) lets a scan starve everything else scheduled there
16//!      (writer flush/compaction in production), halving reader throughput under
17//!      concurrent write load. The pre-#1156 path ran the whole parse under a
18//!      dedicated `spawn_blocking` thread — restore that.
19//!
20//! Both are achievable together. This driver splits the work across THREE stages
21//! of one bounded pipeline (issue #1143 contention fix):
22//!
23//!   - **Blocking I/O + decode half** (`feed_raw_chunks_blocking`): a single
24//!     `spawn_blocking` task, for EVERY backend (issues #1593, #1940). It reads the
25//!     next raw compressed chunk, DECODES it (CRC-verify in the read →
26//!     cache-lookup-or-decompress, D2), and hands the decompressed refcounted
27//!     `Bytes` to the parse half over a small bounded channel (`raw` channel,
28//!     capacity [`RAW_CHUNK_CHANNEL_CAP`] = 8 so the feed can read ahead instead of
29//!     ping-ponging on every chunk). Running this off the async worker pool keeps
30//!     BOTH the (possibly synchronously-faulting) read AND the decompression CPU
31//!     off the reactor — a decode on the reactor is the same Epic F starvation the
32//!     parse offload prevents.
33//!   - **Blocking parse half** (`drain_scan_window_blocking`): a single
34//!     `spawn_blocking` task owns the parser, the schema, and the sliding
35//!     window. It pulls ALREADY-DECODED chunks with `blocking_recv`, appends to
36//!     the window, drains every confirmed partition, and accumulates surviving
37//!     `(RowKey, ScanRow)` entries into a BATCH of up to [`BATCH_EMIT_ROWS`], which
38//!     it hands across the blocking→async seam via `tx.blocking_send` as ONE
39//!     `Vec` item. ALL decompress+parse CPU runs here, off the async worker pool.
40//!     Batching is the key contention fix: PR #1156 `blocking_send`'d one row at
41//!     a time, so a `SELECT *` full scan woke the consuming async task O(rows)
42//!     times across the blocking-pool ↔ async-worker boundary; samply attributed
43//!     ~31.5% of read wall time under `mixed.read_while_write` conc=8 to that one
44//!     `parking_lot` condvar. Batching amortizes the wake ~`BATCH_EMIT_ROWS`×.
45//!     To keep that win WITHOUT regressing incremental delivery, the pending
46//!     batch is flushed at a BOUNDED CADENCE — at each chunk/window drain
47//!     boundary (after the per-chunk drain returns NeedMore / empties the
48//!     window) as well as on reaching `BATCH_EMIT_ROWS` — so a sparse or
49//!     sub-`BATCH_EMIT_ROWS` scan (e.g. a `LIMIT`) still delivers its confirmed
50//!     rows promptly instead of waiting for the whole scan to finish. The wake
51//!     rate is thus ~one-per-chunk (plus one-per-full-batch in dense windows),
52//!     far below PR #1156's one-per-row.
53//!   - **Async forwarder task** (in `run_scan_stream_windowed`): adapts the SAME
54//!     internal `Vec`-batched stream to whichever public surface the caller asked
55//!     for (issue #1592, Epic F/F2), selected by [`WindowedOut`]. The
56//!     [`WindowedOut::PerRow`] arm FLATTENS each `Vec` batch back into the caller's
57//!     per-item `tx`, preserving the historical `scan_stream` contract (item type,
58//!     order, backpressure) unchanged — so per-row is a thin flattening adapter
59//!     over the batched internal stream. The [`WindowedOut::Batched`] arm FORWARDS
60//!     each `Vec` batch straight through to the caller's batched `tx`, so the
61//!     consumer is woken once per BATCH, not once per row (the F2 win: the internal
62//!     batch is not re-flattened then re-batched onto the public channel). Runs on
63//!     the async runtime concurrently with the I/O half (both are needed at once;
64//!     running them sequentially would deadlock), so its wakes are cheap
65//!     async-worker wakes, not blocking-pool condvar wakes.
66//!
67//! ## Backpressure (preserved end-to-end)
68//!
69//! A slow consumer blocks the forwarder's `tx.send().await`, which stops draining
70//! the bounded batch channel, which blocks the parse half's `tx.blocking_send`,
71//! which stops the parse loop, which stops draining the `raw` channel, which
72//! (being bounded) blocks `raw_tx.send().await` in the I/O half, which stops
73//! reading from disk. Nothing buffers the whole file; live heap stays
74//! `window + RAW_CHUNK_CHANNEL_CAP` raw chunks + at most
75//! [`MAX_INFLIGHT_BATCH_ROWS`] buffered rows ahead of the caller.
76//!
77//! ## Worst-case resident rows (issue #1143, roborev)
78//!
79//! Be honest and COMPLETE: against a stalled consumer the resident `(RowKey, ScanRow)`
80//! count is the SUM of three inherent terms, not one constant —
81//! `buffer_size + max_partition_size + MAX_INFLIGHT_BATCH_ROWS`:
82//!
83//! - **`buffer_size`** — the public per-item channel, sized from the caller's
84//!   `StreamingConfig::buffer_size`.
85//! - **`max_partition_size`** — INHERENT to any row-materializing partition scan and
86//!   PRE-DATES this change: `drain_scan_window` parses one CONFIRMED partition fully
87//!   into a reused `scratch: Vec<(RowKey, ScanRow)>` before batching (the parser's `FnMut`
88//!   emit is synchronous, so a partition's rows cannot stream out mid-parse), so if
89//!   `blocking_send` stalls mid-iteration the producer still owns that Vec's
90//!   not-yet-batched tail. This is the pre-existing #1156 windowed-scan heap term
91//!   (heap was always `~max_partition_size + one_chunk`); this PR neither introduced
92//!   it nor restructures emission to observe backpressure mid-partition — that is a
93//!   separate #1156 redesign, deliberately out of scope here.
94//! - **`MAX_INFLIGHT_BATCH_ROWS`** — the *additional* bound this PR's batching adds:
95//!   a SECOND in-flight pool NOT sized by `buffer_size`. The bounded batch channel
96//!   (`BATCH_CHANNEL_CAP` batches), the one batch the forwarder `recv()`'d and is
97//!   flattening, AND the one batch the producer is parked-in-`blocking_send` holding
98//!   can ALL be live at once — even when `buffer_size == 1`: a deliberate, BOUNDED
99//!   read-ahead, the price of amortizing the blocking->async wake. It bounds the
100//!   BATCHING subsystem ALONE; it does NOT — and is not claimed to — cover the
101//!   `max_partition_size` term. The public `scan_stream` doc states the full
102//!   three-term sum so callers know the true worst case.
103//!
104//! ## Cancellation (issue #1143 finding 2)
105//!
106//! The outer scan runs inside the `tokio::spawn` in `scan_stream`; if that task
107//! is dropped/cancelled at an `await`, the parse task's `JoinHandle` (held in
108//! `run_scan_stream_windowed`) is dropped too. Dropping a `spawn_blocking`
109//! `JoinHandle` DETACHES the task — it does NOT abort it (there is no portable
110//! way to interrupt a running blocking thread). The detached parse task keeps
111//! running: `raw_rx.blocking_recv()` observes the dropped `raw_tx`, and because a
112//! clean cancellation leaves `io_failed == false`, it proceeds to a final drain
113//! and `tx.blocking_send`s its trailing batch into the batch channel.
114//!
115//! This is harmless in practice and needs no abort machinery: on cancellation
116//! the consumer drops the `mpsc::Receiver` (`rx`) returned by `scan_stream`, so
117//! the forwarder's next `fwd_tx.send` fails, the forwarder returns and drops the
118//! batch receiver, so the parse half's next `tx.blocking_send` fails
119//! (`*broke = true`), the parse loop returns immediately, and the task — and the
120//! `reader: Arc<Self>` it holds — are released. The only window in which it can
121//! still emit is when a batch was already in flight AND the consumer's `rx` has
122//! not yet dropped, i.e. the consumer is still reading; those rows are valid scan
123//! output, not garbage. Worst case the task lingers for one partition's parse
124//! before its `blocking_send` fails, keeping `Arc<Self>` alive only that long.
125//! Pre-#1156 the parse ran inline on the cancellable async task, so this detach
126//! window is new to the offload split; it is bounded and self-terminating, so we
127//! document it rather than add abort plumbing.
128//!
129//! ## Parity
130//!
131//! The emitted set/order is byte-identical to the prior inline driver: same
132//! schema resolution, same incompressible-chunk raw fallback, same
133//! `table_ids_match` / key-range / `filter_tombstone` filters, same
134//! NeedMore/Done straddle handling and final-chunk semantics, same
135//! `READ_SCAN_WINDOW_REFILL` counter. The only change is WHERE the CPU runs.

179/// Bound on the raw-compressed-chunk channel feeding the blocking parse task.
180///
181/// This is the I/O-half → parse-half hand-off depth. It must stay small enough
182/// to bound live heap (combined with the sliding window: live heap is
183/// `max_partition_size + (RAW_CHUNK_CHANNEL_CAP + 1) * one_chunk`), but a value
184/// of 2 (PR #1156's original) makes the two halves ping-pong: the I/O half fills
185/// the channel, parks on `raw_tx.send().await`, and is unparked again after the
186/// parse half drains essentially every chunk. Under concurrent write load (issue
187/// #1143, `mixed.read_while_write` conc=8) samply showed ~42% of read wall time
188/// parked on futexes, dominated by this channel's park/unpark, roughly doubling
189/// read p99 vs the pre-windowing baseline.
190///
191/// Raising the depth to 8 lets the I/O half read ahead up to 8 compressed chunks
192/// before it has to park, amortizing the wake round-trips ~4x while preserving
193/// the bounded-heap intent of PR #1156. The chunks are RAW COMPRESSED data
194/// (~`one_chunk` = the SSTable's compression chunk length, typically 16–64 KiB),
195/// so the added buffer is at most `(8 - 2) * one_chunk` ≈ 384 KiB per scan at
196/// 64 KiB chunks. At the issue #1143 concurrency of 8 readers that is < 3 MiB of
197/// channel buffers total — negligible against the < 128 MiB budget, and far
198/// smaller than the O(file) stitch buffer PR #1156 eliminated. Backpressure is
199/// unchanged: a full channel still blocks the I/O half, which still blocks disk
200/// reads, so nothing buffers the whole file.
201const RAW_CHUNK_CHANNEL_CAP: usize = 8;
202
203/// Number of surviving `(RowKey, ScanRow)` entries the blocking parse half buffers
204/// before it hands a batch across the blocking→async seam.
205///
206/// PR #1156's blocking parse half `blocking_send`s ONE row at a time into the
207/// async consumer's channel. Each such send parks/unparks across the
208/// blocking-pool ↔ async-worker boundary (a `parking_lot` condvar wake under
209/// tokio's blocking pool). For a `SELECT *` full scan that is O(rows) wakes per
210/// scan — and samply attributed ~31.5% of read wall time to that one condvar
211/// under `mixed.read_while_write` conc=8 (issue #1143). The cap-bump on the
212/// raw-chunk channel alone did not move read p99 in the external harness, because
213/// the cost is dominated by THIS per-row cross-thread wake, not the chunk hand-off.
214///
215/// Batching `BATCH_EMIT_ROWS` rows into a single `Vec` item amortizes that wake
216/// ~`BATCH_EMIT_ROWS`× (one wake per batch instead of one per row) while keeping
217/// the bounded-heap and backpressure guarantees: a batch holds at most this many
218/// `(RowKey, ScanRow)` already-owned entries (the same entries the prior code held
219/// transiently in `scratch`), and the batch channel is bounded
220/// ([`BATCH_CHANNEL_CAP`]) so a slow consumer still stops the parse loop, which
221/// still stops draining raw chunks, which still stops disk reads. Order is
222/// preserved (entries are pushed and drained FIFO, batches sent in order). A
223/// modest value keeps the per-batch heap small; tiny / sparse result sets do not
224/// wait for a full batch because the pending tail is flushed at every chunk/window
225/// drain boundary (and at stream end), preserving incremental first-row delivery.
226pub(crate) const BATCH_EMIT_ROWS: usize = 256;
227
228/// Bound on the batched-row channel feeding the async forwarder. Small: the
229/// forwarder flattens batches into the public per-item channel roughly as fast as
230/// the parse half produces them. Live heap on this channel is at most
231/// `BATCH_CHANNEL_CAP * BATCH_EMIT_ROWS` entries; with the defaults that is
232/// ~512 small `(RowKey, ScanRow)` entries — negligible against the <128MB budget.
233const BATCH_CHANNEL_CAP: usize = 2;
234
235/// Documented bound on the rows the windowed scan's BATCHING SUBSYSTEM may hold in
236/// flight ahead of the caller, INDEPENDENT of `scan_stream`'s `buffer_size`
237/// (roborev finding, issue #1143).
238///
239/// # Scope (read this first)
240///
241/// This bounds the BATCHING subsystem ALONE — the pending `batch`, the bounded batch
242/// channel, and the parked-in-`blocking_send` batch — the *additional* in-flight pool
243/// issue-#1143 batching adds, NOT sized by `buffer_size`. It is NOT the whole-pipeline
244/// resident-row bound: the complete worst case (module doc) is
245/// `buffer_size + max_partition_size + MAX_INFLIGHT_BATCH_ROWS`, and this constant
246/// does NOT cover the inherent pre-existing-#1156 `max_partition_size` term (the one
247/// confirmed partition `drain_scan_window` materializes in `scratch` before
248/// batching). It is named/tested so a future `BATCH_EMIT_ROWS`/`BATCH_CHANNEL_CAP`
249/// tweak cannot silently let batching run arbitrarily far ahead of a stalled consumer.
250///
251/// # The bound (batching subsystem)
252///
253/// When the public consumer is stalled, THREE full batches coexist in flight — not
254/// two (each up to `BATCH_EMIT_ROWS` rows):
255///   1. **Forwarder-held.** The async forwarder `recv()`'d one batch and is blocked
256///      flattening it into the caller's full `tx`; it has LEFT the batch channel.
257///   2. **Channel-resident.** The bounded batch channel is FULL —
258///      `BATCH_CHANNEL_CAP` items — because the forwarder (stuck on (1)) stopped draining.
259///   3. **Producer-blocked.** The `spawn_blocking` parse half assembled its NEXT
260///      full batch and is PARKED in `tx.blocking_send`, still OWNING it because the
261///      channel (full, per (2)) has no slot — `blocking_send` moves the value only
262///      on success, so a parked send holds a third, distinct batch.
263///
264/// All three coexist at one instant; the pending tail in `drain_scan_window` is NOT
265/// a fourth — once it REACHES `BATCH_EMIT_ROWS` it BECOMES (3) via `blocking_send`,
266/// and a producer parked in that send accumulates no further tail. So bounding by
267/// `(BATCH_CHANNEL_CAP + 2) * BATCH_EMIT_ROWS` covers channel + forwarder-held (+1)
268/// + producer-blocked-in-send (+1).
269///
270/// With the defaults (`256 * 4 = 1024`) this equals — never exceeds — every real
271/// caller's `buffer_size` (`StreamingConfig::buffer_size` defaults to 1024, the
272/// text preset is 512 ≤ this), keeping this batching term comparable to the
273/// channel term — yet the bound is a CONSTANT, not `buffer_size`-scaled, so it
274/// holds even for `buffer_size = 1`. (The full resident-row worst case adds the
275/// `max_partition_size` term on top; see the module doc.)
276///
277/// [`tests::batch_inflight_rows_are_bounded_independent_of_buffer_size`] asserts
278/// the batching subsystem's runtime worst case never exceeds this; any sizing
279/// change that breaks the bound must update this constant AND keep that test green.
280pub(super) const MAX_INFLIGHT_BATCH_ROWS: usize = (BATCH_CHANNEL_CAP + 2) * BATCH_EMIT_ROWS;

282/// Which public surface the windowed driver's forwarder adapts its single
283/// internal `Vec`-batched stream to (issue #1592, Epic F/F2).
284///
285/// The driver ([`SSTableReader::run_scan_stream_windowed`]) always produces one
286/// internal batched stream (the pre-existing #1143 batch channel). This selects
287/// how [`SSTableReader::spawn_windowed_forwarder`] delivers it to the caller —
288/// flattened to per-row (the historical contract, an adapter over the batches) or
289/// forwarded straight through as `Vec` batches (one async wake per batch).
290pub(super) enum WindowedOut {
291    /// Historical per-item surface: each `Vec` batch is FLATTENED into
292    /// `(RowKey, ScanRow)` items on `tx`, one send per row.
293    PerRow(mpsc::Sender<Result<(RowKey, ScanRow)>>),
294    /// Batched surface (F2): each internal `Vec` batch is forwarded straight
295    /// through on `tx`, one send per batch — so the consumer is woken once per
296    /// batch instead of once per row.
297    Batched(mpsc::Sender<Result<Vec<(RowKey, ScanRow)>>>),
298}

300/// Decide whether the blocking parse half should run its terminal
301/// (`at_final_chunk = true`) drain once the raw-chunk stream has ended.
302///
303/// The terminal drain parses the trailing window AS IF it were a complete final
304/// partition (it collapses `NeedMore` → `Done`). That is correct only on a CLEAN
305/// EOF. If the I/O half stopped on a mid-stream read error it sets `io_failed`
306/// before dropping the raw-chunk sender, so the trailing window is a TRUNCATED
307/// fragment; running the terminal drain on it would emit a spurious/garbage
308/// partition through `tx` BEFORE the caller surfaces the I/O `Err` (issue #1143
309/// finding 2). Skipping it makes a truncated/corrupt stream yield ONLY the error.
310///
311/// Pulled out as a tiny pure function so the drain-skip decision is unit-tested
312/// directly (issue #1143 finding 1): a future refactor that drops the flag,
313/// flips the load, or reorders the store-before-`drop(raw_tx)` must fail
314/// [`tests::terminal_drain_skipped_iff_io_failed`].
315#[inline]
316fn should_run_terminal_drain(io_failed: bool) -> bool {
317    !io_failed
318}

320/// Flush any rows already buffered in `batch` to the batched-row channel as one
321/// item, draining `batch`. Used at EVERY error-exit of the blocking parse half
322/// so confirmed rows produced before a mid-stream parse/decompress error are
323/// delivered to the consumer ahead of the terminal `Err` — matching the
324/// pre-#1156 per-row send contract (the consumer must see all confirmed rows up
325/// to the failure, not just the earlier full batches).
326///
327/// Returns the send result; the caller propagates the original error regardless
328/// (a failed flush means the consumer already dropped `rx`, so there is nobody
329/// left to receive the rows OR the error — the scan is terminating either way).
330/// A no-op when `batch` is empty. Roborev finding (issue #1143): the batching
331/// change must not silently drop confirmed-up-to-error rows.
332#[inline]
333fn flush_pending(
334    batch: &mut Vec<(RowKey, ScanRow)>,
335    tx: &mpsc::Sender<Result<Vec<(RowKey, ScanRow)>>>,
336) {
337    if !batch.is_empty() {
338        let _ = tx.blocking_send(Ok(std::mem::take(batch)));
339    }
340}
341
342/// Finish the blocking parse half: deliver the rows still pending in `batch` and
343/// return the drain outcome to the caller.
344///
345/// This is the load-bearing error-flush seam (roborev finding, issue #1143).
346/// `drained` is the result of the fallible parse loop + terminal drain:
347///
348///   - `Err(e)`: a mid-stream decompress/parse error. FLUSH `batch` first so the
349///     consumer receives every confirmed-up-to-error row ahead of the terminal
350///     `Err` — matching the pre-batching per-row send contract — THEN propagate
351///     `e`. Removing this flush silently drops the confirmed-but-unflushed pending
352///     rows on an error, which is exactly the regression
353///     [`tests::finish_blocking_drain_flushes_pending_before_error`] pins.
354///   - `Ok(())` and the consumer is still attached (`!broke`): flush the trailing
355///     partial batch so the last rows reach the consumer.
356///   - `Ok(())` but `broke` (consumer dropped): nothing to deliver — drop `batch`.
357///
358/// Pulled out of [`SSTableReader::drain_scan_window_blocking`] so the error-path
359/// flush is unit-tested in isolation with a genuinely NON-EMPTY pending batch. In
360/// the live driver the in-stream per-chunk flush usually empties `batch` at a
361/// chunk boundary BEFORE a separate-chunk decompress error fires, which would make
362/// an end-to-end "corrupt trailing chunk" test vacuous; testing this seam directly
363/// guarantees the error flush is exercised and FAILS if it is removed.
364fn finish_blocking_drain(
365    drained: Result<()>,
366    batch: &mut Vec<(RowKey, ScanRow)>,
367    broke: bool,
368    tx: &mpsc::Sender<Result<Vec<(RowKey, ScanRow)>>>,
369) -> Result<()> {
370    match drained {
371        Err(e) => {
372            flush_pending(batch, tx);
373            Err(e)
374        }
375        Ok(()) => {
376            if !broke {
377                flush_pending(batch, tx);
378            }
379            Ok(())
380        }
381    }
382}

384/// Inputs the blocking parse half needs that the I/O half resolves once up front
385/// (so the blocking task does not have to touch the async runtime).
386struct WindowParseCtx {
387    // Issue #1578: no `table_id` — the stitch path does not filter by it (see the
388    // parse closure in `run_scan_stream_windowed`).
389    start_key: Option<RowKey>,
390    end_key: Option<RowKey>,
391    schema: Option<crate::schema::TableSchema>,
392    /// Cassandra stores a chunk RAW when its compressed length would meet or
393    /// exceed this (Bug #639, epic #970, issue #1104); honour the same rule as
394    /// `stitch_all_chunks` so the windowed path decodes identically.
395    max_compressed_length: usize,
396}

398impl SSTableReader {
399    /// Async I/O half of the windowed streaming scan (issue #1143).
400    ///
401    /// Reads raw compressed chunks from `cursor` and forwards them to a single
402    /// `spawn_blocking` parse task ([`drain_scan_window_blocking`]) over a
403    /// bounded channel; the parse task owns all decompress+parse CPU and emits
404    /// results through `tx`. See the module docs for the full rationale.
405    ///
406    /// Precondition: `cursor`'s file is seeked to the start of the data section.
407    pub(super) async fn run_scan_stream_windowed(
408        self: Arc<Self>,
409        // Issue #1578: unused — the stitch path does not filter by table_id.
410        _table_id: TableId,
411        start_key: Option<RowKey>,
412        end_key: Option<RowKey>,
413        schema: Option<crate::schema::TableSchema>,
414        cursor: &ScanCursor,
415        // Which public surface to adapt the internal batched stream to (issue
416        // #1592): per-row (flatten) or batched (straight-through). The rest of the
417        // driver — I/O feed, blocking parse, join, backpressure — is identical for
418        // both; only the forwarder arm differs.
419        out: WindowedOut,
420    ) -> Result<()> {
421        // Admission control (issue #1594, F4) is applied by the CALLER at
422        // top-level scan-OPERATION granularity, NOT here per sub-scan: a direct
423        // scan acquires its permit in `run_scan_stream` (`ScanAdmission::Acquire`),
424        // and a cross-generation fan-out merge acquires ONE permit for the whole
425        // operation and opens each sub-scan `ScanAdmission::Exempt`. So this
426        // windowed sub-scan does NOT admit — a fan-out to `N > cap` generations
427        // would otherwise let `cap` sub-scans hold permits and park in backpressure
428        // while the priming merge blocks forever waiting on the rest (the deadlock
429        // the per-sub-scan design introduced). See `scan_admission`'s module docs.
430
431        // Resolve everything the parser needs ONCE, here on the async side, so
432        // the blocking task never touches the async runtime. Schema resolution
433        // matches the previous `parse_stitched_stream` resolution exactly.
434        let ctx = WindowParseCtx {
435            start_key,
436            end_key,
437            schema: schema.or_else(|| self.get_table_schema(None)),
438            max_compressed_length: self
439                .compression_info
440                .as_ref()
441                .map(|ci| ci.max_compressed_length as usize)
442                .unwrap_or(usize::MAX),
443        };
444        // Capture the incompressible-raw threshold for the IO-half decode BEFORE
445        // `ctx` is moved into the parse task below (issue #1940, D2).
446        let max_compressed_length = ctx.max_compressed_length;
447
448        // Decompressed-chunk pipe: I/O half -> blocking parse half (bounded for heap
449        // + backpressure). Issue #1940 (D2): the IO half now DECODES each chunk
450        // (CRC-verify → cache-lookup-or-decompress) and ships the refcounted
451        // decompressed `Bytes` substrate, NOT the raw compressed `Vec<u8>`. This lets
452        // the IO half reuse ONE per-loop compressed-read scratch (no per-chunk
453        // compressed-buffer allocation) and lets the parse half's window borrow a
454        // refcounted view of the chunk (the ≤1-alloc/chunk substrate). CRC is still
455        // verified BEFORE decompression, in the same order as before (inside the
456        // read+decode path), and decompression stays in the single decode plane
457        // (`chunk_source`). Backpressure/bounded-heap semantics are unchanged: the
458        // channel is still bounded and a full channel still parks the IO half.
459        let (raw_tx, raw_rx) = mpsc::channel::<bytes::Bytes>(RAW_CHUNK_CHANNEL_CAP);
460        // Batched-row pipe: blocking parse half -> async forwarder task. The
461        // parse half buffers up to `BATCH_EMIT_ROWS` surviving entries per item so
462        // the expensive blocking→async wake happens once per batch instead of once
463        // per row (issue #1143). The forwarder task flattens each batch into the
464        // caller's per-item `tx`, preserving the public stream contract.
465        let (batch_tx, batch_rx) =
466            mpsc::channel::<Result<Vec<(RowKey, ScanRow)>>>(BATCH_CHANNEL_CAP);
467        // The batching subsystem (this bounded channel + the forwarder-held batch +
468        // the producer's parked-in-send batch) holds at most `MAX_INFLIGHT_BATCH_ROWS`
469        // confirmed rows ahead of a stalled caller, INDEPENDENT of `scan_stream`'s
470        // `buffer_size` (roborev finding, issue #1143). The assert ties the runtime
471        // channel sizing to that named bound so a capacity change cannot exceed it.
472        debug_assert!(
473            (BATCH_CHANNEL_CAP + 2) * BATCH_EMIT_ROWS <= MAX_INFLIGHT_BATCH_ROWS,
474            "batch channel sizing must stay within the documented MAX_INFLIGHT_BATCH_ROWS bound \
475             (channel-resident BATCH_CHANNEL_CAP + forwarder-held 1 + producer-blocked-in-send 1)"
476        );
477        // Distinguishes a clean EOF (sender dropped after `Ok(None)`) from a
478        // mid-stream read error (sender dropped after `Err`). On error the parse
479        // half must NOT run its `at_final_chunk = true` terminal drain — a
480        // truncated/partial trailing window would otherwise emit a spurious
481        // partition through `tx` BEFORE this function returns the `Err` (issue
482        // #1143 finding 2; the pre-#1156 path `?`-propagated the read error and
483        // never ran a final drain). Set before `raw_tx` is dropped so the parse
484        // half observes it via the channel-close happens-before.
485        let io_failed = Arc::new(AtomicBool::new(false));
486        let reader = Arc::clone(&self);
487        let task_io_failed = Arc::clone(&io_failed);
488        let parse_task = tokio::task::spawn_blocking(move || {
489            reader.drain_scan_window_blocking(ctx, raw_rx, batch_tx, task_io_failed)
490        });
491
492        // Forwarder task: adapt the blocking parse half's batched stream to the
493        // caller's chosen public surface (per-row flatten or batched
494        // straight-through; issue #1592). Runs CONCURRENTLY with the I/O feed loop
495        // below — both are needed at once (the I/O loop produces the raw chunks
496        // the parse half consumes; the parse half produces the batches this task
497        // drains), so running them sequentially would deadlock. On the async
498        // runtime, so its wakes are cheap async-worker wakes, not blocking-pool
499        // condvar wakes.
500        //
501        // Backpressure: a slow consumer blocks the `send().await` inside the
502        // forwarder, which stops draining `batch_rx`, which (being bounded) blocks
503        // the parse half's `blocking_send`, which stops the parse loop and
504        // ultimately disk reads — the exact end-to-end backpressure shape PR #1156
505        // had, just batched, on BOTH arms. If the consumer drops its receiver, the
506        // send fails, the forwarder returns and drops `batch_rx`; the parse half's
507        // next `blocking_send` then fails so it terminates (`*broke = true`).
508        let forwarder = Self::spawn_windowed_forwarder(out, batch_rx);
509
510        // Feed raw chunks to the parse task, DECODING each on the way (issue #1940,
511        // D2). The bounded `raw_tx` applies backpressure all the way back to disk
512        // reads when the consumer (and thus the parse task) falls behind.
513        //
514        // The feed loop runs on ONE `spawn_blocking` thread for EVERY backend
515        // (issue #1940). Two CPU-bound steps live here: the raw chunk read AND its
516        // decompression (`decode_scan_chunk`). Neither may run on the small async
517        // worker pool — decode CPU on the reactor is the Epic F starvation the
518        // parse-offload (#1143) and IO-offload (#1593) fixes exist to prevent. The
519        // read is now a SYNCHRONOUS positional read on `self.point_source` for
520        // EVERY backend (issue #1940 restructure): no `tokio::fs`, no
521        // `futures::executor::block_on`, and therefore ZERO blocking-pool
522        // amplification (the former `block_on(read_next_block_parts(..))` re-
523        // dispatched each buffered read to a SECOND blocking-pool thread, a latent
524        // hang under a small custom `max_blocking_threads` — owner-decided to remove
525        // the whole hazard class). Positional reads carry their offset as a
526        // parameter and touch no tokio reactor, so mmap (slice), `O_DIRECT` (aligned
527        // pread), and buffered (`pread` on a dedicated fd) all complete on THIS
528        // thread. Decompression stays here too (`decode_scan_chunk`), off the
529        // reactor for every backend.
530        let io_err: Option<Error> = Self::feed_raw_chunks_blocking(
531            Arc::clone(&self),
532            raw_tx,
533            &io_failed,
534            max_compressed_length,
535        )
536        .await;
537        // `cursor` is retained in the signature for the caller's data-section-start
538        // convention (and the non-windowed branch of the same scan functions), but
539        // the windowed feed now reads positionally via `point_source`, so it does
540        // not use the cursor's file handle or chunk index.
541        let _ = cursor;
542
543        // Join the parse task; its Result is the scan's Result. An I/O error
544        // takes precedence (the task only saw a truncated stream). The parse task
545        // owns `batch_tx`; when it returns, `batch_tx` drops, so the forwarder's
546        // `batch_rx.recv()` will observe channel close after the last batch.
547        let parse_result = match parse_task.await {
548            Ok(r) => r,
549            Err(join_err) => Err(Error::corruption(format!(
550                "run_scan_stream_windowed: parse task failed: {join_err}"
551            ))),
552        };
553        // Then await the forwarder so every batched row reaches the consumer
554        // before this function returns (the public stream must not drop the
555        // trailing batch). The forwarder cannot fail the scan — it only flattens
556        // already-produced rows — so a join error there is non-fatal; the parse
557        // task's `Result` plus `io_err` remain canonical.
558        let _ = forwarder.await;
559        if let Some(e) = io_err {
560            return Err(e);
561        }
562        parse_result
563    }
564
565    /// Spawn the forwarder that drains the internal `Vec`-batched channel into the
566    /// caller's public surface (issue #1592, Epic F/F2).
567    ///
568    /// This is the ONE place per-row and batched delivery diverge; everything
569    /// upstream (I/O feed, blocking decompress+parse, the internal batch channel,
570    /// backpressure) is shared. The per-row arm is a thin flattening adapter over
571    /// the same batched stream the batched arm forwards straight through, so the
572    /// two surfaces are guaranteed to yield identical rows in identical order (the
573    /// batched arm's output flattened equals the per-row arm's output).
574    ///
575    /// Both arms preserve backpressure: a stalled consumer blocks the `send().await`
576    /// here, stopping the drain of `batch_rx`, which (bounded) blocks the parse
577    /// half's `blocking_send`, all the way back to disk reads. On consumer drop the
578    /// `send` fails and the forwarder returns, dropping `batch_rx` so the parse
579    /// half terminates.
580    fn spawn_windowed_forwarder(
581        out: WindowedOut,
582        mut batch_rx: mpsc::Receiver<Result<Vec<(RowKey, ScanRow)>>>,
583    ) -> tokio::task::JoinHandle<()> {
584        tokio::spawn(async move {
585            match out {
586                // Per-row (historical) surface: FLATTEN each confirmed batch back
587                // into single `(RowKey, ScanRow)` items. One send per row.
588                WindowedOut::PerRow(tx) => {
589                    while let Some(batch) = batch_rx.recv().await {
590                        match batch {
591                            Ok(rows) => {
592                                for entry in rows {
593                                    if tx.send(Ok(entry)).await.is_err() {
594                                        return; // consumer dropped
595                                    }
596                                }
597                            }
598                            Err(e) => {
599                                // Parse half surfaced a mid-stream error; forward it
600                                // as a terminal item and stop. The parse half also
601                                // returns the same error via its `Result`.
602                                let _ = tx.send(Err(e)).await;
603                                return;
604                            }
605                        }
606                    }
607                }
608                // Batched (F2) surface: FORWARD each confirmed batch straight
609                // through — one send per batch, not per row. A terminal error is
610                // forwarded as one item then the stream ends.
611                WindowedOut::Batched(tx) => {
612                    while let Some(batch) = batch_rx.recv().await {
613                        let terminal = batch.is_err();
614                        if tx.send(batch).await.is_err() {
615                            return; // consumer dropped
616                        }
617                        if terminal {
618                            return;
619                        }
620                    }
621                }
622            }
623        })
624    }

626    /// I/O + decode feed loop for the windowed scan — runs on ONE `spawn_blocking`
627    /// thread for EVERY backend (issue #1593 F3 for the read; issue #1940 for the
628    /// decode + the synchronous-read restructure).
629    ///
630    /// Two CPU-bound steps run here: the raw chunk read AND its decompression
631    /// (`decode_scan_chunk`, D2). Neither may run on the async worker pool — a
632    /// decode on the reactor is the Epic F starvation the offload fixes prevent —
633    /// so the whole loop runs off the async runtime under one `spawn_blocking`
634    /// (mirroring the parse half — one offload per scan, never per chunk, which
635    /// would over-spawn; per-scan admission is F4's scope).
636    ///
637    /// The read is a SYNCHRONOUS positional read on `reader.point_source` (issue
638    /// #1940 restructure): a `pread`-style call carrying its offset as a parameter,
639    /// which touches NO tokio reactor/timer and completes fully on THIS blocking
640    /// thread for every backend (mmap = resident slice; `O_DIRECT` = aligned pread;
641    /// buffered = `pread` on a dedicated `std::fs::File`). This deliberately
642    /// eliminates the former `futures::executor::block_on(read_next_block_parts(..))`,
643    /// whose buffered arm drove a `tokio::fs` read that RE-DISPATCHED the actual
644    /// `read(2)` to a SECOND blocking-pool thread — bounded (ncpu cap ≪ 512) but a
645    /// latent hang under a small custom `max_blocking_threads`. Owner decision:
646    /// remove the hazard class, not bound it. There is now ZERO nested async and
647    /// ZERO blocking-pool amplification on the feed path.
648    ///
649    /// Feeds the bounded `raw_tx` via `blocking_send` (backpressure preserved: a
650    /// full channel parks this thread). Consumes `raw_tx` (moved into the task) so
651    /// it drops when the task returns, signalling EOF to the parse half (only when
652    /// `io_failed` stayed false — see the parse half).
653    async fn feed_raw_chunks_blocking(
654        reader: Arc<Self>,
655        raw_tx: mpsc::Sender<bytes::Bytes>,
656        io_failed: &Arc<AtomicBool>,
657        max_compressed_length: usize,
658    ) -> Option<Error> {
659        let io_failed_feed = Arc::clone(io_failed);
660        let feed = tokio::task::spawn_blocking(move || -> Option<Error> {
661            // Panic/early-exit guard (roborev finding, issue #1593). `raw_tx` is
662            // captured (moved) into this closure and drops when the closure
663            // returns OR unwinds; the parse half reads a `raw_tx` close with
664            // `io_failed == false` as a CLEAN EOF and runs its terminal drain. If
665            // this closure PANICS, `raw_tx` drops during unwind while the only
666            // other `io_failed = true` store (the `Err(join_err)` arm below) runs
667            // LATER — so the parse half would spuriously terminal-drain a
668            // truncated window. Arming this guard as a BODY-LOCAL flips
669            // `io_failed = true` on unwind BEFORE the captured `raw_tx` drops
670            // (body locals drop before a move closure's captured environment).
671            // Disarmed on the clean-EOF / consumer-ended exit so the happy path is
672            // byte-identical.
673            let mut panic_guard = FeedFailureGuard::armed(&io_failed_feed);
674            // The raw-read thread is recorded at the ACTUAL positional read syscall
675            // (`positional_read_exact_retry_once`, issue #1940 guard integrity), NOT
676            // here at the top of the feed closure: recording at the syscall pins the
677            // thread that performs the real read, so if a future change dispatched
678            // the read off this feed thread (a reintroduced `block_on`/`tokio::fs`
679            // nesting) the recorded read thread would differ from the decode thread
680            // and the no-nesting equality guard would catch it. Compiled only under
681            // the non-default `scan-offload-probe` feature.
682            let feed_result = if reader.compression_info.is_some() {
683                Self::feed_compressed_chunks(&reader, &raw_tx, max_compressed_length)
684            } else {
685                // Uncompressed NB (no CompressionInfo — CQLite's own write surface)
686                // also reaches this feed via `requires_chunk_stitching()` (NB row
687                // format, is_nb_format() true). The data section starts at the
688                // header boundary; positional reads walk it in bounded pieces.
689                Self::feed_uncompressed_pieces(&reader, &raw_tx)
690            };
691            match feed_result {
692                Ok(()) => {
693                    // Clean EOF (or consumer ended early): leave `io_failed` false so
694                    // the parse half runs its terminal drain exactly as before.
695                    panic_guard.disarm();
696                    None
697                }
698                Err(e) => {
699                    io_failed_feed.store(true, Ordering::SeqCst);
700                    Some(e)
701                }
702            }
703            // `raw_tx` drops here (moved into the closure), signalling EOF.
704        });
705        match feed.await {
706            Ok(e) => e,
707            Err(join_err) => {
708                io_failed.store(true, Ordering::SeqCst);
709                Some(Error::corruption(format!(
710                    "run_scan_stream_windowed: I/O feed task failed: {join_err}"
711                )))
712            }
713        }
714    }

716    /// Blocking parse half of the windowed streaming scan (issue #1143).
717    ///
718    /// Runs entirely on a `spawn_blocking` thread — NEVER on an async worker.
719    /// Owns the sliding `window` (a [`WindowCursor`], issue #1589); for each
720    /// already-decoded `Bytes` chunk pulled from `raw_rx` (the IO half decodes now,
721    /// issue #1940) it appends to the window and drains every confirmed partition
722    /// via [`drain_scan_window`]. On a CLEAN `raw_rx` close (I/O EOF) it runs a final
723    /// drain with `at_final_chunk = true`; on a close caused by a mid-stream read
724    /// error (`io_failed` set by the I/O half before it dropped the sender) it
725    /// SKIPS that terminal drain so a truncated window cannot emit a spurious
726    /// trailing partition (issue #1143 finding 2). Surviving `(RowKey, ScanRow)`
727    /// entries are accumulated into batches of up to [`BATCH_EMIT_ROWS`] and sent
728    /// through `tx` (a `Vec`-batched channel) with `blocking_send`, mirroring the
729    /// pre-#1156 `parse_stitched_stream` backpressure but amortizing the
730    /// blocking→async wake one-per-batch instead of one-per-row (issue #1143).
731    ///
732    /// On a mid-stream decompress/parse `Err`, any rows already buffered in the
733    /// pending batch are flushed to `tx` BEFORE the error is propagated (via
734    /// [`flush_pending`]), so the consumer receives every confirmed-up-to-error
735    /// row ahead of the terminal `Err` — preserving the pre-batching per-row
736    /// send contract (roborev finding, issue #1143).
737    fn drain_scan_window_blocking(
738        &self,
739        ctx: WindowParseCtx,
740        mut raw_rx: mpsc::Receiver<bytes::Bytes>,
741        tx: mpsc::Sender<Result<Vec<(RowKey, ScanRow)>>>,
742        io_failed: Arc<AtomicBool>,
743    ) -> Result<()> {
744        // Issue #1741: single-gen full-scan read path applies SELECT-semantic
745        // read shadowing (partition/range tombstone + TTL), so build the parser
746        // with read_shadowing = true.
747        let parser = self.build_v5_parser(true);
748        // Sliding front-cursor window (issue #1589): compacts once per refill.
749        let mut window = WindowCursor::new();
750        let mut broke = false;
751        let mut chunk_count = 0usize;
752        // Pending surviving rows not yet handed to the forwarder. Flushed as a
753        // single batch item when it reaches `BATCH_EMIT_ROWS`, and once more at
754        // stream end (the partial tail). Bounded by `BATCH_EMIT_ROWS` + one
755        // partition's worth of rows, so it stays within the sliding-window heap
756        // bound.
757        let mut batch: Vec<(RowKey, ScanRow)> = Vec::with_capacity(BATCH_EMIT_ROWS);
758        // Reused scratch buffer for ONE confirmed partition's surviving
759        // `(RowKey, ScanRow)` entries. Hoisted OUT of the per-partition loop in
760        // [`drain_scan_window`] (issue #1333, follow-up to #1046) and passed by
761        // `&mut` so it is allocated ONCE for the whole scan and `.clear()`-reused
762        // per partition. `clear()` drops the prior partition's entries but PRESERVES
763        // capacity, so a warmed buffer performs ZERO per-partition backing
764        // allocations — the #1046 "buffers should be reused, do not allocate as we
765        // iterate" mandate, extended to the per-partition scratch. Its peak size is
766        // still bounded by one partition's rows (`max_partition_size`), the same
767        // bound the transient per-partition `Vec::new()` had.
768        let mut scratch: Vec<(RowKey, ScanRow)> = Vec::new();
769
770        // The parse loop + terminal drain are fallible; on ANY `Err` we must
771        // first deliver the rows already buffered in `batch` (confirmed rows
772        // produced before the failure) so the consumer sees them ahead of the
773        // terminal error — the pre-#1156 per-row send delivered every
774        // confirmed-up-to-error row, and batching must preserve that (roborev
775        // finding, issue #1143). Run the fallible work in a closure and flush
776        // `batch` before propagating any error it returns.
777        let drained: Result<()> = (|| {
778            // Issue #1940 (D2): the IO half already DECODED each chunk (CRC-verify →
779            // cache-lookup-or-decompress, single decode plane) and shipped the
780            // decompressed refcounted `Bytes` substrate; the parse half just refills
781            // the window from it — no decode here.
782            while let Some(chunk) = raw_rx.blocking_recv() {
783                window.refill(&chunk);
784                chunk_count += 1;
785
786                // Not the final chunk yet: drain confirmed partitions; NeedMore
787                // means "await more bytes" (a partition straddles this boundary).
788                self.drain_scan_window(
789                    &parser,
790                    &ctx,
791                    &mut window,
792                    false,
793                    &tx,
794                    &mut batch,
795                    &mut scratch,
796                    &mut broke,
797                )?;
798                if broke {
799                    return Ok(());
800                }
801
802                // Per-chunk flush cadence (roborev finding, issue #1143). The
803                // drain above stopped because no further partition can be
804                // confirmed until the NEXT raw chunk arrives (NeedMore / empty
805                // window), so any rows still buffered in `batch` are FULLY
806                // confirmed — they will not be amended or joined by a same-chunk
807                // partition. Flushing the pending tail here (a no-op when empty)
808                // restores `scan_stream`'s incremental-delivery contract and
809                // first-row latency for sparse / sub-`BATCH_EMIT_ROWS` result
810                // sets, which the pure-batching change regressed (those emitted
811                // nothing until full scan completion). Dense windows still hit
812                // the full-batch flush inside `drain_scan_window`, so we wake the
813                // forwarder at most ~once per chunk PLUS once per full batch —
814                // far below PR #1156's one-wake-per-ROW, preserving the perf win.
815                if !batch.is_empty() {
816                    if tx.blocking_send(Ok(std::mem::take(&mut batch))).is_err() {
817                        broke = true; // consumer dropped
818                        return Ok(());
819                    }
820                    batch.reserve(BATCH_EMIT_ROWS);
821                }
822            }
823
824            // Stream end. On a CLEAN EOF run the final drain — a trailing
825            // partition with no END_OF_PARTITION marker is now terminal (Done),
826            // not a refill request that will never come. But if the I/O half
827            // stopped on a read ERROR (`io_failed`), the trailing window is a
828            // truncated fragment of a partition; running `at_final_chunk = true`
829            // here would parse and emit it as if complete, surfacing a
830            // partial/garbage row BEFORE the caller returns the I/O `Err`. Skip
831            // the final drain so a truncated/corrupt stream yields ONLY the error
832            // (issue #1143 finding 2). The store in the I/O half happens-before
833            // the `drop(raw_tx)` that ended `blocking_recv`, so this load
834            // observes it.
835            if !broke && should_run_terminal_drain(io_failed.load(Ordering::SeqCst)) {
836                self.drain_scan_window(
837                    &parser,
838                    &ctx,
839                    &mut window,
840                    true,
841                    &tx,
842                    &mut batch,
843                    &mut scratch,
844                    &mut broke,
845                )?;
846            }
847            Ok(())
848        })();
849
850        // Finish: deliver any rows still in `batch` and propagate the drain
851        // outcome. On `Err`, the pending rows are flushed BEFORE the error so the
852        // consumer sees every confirmed-up-to-error row ahead of the terminal Err
853        // (roborev finding, issue #1143); on success the trailing partial batch is
854        // flushed (unless the consumer already dropped, `broke`). Extracted so the
855        // error-path flush is unit-tested directly with a NON-EMPTY pending batch
856        // (`tests::finish_blocking_drain_flushes_pending_before_error`) — that test
857        // fails if the error flush is dropped, keeping the guard non-vacuous even
858        // though the in-stream per-chunk flush usually empties `batch` first.
859        finish_blocking_drain(drained, &mut batch, broke, &tx)?;
860
861        // Test-only probe (issue #1143 regression guard): record the thread that
862        // ran the parse so a guard test can prove it was NOT an async worker.
863        // Compiled ONLY under the non-default `scan-offload-probe` feature; a
864        // true no-op (not even referenced) in normal/release builds.
865        #[cfg(feature = "scan-offload-probe")]
866        probe::record_parse_thread();
867
868        tracing::debug!(
869            "drain_scan_window_blocking: drained {} chunks (final window {} bytes)",
870            chunk_count,
871            window.len()
872        );
873        Ok(())
874    }

876    /// Drain every confirmed partition from the front of the sliding `window`,
877    /// accumulating each surviving `(RowKey, ScanRow)` into `batch` and flushing a
878    /// full `BATCH_EMIT_ROWS`-sized batch through `tx` (issue #1143).
879    ///
880    /// Synchronous (runs on the `spawn_blocking` thread). Drives
881    /// [`parse_one_partition_with_timestamps`], drops the per-row timestamp, and
882    /// applies the same `table_ids_match` + key-range + `filter_tombstone`
883    /// filters the prior driver applied. After each `Emitted(consumed)` the
884    /// consumed prefix is removed, keeping the window's peak bounded by
885    /// `max_partition_size + one_chunk`. Rows are pushed onto `batch` in scan
886    /// order; whenever `batch` reaches `BATCH_EMIT_ROWS` it is flushed as ONE
887    /// channel item (amortizing the blocking→async wake). The trailing partial
888    /// batch is flushed by the caller at stream end. Stops at `NeedMore` / `Done`
889    /// (await the next chunk / genuine end) or when the consumer is dropped
890    /// (`*broke`).
891    #[allow(clippy::too_many_arguments)]
892    fn drain_scan_window(
893        &self,
894        parser: &crate::storage::sstable::reader::parsing::V5CompressedLegacyParser,
895        ctx: &WindowParseCtx,
896        window: &mut WindowCursor,
897        at_final_chunk: bool,
898        tx: &mpsc::Sender<Result<Vec<(RowKey, ScanRow)>>>,
899        batch: &mut Vec<(RowKey, ScanRow)>,
900        scratch: &mut Vec<(RowKey, ScanRow)>,
901        broke: &mut bool,
902    ) -> Result<()> {
903        use crate::storage::sstable::reader::parsing::ParseStep;
904
905        loop {
906            if *broke || window.is_empty() {
907                return Ok(());
908            }
909
910            // Buffer this partition's surviving entries in the caller's REUSED
911            // `scratch` buffer, then forward them via `blocking_send` AFTER the
912            // parser returns. `parse_one_partition_with_timestamps` takes a
913            // synchronous `FnMut` emit, so we cannot send inside it; a partition's
914            // rows are bounded by `max_partition_size`, so this stays within the
915            // window bound. `clear()` drops the previous partition's entries but
916            // PRESERVES the backing capacity, so after warmup this loop performs
917            // NO per-partition allocation for `scratch` (issue #1333, follow-up to
918            // #1046). NeedMore/Done leave `scratch` empty (the parser only invokes
919            // the emit closure on a CONFIRMED `Emitted`), so nothing leaks across
920            // partitions. Issue #1334: entries carry the `ScanRow` row carrier.
921            scratch.clear();
922            // Snapshot the (retained) capacity BEFORE this partition's pushes so
923            // the offload probe can count how many times `scratch` actually grows
924            // its backing store across the whole scan — the direct signal that the
925            // buffer is reused, not reallocated per partition (issue #1333 guard).
926            #[cfg(feature = "scan-offload-probe")]
927            let scratch_cap_before = scratch.capacity();
928            let step = parser.parse_one_partition_with_timestamps(
929                window.as_slice(),
930                ctx.schema.as_ref(),
931                self,
932                at_final_chunk,
933                &mut |(_entry_table_id, key, value, _ts)| {
934                    // Issue #1578: this stitching path deliberately does NOT filter
935                    // by `table_ids_match` — it mirrors the authoritative
936                    // materializing `sequential_scan` stitch path, which skips it
937                    // because the nb parser may report header-default table_ids.
938                    // Applying it here dropped EVERY row of an nb SSTable whose parsed
939                    // table_id diverged from the query (e.g. CQLite-written output).
940                    if let Some(start) = ctx.start_key.as_ref() {
941                        if &key < start {
942                            return Ok(std::ops::ControlFlow::Continue(()));
943                        }
944                    }
945                    if let Some(end) = ctx.end_key.as_ref() {
946                        if &key > end {
947                            return Ok(std::ops::ControlFlow::Continue(()));
948                        }
949                    }
950                    // Suppress row tombstones from user-facing scan output (#505).
951                    if !self.filter_tombstone(&value) {
952                        return Ok(std::ops::ControlFlow::Continue(()));
953                    }
954                    scratch.push((key, value));
955                    Ok(std::ops::ControlFlow::Continue(()))
956                },
957            )?;
958
959            // Record whether this partition forced `scratch` to (re)allocate its
960            // backing store. With the hoist this happens only while the buffer
961            // grows to its high-water mark (a small bounded number of times per
962            // scan); if the buffer were freshly allocated per partition it would
963            // grow from empty EVERY partition, so the count would scale with
964            // partition count — exactly what the #1333 guard asserts it does not.
965            #[cfg(feature = "scan-offload-probe")]
966            probe::note_scratch_capacity(scratch_cap_before, scratch.capacity());
967
968            match step {
969                ParseStep::Emitted(consumed) => {
970                    let take = if consumed == 0 { 1 } else { consumed };
971                    // Advance the cursor (no memmove); `consume` clamps to remaining.
972                    window.consume(take);
973                    // Accumulate this partition's surviving entries in scan order,
974                    // flushing a full batch as ONE channel item whenever it
975                    // reaches `BATCH_EMIT_ROWS`. `blocking_send` carries the same
976                    // backpressure as the prior per-row send (this runs on a
977                    // spawn_blocking thread) but wakes the async forwarder once per
978                    // batch instead of once per row (issue #1143).
979                    for entry in scratch.drain(..) {
980                        batch.push(entry);
981                        if batch.len() >= BATCH_EMIT_ROWS {
982                            let full =
983                                std::mem::replace(batch, Vec::with_capacity(BATCH_EMIT_ROWS));
984                            if tx.blocking_send(Ok(full)).is_err() {
985                                *broke = true; // consumer dropped
986                                return Ok(());
987                            }
988                        }
989                    }
990                }
991                // NeedMore: the partition straddles this chunk boundary. The
992                // per-partition parser buffers a partition's rows internally and
993                // only invokes our emit closure on a CONFIRMED `Emitted` return,
994                // so on `NeedMore` our `scratch` buffer is empty — nothing was
995                // forwarded and nothing is dropped. The caller appends the next
996                // chunk and we re-parse this partition from its start, so no row
997                // is duplicated or lost across the boundary. Record the straddle
998                // (issue #1143) so the boundary re-parse path is observable; it is
999                // suppressed at the final chunk (parser collapses NeedMore→Done).
1000                ParseStep::NeedMore => {
1001                    crate::observability::add_counter(
1002                        crate::observability::catalog::READ_SCAN_WINDOW_REFILL,
1003                        1,
1004                        &[],
1005                    );
1006                    return Ok(());
1007                }
1008                // Done: genuine end of partitions / terminal truncation.
1009                ParseStep::Done => return Ok(()),
1010            }
1011        }
1012    }
1013}
