1//! The producer→consumer CHANNEL PROTOCOL for the k-way merge (issue #3120).
2//!
3//! # Why a protocol, and not just `Result<MergeEntry, _>`
4//!
5//! Every merge run is fed by a detached producer THREAD over a bounded
6//! `sync_channel` ([`producer_iter`](super::producer_iter) for the path-based
7//! shape, [`from_readers`](super::from_readers) for the shared-reader shape).
8//! Before this issue the channel item was `Result<MergeEntry,
9//! MergeProducerError>` and there was NO terminator: a producer that finished
10//! and a producer that UNWOUND both simply dropped their `SyncSender`, and the
11//! consumer mapped that channel DISCONNECT onto `None` = "this run is
12//! exhausted". So a panicking producer made its run look EXHAUSTED:
13//!
14//! * on the READ path, a silently short result set served as a successful scan;
15//! * on the WRITE path, `compact_sstables` rewrote an SSTable **missing rows**
16//!   and then deleted (or superseded) its inputs — silent data loss at rest.
17//!
18//! [`MergeMsg`] makes completion an OBSERVED FACT instead of an inference. The
19//! producer's last act on EVERY exit path is exactly one terminator
20//! ([`MergeMsg::Done`] or [`MergeMsg::Failed`]), sent with the BLOCKING
21//! `SyncSender::send` (a `try_send` that dropped the terminator would recreate
22//! the very ambiguity this closes), and the consumer reports end-of-input ONLY
23//! on `Done`. This is the same treatment issue #3106 gave the query row stream's
24//! two producer boundaries.
25//!
26//! Deliberately NOT `Err(MergeProducerError::Done)` (a sentinel inside the
27//! `Result`): that makes normal completion an *error* every match site has to
28//! special-case, still permits a non-terminal `Err` to ride in the DATA slot,
29//! and would make the terminator untracked on the egress-depth gauge by
30//! ACCIDENT (right answer, wrong reason — see [`MergeMsg::tracked_entries`]).
31//!
32//! # Both halves are needed, and they cover different builds
33//!
34//! `catch_unwind` in the producer thread body turns a panic into an INFORMATIVE
35//! terminal [`MergeProducerError::Panicked`], but it only fires under `panic =
36//! "unwind"`. The `Done` terminator needs no unwinding at all: it makes any
37//! *other* way a producer thread can stop without reporting — a future exit path
38//! that forgets its terminator included — fail CLOSED in every profile.
39

44/// Channel-safe error payload sent from a producer thread to the merge (issue
45/// #2264).
46///
47/// The producer thread runs the reader's compaction scan under `Result<_,
48/// crate::Error>`, but `crate::Error` is not `Clone` and the channel item is
49/// consumed once anyway, so this small enum is the minimal payload that
50/// SURVIVES the thread boundary while still distinguishing a cooperative
51/// cancellation (`Error::Cancelled`) from every other failure. Without this,
52/// stringifying every error the same way would make a genuine I/O/corruption
53/// error indistinguishable from a cancelled scan at the receiving end — exactly
54/// the ambiguity `SSTableRowIterator::next` and `drive_merge` must NOT have.
55///
56/// Deliberately NOT `Clone` (rust-reviewer, issue #3120): the consumer stores the
57/// terminal verdict on the run's state by MOVE, and re-reports it through
58/// [`Self::to_error`], which borrows. Nothing ever clones one, so a `Clone` derive
59/// would only invite a needless copy of the payload string.
60#[derive(Debug)]
61pub(super) enum MergeProducerError {
62    /// The scan was cooperatively cancelled (`Error::Cancelled`).
63    Cancelled,
64    /// Any other failure, stringified (matches the pre-#2264 behaviour).
65    Other(String),
66    /// The producer thread UNWOUND — a `panic!`/assertion anywhere in its
67    /// walk/decode — carrying the panic payload (issue #3120).
68    ///
69    /// A DISTINCT variant, not folded into [`Self::Other`], because it is the
70    /// event this issue exists to make visible: the run is TRUNCATED at an
71    /// arbitrary point, so it must never be reconciled or written as if it were
72    /// complete.
73    Panicked(String),
74}
75
76impl From<Error> for MergeProducerError {
77    fn from(e: Error) -> Self {
78        match e {
79            Error::Cancelled => MergeProducerError::Cancelled,
80            other => MergeProducerError::Other(other.to_string()),
81        }
82    }
83}
84
85impl MergeProducerError {
86    /// Rebuild the consumer-side [`Error`] for this terminal verdict.
87    ///
88    /// Total and side-effect free, so a run whose verdict is STICKY can
89    /// re-report the identical error on every subsequent poll rather than
90    /// downgrading to `None` once the payload has been handed out (issue #3120).
91    ///
92    /// [`Self::Panicked`] maps to [`Error::internal`], NOT `Error::Storage`
93    /// (roborev, issue #3106): `Storage.is_recoverable() == true`, which would
94    /// advertise a deterministic dead-producer failure as RETRYABLE to the
95    /// Node/Python error mapping. Nothing suggests the `Data.db` is bad either,
96    /// so `Corruption` would send an operator hunting a nonexistent bad file.
97    /// `Internal` is `is_recoverable() == false` and is the honest variant for a
98    /// violated internal invariant.
99    pub(super) fn to_error(&self) -> Error {
100        match self {
101            // Issue #2264: reconstructed DISTINCTLY so a cancelled scan is never
102            // confused with a genuine I/O/corruption error at the
103            // merge/producer boundary — `drive_merge` matches on the variant.
104            MergeProducerError::Cancelled => Error::Cancelled,
105            MergeProducerError::Other(msg) => {
106                Error::Storage(format!("streaming merge producer error: {msg}"))
107            }
108            MergeProducerError::Panicked(message) => Error::internal(format!(
109                "streaming merge producer: the producer thread PANICKED mid-walk \
110                 ({message}) — this run is TRUNCATED and cannot be merged as if it \
111                 were complete (issue #3120)"
112            )),
113        }
114    }
115}

117/// One message on a merge producer→consumer channel (issue #3120).
118///
119/// INTERNAL to the merge: the terminator is deliberately not observable by any
120/// merge CONSUMER (`SSTableRowIterator::next` keeps its
121/// `Option<Result<MergeEntry>>` signature), so no `SSTableRowIterator`
122/// implementation — `VecRun`, `SinglePartitionFilterRun`, the synthetic
123/// streaming iterators — has to know this protocol exists. Only the two
124/// producer-thread shapes and the one adapter that consumes their channels do.
125// Issue #2820: the DATA variant carries a `Vec` BATCH of entries, not one entry
126// (~288 bytes) — so every variant of this enum is now small and no
127// `large_enum_variant` allowance is needed. The batch's ONE heap allocation is
128// amortised over up to `BATCH_EMIT_ROWS_MERGE` rows, unlike the per-entry
129// allocation issue #1664 removed; what it buys is one cross-thread park/wake per
130// BATCH instead of per ROW (measured at 49.9% of single-stream CPU before this
131// change). See `egress_batch` for the batching contract.
132#[derive(Debug)]
133pub(super) enum MergeMsg {
134    /// One BATCH of decoded merge entries, in scan order (issue #2820). Carries
135    /// DATA rows and NOTHING else BY CONSTRUCTION (issue #3120): a failure is
136    /// [`MergeMsg::Failed`], so "this message ends the run" is a structural
137    /// property of the variant rather than an unenforced invariant about where an
138    /// `Err` was built.
139    ///
140    /// NON-EMPTY by construction (`EgressBatcher::flush` returns early on an
141    /// empty accumulator); the consumer treats an empty batch as "nothing to hand
142    /// out" and polls again rather than trusting that, so an empty one could never
143    /// be mistaken for end-of-input.
144    ///
145    /// This is why `forward_row` no longer sends a conversion failure as a
146    /// mid-walk channel message: a non-terminal error in the DATA slot, after
147    /// which the walk KEEPS GOING, is exactly the shape that would let a later
148    /// genuine dead-producer disconnect revert to a clean end-of-input.
149    Batch(Vec<MergeEntry>),
150    /// The run failed. TERMINAL: the producer sends exactly one of this or
151    /// [`MergeMsg::Done`], as its last act, on every exit path.
152    Failed(MergeProducerError),
153    /// The producer finished its walk and is exiting normally. The ONLY thing
154    /// that makes the consuming adapter report a clean end-of-input; a
155    /// disconnect without it is a dead producer, i.e. a TRUNCATED run.
156    Done,
157}
158
159impl MergeMsg {
160    /// How many entries of this message occupy TRACKED data slots on the
161    /// egress-depth gauge ([`channel_depth`](super::channel_depth)) — the gauge's
162    /// unit is ENTRIES (rows), and issue #2820 did not change that: a batch of
163    /// `n` rows counts `n`, exactly as `n` per-row messages used to.
164    ///
165    /// Called at the SEND site (`egress_batch::EgressBatcher::flush`). It is worth
166    /// being precise about what this does and does not buy, because overclaiming
167    /// here is how the next reader stops looking (rust-reviewer, issue #3120):
168    ///
169    /// * At that call site it is a **TAUTOLOGY** — the batcher builds
170    ///   `MergeMsg::Batch(batch)` unconditionally, so the answer can only be the
171    ///   batch length. It is not a runtime filter; it is a **compile-time
172    ///   tripwire**. Because the body below is an EXHAUSTIVE match with no
173    ///   wildcard, adding a 4th `MergeMsg` variant forces an explicit
174    ///   tracked/untracked decision here instead of a silent default.
175    /// * The RECEIVE site (`producer_iter`'s `next`) does NOT call this. It is a
176    ///   hand-written `MergeMsg::Batch(entries)` match arm, held correct by its own
177    ///   two properties: that `match` is exhaustive with no wildcard, and
178    ///   `channel_depth::received_n` / `received_count` each appear at exactly ONE
179    ///   site in the crate, both inside that arm (issue #2820 moved
180    ///   `add_merge_run_entry_decoded` to the per-ENTRY hand-out below it, since
181    ///   its unit is entries decoded, not messages received).
182    ///
183    /// Why it matters at all: before issue #3120 the two sides were two DIFFERENT
184    /// expressions of one rule — `msg.is_ok()` on send versus an `Ok(Ok(_))`
185    /// pattern on receive — and a message counted on exactly one side drives the
186    /// reconcile residual NEGATIVE, which
187    /// `channel_depth::reconcile_residual`'s `> 0` guard skips and `record`'s
188    /// `max(0)` floor then hides from every observer, permanently.
189    pub(super) fn tracked_entries(&self) -> usize {
190        match self {
191            MergeMsg::Batch(entries) => entries.len(),
192            // TERMINATORS are untracked on BOTH sides, so they can never
193            // unbalance the level.
194            MergeMsg::Failed(_) | MergeMsg::Done => 0,
195        }
196    }
197}

199/// The fail-closed error for a producer that disconnected WITHOUT a terminator
200/// (issue #3120).
201///
202/// [`Error::internal`] for the same reason [`MergeProducerError::Panicked`] is
203/// (see [`MergeProducerError::to_error`]): a dead producer is a violated
204/// internal invariant, not a retryable storage condition and not a bad file.
205pub(super) fn dead_producer_error() -> Error {
206    Error::internal(
207        "streaming merge producer: the channel disconnected WITHOUT a terminal Done \
208         message — the producer thread died mid-walk, so this run is TRUNCATED and \
209         must not be merged (or written) as if it were exhausted (issue #3120)",
210    )
211}

213/// Turn a caught producer-thread panic payload into a
214/// [`MergeProducerError::Panicked`].
215///
216/// The payload is a `String`/`&str` for every `panic!`/assertion (the only other
217/// shapes are hand-rolled `panic_any`), so an unrecognized payload degrades to a
218/// named placeholder rather than being dropped — the terminator is still sent
219/// either way, which is the property that matters.
220pub(super) fn panicked_producer_error(payload: &(dyn std::any::Any + Send)) -> MergeProducerError {
221    let message = payload
222        .downcast_ref::<String>()
223        .map(String::as_str)
224        .or_else(|| payload.downcast_ref::<&'static str>().copied())
225        .unwrap_or("<non-string panic payload>");
226    MergeProducerError::Panicked(message.to_string())
227}

229#[cfg(test)]
230mod tests {
231    use super::*;
232    use crate::storage::write_engine::merge::{CellData, RowData};
233    use crate::storage::write_engine::mutation::DecoratedKey;
234    use crate::types::Value;
235
236    fn entry(n: i64) -> MergeEntry {
237        MergeEntry::new(
238            0,
239            DecoratedKey::new(n, n.to_be_bytes().to_vec()),
240            None,
241            100,
242            RowData::Live {
243                cells: vec![CellData::new("name".to_string(), Value::text("v"), 100)],
244            },
245        )
246    }
247
248    fn batch(rows: usize) -> MergeMsg {
249        MergeMsg::Batch((0..rows as i64).map(entry).collect())
250    }
251
252    /// The gauge unit is ENTRIES: a DATA batch of `n` rows counts `n` tracked
253    /// slots (issue #2820 — batching changed the MESSAGE count, never the gauge
254    /// unit), and EVERY terminator counts zero (issue #3120). Asserted on the real
255    /// values both the send site and the receive site key on, so an asymmetry
256    /// between them cannot hide here.
257    #[test]
258    fn a_data_batch_tracks_one_slot_per_entry_and_a_terminator_tracks_none() {
259        for rows in [1usize, 2, 7, 256] {
260            assert_eq!(
261                batch(rows).tracked_entries(),
262                rows,
263                "a batch of {rows} DATA entries occupies {rows} tracked channel \
264                 slots — counting it as ONE would make the #2419 gauge read \
265                 messages while its unit says entries"
266            );
267        }
268        for terminator in [
269            MergeMsg::Done,
270            MergeMsg::Failed(MergeProducerError::Cancelled),
271            MergeMsg::Failed(MergeProducerError::Other("io".to_string())),
272            MergeMsg::Failed(MergeProducerError::Panicked("boom".to_string())),
273        ] {
274            assert_eq!(
275                terminator.tracked_entries(),
276                0,
277                "a terminator must be UNTRACKED on both send and receive, else the \
278                 reconcile residual goes negative and is hidden by the `> 0` guard \
279                 + `max(0)` floor forever (issue #3120): {terminator:?}"
280            );
281        }
282    }
283
284    /// A panicked producer must surface as a NON-recoverable `Internal` error
285    /// naming the panic — never `Storage`, whose `is_recoverable() == true`
286    /// would advertise a deterministic dead-producer failure as RETRYABLE to the
287    /// bindings' error mapping (roborev, issue #3106).
288    #[test]
289    fn a_panicked_producer_maps_to_a_non_recoverable_internal_error() {
290        let payload: Box<dyn std::any::Any + Send> = Box::new("boom-from-the-walk".to_string());
291        let error = panicked_producer_error(payload.as_ref()).to_error();
292        assert!(
293            !error.is_recoverable(),
294            "a dead producer is deterministic, not retryable: {error}"
295        );
296        let text = error.to_string();
297        assert!(
298            text.contains("PANICKED") && text.contains("boom-from-the-walk"),
299            "the error must name the panic and carry its payload so the failure is \
300             debuggable rather than a generic 'the producer died', got: {text}"
301        );
302        assert!(
303            text.contains("TRUNCATED"),
304            "the error must state the run is incomplete, got: {text}"
305        );
306    }
307
308    /// The bare-disconnect backstop is the same non-recoverable `Internal`
309    /// class, and says so.
310    #[test]
311    fn a_bare_disconnect_maps_to_a_non_recoverable_internal_error() {
312        let error = dead_producer_error();
313        assert!(!error.is_recoverable(), "not retryable: {error}");
314        assert!(error.to_string().contains("TRUNCATED"));
315    }
316
317    /// Cancellation stays a DISTINCT `Error::Cancelled` through the terminator
318    /// protocol (issue #2264): a cancelled scan must never be reported as a dead
319    /// producer, which is the likeliest false positive of this fix.
320    #[test]
321    fn cancellation_survives_the_terminator_protocol_as_cancelled() {
322        assert!(matches!(
323            MergeProducerError::from(Error::Cancelled).to_error(),
324            Error::Cancelled
325        ));
326    }
