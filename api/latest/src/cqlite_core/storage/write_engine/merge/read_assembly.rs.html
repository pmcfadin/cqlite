1//! Read-shape reassembly of a merged row's per-column cells (issue #2324).
2//!
3//! The k-way merger emits a live row as a flat `Vec<CellData>` where every
4//! element of a non-frozen collection (`list` / `set` / `map`) is its OWN
5//! [`CellData`] — one cell per element, all sharing the column name, each keyed
6//! by its authoritative `cell_path` (epic #899, byte-parity write substrate).
7//! That per-element shape is correct for the compaction WRITE path but WRONG for
8//! any read consumer that keys cells by column name: keying the elements by name
9//! (e.g. the Arrow Flight producer's `build_row_from_scan`, whose `values` is a
10//! `HashMap<column, Value>`) keeps only the LAST element and silently drops the
11//! rest of the collection.
12//!
13//! [`assemble_read_cells`] collapses those per-element cells back into a single
14//! `Value::List` / `Value::Set` / `Value::Map` per column, so a read that goes
15//! through the merger (the Flight `do_get` path) sees the SAME whole collection a
16//! plain single-generation `SELECT` sees.
17//!
18//! Semantics are taken from authoritative metadata only (issue #28): elements are
19//! ordered by their authoritative `cell_path` with the collection-appropriate
20//! comparator (list = position-timeuuid byte order; set/map = the declared
21//! element/key comparator), the set/list member is the reader-decoded
22//! `CellData.value`, and the map key is decoded from the element's `cell_path`
23//! with the schema's declared key type via the canonical
24//! [`deserialize_value_bytes`] codec (never guessed).
25//!
26//! Non-scalar set elements / map keys (`frozen<tuple>`, `frozen<udt>`, nested
27//! `frozen<collection>`) are not decodable by the scalar `deserialize_value_bytes`
28//! codec, and serving them as an opaque `Value::Blob(cell_path)` does not actually
29//! reassemble them — the typed Arrow builder downstream expects a tuple/struct
30//! value for the declared type and BREAKS on raw bytes. Issue #2339 therefore
31//! decodes them STRUCTURALLY from their authoritative `cell_path` identity bytes
32//! with the canonical value deserializer
33//! (`comparator_value_parsing::parse_value_with_comparator` — the SAME decoder the
34//! single-generation/bypass arm uses, never a second structural decoder), so a
35//! `set<frozen<udt>>` / `map<frozen<tuple>, V>` reads IDENTICALLY however many
36//! SSTable generations the table has. Before #2339 this path failed closed, which
37//! made a correctness outcome flip on generation count.
38//!
39//! Composite decode needs the table's [`UdtRegistry`]: an all-lowercase UDT name
40//! parses to a bare `CqlType::Custom` with no field list, so without the registry
41//! there is no structure to decode into and the path STILL fails closed with a
42//! clear error naming the column + declared type (never opaque bytes, never a
43//! guess). The composite/scalar choice branches on the DECLARED schema type only
44//! (no-heuristics, issue #28).
45//!
46//! Two decodable scalars — `inet` (`InetAddressType`) and `time` (`TimeType`) —
47//! have serialized `cell_path` forms that ARE unsigned-byte-comparable, so they
48//! are ordered by raw `cell_path` bytes rather than decoded and routed through
49//! the scalar comparator ([`comparator_orders_by_raw_cell_path_bytes`], roborev
50//! 1631/1632). The scalar comparator used to order them by FORMATTED string;
51//! since #3790 it agrees, so raw-byte order stays equivalent and cheaper.
52//!
53//! Tombstone handling follows Cassandra SELECT semantics (issue #1742: SELECT
54//! output is the read-path authority), NOT the single-generation reader's
55//! physical `collapsed_value`: a deleted set/list member or deleted MAP entry is
56//! OMITTED from the reassembled collection. This intentionally DIVERGES from
57//! `complex_column.rs`'s collapsed_value, which surfaces a deleted map entry as a
58//! physical `(key, Null)` pair; that quirk is the physical-dump side and is
59//! tracked separately (issue #2336 family). A `SELECT` never returns a deleted
60//! map key, so the merger read-shape must not either.

98/// One column's accumulated cells while grouping a row's flat cell list.
99///
100/// The two shapes are mutually exclusive for any one column: in Cassandra 5.0
101/// (na+) a column's frozen-ness is a FIXED schema property (you cannot `ALTER`
102/// a column between frozen and non-frozen), so a single consistent row can never
103/// carry BOTH a whole-value (simple) cell AND per-element (complex) cells for the
104/// same column. If both nonetheless arrive during grouping the row is
105/// inconsistent/corrupt, so [`assemble_read_cells`] fails closed (issue #28)
106/// rather than silently keep whichever shape arrived first and drop the other.
107#[cfg(feature = "write-support")]
108enum ColumnAccum {
109    /// A simple (single-cell) column: its one decoded value.
110    Simple(Value),
111    /// A complex (multi-cell) column: its surviving live elements in arrival
112    /// order (re-sorted by `cell_path` at collapse time). Element tombstones are
113    /// already dropped.
114    Complex(Vec<CellData>),
115}
116
117/// Fail-closed error for a column that arrives with BOTH simple and complex
118/// cells in one merged row (see [`ColumnAccum`] — impossible for a consistent
119/// na+ schema). Names the offending column; never silently drops a shape.
120#[cfg(feature = "write-support")]
121fn mixed_shape_error(column: &str) -> Error {
122    Error::corruption(format!(
123        "column '{column}': merged row mixes a whole-value (simple) cell and \
124         per-element (complex) cells for one column — impossible for a consistent \
125         Cassandra 5.0 (na+) schema (frozen-ness is fixed, un-ALTERable); failing \
126         closed rather than silently dropping either shape (issues #28/#2324)"
127    ))
128}

130/// Which [`UdtRegistry`], and under WHICH KEYSPACE, an UNQUALIFIED UDT reference
131/// in a declared type resolves for merged-read reassembly (issue #2339).
132///
133/// The two facts travel together because neither is usable alone: the registry is
134/// keyed by keyspace, and a caller's `TableSchema.keyspace` is NOT always the one
135/// the registry was built under — `schema::parse_cql_schema` yields the literal
136/// placeholder `"default"` for an unqualified `CREATE TABLE`, which is what a
137/// Flight ticket DDL is, while its registry is keyed by the ticket's real
138/// keyspace. Passing the keyspace explicitly makes that mismatch impossible to
139/// re-introduce silently: a missed lookup leaves a UDT reference an opaque
140/// `Custom` and (correctly) fails the composite decode closed, which reads as
141/// "unsupported" rather than "mis-wired".
142///
143/// `None` at the call site means NO registry: a composite whose element/key is a
144/// bare UDT reference then has no field list to decode into and fails closed
145/// (never a guess — no-heuristics, issue #28).
146#[cfg(feature = "write-support")]
147#[derive(Debug, Clone, Copy)]
148pub struct UdtScope<'a> {
149    /// The authoritative UDT definitions.
150    pub registry: &'a UdtRegistry,
151    /// The keyspace an unqualified UDT reference resolves under.
152    pub keyspace: &'a str,
153}

155/// Reassemble a merged live row's per-column cells into user-facing
156/// [`RowCells`], collapsing multi-cell collection columns into a single
157/// `Value::List` / `Value::Set` / `Value::Map` (issue #2324).
158///
159/// Cell tombstones (`Value::Tombstone` on a simple cell) and deleted complex
160/// elements (`is_deleted`) are dropped, so a column reads as its surviving live
161/// content — an absent simple column becomes null downstream, an all-deleted
162/// collection becomes the empty collection.
163///
164/// A non-collection complex column (e.g. a non-frozen top-level UDT) is left as
165/// its individual cells — this reassembles collections only, the columns the
166/// issue names; other multi-cell shapes are unchanged (no worse than before).
167///
168/// `needed` is the projection-aware set of column names this scan will actually
169/// read (the output projection ∪ predicate-referenced ∪ aggregation-referenced
170/// columns); `None` means "every column" (a plain `SELECT *`). Cells of a column
171/// NOT in `needed` are dropped BEFORE reassembly — they are never emitted
172/// downstream (projection removes them from Arrow output, the filter and
173/// aggregation don't reference them). This scopes the composite-keyed-collection
174/// fail-closed error (a frozen tuple/UDT/nested-collection key/element the scalar
175/// codec cannot materialize, #2339) to the columns a query actually reads: an
176/// unrelated `SELECT` of scalar columns from a row that merely COEXISTS with an
177/// unsupported composite-keyed collection column SUCCEEDS — matching the
178/// observable pre-#2324 behaviour — while the clean error still fires when that
179/// composite column IS projected or referenced (issue #2324, roborev 1633). It
180/// is also a small perf win (unprojected collections are never reassembled).
181/// The BACK-COMPATIBLE entry point, at this function's pre-#2339 signature.
182///
183/// `assemble_read_cells` is public API of `cqlite-core` (re-exported through
184/// `storage::write_engine::merge`), so #2339 may not change its arity: adding a
185/// required parameter would break every external consumer at compile time
186/// (roborev job 110 F2). It therefore keeps its three arguments and delegates
187/// with NO registry.
188///
189/// Composite/UDT-aware callers want [`assemble_read_cells_with_udts`]: with no
190/// registry, a composite whose element/key is a bare UDT reference has no field
191/// list to decode into and fails closed (never a guess — no-heuristics, #28).
192/// Behaviour here is otherwise IDENTICAL, because this is a delegation and not a
193/// second implementation — there is exactly one body.
194///
195/// Deliberately NOT `#[deprecated]`: this is the correct entry point for a caller
196/// with no UDT registry, and the attribute would red `-D warnings` on every
197/// in-repo use of it.
198#[cfg(feature = "write-support")]
199pub fn assemble_read_cells(
200    cells: Vec<CellData>,
201    schema: &TableSchema,
202    needed: Option<&HashSet<String>>,
203) -> Result<RowCells> {
204    assemble_read_cells_with_udts(cells, schema, needed, None)
205}

207/// As [`assemble_read_cells`], plus the [`UdtScope`] an unqualified UDT reference
208/// in a declared element/key type resolves against (issue #2339).
209///
210/// This holds the implementation; the three-argument form delegates here with
211/// `udts: None`.
212#[cfg(feature = "write-support")]
213pub fn assemble_read_cells_with_udts(
214    cells: Vec<CellData>,
215    schema: &TableSchema,
216    needed: Option<&HashSet<String>>,
217    udts: Option<UdtScope<'_>>,
218) -> Result<RowCells> {
219    // Group cells by column, preserving first-seen order so a stable, schema-
220    // independent ordering results (downstream keys by name, so order is not
221    // load-bearing — but a deterministic order keeps output reproducible).
222    let mut order: Vec<Arc<str>> = Vec::new();
223    let mut index: HashMap<Arc<str>, usize> = HashMap::new();
224    let mut accums: Vec<ColumnAccum> = Vec::new();
225
226    for cell in cells {
227        // Projection-aware assembly (issue #2324, roborev 1633): drop cells of a
228        // column this scan never reads before touching the (fallible) reassembly.
229        // `None` = all columns → nothing dropped. This keeps the composite-keyed
230        // collection fail-closed error (#2339) from firing on a column an unrelated
231        // query does not project or reference (see the fn-level doc).
232        if let Some(needed) = needed {
233            if !needed.contains(cell.column.as_str()) {
234                continue;
235            }
236        }
237        let name: Arc<str> = Arc::from(cell.column.as_str());
238        if cell.is_complex_element {
239            // Drop element tombstones (a deleted set/list member OR map entry):
240            // the whole element is removed. A collection with NO surviving live
241            // element is left absent (reads null downstream) — an empty non-frozen
242            // collection IS null in Cassandra, and this preserves the pre-fix
243            // behaviour for that edge (the fix only recovers dropped LIVE elements).
244            //
245            // ADJUDICATION (issue #2324, roborev 1628): dropping a deleted MAP
246            // entry — rather than surfacing it as `(key, Null)` — is DELIBERATE and
247            // matches real Cassandra SELECT output, the read-path authority per the
248            // #1742 query-semantics-oracle doctrine: a `SELECT` never returns a
249            // deleted map key. This DIVERGES from the single-generation reader's
250            // physical `collapsed_value` (complex_column.rs ~L663-733), which keeps
251            // the `(key, Null)` pair for the physical-dump oracle; that quirk is the
252            // divergent physical side, tracked separately (issue #2336 family). Do
253            // NOT "fix" this to preserve `(key, Null)` here — that would corrupt the
254            // merger read-shape a `do_get` returns.
255            // TOMBSTONES ARE RETAINED HERE AND DROPPED LATER (issue #2339, roborev
256            // job 119, High). They USED to be skipped at this point, which resurrected
257            // data: a NEWER tombstone whose composite cell path is comparator-EQUAL to
258            // an OLDER live cell's — an explicit all-null suffix versus an omitted one
259            // — was discarded before it could reach `cell_wins`, so the older value
260            // survived. Reproduced: ts-200 tombstone + ts-100 live yielded
261            // `Map([(Tuple([1]), BigInt(1))])` where Cassandra returns an EMPTY map.
262            //
263            // `reconcile.rs` cannot prevent it either, because it keys cells by RAW
264            // `cell_path` and the two encodings are different bytes.
265            //
266            // The DROP still happens — `assemble_complex` does it, either before
267            // assembly for a non-composite identity (byte-identical behaviour to
268            // skipping here, since nothing coalesces those) or AFTER comparator-equal
269            // reconciliation for a composite one, where the tombstone must be present
270            // to win. The adjudication below is unchanged: a deleted entry is OMITTED
271            // from the reassembled collection, never surfaced as `(key, Null)`.
272            let elems = register_complex(&mut order, &mut index, &mut accums, name)?;
273            elems.push(cell);
274        } else {
275            // Simple cell: a tombstoned simple cell leaves the column absent
276            // (reads null downstream) — mirror the prior producer filter.
277            if matches!(cell.value, Value::Tombstone(_)) {
278                continue;
279            }
280            match index.get(name.as_ref()) {
281                Some(&i) => match &mut accums[i] {
282                    ColumnAccum::Simple(v) => *v = cell.value,
283                    // Mixed shape: complex elements already present for this column.
284                    ColumnAccum::Complex(_) => return Err(mixed_shape_error(&name)),
285                },
286                None => {
287                    index.insert(Arc::clone(&name), accums.len());
288                    order.push(name);
289                    accums.push(ColumnAccum::Simple(cell.value));
290                }
291            }
292        }
293    }
294
295    let mut out: RowCells = Vec::with_capacity(order.len());
296    for (name, accum) in order.into_iter().zip(accums) {
297        match accum {
298            ColumnAccum::Simple(value) => out.push((name, value)),
299            ColumnAccum::Complex(elements) => {
300                // `None` = the column is ABSENT: every element it accumulated was a
301                // deletion, so an empty non-frozen collection reads as null (the
302                // pre-existing invariant `all_deleted_collection_is_absent` pins).
303                // Absence is decided INSIDE `assemble_complex` because tombstones now
304                // survive accumulation and, for a composite identity, are only
305                // resolved after comparator-equal reconciliation (roborev job 119).
306                if let Some(value) = assemble_complex(&name, elements, schema, udts)? {
307                    out.push((name, value));
308                }
309            }
310        }
311    }
312    Ok(out)
313}

315/// Fetch (creating if absent) the [`ColumnAccum::Complex`] slot for `name`,
316/// returning a mutable reference to its element vec. Fails closed with
317/// [`mixed_shape_error`] if the column already holds a simple cell (see
318/// [`ColumnAccum`]).
319#[cfg(feature = "write-support")]
320fn register_complex<'a>(
321    order: &mut Vec<Arc<str>>,
322    index: &mut HashMap<Arc<str>, usize>,
323    accums: &'a mut Vec<ColumnAccum>,
324    name: Arc<str>,
325) -> Result<&'a mut Vec<CellData>> {
326    let i = match index.get(name.as_ref()) {
327        Some(&i) => i,
328        None => {
329            let i = accums.len();
330            index.insert(Arc::clone(&name), i);
331            order.push(name);
332            accums.push(ColumnAccum::Complex(Vec::new()));
333            i
334        }
335    };
336    // `order[i]` is the column name for `accums[i]` (both pushed together), and
337    // borrows a different vec than `accums`, so it stays available for the error.
338    match &mut accums[i] {
339        ColumnAccum::Complex(elems) => Ok(elems),
340        ColumnAccum::Simple(_) => Err(mixed_shape_error(&order[i])),
341    }
342}

344/// Collapse the surviving live elements of one complex column into a single
345/// `Value`, using the column's declared collection type from `schema`.
346#[cfg(feature = "write-support")]
347fn assemble_complex(
348    name: &str,
349    mut elements: Vec<CellData>,
350    schema: &TableSchema,
351    udts: Option<UdtScope<'_>>,
352) -> Result<Option<Value>> {
353    // Resolve the declared collection type. An undeclared column (the Flight
354    // producer builds cells for every on-disk column, even ones the caller did
355    // not declare) has no type here; such columns are never emitted to Arrow, so
356    // fall back to the last live element's value rather than fail the whole row.
357    // ALL-TOMBSTONE SHORT-CIRCUIT, BEFORE any type resolution or decoding (issue
358    // #2339, roborev job 120 F2). Retaining tombstones for reconciliation made an
359    // ABSENT collection walk the whole composite path — comparator construction and
360    // structural cell-path decode — so an unresolved UDT or a malformed DELETED key
361    // could turn "the column is absent" into an unsupported-format / corruption
362    // ERROR, where the pre-#2339 code simply returned absent. No element can survive
363    // here, so none of that work can change the answer.
364    if elements.iter().all(is_tombstone_cell) {
365        return Ok(None);
366    }
367
368    let declared = schema
369        .columns
370        .iter()
371        .find(|c| c.name == name)
372        .map(|c| c.data_type.as_str());
373
374    let cql_type = match declared {
375        Some(dt) => CqlType::parse(dt)?,
376        None => {
377            drop_tombstones(&mut elements);
378            return Ok(absent_if_empty(&elements).map(|()| last_value(elements)));
379        }
380    };
381    let cql_type = unwrap_frozen(&cql_type);
382
383    // WHERE THE TOMBSTONE DROP LIVES (issue #2339, roborev job 119). Accumulation now
384    // RETAINS tombstones so a composite identity can reconcile them; everything whose
385    // identity is NOT a comparator-compared composite drops them right here, which is
386    // byte-identical to the previous skip-at-accumulation because nothing coalesces
387    // those paths. A composite identity keeps them through `sort_composite` and drops
388    // the losers afterwards, in `drop_tombstone_winners`.
389    let identity_is_composite = match &cql_type {
390        CqlType::Set(inner) => key_is_opaque_composite(&element_comparator(inner, udts)?),
391        CqlType::Map(key_type, _) => key_is_opaque_composite(&element_comparator(key_type, udts)?),
392        _ => false,
393    };
394    if !identity_is_composite {
395        drop_tombstones(&mut elements);
396        // Everything it had was a deletion => the column is absent. Checked here so
397        // the non-composite paths behave EXACTLY as they did when the skip happened
398        // at accumulation time.
399        if elements.is_empty() {
400            return Ok(None);
401        }
402    }
403
404    match cql_type {
405        // A set's element identity IS its `cell_path`; order by the declared
406        // element comparator so a set spanning multiple SSTables (whose elements
407        // arrive in run-encounter, not disk, order) reconstructs in the SAME order
408        // a single-generation `SELECT` returns (issue #2324, roborev 1628).
409        CqlType::Set(inner) => {
410            let elem_cmp = element_comparator(inner, udts)?;
411            if key_is_opaque_composite(&elem_cmp) {
412                // A composite (frozen tuple / UDT / nested collection) set element
413                // IS its `cell_path` — `e.value` is EMPTY for a set cell, as the
414                // sstabledump golden confirms (`"value":""`). Decode the identity
415                // bytes structurally with the declared element type, then order the
416                // DECODED values with Cassandra's own type comparator (issue #2339;
417                // see the `composite` module for why raw `cell_path` byte order
418                // is NOT Cassandra's order for a composite).
419                let keyed = decode_composite_elements(name, "set element", elements, &elem_cmp)?;
420                let survivors = drop_tombstone_winners(sort_composite(name, keyed, &elem_cmp)?);
421                if survivors.is_empty() {
422                    return Ok(None);
423                }
424                return Ok(Some(Value::Set(
425                    survivors.into_iter().map(|(v, _)| v).collect(),
426                )));
427            }
428            // A set's element identity IS its `cell_path`; order by the declared
429            // element comparator so a set spanning multiple SSTables reconstructs
430            // in the SAME order a single-generation `SELECT` returns.
431            sort_elements_by_cell_path(&mut elements, &elem_cmp)?;
432            Ok(Some(Value::Set(
433                elements.into_iter().map(|e| e.value).collect(),
434            )))
435        }
436        // A list element's `cell_path` is its position timeuuid, which orders by
437        // raw byte comparison — sort by `cell_path` bytes so multi-SSTable list
438        // elements land in authoritative position order, not arrival order.
439        CqlType::List(_) => {
440            elements.sort_by(|a, b| cell_path_bytes(a).cmp(cell_path_bytes(b)));
441            Ok(Some(Value::List(
442                elements.into_iter().map(|e| e.value).collect(),
443            )))
444        }
445        CqlType::Map(key_type, _) => {
446            let key_cmp = element_comparator(key_type, udts)?;
447            if key_is_opaque_composite(&key_cmp) {
448                // A composite map KEY is the element's `cell_path`: decode it
449                // structurally, then order entries with Cassandra's own type
450                // comparator over the DECODED keys (issue #2339).
451                let keyed = decode_composite_elements(name, "map key", elements, &key_cmp)?;
452                let survivors = drop_tombstone_winners(sort_composite(name, keyed, &key_cmp)?);
453                if survivors.is_empty() {
454                    return Ok(None);
455                }
456                return Ok(Some(Value::Map(
457                    survivors
458                        .into_iter()
459                        .map(|(key, cell)| (key, cell.value))
460                        .collect(),
461                )));
462            }
463            // Order entries by the declared scalar key comparator so a map spanning
464            // multiple SSTables reconstructs in authoritative key order — done on
465            // the cells up front so the key is decoded once, at build time.
466            sort_elements_by_cell_path(&mut elements, &key_cmp)?;
467            let mut entries = Vec::with_capacity(elements.len());
468            for e in elements {
469                // The map key is the element's cell_path (raw key bytes, no length
470                // prefix), decoded with the declared scalar type.
471                let key_bytes = e.cell_path.as_deref().unwrap_or(&[]);
472                let key = deserialize_value_bytes(key_bytes, &key_cmp)?;
473                entries.push((key, e.value));
474            }
475            Ok(Some(Value::Map(entries)))
476        }
477        // A non-collection complex column (e.g. non-frozen top-level UDT):
478        // reassembly of those shapes is out of this issue's scope. Keep the last
479        // element's value (prior behaviour) so nothing regresses.
480        _ => Ok(Some(last_value(elements))),
481    }
482}

484/// The element's authoritative `cell_path` bytes (empty when absent).
485#[cfg(feature = "write-support")]
486fn cell_path_bytes(cell: &CellData) -> &[u8] {
487    cell.cell_path.as_deref().unwrap_or(&[])
488}

490/// Order collection cells by their `cell_path` (the element/key identity), in
491/// place, using the declared element/key comparator.
492///
493/// Reached for SCALAR element/key types only: an OPAQUE COMPOSITE
494/// ([`key_is_opaque_composite`]) is decoded and ordered by [`sort_composite`]
495/// before this is called, because Cassandra orders a composite by its TYPE
496/// comparator and not by raw `cell_path` bytes (issue #2339). Should a composite
497/// nonetheless reach here, `deserialize_value_bytes` fails closed rather than
498/// silently mis-ordering it. Two scalar shapes:
499///   * A `inet`/`time` comparator ([`comparator_orders_by_raw_cell_path_bytes`])
500///     orders by raw `cell_path` byte comparison — its serialized form's unsigned
501///     byte order IS its Cassandra order (roborev 1631/1632; the scalar comparator
502///     mis-ordered these by formatted string until #3790).
503///   * Any other scalar decodes each `cell_path` to a `Value` and orders by the
504///     type comparator (e.g. signed-int order != raw byte order), surfacing any
505///     genuine decode error (wrong-width scalar) rather than masking it.
506#[cfg(feature = "write-support")]
507fn sort_elements_by_cell_path(elements: &mut Vec<CellData>, cmp: &ComparatorType) -> Result<()> {
508    if comparator_orders_by_raw_cell_path_bytes(cmp) {
509        elements.sort_by(|a, b| cell_path_bytes(a).cmp(cell_path_bytes(b)));
510        return Ok(());
511    }
512    // Decode each `cell_path` once up front (fallible → propagated) so the sort
513    // itself is total and infallible.
514    let mut keyed: Vec<(Value, CellData)> = Vec::with_capacity(elements.len());
515    for cell in std::mem::take(elements) {
516        let key = deserialize_value_bytes(cell_path_bytes(&cell), cmp)?;
517        keyed.push((key, cell));
518    }
519    sort_by_comparator(&mut keyed, cmp)?;
520    elements.extend(keyed.into_iter().map(|(_, cell)| cell));
521    Ok(())
522}

524/// True when `cmp` names an element/key type the scalar [`deserialize_value_bytes`]
525/// codec CANNOT decode — a frozen tuple / UDT / nested collection (or any other
526/// non-scalar `Custom`).
527///
528/// Such a key/element is decoded STRUCTURALLY from its `cell_path` by
529/// `composite::decode_composite` and ORDERED by `composite::compare_composite`,
530/// which implements Cassandra's own type comparators (issue #2339). Decoding and
531/// ordering are deliberately separate concerns.
532///
533/// This predicate is therefore no longer a fail-closed guard: it SELECTS the
534/// structural path. It still fails closed for one case only — a UDT reference
535/// that the table's `UdtRegistry` cannot resolve has no field list to decode
536/// into, and is refused by name (see [`composite_collection_unsupported`], whose
537/// doc records why the opaque-blob route was abandoned).
538///
539/// The set of decodable scalars is kept in lockstep with
540/// `deserialize_value_bytes`; branching on the DECLARED type only, never a byte
541/// pattern (no-heuristics, issue #28).
542///
543/// The SINGLE-generation reader's behaviour per type is stated ONCE in
544/// `cell_path_key.rs`'s asymmetry section (issue #3612) — cite, never restate.
545/// That asymmetry is now CLOSED for the shapes #2339 covers: both arms decode a
546/// composite cell-path key/element structurally, so the outcome no longer depends
547/// on SSTable generation count.
548#[cfg(feature = "write-support")]
549fn key_is_opaque_composite(cmp: &ComparatorType) -> bool {
550    match cmp {
551        // `frozen` only ever wraps a composite in a map key / collection element,
552        // but recurse defensively so a hypothetical frozen scalar still decodes.
553        ComparatorType::Frozen(inner) => key_is_opaque_composite(inner),
554        ComparatorType::Boolean
555        | ComparatorType::TinyInt
556        | ComparatorType::SmallInt
557        | ComparatorType::Int
558        | ComparatorType::BigInt
559        | ComparatorType::Counter
560        | ComparatorType::Float32
561        | ComparatorType::Float
562        | ComparatorType::Text
563        | ComparatorType::Blob
564        | ComparatorType::Timestamp
565        | ComparatorType::Date
566        | ComparatorType::Uuid
567        | ComparatorType::Varint
568        | ComparatorType::Decimal
569        | ComparatorType::Duration => false,
570        // `deserialize_value_bytes` decodes only these two Custom names.
571        ComparatorType::Custom(name) => !(name == "time" || name == "inet"),
572        // Tuple / Udt / Set / List / Map: undecodable by the scalar codec.
573        _ => true,
574    }
575}

577/// True when the element/key type's Cassandra ordering IS unsigned raw-byte
578/// comparison of the `cell_path`, so the raw bytes can be compared directly with
579/// no decode round-trip.
580///
581/// The two decodable `Custom` names — `inet` and `time` — are the ONLY declared
582/// scalar types in this sort path without a dedicated [`ComparatorType`] arm.
583/// Both have a canonical serialized form whose UNSIGNED byte order equals their
584/// Cassandra order, and the element/key `cell_path` IS that serialized form, so
585/// ordering by raw `cell_path` bytes matches Cassandra exactly and needs no
586/// decode round-trip (roborev 1631/1632). Until #3790 the scalar `Custom` arm
587/// ordered both by FORMATTED string; correct either way here, but only `inet`
588/// actually diverged (roborev job 67):
589///   * `inet` (`InetAddressType`): raw address bytes — `9.0.0.1` = `[9,0,0,1]`
590///     precedes `10.0.0.1`, the REVERSE of string order: a real misordering.
591///   * `time` (`TimeType`): nanos-of-day, BYTE_ORDER — raw `cell_path` bytes ARE
592///     Cassandra's order for EVERY 8-byte value, negatives included (#3935 refuted
593///     the "always non-negative" premise; citations in `custom::compare_time`).
594///
595/// Branches on the DECLARED type only (no-heuristics, issue #28); recurses through
596/// `Frozen` defensively though neither inet nor time is ever frozen here.
597#[cfg(feature = "write-support")]
598fn comparator_orders_by_raw_cell_path_bytes(cmp: &ComparatorType) -> bool {
599    match cmp {
600        ComparatorType::Frozen(inner) => comparator_orders_by_raw_cell_path_bytes(inner),
601        ComparatorType::Custom(name) => name == "inet" || name == "time",
602        _ => false,
603    }
604}

606/// Resolve a collection's declared element/key type to a [`ComparatorType`],
607/// resolving UDT REFERENCES through `udts` when a scope is available (issue
608/// #2339).
609///
610/// The registry is what makes a composite element/key decodable at all:
611/// `CqlType::parse("set<frozen<contact_info>>")` yields
612/// `Set(Frozen(Custom("contact_info")))` — an all-lowercase UDT name parses to a
613/// bare `Custom` carrying NO field list — so without the registry there is no
614/// field structure to decode INTO and the type stays an opaque `Custom`
615/// ([`key_is_opaque_composite`] still names it, so the path fails closed with a
616/// clear error rather than guessing).
617///
618/// UDT references are resolved by [`UdtRegistry::resolve_type`] — the SINGLE
619/// shared resolver, not a second implementation (roborev F2). This matters for
620/// correctness, not just tidiness: `from_cql_type_with_registry`'s own `Custom`
621/// arm looks a reference up with `registry.get_udt(keyspace, name)`, which is NOT
622/// qualifier-aware, so a Cassandra-style QUALIFIED reference (`ks.contact_info`,
623/// which the CQL parser retains) missed the registry and stayed an opaque
624/// `Custom` — while the Flight bypass predicate answers the same question with
625/// `resolve_type`, which IS qualifier-aware (`split_qualified_udt`). The two
626/// therefore DISAGREED: the predicate called the type resolvable and selected the
627/// single-generation arm, while a MULTI-generation merged read of the same table
628/// failed closed — reintroducing exactly the generation-dependent correctness
629/// outcome this issue exists to remove. Resolving here first makes both arms agree
630/// BY CONSTRUCTION: one resolver, one answer.
631///
632/// Resolution is fail-open by design (an unknown reference is left UNCHANGED,
633/// never fabricated — no-heuristics, issue #28), so a genuinely unresolvable UDT
634/// still arrives as a bare `Custom` and `decode_composite` still fails closed
635/// naming the column and the declared type.
636#[cfg(feature = "write-support")]
637fn element_comparator(declared: &CqlType, udts: Option<UdtScope<'_>>) -> Result<ComparatorType> {
638    match udts {
639        Some(udts) => {
640            let resolved = udts.registry.resolve_type(declared, udts.keyspace);
641            ComparatorType::from_cql_type_with_registry(&resolved, udts.registry, udts.keyspace)
642        }
643        None => ComparatorType::from_cql_type(declared),
644    }
645}

647/// Decode every element's composite `cell_path` identity once, pairing each
648/// decoded key/element with its cell (issue #2339).
649#[cfg(feature = "write-support")]
650fn decode_composite_elements(
651    column: &str,
652    kind: &str,
653    elements: Vec<CellData>,
654    cmp: &ComparatorType,
655) -> Result<Vec<(Value, CellData)>> {
656    let mut keyed = Vec::with_capacity(elements.len());
657    for cell in elements {
658        let value = decode_composite(column, kind, cell_path_bytes(&cell), cmp)?;
659        keyed.push((value, cell));
660    }
661    Ok(keyed)
662}

664/// Order decoded composite keys/elements with Cassandra's own type comparator.
665///
666/// NOT raw `cell_path` byte order: Cassandra writes a collection's cells in
667/// `cellPathComparator()` order, which for a composite is the declared type's
668/// component-wise comparator, and the two orders genuinely DISAGREE on
669/// Cassandra-written bytes (see [`composite`] for the
670/// measured cases). The decode is fallible and already done, so the sort itself is
671/// total; a comparison error is captured and surfaced rather than silently
672/// mis-ordering. Two shapes reach here: a decoded shape the declared type
673/// contradicts, and a leaf type whose central comparator is known to diverge from
674/// Cassandra's and is therefore REFUSED (`varint`/`decimal`/`uuid`, issue #4063 —
675/// see `composite::divergent_leaf`). `column` is carried in only so those refusals
676/// can name it.
677#[cfg(feature = "write-support")]
678fn sort_composite(
679    column: &str,
680    mut keyed: Vec<(Value, CellData)>,
681    cmp: &ComparatorType,
682) -> Result<Vec<(Value, CellData)>> {
683    let mut first_err: Option<Error> = None;
684    keyed.sort_by(|a, b| match compare_composite(column, &a.0, &b.0, cmp) {
685        Ok(ord) => ord,
686        Err(e) => {
687            if first_err.is_none() {
688                first_err = Some(e);
689            }
690            Ordering::Equal
691        }
692    });
693    if let Some(e) = first_err {
694        return Err(e);
695    }
696    coalesce_comparator_equal(column, keyed, cmp)
697}

699/// Collapse runs of comparator-EQUAL cell paths to ONE cell, by the shared
700/// reconciliation rule (issue #2339, roborev job 117).
701///
702/// **The defect this closes, reproduced before it was written.** Two encodings can be
703/// DIFFERENT BYTES and comparator-EQUAL — an omitted trailing tuple component versus
704/// an explicit null one, which `TupleType.compareCustom` returns 0 for and which
705/// `an_omitted_tuple_suffix_compares_equal_to_an_explicit_all_null_suffix` already
706/// pins. But `reconcile.rs` keys cells by `(column, RAW cell_path)`, so two
707/// generations carrying the two encodings both SURVIVE reconciliation and assembly
708/// emitted BOTH:
709///
710/// ```text
711/// Map([(Frozen(Tuple([Integer(1)])),       BigInt(1)),
712///      (Frozen(Tuple([Integer(1), Null])), BigInt(2))])
713/// ```
714///
715/// That is not a valid CQL map — one logical key, two entries — and Cassandra would
716/// return the later-timestamped winner alone.
717///
718/// **Why HERE and not in `reconcile.rs`.** Making `CellKey` comparator-aware would
719/// change the identity of every multi-cell column in the engine, needs the declared
720/// type at a layer that deliberately does not have it, and is far outside this
721/// issue. This runs where the comparator IS known and the run is already SORTED, so
722/// equal keys are adjacent and one linear pass suffices.
723///
724/// **The winner rule is NOT reimplemented**: `reconcile_rules::cell_wins` is the
725/// SHARED predicate already used by both the merge path and the flush/write path
726/// (issue #947) — higher timestamp, then a tombstone beats a live/expiring cell at
727/// equal timestamp, then first-seen. A second copy here would be a second
728/// reconciliation authority, which is the divergence class #2339 exists to remove.
729///
730/// The WINNER's own key encoding is the one kept, matching Cassandra keeping the
731/// winning cell rather than synthesising a canonical form.
732#[cfg(feature = "write-support")]
733fn coalesce_comparator_equal(
734    column: &str,
735    keyed: Vec<(Value, CellData)>,
736    cmp: &ComparatorType,
737) -> Result<Vec<(Value, CellData)>> {
738    let mut out: Vec<(Value, CellData)> = Vec::with_capacity(keyed.len());
739    for (key, cell) in keyed {
740        let collapses = match out.last() {
741            // The run is sorted, so a comparator-equal peer can only be the LAST
742            // pushed entry. Errors propagate rather than being swallowed into
743            // "not equal", which would silently re-admit the duplicate.
744            Some((prev_key, _)) => {
745                compare_composite(column, prev_key, &key, cmp)? == Ordering::Equal
746            }
747            None => false,
748        };
749        if collapses {
750            if let Some((prev_key, prev_cell)) = out.last_mut() {
751                if crate::storage::write_engine::reconcile_rules::cell_wins(&cell, prev_cell) {
752                    *prev_key = key;
753                    *prev_cell = cell;
754                }
755            }
756            continue;
757        }
758        out.push((key, cell));
759    }
760    Ok(out)
761}

763/// Sort `items` by the first tuple element with the fallible [`ComparatorType`],
764/// capturing the first comparison error (a type mismatch the declared metadata
765/// should never produce) and surfacing it rather than silently mis-ordering.
766#[cfg(feature = "write-support")]
767fn sort_by_comparator<T>(items: &mut [(Value, T)], cmp: &ComparatorType) -> Result<()> {
768    let mut first_err: Option<Error> = None;
769    items.sort_by(|a, b| match cmp.compare(&a.0, &b.0) {
770        Ok(ord) => ord,
771        Err(e) => {
772            if first_err.is_none() {
773                first_err = Some(e);
774            }
775            Ordering::Equal
776        }
777    });
778    match first_err {
779        Some(e) => Err(e),
780        None => Ok(()),
781    }
782}

794/// The last element's value, or `Value::Null` when there are none — the safe
795/// fallback for a column whose collection type cannot be resolved.
796#[cfg(feature = "write-support")]
797/// Does this column have any cell that SURVIVES reconciliation? (issue #2339, roborev
798/// job 128.)
799///
800/// **Why this exists.** `cqlite-flight` decides row VISIBILITY from the full
801/// pre-projection cell set, but a raw cell can look live and still lose: a composite
802/// cell path written with an omitted trailing component is comparator-EQUAL to one
803/// written with an explicit null, so a NEWER tombstone in the other encoding supersedes
804/// it. When that column is EXCLUDED by the projection, the assembled row cannot correct
805/// the decision, and the row surfaces as a PHANTOM key-only row. Deciding it from raw
806/// cells is therefore wrong, and deciding it from the PROJECTED assembly cannot see the
807/// excluded column.
808///
809/// **Why it delegates to [`assemble_complex`] rather than reimplementing the rule.**
810/// This is exactly the question assembly already answers — `None` means the column is
811/// absent because every element was a deletion or lost reconciliation. A second,
812/// "lightweight" copy of comparator-equal coalescing plus tombstone-winner selection is
813/// a second reconciliation authority, which is the divergence class #2339 exists to
814/// remove; it would also have to be kept in step with `cell_wins` by hand. So there is
815/// ONE decision procedure and this is a thin projection of it.
816///
817/// **The cost, stated rather than hidden.** For a column the projection EXCLUDED this
818/// does build that column's `Value` in order to discard it. That is accepted because the
819/// caller only asks about columns whose liveness is genuinely AMBIGUOUS from timestamps
820/// alone — every live cell outranked by a tombstone in the same column — which is rare,
821/// and because the alternative is a wrong answer. It performs no Arrow conversion.
822#[cfg(feature = "write-support")]
823pub fn column_has_surviving_live_cell(
824    name: &str,
825    cells: Vec<CellData>,
826    schema: &TableSchema,
827    udts: Option<UdtScope<'_>>,
828) -> Result<bool> {
829    Ok(assemble_complex(name, cells, schema, udts)?.is_some())
830}

832/// A deleted collection element is OMITTED from the reassembled value, never
833/// surfaced as `(key, Null)` — the #2324 / roborev-1628 adjudication, unchanged.
834/// Only the POINT at which it is dropped moved (issue #2339, roborev job 119).
835#[cfg(feature = "write-support")]
836fn drop_tombstones(elements: &mut Vec<CellData>) {
837    elements.retain(|c| !is_tombstone_cell(c));

840/// Drop reconciliation WINNERS that are tombstones, after comparator-equal
841/// coalescing (issue #2339, roborev job 119).
842///
843/// A tombstone that LOST is already gone — `cell_wins` replaced it. A tombstone that
844/// WON means the newest write for that logical key was a delete, so the entry is
845/// omitted, which is what a Cassandra `SELECT` returns. Doing this before coalescing
846/// is the resurrection bug: the tombstone has to be present to win.
847#[cfg(feature = "write-support")]
848fn drop_tombstone_winners(keyed: Vec<(Value, CellData)>) -> Vec<(Value, CellData)> {
849    keyed
850        .into_iter()
851        .filter(|(_, cell)| !is_tombstone_cell(cell))
852        .collect()
853}

855/// `Some(())` when at least one element survived, `None` when the column is absent.

862/// ONE spelling of "this cell is a deletion", so the retain/filter pair cannot drift.
863#[cfg(feature = "write-support")]
864fn is_tombstone_cell(cell: &CellData) -> bool {
865    cell.is_deleted || matches!(cell.value, Value::Tombstone(_))
866}
