1//! Process-global adaptive egress budget for concurrent k-way merges
2//! (issues #2765/#2600/#2367).
3//!
4//! A k-way merge streams each of its `K` input SSTables through a bounded
5//! producer→consumer `sync_channel` that buffers prefetched `MergeEntry` values
6//! (see `STREAMING_CHANNEL_CAPACITY`, `merge/mod.rs`). With a FIXED per-channel
7//! capacity, the rows buffered by a SINGLE merge grew as `K × per_source`, and
8//! across the process as `active_merges × K × per_source` — an unbounded
9//! aggregate working set under concurrent scan/compaction load (the #2600/#2367
10//! backpressure gap; the field signal was ~80 producer threads live at once).
11//!
12//! ## `per_source` — the ONE quantity every aggregate here multiplies (#2820)
13//!
14//! Every figure below is a PRODUCT of a per-source row bound, so it is stated in
15//! terms of that quantity rather than a literal — the literals moved once
16//! already. Since #2820 an egress channel carries BATCHES, and three populations
17//! coexist at one instant (channel-resident, consumer-held, and the batch a
18//! producer is PARKED holding in `send`), so:
19//!
20//! ```text
21//! per_source = egress_batch::max_inflight_rows(cap_per_channel)
22//!            = (msg_cap + 2) × batch_ceiling
23//!            = 4 × cap_per_channel        (at every reachable setting)
24//! ```
25//!
26//! of which `egress_batch::rows_resident_in_channel(cap_per_channel)` =
27//! `2 × cap_per_channel` is the strictly smaller half the #2419 depth gauge can
28//! observe, and a cold-started producer parks holding less again
29//! (`egress_batch::rows_in_full_channel(cap) + batch_ceiling + 1`, the ramp sum).
30//!
31//! The pre-#2820 per-source figure was `cap_per_channel` ITSELF (one row per
32//! channel slot), so **every product in this module is 4× what the same sentence
33//! said before #2820**. That 4× is the envelope of record for #2820 — the
34//! reconciliation that makes a ~256× reduction in cross-thread sends safe — not
35//! an accidental regression, and it is measured, not argued (dhat peak FELL
36//! against the pre-change baseline, because batching also shortens the interval
37//! over which a producer holds rows at all). Two substitutions to refuse:
38//! putting the channel-resident figure in for `per_source` understates the
39//! MEMORY bound 2×, and putting `cap_per_channel` in understates it 4× — which
40//! is exactly how the four aggregate sentences below went stale.
41//!
42//! ## The unit is a MERGE, not a source channel
43//!
44//! The count keyed here is **concurrent k-way MERGE operations**, incremented
45//! exactly ONCE per merge — when a [`KWayMerger`](super::KWayMerger) is
46//! constructed — NOT once per source channel. (An earlier revision counted per
47//! source adapter, so a solo `K`-way compaction registered `K` "merges" and its
48//! own later source channels shrank below 256 — violating the "a single merge is
49//! unchanged = 256 per source" contract regardless of `K`. Keying per merge
50//! fixes that.) This is also why the count deliberately differs from
51//! [`producer_gauge`](super::producer_gauge)'s `LIVE`, which counts per-SOURCE
52//! producer THREADS (`O(K × active_merges)`): that gauge answers "how many
53//! producer threads exist"; this counter answers "how many merge operations are
54//! competing for the egress budget".
55//!
56//! ## Capacity snapshot
57//!
58//! At merge construction the active-merge count is incremented ONCE (via
59//! [`begin_merge`], returning an [`ActiveMergeGuard`] stored on the
60//! `KWayMerger`, decremented exactly once when the whole merge is dropped — even
61//! on panic/early-return) and a single per-channel capacity is snapshotted:
62//!
63//! ```text
64//! cap_per_channel = clamp(EGRESS_ROW_BUDGET / active_merge_count, MIN_CAP, MAX_CAP)
65//! ```
66//!
67//! ALL `K` source channels of that merge use the SAME snapshot. So a SOLO merge
68//! (active = 1) gives 256 per source for ANY `K` (single-merge behavior
69//! unchanged); the cap shrinks only as CONCURRENT merges rise.
70//!
71//! ## Honest bound (NOT a strict global `≤ EGRESS_ROW_BUDGET`)
72//!
73//! [`EGRESS_ROW_BUDGET`] is a per-ACTIVE-MERGE-SLOT budget, not a hard global
74//! ceiling. Because every source channel of a merge gets `cap_per_channel`, the
75//! honest worst-case global working set is
76//!
77//! ```text
78//! working_set ≈ active_merges × K × per_source
79//!             = active_merges × K × max_inflight_rows(cap_per_channel)
80//!             = 4 × active_merges × K × cap_per_channel
81//! ```
82//!
83//! which for `active_merges ≥ EGRESS_ROW_BUDGET / MAX_CAP` is `≈ 4 × K × budget`
84//! (the `/active` division cancels the outer `active` factor down to ONE budget
85//! per source-fanout, and `per_source` keeps its 4×), and is floored by
86//! `active_merges × K × max_inflight_rows(MIN_CAP)` = `4 × active_merges × K ×
87//! MIN_CAP` — the deliberate cost of the forward-progress floor. Of that working
88//! set, half is channel-RESIDENT (`2 ×` rather than `4 ×`); the other half is the
89//! consumer-held and producer-parked batches, which are just as real to the
90//! allocator and so belong in a MEMORY figure. The win vs. the fixed cap is
91//! unchanged and is the removal of the per-source CONSTANT: `per_source` is a
92//! multiple of `cap_per_channel` at every setting, so caps fall toward
93//! [`MIN_CAP`] as concurrency climbs instead of every channel holding a fixed
94//! `MAX_CAP` worth. Do NOT read this as a strict `≤ EGRESS_ROW_BUDGET` global
95//! bound — it never was one, and since #2820 it is 4× further from one.
96//!
97//! Residual K-linear dimension: the budget divides by merge COUNT only, never by
98//! per-merge fanout `K`, so a SINGLE wide merge still buffers up to
99//! `K × max_inflight_rows(MAX_CAP)` = `4 × K × MAX_CAP` entries invariant to
100//! concurrency — intended (the owner's "a solo merge is unchanged for any `K`"
101//! contract), and 4× the pre-#2820 `K × MAX_CAP`, so the ~60 MB this doc used to
102//! quote at `K = 100` is ~240 MB at the same ~2.4 KB/row. For any row shape fat
103//! enough to matter the BYTE budget binds first and is the figure to reason with:
104//! `K × egress_batch::max_inflight_bytes(cap, max_row_bytes)` =
105//! `4 × K × (BATCH_EMIT_BYTES_MERGE + max_row_bytes)`, ≈ 4 MiB per source. Both
106//! are worst-case row bounds against a STALLED consumer, not steady state. The
107//! high-`K` envelope is validated by the #2895 loadgen sweep (deferred
108//! follow-up).
109//!
110//! The snapshot is taken ONCE at construction and never revised, so it is
111//! order-dependent, not fair: a long-lived merge that starts during a burst
112//! stays PINNED at its low snapshot cap for its entire life, even after the
113//! burst clears and concurrency drops back to one. Conversely a merge that
114//! starts while the process is idle keeps the full 256 per channel even as later
115//! merges arriving during ITS lifetime are squeezed toward [`MIN_CAP`] — the
116//! throttle falls on the newcomers, not the incumbent.
117//!
118//! ## Operator knobs
119//!
120//! Both bounds are runtime-overridable env knobs (parsed ONCE per process — see
121//! [`resolved`] — never on the per-merge hot path), defaulting to the shipped
122//! values so behavior is unchanged when unset:
123//!
124//! * `CQLITE_EGRESS_ROW_BUDGET` → [`EGRESS_ROW_BUDGET`] (default `2048`): the
125//!   per-active-merge-slot budget divided among a merge's channels.
126//! * `CQLITE_EGRESS_MIN_CAP` → [`MIN_CAP`] (default `8`): the forward-progress
127//!   floor, clamped to `[1, MAX_CAP]`; the budget is forced `≥ min_cap`.
128//!
129//! A missing/unparseable/zero value falls back to the default (never panics).
130//!
131//! ## AC#3 grounding (throughput evidence) — NOT "gap closed"
132//!
133//! With the DEFAULT budget `2048` / `MAX_CAP` `256` the throttle is INERT at ≤ 8
134//! concurrent merges (`2048 / 8 = 256`, i.e. the cap stays at the pre-change
135//! 256): it ENGAGES (per-channel cap falls below 256) only ABOVE 8 concurrent
136//! merges, and the [`MIN_CAP`] floor only at `budget / min_cap` ≈ 256 concurrent
137//! merges. So this change does NOT by itself "close" the #2600/#2367
138//! backpressure gap — it installs the MECHANISM (and the operator knobs to tune
139//! it); whether the DEFAULT bounds are the right ones at field concurrency is
140//! validated/tuned by the **#2895** flight-loadgen sweep (deferred follow-up).
141//!
142//! The reverted `STREAMING_CHANNEL_CAPACITY = 32` experiment in #2765 measured
143//! the egress-channel depth SHRINKING at FLAT qps and p99 — i.e. the buffering
144//! was slack, not a throughput floor, so bounding it does not cost throughput at
145//! the concurrency levels tested.
146//!
147//! This budget is ORTHOGONAL to the #2419 `channel_depth` gauge: that gauge
148//! observes live occupancy; this bounds the per-channel capacity ceiling. Kept
149//! out of `merge/mod.rs` to bound that file.

156/// DEFAULT per-active-merge-SLOT egress budget in prefetched `MergeEntry` values
157/// (issue #2765) — overridable at runtime by [`BUDGET_ENV`]. The per-channel
158/// capacity a merge receives is `budget / active_merges` (clamped). Chosen so
159/// that at the pre-change fixed capacity of 256 the budget is fully consumed by
160/// ~8 concurrent merges; beyond that, per-channel capacity shrinks (down to
161/// [`MIN_CAP`]) instead of every channel holding a fixed 256. See the module doc
162/// for why this is a per-slot budget, NOT a strict global ceiling — and for
163/// `per_source`, the quantity a solo merge's footprint actually multiplies:
164/// `K × per_source` = `4 × K × MAX_CAP` rows since #2820, NOT `K × 256`. The
165/// module doc carries the one derivation and the one per-row constant; do not
166/// re-derive a second here, which is how these two figures drifted apart in the
167/// first place. For a fat-row workload the BYTE term
168/// (`egress_batch::max_inflight_bytes`, ≈4 MiB/source) binds first, and the
169/// high-`K` envelope is #2895's to validate.
170pub(super) const EGRESS_ROW_BUDGET: usize = 2048;
171
172/// DEFAULT minimum per-channel capacity (issue #2765) — overridable at runtime
173/// by [`MIN_CAP_ENV`]. Guarantees forward progress: no matter how many merges
174/// are concurrently active, every producer can always place at least this many
175/// entries, so a bounded `sync_channel` can never be constructed with capacity 0
176/// (which would wedge the producer on its first `send`). Kept ≥ 1 by
177/// construction, in both the default and the resolved-override path.
178pub(super) const MIN_CAP: usize = 8;
179
180/// Maximum per-channel capacity — the unchanged single-merge value
181/// (`STREAMING_CHANNEL_CAPACITY` in `merge/mod.rs`). At LOW concurrency the cap
182/// clamps up to this, so single-merge behavior is byte-for-byte unchanged. NOT
183/// operator-overridable (it is the memory-bounded ceiling of one channel).
184pub(super) const MAX_CAP: usize = super::STREAMING_CHANNEL_CAPACITY;
185
186/// Operator env knob overriding [`EGRESS_ROW_BUDGET`] (issue #2765). Parsed ONCE
187/// per process (see [`resolved`]); a missing/unparseable/zero value falls back
188/// to the default, and the result is clamped `≥ resolved MIN_CAP`.
189const BUDGET_ENV: &str = "CQLITE_EGRESS_ROW_BUDGET";
190
191/// Operator env knob overriding [`MIN_CAP`] (issue #2765). Parsed ONCE per
192/// process; a missing/unparseable/zero value falls back to the default, and the
193/// result is clamped to `[1, MAX_CAP]` (the ≥1 forward-progress invariant).
194const MIN_CAP_ENV: &str = "CQLITE_EGRESS_MIN_CAP";
195
196/// The resolved `(budget, min_cap)` pair, read from the environment ONCE per
197/// process into a `OnceLock` (mirroring `select_executor::forcing`'s cached-env
198/// pattern) so env parsing is OFF the per-merge hot path. Every `capacity_for`
199/// call reads this cached tuple, never `std::env`.
200fn resolved() -> (usize, usize) {
201    static RESOLVED: OnceLock<(usize, usize)> = OnceLock::new();
202    *RESOLVED.get_or_init(|| {
203        let (budget, min_cap) = resolve_budget(
204            std::env::var(BUDGET_ENV).ok().as_deref(),
205            std::env::var(MIN_CAP_ENV).ok().as_deref(),
206        );
207        // One-time operator signal (issue #2765): warn on the two inert-throttle
208        // configs this predicate covers — the floor meets the ceiling
209        // (`min_cap >= MAX_CAP`, so every channel is 256 at any concurrency) or
210        // the range is degenerate (`budget < 2 × min_cap`, i.e. `budget / min_cap
211        // <= 1`, so the cap is pinned at `min_cap` regardless of concurrency).
212        // NOTE: this does NOT cover a very LARGE budget (e.g. 1_000_000), where
213        // caps stay at 256 until ~`budget / MAX_CAP` concurrent merges with no
214        // warn — that direction is intentionally un-warned here (no behavior
215        // change). Runs once (OnceLock init).
216        if min_cap >= MAX_CAP || budget / min_cap <= 1 {
217            tracing::warn!(
218                budget,
219                min_cap,
220                max_cap = MAX_CAP,
221                "{BUDGET_ENV}/{MIN_CAP_ENV} leave the adaptive merge egress \
222                 throttle INERT (per-channel capacity does not shrink with \
223                 concurrency); see cqlite.merge.active_merges / #2765"
224            );
225        }
226        (budget, min_cap)
227    })
228}

230/// Pure resolver over the two raw env values (injectable seam for tests — the
231/// #2451-safe alternative to mutating real process env in a shared-binary test).
232/// Validates/clamps defensively and NEVER panics: a `None`/unparseable/zero
233/// value falls back to the default; `min_cap` is clamped to `[1, MAX_CAP]` (the
234/// forward-progress invariant) and `budget` to `≥ min_cap` (so `budget/1` can
235/// never fall below the floor). Returns `(budget, min_cap)`.
236fn resolve_budget(env_budget: Option<&str>, env_min_cap: Option<&str>) -> (usize, usize) {
237    let parse = |raw: Option<&str>| {
238        raw.and_then(|s| s.trim().parse::<usize>().ok())
239            .filter(|&v| v > 0)
240    };
241    let min_cap = parse(env_min_cap).unwrap_or(MIN_CAP).clamp(1, MAX_CAP);
242    let budget = parse(env_budget).unwrap_or(EGRESS_ROW_BUDGET).max(min_cap);
243    (budget, min_cap)
244}

246/// Process-global live count of in-flight streaming merges. Incremented by
247/// [`begin_merge`] when a merge's egress channel is constructed and decremented
248/// by [`ActiveMergeGuard`]'s drop when that merge finishes (or is torn down).
249static ACTIVE: AtomicUsize = AtomicUsize::new(0);
250
251/// Record the operator-facing `cqlite.merge.active_merges` gauge (issue #2765),
252/// mirroring the `producer_gauge::record` pattern: publish the post-transition
253/// `level` the caller already computed from its own `fetch_add`/`fetch_sub`.
254///
255/// The gauge is EVENTUALLY-CONSISTENT, not strictly synchronized: the atomic
256/// update and this record are two separate steps, so two concurrent transitions
257/// can publish out of order and the gauge may briefly show a stale level until
258/// the NEXT begin/drop re-publishes — the same lock-free convention as
259/// `producer_gauge`. A lock/seqlock would be overkill for a diagnostic gauge.
260fn record_active(level: usize) {
261    observability::record_gauge(
262        observability::catalog::MERGE_ACTIVE_MERGES,
263        level as i64,
264        &[],
265    );
266}

268/// Current live process-global active-merge count (test/observability hook —
269/// mirrors the [`MERGE_ACTIVE_MERGES`](crate::observability::catalog::MERGE_ACTIVE_MERGES)
270/// gauge, exposed to integration tests via `merge::active_merge_count`).
271pub(super) fn active_count() -> usize {
272    ACTIVE.load(Ordering::SeqCst)
273}

275/// Resolve the per-merge channel capacity for a given live active-merge count,
276/// using the runtime-[`resolved`] `(budget, min_cap)` (env-overridable).
277///
278/// `clamp(budget / active, min_cap, MAX_CAP)`. `active` is floored at 1 (via
279/// [`usize::max`]) so the division is always well-defined and the result is
280/// never 0 — combined with the `min_cap ≥ 1` clamp this is doubly safe against a
281/// zero-capacity channel.
282pub(super) fn capacity_for(active: usize) -> usize {
283    let (budget, min_cap) = resolved();
284    capacity_from(active, budget, min_cap)
285}
286
287/// The pure `clamp(budget / active, min_cap, MAX_CAP)` kernel — shared by
288/// [`capacity_for`] (resolved values) and the override test (injected values).
289/// `min_cap ≤ MAX_CAP` is guaranteed by [`resolve_budget`], so the clamp bounds
290/// are always valid.
291fn capacity_from(active: usize, budget: usize, min_cap: usize) -> usize {
292    let active = active.max(1);
293    (budget / active).clamp(min_cap, MAX_CAP)
294}

311/// Register a starting k-way MERGE (called ONCE per merge, at `KWayMerger`
312/// construction — NOT per source channel) and return the per-channel capacity
313/// ALL its source channels share, together with the RAII [`ActiveMergeGuard`]
314/// that decrements the live count once when the whole merge is dropped.
315///
316/// The active count is incremented FIRST, then the capacity is computed from the
317/// post-increment count, so the current merge counts itself: `N` merges each
318/// starting when `N` are active observe `active >= N` and receive `budget / N`
319/// per channel. The returned guard MUST be stored for the merge's lifetime (on
320/// the `KWayMerger`, dropped AFTER its runs/channels) so exactly one decrement
321/// pairs with this increment on every exit path.
322///
323/// Always targets the process-global [`ACTIVE`] and always publishes the gauge —
324/// no injectable atomic and no `record` branch on this hot path (the per-test
325/// private-atomic seam is the `#[cfg(test)]`-only [`begin_on_for_test`]).
326#[must_use]
327pub(super) fn begin_merge() -> (usize, ActiveMergeGuard) {
328    let active = ACTIVE.fetch_add(1, Ordering::SeqCst) + 1;
329    record_active(active);
330    (capacity_for(active), ActiveMergeGuard)
331}
332
333/// RAII guard that decrements the process-global active-merge count (and
334/// re-publishes the gauge) when a streaming merge finishes — on normal
335/// completion, early return, or panic. Stored on the `KWayMerger` (dropped after
336/// its runs/channels) so exactly one decrement pairs with the merge's single
337/// [`begin_merge`] increment.
338#[derive(Debug)]
339pub(super) struct ActiveMergeGuard;
340
341impl Drop for ActiveMergeGuard {
342    fn drop(&mut self) {
343        let level = ACTIVE.fetch_sub(1, Ordering::SeqCst) - 1;
344        record_active(level);
345    }
346}

348/// Test-only injectable seam: run the EXACT increment/capacity/guard-drop pairing
349/// [`begin_merge`] uses, but against a PRIVATE `&'static AtomicUsize` (a
350/// `Box::leak`ed per-test counter) and WITHOUT touching the process-global gauge
351/// — so a test can drive deterministic concurrency without racing the shared
352/// [`ACTIVE`] or publishing a bogus `cqlite.merge.active_merges` level (#2451
353/// isolation). The returned guard decrements that private counter on drop.
354#[cfg(test)]
355pub(super) fn begin_on_for_test(counter: &'static AtomicUsize) -> (usize, TestMergeGuard) {
356    let active = counter.fetch_add(1, Ordering::SeqCst) + 1;
357    (capacity_for(active), TestMergeGuard { counter })
358}

375impl super::KWayMerger {
376    /// Attach the adaptive egress-budget slot guard (issue #2765) to a merger
377    /// whose source channels were opened OUTSIDE its constructor — the point-read
378    /// builders (`build_single_partition_merger*`) open their fail-safe adapters,
379    /// with the shared capacity snapshot, before calling `from_row_iterators`,
380    /// then move the matching guard onto the built merger here so it decrements
381    /// exactly once at merge end. See [`begin_merge`].
382    ///
383    /// Takes the guard BY VALUE (not `Option`), so it is impossible to call this
384    /// with `None` and silently un-register a live merge; the `debug_assert`
385    /// additionally catches a double-attach that would drop a still-live guard
386    /// early and under-count concurrency. Kept in this sibling module (not
387    /// `merge/mod.rs`) to bound that over-threshold file (#1116). `pub(super)`
388    /// (matching [`ActiveMergeGuard`]'s visibility) — uncallable outside `merge`.
389    #[must_use]
390    pub(super) fn with_egress_slot(mut self, egress_slot: ActiveMergeGuard) -> Self {
391        debug_assert!(
392            self._egress_slot.is_none(),
393            "with_egress_slot must not overwrite a live active-merge slot"
394        );
395        self._egress_slot = Some(egress_slot);
396        self
397    }
398}

423    /// Evaluate the capacity kernel against the SHIPPED DEFAULTS, bypassing the
424    /// env-reading `capacity_for` — so exporting `CQLITE_EGRESS_*` (an operator
425    /// knob this change added) can never break these compile-time-constant
426    /// assertions. The env plumbing itself is covered by
427    /// `env_knobs_resolve_validate_and_drive_capacity`.
428    fn cap_default(active: usize) -> usize {
429        capacity_from(active, EGRESS_ROW_BUDGET, MIN_CAP)
430    }

432    #[test]
433    fn low_concurrency_resolves_to_max_cap() {
434        // Criterion 1: a single active merge gets the unchanged 256 cap.
435        assert_eq!(cap_default(1), MAX_CAP);
436        assert_eq!(MAX_CAP, 256);
437        // Zero active (defensive) is floored to 1 → MAX_CAP, never a div-by-zero.
438        assert_eq!(cap_default(0), MAX_CAP);
439    }

441    #[test]
442    fn env_knobs_resolve_validate_and_drive_capacity() {
443        // Inject via the PURE seam (`resolve_budget`), never real process env, so
444        // this cannot perturb the OnceLock other tests observe (#2451-safe).
445        // Unset → the shipped defaults (behavior unchanged when the knobs absent).
446        assert_eq!(resolve_budget(None, None), (EGRESS_ROW_BUDGET, MIN_CAP));
447
448        // A clean override flows through the SAME clamp kernel `capacity_for` uses.
449        let (budget, min_cap) = resolve_budget(Some("4096"), Some("16"));
450        assert_eq!((budget, min_cap), (4096, 16));
451        assert_eq!(capacity_from(1, budget, min_cap), MAX_CAP); // 4096 clamps to 256
452        assert_eq!(capacity_from(16, budget, min_cap), 256); // 4096/16 = 256
453        assert_eq!(capacity_from(4096, budget, min_cap), 16); // floors at the raised min_cap
454
455        // Defensive: missing / unparseable / zero each fall back to the default,
456        // never a panic.
457        assert_eq!(
458            resolve_budget(Some(""), Some("nope")),
459            (EGRESS_ROW_BUDGET, MIN_CAP)
460        );
461        assert_eq!(
462            resolve_budget(Some("0"), Some("0")),
463            (EGRESS_ROW_BUDGET, MIN_CAP)
464        );
465        assert_eq!(resolve_budget(Some("  1024  "), None), (1024, MIN_CAP)); // trims
466
467        // Invariants: min_cap clamped to [1, MAX_CAP]; budget forced ≥ min_cap so
468        // `budget/1` can never dip under the forward-progress floor.
469        let (b, m) = resolve_budget(Some("10"), Some("100000"));

472        assert!(m >= 1, "forward-progress floor: min_cap ≥ 1");
473        assert!(
474            capacity_from(usize::MAX, b, m) >= 1,
475            "never a zero-capacity channel"
476        );

489    #[test]
490    fn per_slot_bound_holds_and_min_cap_floor_is_honest() {
491        // The per-ACTIVE-MERGE-SLOT invariant (see module doc "Honest bound"):
492        // at any concurrency `a`, one merge's per-channel share `cap_default(a)`
493        // times `a` stays within the budget — whereas the pre-change fixed cap
494        // of 256 gives `a × 256`, blowing past the budget for a > 8 (a == 8
495        // exactly saturates it: 8 × 256 == 2048). Beyond the clamp point the
496        // per-slot product is BELOW budget because the cap floors at MIN_CAP —
497        // the deliberate, explicit cost of guaranteeing forward progress.
498        //
499        // Low #6: exercise BOTH the divide region AND the MIN_CAP-floor region so
500        // the floor's cost (per-slot product falling under budget) is explicit.
501        let clamp_point = EGRESS_ROW_BUDGET / MAX_CAP; // 8: highest `a` with cap==MAX_CAP
502        let floor_point = EGRESS_ROW_BUDGET / MIN_CAP; // 256: lowest `a` with cap==MIN_CAP
503        assert!(floor_point > clamp_point);
504        for a in 1..=(floor_point + 64) {
505            let cap = cap_default(a);
506            assert!((MIN_CAP..=MAX_CAP).contains(&cap), "cap {cap} within clamp");
507            // Per-slot product never exceeds the budget.
508            assert!(
509                a * cap <= EGRESS_ROW_BUDGET || cap == MIN_CAP,
510                "per-slot product {} must stay within budget at a={a}",
511                a * cap
512            );
513            if a > clamp_point {
514                assert!(
515                    a * MAX_CAP > EGRESS_ROW_BUDGET,
516                    "pre-change fixed cap {MAX_CAP} × {a} exceeds budget"
517                );
518            }
519            if a >= floor_point {
520                // MIN_CAP-floor region: the cap has bottomed out; the per-slot
521                // product now GROWS as `a × MIN_CAP` — the forward-progress cost.
522                assert_eq!(cap, MIN_CAP, "cap floored at MIN_CAP for a={a}");
523                assert_eq!(a * cap, a * MIN_CAP);
524            }
525        }
526    }

528    #[test]
529    fn concurrent_begin_shrinks_per_channel_capacity() {
530        use std::sync::{Arc, Barrier};
531
532        // Drive `n` concurrent MERGE registrations through the SAME
533        // increment/snapshot logic `begin_merge` uses, via the test-only
534        // `begin_on_for_test` seam against a PRIVATE atomic (issue #2451
535        // isolation, mirroring the pairing test) so this test can
536        // NEVER inflate the shared global `ACTIVE` and shrink a parallel
537        // merger-building test's caps. Assert the per-channel capacity a merge is
538        // HANDED shrinks below the fixed 256 as concurrent merges rise — and
539        // never below the resolved floor. (KWayMerger-level end-to-end wiring, on
540        // the real global, lives in `egress_wiring_tests`.)
541        //
542        // `n` is sized from the RESOLVED budget (not a fixed 16): `begin_on_for_test`
543        // calls the env-resolved `capacity_for`, so under `CQLITE_EGRESS_ROW_BUDGET=8192`
544        // a fixed 16 would leave `8192/16 == 512` clamped back to 256 and never
545        // shrink. `budget/MAX_CAP + 8` makes the last-registering thread see
546        // `capacity_for(n) < MAX_CAP` for any realistic budget — but is CLAMPED to
547        // 64 so a pathological `CQLITE_EGRESS_ROW_BUDGET` can't spawn thousands of
548        // threads. If the clamp defeats the shrink precondition (a huge budget
549        // where even 64 concurrency stays at the 256 clamp), skip: the property is
550        // unobservable within a bounded workload, not violated.
551        // UNCONDITIONAL kernel-path proof (env-INDEPENDENT — uses the compile-time
552        // DEFAULT budget/floor via `capacity_from`): at the crossover concurrency
553        // the default kernel shrinks below the 256 ceiling. So even when the
554        // threaded phase below is skipped under a large env override, this test
555        // always proves the shrink math.
556        let default_crossover = EGRESS_ROW_BUDGET / MAX_CAP + 1;
557        assert!(
558            capacity_from(default_crossover, EGRESS_ROW_BUDGET, MIN_CAP) < MAX_CAP,
559            "default kernel must shrink below {MAX_CAP} at concurrency {default_crossover}"
560        );
561
562        let counter: &'static AtomicUsize = Box::leak(Box::new(AtomicUsize::new(0)));
563        let floor = min_cap();
564        let n = (budget() / MAX_CAP + 8).min(64);
565        if capacity_for(n) >= MAX_CAP {
566            eprintln!(
567                "SKIP: concurrent_begin_shrinks_per_channel_capacity — budget={} \
568                 min_cap={} defeats the bounded-workload shrink precondition \
569                 (clamp={n}); default kernel path asserted above",
570                budget(),
571                floor
572            );
573            return;
574        }
575        let registered = Arc::new(Barrier::new(n));
576        let released = Arc::new(Barrier::new(n));
577
578        let handles: Vec<_> = (0..n)
579            .map(|_| {
580                let registered = registered.clone();
581                let released = released.clone();
582                std::thread::spawn(move || {
583                    // Register FIRST (increments the PRIVATE count + snapshots the
584                    // cap), THEN barrier — so all `n` are counted before any reads;
585                    // the second barrier holds every guard alive until all have
586                    // observed, modelling `n` concurrent merges. `begin_on_for_test`
587                    // never publishes the global gauge (structural suppression).
588                    let (cap, _guard) = begin_on_for_test(counter);
589                    registered.wait();
590                    let live = counter.load(Ordering::SeqCst);
591                    released.wait();
592                    (live, cap)
593                })
594            })
595            .collect();
596
597        let results: Vec<(usize, usize)> = handles
598            .into_iter()
599            .map(|h| h.join().expect("merge thread joins"))
600            .collect();
601
602        // The private atomic is touched ONLY by this test's `n` threads, so the
603        // observed concurrency is EXACTLY `n` (deterministic, not `>=`).
604        let max_live = results.iter().map(|(l, _)| *l).max().unwrap_or(0);
605        assert_eq!(
606            max_live, n,
607            "private-atomic concurrency must be exactly {n}"
608        );
609        // The merges that registered while the count was already high got a
610        // capacity strictly below the pre-change fixed 256 — the shrink property.
611        let min_cap_seen = results.iter().map(|(_, c)| *c).min().unwrap_or(MAX_CAP);
612        assert!(
613            min_cap_seen < MAX_CAP,
614            "with {n} concurrent merges at least one per-channel cap must fall \
615             below {MAX_CAP} (min seen = {min_cap_seen})"
616        );
617        // Forward progress: no merge is ever handed a sub-floor capacity (uses the
618        // RESOLVED floor, so it holds under a `CQLITE_EGRESS_MIN_CAP` override).
619        for (_, cap) in &results {
620            assert!(
621                *cap >= floor,
622                "per-channel cap {cap} >= resolved floor {floor}"
623            );
624        }
625        // Every guard dropped on join → the private count returns to zero.
626        assert_eq!(
627            counter.load(Ordering::SeqCst),
628            0,
629            "no leak: all guards dropped"
630        );
631    }

633    #[test]
634    fn guard_increments_and_decrements_a_private_count() {
635        // Deterministic pairing test against a PRIVATE atomic (mirroring
636        // `channel_depth`'s per-test-atomic pattern): `begin_on_for_test`
637        // increments and the returned guard's drop decrements, so the count
638        // returns to baseline on every scope exit. A private atomic cannot be
639        // perturbed by the other tests in this binary that drive real merges
640        // through the shared global, and `begin_on_for_test` never publishes the
641        // process-global operator gauge (structural suppression).
642        let counter: &'static AtomicUsize = Box::leak(Box::new(AtomicUsize::new(0)));
643        assert_eq!(counter.load(Ordering::SeqCst), 0);
644        {
645            let (cap0, _g0) = begin_on_for_test(counter);
646            assert_eq!(counter.load(Ordering::SeqCst), 1);
647            assert_eq!(cap0, capacity_for(1), "first merge sees active=1");
648            {
649                let (cap1, _g1) = begin_on_for_test(counter);
650                assert_eq!(counter.load(Ordering::SeqCst), 2);
651                assert_eq!(cap1, capacity_for(2), "second merge sees active=2");
652            }
653            assert_eq!(
654                counter.load(Ordering::SeqCst),
655                1,
656                "inner guard drop decremented"
657            );
658        }
659        assert_eq!(
660            counter.load(Ordering::SeqCst),
661            0,
662            "outer guard drop returned to baseline (no leak on any exit path)"
663        );
664    }
