1//! Egress-channel-depth gauge for the k-way merge (issue #2419, WS2).
2//!
3//! Backs the [`crate::observability::catalog::MERGE_EGRESS_CHANNEL_DEPTH`] gauge
4//! with a process-global live count of merged DATA entries currently buffered in
5//! the bounded producer→consumer `sync_channel`. `std::sync::mpsc`'s
6//! `sync_channel` exposes no `len()`, so occupancy is tracked explicitly, exactly
7//! as the #2316 producer-thread gauge tracks live producer threads:
8//!
9//! * [`sent_n`] adds the entries of one successfully sent DATA BATCH
10//!   (`egress_batch::EgressBatcher::flush`).
11//! * [`received_n`] subtracts them when the consumer pulls that batch off the
12//!   channel (`SSTableRowIteratorAdapter::next`).
13//!
14//! # THE UNIT IS ENTRIES (rows), and issue #2820 did not change it
15//!
16//! The channel carries BATCHES since #2820 (one message per up to
17//! `egress_batch::BATCH_EMIT_ROWS_MERGE` rows, so its `sync_channel` capacity is
18//! in MESSAGES — `egress_budget`'s row budget converted by
19//! `egress_batch::message_capacity_for_rows`), but this gauge stays in ENTRIES on
20//! BOTH sides: a batch of `n` rows moves the level by `n`, never by 1. Counting
21//! messages on one side and entries on the other is precisely the invisible
22//! asymmetry documented below.
23//!
24//! # THIS gauge's ceiling is CHANNEL-RESIDENT rows, not the in-flight bound
25//!
26//! Because [`sent_n`] fires on a successful `send` and [`received_n`] on the
27//! consumer's `recv`, the level counts ONLY entries currently sitting in the
28//! channel — never the batch the consumer is handing out (already received) nor
29//! the batch a producer is PARKED holding (never sent). So the ceiling is
30//! `egress_batch::rows_resident_in_channel(rows_cap)` = `msg_cap × batch_ceiling`
31//! (512 rows at the shipped default), NOT
32//! `egress_batch::max_inflight_rows(rows_cap)` = `(msg_cap + 2) × batch_ceiling`
33//! (1024), which is the MEMORY bound and overstates what this gauge can reach by
34//! exactly two batches. Both scale with the #2765 adaptive row capacity since
35//! #2820 (`2 × rows_cap` and `4 × rows_cap`), so neither is a constant.
36//! * [`reconcile_residual`] (issue #2419 roborev job 1733) subtracts, in ONE
37//!   atomic op, any entries a producer sent but its consumer never received — a
38//!   cancelled/disconnected merge whose channel was torn down while entries were
39//!   still buffered (or racing the teardown). Called ONLY from
40//!   `SSTableRowIteratorAdapter::drop`, AFTER its producer thread has been
41//!   joined: reading a per-adapter sent/received delta BEFORE the join (or
42//!   trying to drain-then-decrement before dropping the receiver) races a
43//!   concurrently-running producer thread and can leak the gauge upward
44//!   permanently — see that `Drop` impl's doc for the full derivation.
45//!
46//! # THE invariant this module depends on (issue #3120)
47//!
48//! Only DATA entries (the rows of a `MergeMsg::Batch`) are tracked, and they are
49//! tracked on BOTH sides. The TERMINATORS (`MergeMsg::Failed` / `MergeMsg::Done`)
50//! are untracked on send AND on receive, so they can never unbalance the level.
51//! Formally, per adapter `A`, with `data(m)` = the number of DATA entries in `m`:
52//!
53//! ```text
54//! ∀ m:  counted_on_send(m) = counted_on_receive_or_residual(m) = data(m)
55//! and   sentA − recvA ≥ 0 at every join point
56//! ```
57//!
58//! An asymmetry here is INVISIBLE without help: a message counted on exactly one
59//! side drives the residual NEGATIVE, [`reconcile_residual`]'s `> 0` guard then
60//! SKIPS it, and [`record`]'s `max(0)` floor hides the resulting drift from every
61//! observer, permanently.
62//!
63//! ## What actually holds the invariant up (stated precisely — rust-reviewer)
64//!
65//! NOT "both sides call one shared predicate". They do not, and claiming they do
66//! would hide the real gap:
67//!
68//! * **Receive side** (`SSTableRowIteratorAdapter::next`) is a hand-written
69//!   `MergeMsg::Batch(entries)` match arm that never calls `tracked_entries`. Two
70//!   properties make it correct anyway: that `match` is **EXHAUSTIVE with no
71//!   wildcard arm**, so a future 4th `MergeMsg` variant is a COMPILE ERROR there
72//!   rather than silently falling into a catch-all; and [`received_n`] and
73//!   `received_count` each appear at EXACTLY ONE site in the crate, both inside
74//!   that `Batch` arm, and both are passed the SAME `entries.len()` (issue #2820:
75//!   the arm decrements by the batch length, so a batch counted as ONE message
76//!   here against `n` entries on send would drive the residual negative — the
77//!   defect this section exists for).
78//! * **Send side** (`egress_batch::EgressBatcher::flush`) builds
79//!   `MergeMsg::Batch(batch)` unconditionally, so its `msg.tracked_entries()` is a
80//!   TAUTOLOGY today — it can only be the batch length. Its value is as a
81//!   compile-time tripwire, not a runtime test: `MergeMsg::tracked_entries`'s body
82//!   is itself an exhaustive match, so adding a variant forces an explicit
83//!   tracked/untracked decision there.
84//! * The `channel_depth` test below pins `tracked_entries`'s CLASSIFICATION (that
85//!   a batch counts per ENTRY and both terminators are untracked). It cannot — and
86//!   does not claim to — detect a divergence at the hand-written receive site.
87//! * [`reconcile_residual`] checks `residual >= 0` at the one place a violation
88//!   becomes observable, reporting it WITHOUT panicking from a `Drop` (see that
89//!   function).
90//!
91//! The `max(0)` floor stays (it matches `RpcMetrics::finish`) as the last-resort
92//! backstop so no negative gauge is ever recorded.
93//!
94//! The gauge is OS-independent — it always emits on every platform (unlike the
95//! `/proc`-derived `cqlite.proc.*` saturation gauges).
96
97use std::sync::atomic::{AtomicI64, Ordering};

101static DEPTH: AtomicI64 = AtomicI64::new(0);
102
103fn record(level: i64) {
104    observability::record_gauge(
105        observability::catalog::MERGE_EGRESS_CHANNEL_DEPTH,
106        // Floor at 0 so an unexpected imbalance never records a negative gauge
107        // (matches `RpcMetrics::finish`).
108        level.max(0),
109        &[],
110    );
111}
112
113/// Apply `delta` to `atomic` and return the resulting level — the exact
114/// arithmetic [`sent_n`], [`received_n`], and [`reconcile_residual`] apply to the
115/// shared [`DEPTH`]. Parameterized over the atomic (issue #2419 roborev job
116/// 1733, the #2451 flake class) so a test can pin this SAME logic against a
117/// private, per-test atomic instead of racing every other concurrently-running
118/// test that also drives a real merge egress channel through the shared global.
119fn adjust(atomic: &AtomicI64, delta: i64) -> i64 {
120    atomic.fetch_add(delta, Ordering::SeqCst) + delta
121}
122
123/// Account the `entries` DATA rows of one BATCH that was just successfully sent
124/// into the bounded egress channel (issue #2820 — the gauge's unit is ENTRIES,
125/// not messages; see the module doc). Balanced by exactly one [`received_n`] of
126/// the same count or, for entries a consumer never pulled, by
127/// [`reconcile_residual`] post-join.
128///
129/// `entries` is `MergeMsg::tracked_entries()` of the message actually sent, so a
130/// terminator (0) is a no-op by construction rather than by a caller's judgement.
131pub(super) fn sent_n(entries: usize) {
132    record(adjust(&DEPTH, entries as i64));
133}
134
135/// Account the `entries` DATA rows of one BATCH just received (pulled off the
136/// channel) by the consumer, decrementing the live occupancy by the same count
137/// its send incremented it.
138pub(super) fn received_n(entries: usize) {
139    record(adjust(&DEPTH, -(entries as i64)));
140}
141
142/// Subtract `residual` DATA entries from the shared depth in ONE atomic op
143/// (issue #2419 roborev job 1733) — the post-join reconcile for entries a
144/// producer sent but its consumer never received. A no-op for `residual <= 0`
145/// (the common case: every send was received). See the module doc for why this
146/// must run only after the producer thread has been joined.
147///
148/// # A NEGATIVE residual is reported, never panicked out of a `Drop`
149///
150/// A negative residual means the tracked-send and tracked-receive sites disagreed
151/// (e.g. a terminator counted on exactly one side). The `> 0` guard below would
152/// silently skip it and [`record`]'s `max(0)` floor would hide the drift forever,
153/// so it must be reported — but this function's ONLY production caller is
154/// `SSTableRowIteratorAdapter::drop`, so 100% of its reachable paths are inside a
155/// `Drop` (rust-reviewer, issue #3120). A bare `debug_assert!` there would panic
156/// FROM a `Drop`: any test that fails an assertion with a live `KWayMerger` in
157/// scope drops the adapter while ALREADY UNWINDING → double panic → process
158/// ABORT, which under libtest destroys the original assertion message and every
159/// sibling test's result in the binary. `teardown_tests` drops mergers on purpose,
160/// so this is not hypothetical.
161///
162/// Hence the same idiom `producer_fault::SilencedInjectedPanics::drop` uses for
163/// `set_hook`: skip the panicking route while unwinding. The `tracing::error!`
164/// runs unconditionally, so the signal also exists in a release build (where
165/// `debug_assert!` compiles away entirely).
166///
167/// The invariant itself genuinely holds: every tracked receive is preceded by the
168/// tracked send of that same entry, and the caller reads `sent_count` strictly
169/// AFTER `join()`, which retires every pending `fetch_add`.
170pub(super) fn reconcile_residual(residual: i64) {
171    if residual < 0 {
172        tracing::error!(
173            residual,
174            "egress-depth residual is NEGATIVE: a tracked receive without a matching \
175             tracked send means the send and receive accounting sites disagree — the \
176             `> 0` guard below and `record`'s `max(0)` floor would otherwise hide \
177             this drift permanently (issue #3120)"
178        );
179        // Reaching here at all is the violation, so the assert's condition is
180        // deliberately "…and we are not ALREADY unwinding": it fails loudly on a
181        // normal drop (the signal we want) and stays silent when this `Drop` is
182        // itself running during someone else's panic, where a second panic would
183        // abort the process and take the original failure message with it.
184        debug_assert!(
185            std::thread::panicking(),
186            "egress-depth residual must never be negative (got {residual}): the \
187             send and receive accounting sites disagree — see this module's \
188             invariant (issue #3120)"
189        );
190    }
191    if residual > 0 {
192        record(adjust(&DEPTH, -residual));
193    }
194}

200    /// Producer-fast / consumer-slow harness against the tracked
201    /// send/recv/reconcile arithmetic (issue #2419, spec scenario "Depth rises
202    /// when the consumer is slower than the producer"): the depth climbs above
203    /// zero while sends outrun receives, stays bounded by the notional channel
204    /// capacity, and returns to exactly zero once every send is balanced by a
205    /// receive.
206    ///
207    /// Roborev job 1733 (the #2451 flake class): this now runs against a
208    /// PRIVATE, per-test `AtomicI64` via [`adjust`] — the exact same arithmetic
209    /// [`sent_n`]/[`received_n`] apply to the shared [`DEPTH`] — rather than the
210    /// process-global atomic. The prior version drove `DEPTH` directly, so any
211    /// concurrently-running test in this binary that ALSO exercises a real merge
212    /// egress channel (elsewhere in the crate) could perturb the shared level
213    /// mid-window, flaking this test's exact-equality assertions. A local atomic
214    /// makes the pin fully deterministic: no other test can ever touch it.
215    #[test]
216    fn depth_rises_while_backed_up_and_returns_to_baseline() {
217        let local = AtomicI64::new(0);
218        // The notional per-source CHANNEL-RESIDENT ROW ceiling: issue #2820 made
219        // the channel carry BATCHES, so the bound this gauge can reach is
220        // `rows_resident_in_channel(rows_cap)` — NOT `max_inflight_rows`, which
221        // adds the consumer-held and producer-parked batches this gauge counts on
222        // neither side. Derived from the shipped constants rather than the
223        // pre-batching flat 256.
224        let cap = super::super::egress_batch::rows_resident_in_channel(
225            super::super::STREAMING_CHANNEL_CAPACITY,
226        ) as i64;
227
228        // Producer races ahead in BATCHES (the ramp saturates at this run's
229        // ceiling), filling toward the bounded capacity.
230        let batch = super::super::egress_batch::batch_limit_ceiling(
231            super::super::STREAMING_CHANNEL_CAPACITY,
232        ) as i64;
233        let mut filled = 0;
234        while filled < cap {
235            let rows = batch.min(cap - filled);
236            adjust(&local, rows);
237            filled += rows;
238        }
239        let backed_up = local.load(Ordering::SeqCst);
240        assert!(
241            backed_up > 0,
242            "depth must rise above zero while the producer outruns the consumer \
243             (backed_up={backed_up})"
244        );
245        assert!(
246            backed_up <= cap,
247            "tracked depth must stay bounded by the resident-rows bound \
248             (backed_up={backed_up}, cap={cap})"
249        );
250
251        // Consumer drains every entry, one batch at a time.
252        let mut drained = 0;
253        while drained < cap {
254            let rows = batch.min(cap - drained);
255            adjust(&local, -rows);
256            drained += rows;
257        }
258        assert_eq!(
259            local.load(Ordering::SeqCst),
260            0,
261            "after draining every entry the depth returns to exactly zero \
262             (every tracked send balanced by exactly one tracked receive)"
263        );
264    }

266    /// [`reconcile_residual`] subtracts a positive residual in one op and is a
267    /// no-op for `<= 0` — pinned against a private atomic for the same
268    /// determinism reason as the scenario test above.
269    #[test]
270    fn reconcile_residual_subtracts_positive_and_ignores_non_positive() {
271        let local = AtomicI64::new(10);
272        // Mirror `reconcile_residual`'s logic directly against the local atomic
273        // (the public function only targets the shared `DEPTH`).
274        let residual = 4;
275        if residual > 0 {
276            adjust(&local, -residual);
277        }
278        assert_eq!(local.load(Ordering::SeqCst), 6);
279
280        let before = local.load(Ordering::SeqCst);
281        for non_positive in [0, -3] {
282            if non_positive > 0 {
283                adjust(&local, -non_positive);
284            }
285        }
286        assert_eq!(
287            local.load(Ordering::SeqCst),
288            before,
289            "a non-positive residual must never adjust the level"
290        );
291    }

293    /// Pins the ACTUAL fix (issue #2419 roborev job 1733): a send that races
294    /// teardown — landing AFTER the point a pre-fix drain-until-`Empty` loop
295    /// would already have stopped looking — is still fully reconciled, because
296    /// the reconcile now runs from an authoritative post-join sent/received
297    /// DELTA computed once the producer thread is provably done, never a live
298    /// drain-then-drop race. Modeled deterministically against a private atomic
299    /// (never the shared `DEPTH`, for the same reason as the tests above): the
300    /// arithmetic mirrors exactly what `sent`/`received`/`reconcile_residual`
301    /// apply, and what `SSTableRowIteratorAdapter::drop` does with its own
302    /// `sent_count`/`received_count` fields.
303    #[test]
304    fn reconcile_after_join_absorbs_a_send_that_raced_teardown() {
305        let depth = AtomicI64::new(0);
306        let baseline = depth.load(Ordering::SeqCst);
307
308        // Normal traffic: three entries sent and received, balanced.
309        let mut sent_count: i64 = 0;
310        let mut received_count: i64 = 0;
311        for _ in 0..3 {
312            adjust(&depth, 1);
313            sent_count += 1;
314            adjust(&depth, -1);
315            received_count += 1;
316        }
317        assert_eq!(depth.load(Ordering::SeqCst), baseline);
318
319        // Teardown begins (cancel tripped, receiver about to be torn down).
320        // Model the exact race this fix addresses: the producer thread, still
321        // alive, gets ONE more send through — precisely the send a
322        // drain-until-`Empty`-then-drop loop could miss because it lands AFTER
323        // that loop's last `Empty` observation. The consumer never receives it.
324        adjust(&depth, 1);
325        sent_count += 1;
326
327        // The producer thread is now joined (guaranteed no more sends
328        // possible). Reconcile using the authoritative post-join delta, exactly
329        // as `SSTableRowIteratorAdapter::drop` does.
330        let residual = sent_count - received_count;
331        assert_eq!(residual, 1, "exactly the one entry that raced teardown");
332        if residual > 0 {
333            adjust(&depth, -residual);
334        }
335
336        assert_eq!(
337            depth.load(Ordering::SeqCst),
338            baseline,
339            "the post-join reconcile must absorb a send that raced teardown, \
340             returning the gauge to its pre-scenario baseline — the #2419 \
341             roborev job 1733 regression this fix eliminates"
342        );
343    }

345    /// Guards the REPORTING mechanism [`reconcile_residual`] uses for a negative
346    /// residual (rust-reviewer, issue #3120), because its condition is subtle
347    /// enough to be "corrected" into a no-op: the assert deliberately requires
348    /// `std::thread::panicking()`, so inverting it to `!panicking()` would silently
349    /// mean the invariant is NEVER checked. Both halves matter:
350    ///
351    /// 1. On a NORMAL (non-unwinding) call it FAILS LOUDLY — the signal.
352    /// 2. When [`reconcile_residual`] runs from a `Drop` that is itself unwinding
353    ///    (the only shape it is reachable in production, and what `teardown_tests`
354    ///    routinely produces), it adds NO second panic, so the ORIGINAL failure
355    ///    message survives instead of the process aborting and taking every
356    ///    sibling test's result with it.
357    ///
358    /// Uses `residual = -1` directly rather than trying to provoke a real
359    /// asymmetry: the invariant genuinely holds today, so the only way to exercise
360    /// the reporting path is to call it with a violating value.
361    #[test]
362    fn a_negative_residual_is_loud_normally_and_silent_while_unwinding() {
363        // (1) `debug_assert!` compiles away in a release build, so only assert the
364        // panic where the assertion actually exists.
365        #[cfg(debug_assertions)]
366        {
367            let died = std::panic::catch_unwind(|| reconcile_residual(-1));
368            assert!(
369                died.is_err(),
370                "a negative residual must fail LOUDLY on a normal (non-unwinding) \
371                 call — if this passes, the invariant is no longer checked at all"
372            );
373        }
374
375        // (2) The production shape: a `Drop` that reconciles while already
376        // unwinding must not double-panic.
377        struct ReconcilesOnDrop;
378        impl Drop for ReconcilesOnDrop {
379            fn drop(&mut self) {
380                reconcile_residual(-1);
381            }
382        }
383        let died = std::panic::catch_unwind(|| {
384            let _guard = ReconcilesOnDrop;
385            panic!("the original failure, whose message must survive the drop");
386        });
387        let payload = died.expect_err("the original panic must still propagate");
388        let message = payload
389            .downcast_ref::<&'static str>()
390            .copied()
391            .unwrap_or("<payload lost — a double panic would have aborted instead>");
392        assert!(
393            message.contains("the original failure"),
394            "the ORIGINAL panic message must survive a reconcile during unwind; a \
395             second panic here aborts the process under libtest, destroying this \
396             message and every sibling test's result, got: {message}"
397        );
398    }

400    /// Issue #3120: `MergeMsg::tracked_entries` CLASSIFIES both terminators as
401    /// untracked, so a run that ends with one returns the depth to exactly baseline
402    /// and leaves a residual of exactly ZERO — never a negative residual, which the
403    /// `> 0` guard would skip and the `max(0)` floor would hide forever.
404    ///
405    /// Issue #2820 adds the BATCH dimension to the same property: the DATA
406    /// messages here carry MULTI-row batches, and both sides account the batch
407    /// LENGTH, so the residual is zero for a batched run exactly as it was for a
408    /// per-row one. A side that counted messages instead of entries leaves a
409    /// residual of `entries - messages` (positive here, i.e. a permanent upward
410    /// gauge leak) or its negative mirror, and this test fails on both.
411    ///
412    /// SCOPE, stated honestly (rust-reviewer): this pins the PREDICATE, not the
413    /// symmetry of the two production call sites. The receive site
414    /// (`SSTableRowIteratorAdapter::next`) is a hand-written `MergeMsg::Batch` match
415    /// arm that never calls `tracked_entries`, so a divergence introduced THERE
416    /// would not fail this test. What protects that site is structural, not this
417    /// test: its `match` is exhaustive with no wildcard arm (a 4th variant is a
418    /// compile error) and the receive-side accounting calls each appear at exactly
419    /// one place, inside that arm. See the module doc.
420    ///
421    /// Against a PRIVATE atomic, never the shared `DEPTH` (the #2451 flake class):
422    /// thousands of tests share this binary and several drive real merge egress
423    /// channels.
424    #[test]
425    fn a_terminator_is_untracked_on_both_sides_so_the_residual_is_exactly_zero() {
426        use crate::storage::write_engine::merge::producer_msg::{MergeMsg, MergeProducerError};
427        use crate::storage::write_engine::merge::{CellData, MergeEntry, RowData};
428        use crate::storage::write_engine::mutation::DecoratedKey;
429        use crate::types::Value;
430
431        /// One DATA message carrying `rows` entries — the batched shape every
432        /// producer now sends (issue #2820).
433        fn data_batch(rows: usize) -> MergeMsg {
434            MergeMsg::Batch(
435                (0..rows as i64)
436                    .map(|n| {
437                        MergeEntry::new(
438                            0,
439                            DecoratedKey::new(n, n.to_be_bytes().to_vec()),
440                            None,
441                            100,
442                            RowData::Live {
443                                cells: vec![CellData::new(
444                                    "name".to_string(),
445                                    Value::text("v"),
446                                    100,
447                                )],
448                            },
449                        )
450                    })
451                    .collect(),
452            )
453        }
454
455        // Each run: N data entries followed by exactly ONE terminator — the shape
456        // every producer thread now produces on every exit path.
457        for terminator in [
458            MergeMsg::Done,
459            MergeMsg::Failed(MergeProducerError::Panicked("boom".to_string())),
460            MergeMsg::Failed(MergeProducerError::Cancelled),
461        ] {
462            // A ramped run: batches of 1, 2 then 4 rows — the shape
463            // `EgressBatcher` produces before its limit saturates — so the pin
464            // covers MULTI-row batches, not just the degenerate 1-row one.
465            const BATCH_ROWS: [usize; 3] = [1, 2, 4];
466            let data_entries: i64 = BATCH_ROWS.iter().sum::<usize>() as i64;
467            let depth = AtomicI64::new(0);
468            let baseline = depth.load(Ordering::SeqCst);
469            let mut sent_count: i64 = 0;
470            let mut received_count: i64 = 0;
471
472            let mut stream: Vec<MergeMsg> = BATCH_ROWS.iter().copied().map(data_batch).collect();
473            stream.push(terminator);
474
475            // SEND side: exactly what `egress_batch::EgressBatcher::flush` does.
476            for msg in &stream {
477                let tracked = msg.tracked_entries();
478                if tracked > 0 {
479                    adjust(&depth, tracked as i64);
480                    sent_count += tracked as i64;
481                }
482            }
483            assert_eq!(
484                sent_count, data_entries,
485                "only the DATA entries may be tracked on send, one slot per ENTRY \
486                 (never one per batch) — and the terminator must not be tracked"
487            );
488
489            // RECEIVE side: exactly what the `MergeMsg::Batch` arm of
490            // `SSTableRowIteratorAdapter::next` does (and no other arm does).
491            for msg in &stream {
492                let tracked = msg.tracked_entries();
493                if tracked > 0 {
494                    adjust(&depth, -(tracked as i64));
495                    received_count += tracked as i64;
496                }
497            }
498
499            let residual = sent_count - received_count;
500            assert_eq!(
501                residual, 0,
502                "a fully drained run whose last message is a terminator must leave a \
503                 residual of exactly zero; a NEGATIVE residual is skipped by the \
504                 `> 0` guard and floored away by `max(0)`, hiding the drift forever \
505                 (issue #3120)"
506            );
507            // The production reconcile would be a no-op here; running it proves the
508            // debug_assert is satisfied by the balanced case.
509            reconcile_residual(residual);
510            assert_eq!(
511                depth.load(Ordering::SeqCst),
512                baseline,
513                "the tracked level returns to baseline"
514            );
515        }
516    }
