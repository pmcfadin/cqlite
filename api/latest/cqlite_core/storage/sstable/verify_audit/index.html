cqlite verify --mode audit: cross-component consistency audit (issue #4195).

Where Quick/Full ask “is each component well-formed?”, the audit asks “do the components AGREE with each other?” and reports a CLOSED set of eight named invariants as AuditVerdict: Pass, Fail (a matching VerifyFinding is also pushed) or Skip(<cause>).

§Truthfulness rules (the point of the module)

  • A Pass is only ever produced by a check that RAN TO COMPLETION and AGREED. Absence of a finding is never read as agreement.
  • An unreadable or absent input is Skip(<cause>) naming why, never Pass and never a silent zero. The component’s own corruption is reported by the finding the structural check already pushed.
  • Every check reads decoded, authoritative structures only. There is NO byte-pattern search over Data.db (A11; enforced by scripts/tests/test_verify_audit_no_resync_scan.sh).
