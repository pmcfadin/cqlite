cqlite.read.bti.rows_root_rejected — counter {partition} (issue #3002).

Incremented once per clustering-slice read that could NOT use a BTI partition’s Rows.db row index because the row-index ROOT the TrieIndexEntry resolved to failed structural validation, so the read decoded the WHOLE partition instead (correct rows, no narrowing). Bounded attribute: attr::ROWS_ROOT_REJECT_REASON (the closed RowsTrieRootRejectReason::label() set).

Zero on a healthy table. A non-zero value names the cause of otherwise unexplained clustering-read latency: every slice over the affected partitions is doing a full-partition decode. The known producer is a Rows.db written by CQLite <= 0.16 (mis-based root delta) — re-flush/re-compact those tables.
