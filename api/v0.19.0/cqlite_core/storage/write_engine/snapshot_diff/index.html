cqlite diff — a read-only two-snapshot comparison of one table’s reconciled state, with resurrection-risk classification (issue #4201; OpenSpec change snapshot-diff).

§Mechanism (design.md §D1)

Each side — a flat table directory of generations — is reconciled independently by the unmodified #4193 mechanism cqlite explain drives (merge::build_traced_merger_with_registry in full-compaction configuration at one pinned now, with a recording sink). This module adds only the comparison layer: the two sides’ winner cells are compared per (clustering, column), and every tombstone held by exactly ONE side is cross-checked against the other side’s winners. A tombstone both sides hold is omitted: the report shows disagreement, not an inventory.

A one-sided tombstone T whose scope still holds live data on the other side with writetime <= T.deletion_time is a resurrection risk: once T passes the strict purge boundary local_deletion_time < now - gc_grace_seconds its holder may purge it on its next compaction, and the other side’s shadowed data returns the next time the two are merged. The rules and their cassandra-5.0.8 citations live in resurrection.

§Read-only

Nothing here opens a file for writing, creates a file, or modifies either input. There is no repair path and none may be added: the report is input to sstableloader / repair, never a write.

§Memory

Partitions are folded one at a time: both sides’ recording sinks (bounded by max_result_bytes) are dropped before the next partition. The key list for the un-scoped scan is O(partitions) raw keys; the report itself is bounded by max_result_bytes and exceeding it is crate::Error::ResultTooLarge, never a truncated report.

§Declared gaps

  • A row’s liveness marker is not a cell in the trail (see resurrection).
  • Two sides holding different content at one identical write timestamp are a conflict cell (owner Q21=b), resolved by Cells.resolveRegular; see cells.rs.
