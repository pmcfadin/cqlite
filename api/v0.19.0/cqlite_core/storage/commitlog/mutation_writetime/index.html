Module mutation_writetime

Expand description

The one closed rule for “what is this CommitLog mutation’s writetime” (issue #4205, D4).

A PartitionUpdate’s writetime is the MAXIMUM timestamp it contributes: every row liveness timestamp, every cell timestamp, and every row-deletion markedForDeleteAt. Anything the decoder did not model (a partition deletion, a clustered table, a complex column, a missing schema, …) is Writetime::Unmeasured naming the cause — never a guessed or zero value (#4159 doctrine).

Enums§

Need
One fact a CommitLog mutation must have in the SSTables for the mutation to count as flushed (issue #4205, roborev job 299 M1): the SSTables must hold the same column at a timestamp STRICTLY above the mutation’s, or an EXACTLY equal cell (see the state fields), or a covering deletion at or above it. At an equal timestamp Cassandra resolves cells by tombstone/expiring state, local deletion time, TTL and then value bytes (Cells.resolveRegular, LivenessInfo.supersedes, cassandra-5.0.8), so an equal timestamp alone proves nothing. Only meaningful for a table without clustering columns (the only shape the decoder models).
Writetime
A mutation’s writetime, or the stated reason it could not be measured.
