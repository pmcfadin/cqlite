1//! Read-shape reassembly of a merged row's per-column cells (issue #2324).
2//!
3//! The k-way merger emits a live row as a flat `Vec<CellData>` where every
4//! element of a non-frozen collection (`list` / `set` / `map`) is its OWN
5//! [`CellData`] — one cell per element, all sharing the column name, each keyed
6//! by its authoritative `cell_path` (epic #899, byte-parity write substrate).
7//! That per-element shape is correct for the compaction WRITE path but WRONG for
8//! any read consumer that keys cells by column name: keying the elements by name
9//! (e.g. the Arrow Flight producer's `build_row_from_scan`, whose `values` is a
10//! `HashMap<column, Value>`) keeps only the LAST element and silently drops the
11//! rest of the collection.
12//!
13//! [`assemble_read_cells`] collapses those per-element cells back into a single
14//! `Value::List` / `Value::Set` / `Value::Map` per column, so a read that goes
15//! through the merger (the Flight `do_get` path) sees the SAME whole collection a
16//! plain single-generation `SELECT` sees.
17//!
18//! Semantics are taken from authoritative metadata only (issue #28): elements are
19//! ordered by their authoritative `cell_path` with the collection-appropriate
20//! comparator (list = position-timeuuid byte order; set/map = the declared
21//! element/key comparator), the set/list member is the reader-decoded
22//! `CellData.value`, and the map key is decoded from the element's `cell_path`
23//! with the schema's declared key type via the canonical
24//! [`deserialize_value_bytes`] codec (never guessed).
25//!
26//! Non-scalar set elements / map keys (`frozen<tuple>`, `frozen<udt>`, nested
27//! `frozen<collection>`) are NOT decodable by the scalar `deserialize_value_bytes`
28//! codec. Serving them as an opaque `Value::Blob(cell_path)` does not actually
29//! reassemble them — the typed Arrow builder downstream expects a tuple/struct
30//! value for the declared type and BREAKS on raw bytes, the same failure the
31//! whole-row error produced, one layer deeper. So this path FAILS CLOSED with a
32//! clear error naming the column + declared key/element type
33//! ([`composite_collection_unsupported`]); full composite key/element decode via
34//! the value deserializer is follow-up #2339. The opaque/scalar choice branches
35//! on the DECLARED schema type only (no guessing).
36//!
37//! Two decodable scalars — `inet` (`InetAddressType`) and `time` (`TimeType`) —
38//! route through the comparator's `compare_custom`, which orders by the FORMATTED
39//! string and can diverge from Cassandra's raw-byte order; their serialized
40//! `cell_path` form IS unsigned-byte-comparable, so they are ordered by raw
41//! `cell_path` bytes instead ([`comparator_orders_by_raw_cell_path_bytes`],
42//! roborev 1631/1632).
43//!
44//! Tombstone handling follows Cassandra SELECT semantics (issue #1742: SELECT
45//! output is the read-path authority), NOT the single-generation reader's
46//! physical `collapsed_value`: a deleted set/list member or deleted MAP entry is
47//! OMITTED from the reassembled collection. This intentionally DIVERGES from
48//! `complex_column.rs`'s collapsed_value, which surfaces a deleted map entry as a
49//! physical `(key, Null)` pair; that quirk is the physical-dump side and is
50//! tracked separately (issue #2336 family). A `SELECT` never returns a deleted
51//! map key, so the merger read-shape must not either.
52

72/// One column's accumulated cells while grouping a row's flat cell list.
73///
74/// The two shapes are mutually exclusive for any one column: in Cassandra 5.0
75/// (na+) a column's frozen-ness is a FIXED schema property (you cannot `ALTER`
76/// a column between frozen and non-frozen), so a single consistent row can never
77/// carry BOTH a whole-value (simple) cell AND per-element (complex) cells for the
78/// same column. If both nonetheless arrive during grouping the row is
79/// inconsistent/corrupt, so [`assemble_read_cells`] fails closed (issue #28)
80/// rather than silently keep whichever shape arrived first and drop the other.
81#[cfg(feature = "write-support")]
82enum ColumnAccum {
83    /// A simple (single-cell) column: its one decoded value.
84    Simple(Value),
85    /// A complex (multi-cell) column: its surviving live elements in arrival
86    /// order (re-sorted by `cell_path` at collapse time). Element tombstones are
87    /// already dropped.
88    Complex(Vec<CellData>),
89}
90
91/// Fail-closed error for a column that arrives with BOTH simple and complex
92/// cells in one merged row (see [`ColumnAccum`] — impossible for a consistent
93/// na+ schema). Names the offending column; never silently drops a shape.
94#[cfg(feature = "write-support")]
95fn mixed_shape_error(column: &str) -> Error {
96    Error::corruption(format!(
97        "column '{column}': merged row mixes a whole-value (simple) cell and \
98         per-element (complex) cells for one column — impossible for a consistent \
99         Cassandra 5.0 (na+) schema (frozen-ness is fixed, un-ALTERable); failing \
100         closed rather than silently dropping either shape (issues #28/#2324)"
101    ))
102}

104/// Reassemble a merged live row's per-column cells into user-facing
105/// [`RowCells`], collapsing multi-cell collection columns into a single
106/// `Value::List` / `Value::Set` / `Value::Map` (issue #2324).
107///
108/// Cell tombstones (`Value::Tombstone` on a simple cell) and deleted complex
109/// elements (`is_deleted`) are dropped, so a column reads as its surviving live
110/// content — an absent simple column becomes null downstream, an all-deleted
111/// collection becomes the empty collection.
112///
113/// A non-collection complex column (e.g. a non-frozen top-level UDT) is left as
114/// its individual cells — this reassembles collections only, the columns the
115/// issue names; other multi-cell shapes are unchanged (no worse than before).
116///
117/// `needed` is the projection-aware set of column names this scan will actually
118/// read (the output projection ∪ predicate-referenced ∪ aggregation-referenced
119/// columns); `None` means "every column" (a plain `SELECT *`). Cells of a column
120/// NOT in `needed` are dropped BEFORE reassembly — they are never emitted
121/// downstream (projection removes them from Arrow output, the filter and
122/// aggregation don't reference them). This scopes the composite-keyed-collection
123/// fail-closed error (a frozen tuple/UDT/nested-collection key/element the scalar
124/// codec cannot materialize, #2339) to the columns a query actually reads: an
125/// unrelated `SELECT` of scalar columns from a row that merely COEXISTS with an
126/// unsupported composite-keyed collection column SUCCEEDS — matching the
127/// observable pre-#2324 behaviour — while the clean error still fires when that
128/// composite column IS projected or referenced (issue #2324, roborev 1633). It
129/// is also a small perf win (unprojected collections are never reassembled).
130#[cfg(feature = "write-support")]
131pub fn assemble_read_cells(
132    cells: Vec<CellData>,
133    schema: &TableSchema,
134    needed: Option<&HashSet<String>>,
135) -> Result<RowCells> {
136    // Group cells by column, preserving first-seen order so a stable, schema-
137    // independent ordering results (downstream keys by name, so order is not
138    // load-bearing — but a deterministic order keeps output reproducible).
139    let mut order: Vec<Arc<str>> = Vec::new();
140    let mut index: HashMap<Arc<str>, usize> = HashMap::new();
141    let mut accums: Vec<ColumnAccum> = Vec::new();
142
143    for cell in cells {
144        // Projection-aware assembly (issue #2324, roborev 1633): drop cells of a
145        // column this scan never reads before touching the (fallible) reassembly.
146        // `None` = all columns → nothing dropped. This keeps the composite-keyed
147        // collection fail-closed error (#2339) from firing on a column an unrelated
148        // query does not project or reference (see the fn-level doc).
149        if let Some(needed) = needed {
150            if !needed.contains(cell.column.as_str()) {
151                continue;
152            }
153        }
154        let name: Arc<str> = Arc::from(cell.column.as_str());
155        if cell.is_complex_element {
156            // Drop element tombstones (a deleted set/list member OR map entry):
157            // the whole element is removed. A collection with NO surviving live
158            // element is left absent (reads null downstream) — an empty non-frozen
159            // collection IS null in Cassandra, and this preserves the pre-fix
160            // behaviour for that edge (the fix only recovers dropped LIVE elements).
161            //
162            // ADJUDICATION (issue #2324, roborev 1628): dropping a deleted MAP
163            // entry — rather than surfacing it as `(key, Null)` — is DELIBERATE and
164            // matches real Cassandra SELECT output, the read-path authority per the
165            // #1742 query-semantics-oracle doctrine: a `SELECT` never returns a
166            // deleted map key. This DIVERGES from the single-generation reader's
167            // physical `collapsed_value` (complex_column.rs ~L663-733), which keeps
168            // the `(key, Null)` pair for the physical-dump oracle; that quirk is the
169            // divergent physical side, tracked separately (issue #2336 family). Do
170            // NOT "fix" this to preserve `(key, Null)` here — that would corrupt the
171            // merger read-shape a `do_get` returns.
172            if cell.is_deleted || matches!(cell.value, Value::Tombstone(_)) {
173                continue;
174            }
175            // Fail closed if this column already accumulated a simple cell (mixed
176            // shape — impossible for a consistent na+ schema; see `ColumnAccum`).
177            let elems = register_complex(&mut order, &mut index, &mut accums, name)?;
178            elems.push(cell);
179        } else {
180            // Simple cell: a tombstoned simple cell leaves the column absent
181            // (reads null downstream) — mirror the prior producer filter.
182            if matches!(cell.value, Value::Tombstone(_)) {
183                continue;
184            }
185            match index.get(name.as_ref()) {
186                Some(&i) => match &mut accums[i] {
187                    ColumnAccum::Simple(v) => *v = cell.value,
188                    // Mixed shape: complex elements already present for this column.
189                    ColumnAccum::Complex(_) => return Err(mixed_shape_error(&name)),
190                },
191                None => {
192                    index.insert(Arc::clone(&name), accums.len());
193                    order.push(name);
194                    accums.push(ColumnAccum::Simple(cell.value));
195                }
196            }
197        }
198    }
199
200    let mut out: RowCells = Vec::with_capacity(order.len());
201    for (name, accum) in order.into_iter().zip(accums.into_iter()) {
202        match accum {
203            ColumnAccum::Simple(value) => out.push((name, value)),
204            ColumnAccum::Complex(elements) => {
205                let value = assemble_complex(&name, elements, schema)?;
206                out.push((name, value));
207            }
208        }
209    }
210    Ok(out)
211}

213/// Fetch (creating if absent) the [`ColumnAccum::Complex`] slot for `name`,
214/// returning a mutable reference to its element vec. Fails closed with
215/// [`mixed_shape_error`] if the column already holds a simple cell (see
216/// [`ColumnAccum`]).
217#[cfg(feature = "write-support")]
218fn register_complex<'a>(
219    order: &mut Vec<Arc<str>>,
220    index: &mut HashMap<Arc<str>, usize>,
221    accums: &'a mut Vec<ColumnAccum>,
222    name: Arc<str>,
223) -> Result<&'a mut Vec<CellData>> {
224    let i = match index.get(name.as_ref()) {
225        Some(&i) => i,
226        None => {
227            let i = accums.len();
228            index.insert(Arc::clone(&name), i);
229            order.push(name);
230            accums.push(ColumnAccum::Complex(Vec::new()));
231            i
232        }
233    };
234    // `order[i]` is the column name for `accums[i]` (both pushed together), and
235    // borrows a different vec than `accums`, so it stays available for the error.
236    match &mut accums[i] {
237        ColumnAccum::Complex(elems) => Ok(elems),
238        ColumnAccum::Simple(_) => Err(mixed_shape_error(&order[i])),
239    }
240}

242/// Collapse the surviving live elements of one complex column into a single
243/// `Value`, using the column's declared collection type from `schema`.
244#[cfg(feature = "write-support")]
245fn assemble_complex(
246    name: &str,
247    mut elements: Vec<CellData>,
248    schema: &TableSchema,
249) -> Result<Value> {
250    // Resolve the declared collection type. An undeclared column (the Flight
251    // producer builds cells for every on-disk column, even ones the caller did
252    // not declare) has no type here; such columns are never emitted to Arrow, so
253    // fall back to the last live element's value rather than fail the whole row.
254    let declared = schema
255        .columns
256        .iter()
257        .find(|c| c.name == name)
258        .map(|c| c.data_type.as_str());
259
260    let cql_type = match declared {
261        Some(dt) => CqlType::parse(dt)?,
262        None => return Ok(last_value(elements)),
263    };
264    let cql_type = unwrap_frozen(&cql_type);
265
266    match cql_type {
267        // A set's element identity IS its `cell_path`; order by the declared
268        // element comparator so a set spanning multiple SSTables (whose elements
269        // arrive in run-encounter, not disk, order) reconstructs in the SAME order
270        // a single-generation `SELECT` returns (issue #2324, roborev 1628).
271        CqlType::Set(inner) => {
272            let elem_cmp = ComparatorType::from_cql_type(inner)?;
273            // A frozen tuple/UDT/nested-collection element cannot be materialized
274            // as a typed Arrow value here — fail closed (see #2339) rather than
275            // emit opaque bytes that break the typed builder downstream.
276            if key_is_opaque_composite(&elem_cmp) {
277                return Err(composite_collection_unsupported(name, "set element", inner));
278            }
279            sort_elements_by_cell_path(&mut elements, &elem_cmp)?;
280            Ok(Value::Set(elements.into_iter().map(|e| e.value).collect()))
281        }
282        // A list element's `cell_path` is its position timeuuid, which orders by
283        // raw byte comparison — sort by `cell_path` bytes so multi-SSTable list
284        // elements land in authoritative position order, not arrival order.
285        CqlType::List(_) => {
286            elements.sort_by(|a, b| cell_path_bytes(a).cmp(cell_path_bytes(b)));
287            Ok(Value::List(elements.into_iter().map(|e| e.value).collect()))
288        }
289        CqlType::Map(key_type, _) => {
290            let key_cmp = ComparatorType::from_cql_type(key_type)?;
291            // A frozen tuple/UDT/nested-collection KEY cannot be materialized as a
292            // typed Arrow value here — fail closed (see #2339) rather than serve an
293            // opaque Value::Blob(cell_path) that breaks the typed builder one layer
294            // deeper. Only scalar-keyed maps reassemble on this path.
295            if key_is_opaque_composite(&key_cmp) {
296                return Err(composite_collection_unsupported(name, "map key", key_type));
297            }
298            // Order entries by the declared (scalar) key comparator so a map
299            // spanning multiple SSTables reconstructs in authoritative key order —
300            // done on the cells up front so the key is decoded once, at build time.
301            sort_elements_by_cell_path(&mut elements, &key_cmp)?;
302            let mut entries = Vec::with_capacity(elements.len());
303            for e in elements {
304                // The map key is the element's cell_path (raw key bytes, no length
305                // prefix), decoded with the declared scalar type.
306                let key_bytes = e.cell_path.as_deref().unwrap_or(&[]);
307                let key = deserialize_value_bytes(key_bytes, &key_cmp)?;
308                entries.push((key, e.value));
309            }
310            Ok(Value::Map(entries))
311        }
312        // A non-collection complex column (e.g. non-frozen top-level UDT):
313        // reassembly of those shapes is out of this issue's scope. Keep the last
314        // element's value (prior behaviour) so nothing regresses.
315        _ => Ok(last_value(elements)),
316    }
317}

319/// The element's authoritative `cell_path` bytes (empty when absent).
320#[cfg(feature = "write-support")]
321fn cell_path_bytes(cell: &CellData) -> &[u8] {
322    cell.cell_path.as_deref().unwrap_or(&[])
323}

325/// Order collection cells by their `cell_path` (the element/key identity), in
326/// place, using the declared element/key comparator.
327///
328/// The Set/Map callers now FAIL CLOSED on an opaque composite element/key before
329/// reaching here (see [`composite_collection_unsupported`], #2339), so in practice
330/// `cmp` is always a scalar. Two scalar shapes:
331///   * A `inet`/`time` comparator ([`comparator_orders_by_raw_cell_path_bytes`])
332///     orders by raw `cell_path` byte comparison — its serialized form's unsigned
333///     byte order IS its Cassandra order, and routing it through the scalar
334///     `compare_custom` would mis-order it (roborev 1631/1632).
335///   * Any other scalar decodes each `cell_path` to a `Value` and orders by the
336///     type comparator (e.g. signed-int order != raw byte order), surfacing any
337///     genuine decode error (wrong-width scalar) rather than masking it.
338///
339/// The [`key_is_opaque_composite`] arm is retained as defensive belt-and-suspenders
340/// (raw-byte order) should the helper ever be reused without the upstream guard.
341#[cfg(feature = "write-support")]
342fn sort_elements_by_cell_path(elements: &mut Vec<CellData>, cmp: &ComparatorType) -> Result<()> {
343    if key_is_opaque_composite(cmp) || comparator_orders_by_raw_cell_path_bytes(cmp) {
344        elements.sort_by(|a, b| cell_path_bytes(a).cmp(cell_path_bytes(b)));
345        return Ok(());
346    }
347    // Decode each `cell_path` once up front (fallible → propagated) so the sort
348    // itself is total and infallible.
349    let mut keyed: Vec<(Value, CellData)> = Vec::with_capacity(elements.len());
350    for cell in std::mem::take(elements) {
351        let key = deserialize_value_bytes(cell_path_bytes(&cell), cmp)?;
352        keyed.push((key, cell));
353    }
354    sort_by_comparator(&mut keyed, cmp)?;
355    elements.extend(keyed.into_iter().map(|(_, cell)| cell));
356    Ok(())
357}

359/// True when `cmp` names an element/key type the scalar [`deserialize_value_bytes`]
360/// codec CANNOT decode — a frozen tuple / UDT / nested collection (or any other
361/// non-scalar `Custom`). Such a key/element is served as an opaque
362/// `Value::Blob(cell_path)` in raw-byte order, mirroring the canonical
363/// single-generation reader's `parse_cell_path_key` (complex_column.rs) rather
364/// than failing the whole query. The set of decodable scalars is kept in lockstep
365/// with `deserialize_value_bytes`; branching on the DECLARED type only, never a
366/// byte pattern (no-heuristics, issue #28).
367#[cfg(feature = "write-support")]
368fn key_is_opaque_composite(cmp: &ComparatorType) -> bool {
369    match cmp {
370        // `frozen` only ever wraps a composite in a map key / collection element,
371        // but recurse defensively so a hypothetical frozen scalar still decodes.
372        ComparatorType::Frozen(inner) => key_is_opaque_composite(inner),
373        ComparatorType::Boolean
374        | ComparatorType::TinyInt
375        | ComparatorType::SmallInt
376        | ComparatorType::Int
377        | ComparatorType::BigInt
378        | ComparatorType::Counter
379        | ComparatorType::Float32
380        | ComparatorType::Float
381        | ComparatorType::Text
382        | ComparatorType::Blob
383        | ComparatorType::Timestamp
384        | ComparatorType::Date
385        | ComparatorType::Uuid
386        | ComparatorType::Varint
387        | ComparatorType::Decimal
388        | ComparatorType::Duration => false,
389        // `deserialize_value_bytes` decodes only these two Custom names.
390        ComparatorType::Custom(name) => !(name == "time" || name == "inet"),
391        // Tuple / Udt / Set / List / Map: undecodable by the scalar codec.
392        _ => true,
393    }
394}

396/// True when the element/key type's Cassandra ordering IS unsigned raw-byte
397/// comparison of the `cell_path`, so decoding to a `Value` and routing through
398/// the scalar type comparator would MIS-order it.
399///
400/// Every other scalar [`ComparatorType`] in this sort path has a proper
401/// [`ComparatorType::compare`] arm; the ONLY declared scalar types that fall
402/// through to `compare_custom` (which orders by the FORMATTED string, diverging
403/// from a single-generation `SELECT`) are the two decodable `Custom` names —
404/// `inet` and `time`. Both have a canonical serialized form whose UNSIGNED byte
405/// order equals their Cassandra order, and the element/key `cell_path` IS that
406/// serialized form, so ordering by raw `cell_path` bytes matches Cassandra
407/// exactly and closes the whole `compare_custom` class here (roborev 1631/1632):
408///   * `inet` (`InetAddressType`): raw address bytes, e.g. `9.0.0.1` = `[9,0,0,1]`
409///     precedes `10.0.0.1` = `[10,0,0,1]` (formatted-string order is the reverse).
410///   * `time` (`TimeType`): 8-byte big-endian nanoseconds-of-day, always
411///     non-negative, so byte order == numeric order (formatted `HH:MM:...` string
412///     order misorders, e.g. any value whose text form sorts against its magnitude).
413///
414/// Branches on the DECLARED type only (no-heuristics, issue #28); recurses through
415/// `Frozen` defensively though neither inet nor time is ever frozen here.
416#[cfg(feature = "write-support")]
417fn comparator_orders_by_raw_cell_path_bytes(cmp: &ComparatorType) -> bool {
418    match cmp {
419        ComparatorType::Frozen(inner) => comparator_orders_by_raw_cell_path_bytes(inner),
420        ComparatorType::Custom(name) => name == "inet" || name == "time",
421        _ => false,
422    }
423}

425/// Fail closed when a collection's key/element is an OPAQUE COMPOSITE — a frozen
426/// tuple / UDT / nested collection the scalar codec cannot decode — on the
427/// merged-read (Flight) assembly path.
428///
429/// Serving such a key/element as an opaque `Value::Blob(cell_path)` (the round-2
430/// route) does not actually reassemble it: the typed Arrow builder downstream
431/// expects a tuple/struct value for the declared type and BREAKS on raw bytes —
432/// the same failure the pre-#2324 whole-row error produced, only one layer
433/// deeper. A clear error naming the column + declared key/element type is
434/// strictly better than either, and composite decode was NEVER functional on
435/// this path (it collapsed to a scalar and errored in Arrow conversion). Full
436/// composite key/element decode via the value deserializer is follow-up #2339
437/// (roborev 1632).
438#[cfg(feature = "write-support")]
439fn composite_collection_unsupported(column: &str, kind: &str, declared: &CqlType) -> Error {
440    Error::unsupported_format(format!(
441        "column '{column}': composite-keyed collection decode unsupported on this \
442         path — {kind} type {declared:?} is a frozen tuple/UDT/nested collection the \
443         merged-read assembler cannot materialize as a typed Arrow value; failing \
444         closed rather than emitting opaque bytes (roborev 1632, follow-up #2339)"
445    ))
446}

448/// Sort `items` by the first tuple element with the fallible [`ComparatorType`],
449/// capturing the first comparison error (a type mismatch the declared metadata
450/// should never produce) and surfacing it rather than silently mis-ordering.
451#[cfg(feature = "write-support")]
452fn sort_by_comparator<T>(items: &mut [(Value, T)], cmp: &ComparatorType) -> Result<()> {
453    let mut first_err: Option<Error> = None;
454    items.sort_by(|a, b| match cmp.compare(&a.0, &b.0) {
455        Ok(ord) => ord,
456        Err(e) => {
457            if first_err.is_none() {
458                first_err = Some(e);
459            }
460            Ordering::Equal
461        }
462    });
463    match first_err {
464        Some(e) => Err(e),
465        None => Ok(()),
466    }
467}

469/// Transparently unwrap `Frozen(inner)` so a `frozen<set<...>>` (single-cell,
470/// never reached as complex) and a bare `set<...>` resolve identically.
471#[cfg(feature = "write-support")]
472fn unwrap_frozen(cql: &CqlType) -> &CqlType {
473    match cql {
474        CqlType::Frozen(inner) => unwrap_frozen(inner),
475        other => other,
476    }
477}

479/// The last element's value, or `Value::Null` when there are none — the safe
480/// fallback for a column whose collection type cannot be resolved.
481#[cfg(feature = "write-support")]
482fn last_value(elements: Vec<CellData>) -> Value {
483    elements
484        .into_iter()
485        .last()
486        .map(|e| e.value)
487        .unwrap_or(Value::Null)
488}

634    fn set_of_inet_orders_by_raw_bytes_not_string() {
635        // set<inet>: cell_path (and value) is the raw 4-byte address. Cassandra's
636        // InetAddressType orders by UNSIGNED address bytes, so 9.0.0.1 (bytes
637        // [9,0,0,1]) precedes 10.0.0.1 (bytes [10,0,0,1]). The formatted-string
638        // order the scalar `Custom("inet")` comparator would use is the REVERSE
639        // ("10.0.0.1" < "9.0.0.1"), which would mis-order a multi-SSTable set.
640        // Arrive out of order to prove the sort actually runs (roborev 1631).
641        let ip_9 = vec![9u8, 0, 0, 1];
642        let ip_10 = vec![10u8, 0, 0, 1];
643        let cells = vec![
644            elem("iset", Value::Inet(ip_10.clone()), ip_10.clone()),
645            elem("iset", Value::Inet(ip_9.clone()), ip_9.clone()),
646        ];
647        let out = assemble_read_cells(cells, &schema(), None).unwrap();
648        assert_eq!(
649            get(&out, "iset"),
650            Some(&Value::Set(vec![Value::Inet(ip_9), Value::Inet(ip_10),])),
651            "set<inet> must order by unsigned address bytes (9.0.0.1 before 10.0.0.1), \
652             not the reversed formatted-string order"
653        );
654    }

656    #[test]
657    fn set_of_time_orders_by_raw_bytes_not_formatted_string() {
658        // set<time>: cell_path is the 8-byte big-endian nanoseconds-of-day; Cassandra's
659        // TimeType orders by that raw long (non-negative → byte order == numeric order).
660        // The scalar Custom("time") comparator instead falls to compare_custom's
661        // FORMATTED-string order ("TIME(HH:MM:SS.nnn)"), which — because the hours
662        // field is only zero-padded to two digits — diverges from numeric order once
663        // the hours magnitude changes digit-width. 10h vs 100h: the string
664        // "TIME(100:..." sorts BEFORE "TIME(10:..." ('0' < ':'), the REVERSE of numeric
665        // order, so a multi-SSTable set would mis-order pre-fix. (Valid times-of-day
666        // happen to coincide under the current Display; ordering by the raw cell_path
667        // bytes is the robust, parity-correct rule and closes the compare_custom class,
668        // roborev 1632.) Arrive out of order to prove the sort runs.
669        let t_small = 36_000_000_000_000i64; // 10h in ns
670        let t_big = 360_000_000_000_000i64; // 100h in ns
671        let cells = vec![
672            elem("tset", Value::Time(t_big), t_big.to_be_bytes().to_vec()),
673            elem("tset", Value::Time(t_small), t_small.to_be_bytes().to_vec()),
674        ];
675        let out = assemble_read_cells(cells, &schema(), None).unwrap();
676        assert_eq!(
677            get(&out, "tset"),
678            Some(&Value::Set(vec![Value::Time(t_small), Value::Time(t_big)])),
679            "set<time> must order by the raw big-endian long (10h before 100h), \
680             not the reversed formatted-string order"
681        );
682    }
