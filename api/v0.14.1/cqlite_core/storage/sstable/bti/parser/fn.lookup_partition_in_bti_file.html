Expand description

Look up a partition by its byte-comparable encoded key in a real Cassandra 5.0 Partitions.db BTI trie file.

§Format

The file is a compact trie with no header:

  • Nodes are written bottom-up (children before parents).
  • The root node’s absolute byte offset is stored as the last 8 bytes of the file (big-endian u64).
  • Every partition leaf carries a payload consisting of a 1-byte filter hash plus a SizedInts-encoded signed position (see decode_bti_partition_payload).
  • Negative position → data_offset = ~position (direct Data.db pointer).
  • Non-negative position → rows_offset into Rows.db (wide partition).

§Arguments

  • reader – positioned at any point; this function seeks as needed.
  • encoded_key – the byte-comparable encoding of the partition key (e.g. as produced by ByteComparableEncoder).

§Returns

  • Ok(Some(BtiPartitionLocation::DataOffset(off))) – the partition starts at byte off in Data.db. This is the headline result of issue #755.
  • Ok(Some(BtiPartitionLocation::RowsOffset(off))) – the partition has a row index; consult Rows.db at off for the row-level trie.
  • Ok(None) – the key was not found.
  • Err(_) – structural parse error.

§Reference

Mirrors PartitionIndex.java (Cassandra 5.0.8), specifically the openBlocking + exactCandidate read path; SizedInts.read; and the payload sign convention at PartitionIndex.java:131–135.
