Compare two raw partition keys by Cassandra’s canonical global (token-ring) order: Murmur3 token first, raw key bytes as a deterministic tiebreak.

This is THE cross-partition order Cassandra presents rows in, and the single authoritative definition shared by every access path that concatenates rows from more than one source:

  • the streaming k-way merge (sstable/mod.rs, #1580),
  • the WHERE pk IN (...) fan-out (select_executor::lookup::sort_rows_by_token, #955), and
  • the multi-candidate scan_partition / metadata concat fallbacks (#1917).

Raw-byte order alone is the WRONG global order (it differs from token order for almost all key sets), so all of the above route through this comparator to keep row order identical regardless of which path served the query.
