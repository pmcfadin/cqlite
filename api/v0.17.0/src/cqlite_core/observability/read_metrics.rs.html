1//! Read-path metric emission at BATCH granularity (issue #1701, epic #1686).
2//!
3//! # Why this module exists
4//!
5//! The four headline read metrics — [`catalog::READ_ROWS`], [`catalog::READ_BYTES`],
6//! [`catalog::READ_PARTITIONS`] and [`catalog::READ_DURATION`] — were documented,
7//! registered as instruments, rendered in the operator metric reference and shown
8//! in this module's parent doc example, while NO production read path ever updated
9//! them (finding AI1 of `docs/reports/platform-observability-audit-2026-07-01.md`).
10//! A documented metric that is never written is worse than an absent one: an
11//! operator's dashboard shows a flat zero and reads it as "no reads happening".
12//!
13//! # The granularity rule
14//!
15//! The span-granularity doctrine in [`catalog`] applies to metrics too: emission is
16//! per read OPERATION, never per row. [`ReadOpMeter`] accumulates a scan's rows and
17//! partitions in two `u64` fields and emits ONE counter add per metric plus ONE
18//! duration recording when the operation ends. `read.bytes` is emitted once per
19//! decompressed chunk ([`record_decompressed_bytes`]) — the coarsest grain at which
20//! the decompressed size is actually known.
21//!
22//! # Which SUBSYSTEM's bytes `read.bytes` counts (issue #1701, roborev F3)
23//!
24//! `read.rows` / `read.partitions` / `read.duration` are emitted at an ENUMERATED set
25//! of core query read boundaries — `SSTableManager`'s materializing scans and point
26//! reads, and the `JoinedStream` streaming handles — so a compaction can never
27//! contribute to them: compaction reads its inputs through
28//! `stream_all_partitions_for_compaction` on a reader directly, never through those
29//! boundaries.
30//!
31//! That set is a CLAIM ABOUT THOSE BOUNDARIES, not about the whole product. A caller
32//! that reaches the readers by another route is NOT metered by this module — notably
33//! the Arrow Flight `do_get` path, which drives `KWayMerger`/`QueryRowStream` directly
34//! and emits its own rows/partitions from `cqlite-flight`'s `ScanProgressMeter` with no
35//! duration at all. Extending duration coverage there needs Flight-level metering and
36//! capture infrastructure in that crate, and is deliberately out of scope here; nothing
37//! in this module or the operator reference should be read as claiming it. Flight reads
38//! DO contribute `read.bytes`, because they decode through the same chunk plane.
39//!
40//! `read.bytes` is different, and deliberately so. It is credited inside the CHUNK
41//! DECODE PLANE (`reader::chunk_source`), which is handed a `ReadAt` + a
42//! `CompressionInfo` and cannot know WHO asked — the same plane serves a query read,
43//! a compaction read, and a verification scan. So the metric answers "how many
44//! `Data.db` bytes did this process materialise", including compaction's own reads.
45//!
46//! That is a real limitation for an operator reading query amplification off
47//! `read.bytes` while a compaction runs, and the honest fix is NOT to guess at the
48//! plane: it needs a read-PURPOSE dimension threaded from each caller (or a separate
49//! compaction-bytes-read instrument), which reaches into the compaction merge
50//! producer and is a change to compaction plumbing rather than metric wiring. It is
51//! therefore recorded here and left to a follow-up, not silently approximated: the
52//! plane never invents a purpose label it cannot know, exactly as it never invents
53//! the SSTable format label.
54//!
55//! # Zero-cost when off
56//!
57//! [`ReadOpMeter::start`] consults [`obs::metrics_active`] ONCE (the issue #2819 M1
58//! pattern) and returns an INERT meter when metrics are not being collected: no
59//! [`Instant`] is sampled, no key is retained, and every later `record_*` call is a
60//! single branch on a `None`. With the `observability` feature off,
61//! `metrics_active()` is a compile-time `false`, so the whole meter degenerates to
62//! that branch and the emission helpers compile to no-ops.

73/// The bounded [`catalog::attr::COMPRESSION`] value for "this SSTable has no
74/// compressor", so an uncompressed read is attributed to a NAMED series rather than
75/// an anonymous one (issue #1701). Same spelling the write side uses for
76/// `CompressionAlgorithm::None`.
77pub(crate) const COMPRESSION_NONE: &str = "none";
78
79/// Map a compression algorithm to its bounded [`catalog::attr::COMPRESSION`] value.
80///
81/// Bounded by the `CompressionAlgorithm` enum itself (five variants), never by a
82/// string read out of `CompressionInfo.db` — an on-disk algorithm name is
83/// file-controlled and would be an unbounded metric dimension. Mirrors the write
84/// side's `CompressedDataWriter::compression_attr` (issue #1036).
85pub(crate) fn compression_attr(algorithm: &CompressionAlgorithm) -> &'static str {
86    match algorithm {
87        CompressionAlgorithm::Lz4 => "lz4",
88        CompressionAlgorithm::Snappy => "snappy",
89        CompressionAlgorithm::Deflate => "deflate",
90        CompressionAlgorithm::Zstd => "zstd",
91        CompressionAlgorithm::None => COMPRESSION_NONE,
92    }
93}

95/// Count `bytes` of `Data.db` payload (post-decompression) into
96/// [`catalog::READ_BYTES`], tagged with the bounded `compression` label.
97///
98/// Called once per chunk the read path materialises, from the single chunk decode
99/// plane (`reader::chunk_source`) — every one of its four decode exits, INCLUDING
100/// the ones that hand back raw bytes: an UNCOMPRESSED SSTable (`compression =
101/// "none"`) and a Cassandra-stored-raw incompressible chunk read `Data.db` payload
102/// exactly like a decompressed chunk does. Uncompressed is a first-class read path,
103/// not an edge case — CQLite's own production write surface emits uncompressed
104/// SSTables only (the #1406 claim boundary) — so a `"none"` read that went
105/// uncounted would make the metric silently understate real I/O.
106///
107/// A resident decompressed-chunk cache HIT is counted too, and the reason is a fact
108/// about the feed rather than a preference (issue #1701, roborev round 5): the
109/// windowed scan calls `read_compressed_chunk_sync` /
110/// `read_uncompressed_piece_sync` UNCONDITIONALLY and only then asks the cache, and
111/// neither reader consults it — so the disk read has ALREADY happened and that cache
112/// saves DECOMPRESSION, not I/O. An earlier version of this doc asserted the
113/// opposite, and a test asserted it too; they agreed with each other and were both
114/// wrong, which is how a warm scan came to report zero bytes for I/O it really
115/// performed. The one place a read is genuinely skipped — `get_cached_data`'s
116/// early return, which reads no `Data.db` at all — stays uncounted.
117///
118/// The label is a `&'static str` from [`compression_attr`]'s closed mapping, so this
119/// costs no allocation and no formatting on the per-chunk path.
120pub(crate) fn record_decompressed_bytes(bytes: usize, compression: &'static str) {
121    if bytes == 0 {
122        return;
123    }
124    obs::add_counter(
125        catalog::READ_BYTES,
126        bytes as u64,
127        &[(
128            catalog::attr::COMPRESSION,
129            AttrValue::StaticStr(compression),
130        )],
131    );
132}

134/// One read OPERATION's row/partition/duration accounting, emitted ONCE at the end.
135///
136/// A scan stream owns one of these for its whole lifetime; a point read owns one for
137/// the duration of the lookup. [`finish`](Self::finish) is idempotent and is also
138/// called from `Drop`, so an ABANDONED read (the common `LIMIT` shape: the consumer
139/// stops polling and drops the stream) still reports the work it did instead of
140/// vanishing from the metrics.
141pub(crate) struct ReadOpMeter(Option<Accounting>);
142
143struct Accounting {
144    started: Instant,
145    /// `Some(label)` when the operation reads ONE SSTable of a known format;
146    /// `None` for a cross-generation merge, whose reconciled rows come from
147    /// possibly mixed-format inputs, so no single format label is honest
148    /// (the rule [`catalog::READ_ROWS`] documents).
149    format: Option<&'static str>,
150    rows: u64,
151    partitions: u64,
152    /// The previous row's partition key. Scan producers emit rows GROUPED BY
153    /// partition in on-disk (token) order and every emitted row carries its
154    /// PARTITION key — the row key is the one decoded from the partition header
155    /// (`row_decoder/row_framing.rs::parse_partition_header_full`, cloned onto each
156    /// of that partition's rows in `row_decoder/block_emit.rs`) — so a CHANGE of key
157    /// is a partition boundary.
158    ///
159    /// That is not a new inference: it is the same rule the read-work probe already
160    /// applies at the BTI and BIG walks ("changed partition key = one more partition
161    /// BODY decoded", `work_counters::add_stream_walk_partition_parsed` call sites,
162    /// issues #2398/#3109). Because emission is token-ordered, a partition appearing
163    /// in several inputs of a merge arrives as ONE adjacent run and is counted once.
164    ///
165    /// Retained as an `Arc` clone (a refcount bump, no key copy).
166    last_partition: Option<Arc<[u8]>>,
167    /// This operation's read-PHASE accumulator (issue #1707), shared with the
168    /// pipeline threads that do the io/decompress/decode/merge work. Owned here so
169    /// the four `cqlite.read.phase.*` histograms inherit the whole `ReadOpMeter`
170    /// lifecycle — idempotent [`finish`](ReadOpMeter::finish), `Drop`-safe, and
171    /// absent entirely on an [`inert`](ReadOpMeter::inert) sub-scan, so a fan-out
172    /// merge's per-generation scans can never double-count.
173    phases: Arc<ReadPhaseTimings>,
174    emitted: bool,
175}
176
177impl ReadOpMeter {
178    /// A meter for a read operation that SHOULD be measured.
179    ///
180    /// `format` is the single-SSTable format label, or `None` for a merged
181    /// (format-agnostic) grain. Returns an inert meter when metrics are not being
182    /// collected, so nothing — not even the `Instant` sample — is paid for.
183    pub(crate) fn start(format: Option<&'static str>) -> Self {
184        if !obs::metrics_active() {
185            return Self(None);
186        }
187        Self(Some(Accounting {
188            started: Instant::now(),
189            format,
190            rows: 0,
191            partitions: 0,
192            last_partition: None,
193            phases: Arc::new(ReadPhaseTimings::default()),
194            emitted: false,
195        }))
196    }
197
198    /// A meter that never records and never emits.
199    ///
200    /// Used by the stream boundaries that are NOT a top-level read operation: a
201    /// fan-out merge's per-generation sub-scan (the merge holds the operation) and
202    /// the per-row → batch re-chunker (its source stream is already measured).
203    /// Measuring those would count the same rows two or three times.
204    pub(crate) fn inert() -> Self {
205        Self(None)
206    }
207
208    /// This operation's read-phase accumulator, for propagation to the threads that
209    /// actually perform the work (issue #1707), or `None` for an inert meter.
210    ///
211    /// Handed to each `spawn_blocking` / producer-thread closure at its SPAWN SITE
212    /// and re-installed there: thread-locals are not inherited across a spawn, and
213    /// the io/decompress/decode/merge phases all run on threads that never see this
214    /// meter. `None` (an inert meter, or metrics not being collected) propagates as
215    /// "no sink", which makes every seam a single thread-local peek.
216    pub(crate) fn phase_sink(&self) -> Option<Arc<ReadPhaseTimings>> {
217        self.0.as_ref().map(|acc| Arc::clone(&acc.phases))
218    }
219
220    /// Account one delivered row, and a partition boundary when its key differs
221    /// from the previous row's.
222    ///
223    /// # `read.rows` counts rows this read DELIVERED, not every row decoded
224    ///
225    /// An ABANDONED stream reports the rows it polled plus the rows the producer had
226    /// already enqueued (the `Drop` drain). A row the producer was mid-`send` with when
227    /// the channel closed is NOT counted: it was decoded, then rejected and discarded,
228    /// so it never reached the consumer and could never have appeared in a result set
229    /// (issue #1701, roborev round 5). Counting it would let `read.rows` exceed the rows
230    /// the query could possibly have returned, which is the less useful of the two
231    /// errors. The residual is bounded by the channel's in-flight sends, not by the
232    /// backlog — that unbounded case was the round-2 defect, and closing this one means
233    /// accounting at the producer's materialization boundary through shared state, which
234    /// is a redesign of this seam rather than a fix to it.
235    ///
236    /// # `read.partitions` counts partitions this read DELIVERED rows from
237    ///
238    /// Boundaries come from the keys of EMITTED rows, so a partition whose every row is
239    /// shadowed by a tombstone or expired by TTL emits nothing and contributes ZERO —
240    /// while Flight's k-way MERGE arm calls its own `record_partition()` for a partition
241    /// it scanned, and so counts it. The gap between the two producers is exactly the
242    /// number of fully-suppressed partitions (issue #1701, roborev round 5).
243    ///
244    /// That asymmetry is NOT introduced here, and it is already documented on the Flight
245    /// side between Flight's OWN two arms (`cqlite-flight/src/row_source.rs`): the
246    /// single-generation arm "CANNOT" surface such partitions because "the walk emits
247    /// only SURVIVING rows … the source never learns it existed", and closing it "would
248    /// need a new partition-boundary signal threaded out of two core walks".
249    ///
250    /// Wiring that signal is deliberately NOT attempted here — this issue's scope is
251    /// emitting the metric at batch granularity from the seams that already exist, and
252    /// threading a new boundary signal through two core walks is a separate change with
253    /// its own parity risk. Recorded instead of quietly leaving the two counts to differ,
254    /// because a metric that means two things across producers is worse for an operator
255    /// than one that means a narrower thing consistently. `read.rows` is unaffected: a
256    /// suppressed partition materialises no rows on either producer.
257    pub(crate) fn record_row(&mut self, key: &RowKey) {
258        let Some(acc) = self.0.as_mut() else {
259            return;
260        };
261        acc.rows = acc.rows.saturating_add(1);
262        let same_partition = acc
263            .last_partition
264            .as_ref()
265            .is_some_and(|prev| Arc::ptr_eq(prev, &key.0) || **prev == *key.0);
266        if !same_partition {
267            acc.partitions = acc.partitions.saturating_add(1);
268            acc.last_partition = Some(Arc::clone(&key.0));
269        }
270    }
271
272    /// Account every row of an ALREADY-MATERIALIZED result (issue #1701 F1).
273    ///
274    /// The materializing read boundaries (`SSTableManager::scan` and the
275    /// partition-targeted scans) hand their whole `Vec` here in one call, so the
276    /// emission stays at operation granularity — this is bookkeeping over a result
277    /// the caller already holds, not a per-row emission. Written to take an iterator
278    /// of KEYS so a 2-tuple `(key, row)` and a 3-tuple `(key, row, cell_metadata)`
279    /// result both fit (`rows.iter().map(|(k, ..)| k)`).
280    pub(crate) fn record_keys<'a>(&mut self, keys: impl IntoIterator<Item = &'a RowKey>) {
281        if self.0.is_none() {
282            return;
283        }
284        for key in keys {
285            self.record_row(key);
286        }
287    }

289    /// Suppress this meter permanently: neither [`finish`](Self::finish) nor `Drop`
290    /// will emit (issue #1701, roborev round 4).
291    ///
292    /// # KNOWN GAP a declining boundary leaves, stated rather than implied
293    ///
294    /// The declining attempt's own latency is EXCLUDED from the logical read: the
295    /// fallback path starts a fresh meter, so whatever the attempt spent — reader
296    /// resolution, candidate pruning, and for the reverse seam possibly a promoted-index
297    /// decode — is reported by nobody (issue #1701, roborev round 5). By the
298    /// entry-at-function rule (`manager_point_read`'s module doc) it SHOULD be counted:
299    /// excluding setup hides exactly the stall an operator hunts.
300    ///
301    /// Closing it means ONE meter owned by the common caller
302    /// (`query::select_executor::lookup`) and threaded into both attempts — the pattern
303    /// `stream_generations_for_read` now uses. Not done here: it changes a public-ish
304    /// manager signature with several callers and edits `storage/sstable/mod.rs`, which is
305    /// far over the campsite threshold, so it belongs in its own reviewed change rather
306    /// than a fifth review round of this one. Bounded meanwhile: a decline on the cheap
307    /// eligibility checks (static columns, non-fixed clustering) costs almost nothing;
308    /// only a decline past those carries real excluded latency.
309    ///
310    /// For a read boundary that may DECLINE the read and hand it to a different,
311    /// ALREADY-METERED path. `Drop` emits, so simply returning would report a
312    /// duration for the attempt AND another for the path that actually served the
313    /// read — two operations for one logical read, which is exactly the
314    /// over-counting roborev B1 removed. The declining boundary therefore discards
315    /// its meter rather than dropping it. Distinct from [`inert`](Self::inert),
316    /// which is chosen at CONSTRUCTION for a boundary that is never an operation;
317    /// this is decided at RUNTIME, after the attempt has already begun timing.
318    ///
319    /// Gated to the build that HAS a declining boundary: the only one is
320    /// `SSTableManager::scan_partition_clustering_reverse`, and `reverse_scan.rs` is
321    /// itself `#![cfg(not(feature = "tombstones"))]` (the seek/reverse paths exist only
322    /// on the default build). Under `--all-features` that module is compiled out, so an
323    /// ungated `discard` is dead code and fails the crate's `-D warnings` — and a blanket
324    /// `#[allow(dead_code)]` would silence the NEXT genuinely-dead method too. Widen this
325    /// cfg when a second declining boundary appears outside that module.
326    #[cfg(not(feature = "tombstones"))]
327    pub(crate) fn discard(&mut self) {
328        if let Some(acc) = self.0.as_mut() {
329            acc.emitted = true;
330        }
331    }

333    /// Emit this operation's totals. Idempotent: the second call is a no-op, so a
334    /// stream that observed its own end of stream and is then dropped emits once.
335    pub(crate) fn finish(&mut self) {
336        let Some(acc) = self.0.as_mut() else {
337            return;
338        };
339        if acc.emitted {
340            return;
341        }
342        acc.emitted = true;
343
344        // Held in a local so the borrowed attribute slice below outlives the calls.
345        let format_attr = acc
346            .format
347            .map(|f| [(catalog::attr::SSTABLE_FORMAT, AttrValue::StaticStr(f))]);
348        let attrs: &[(&'static str, AttrValue)] = match format_attr.as_ref() {
349            Some(a) => a,
350            None => &[],
351        };
352
353        if acc.rows > 0 {
354            obs::add_counter(catalog::READ_ROWS, acc.rows, attrs);
355        }
356        if acc.partitions > 0 {
357            obs::add_counter(catalog::READ_PARTITIONS, acc.partitions, attrs);
358        }
359        // Always ONE recording per completed operation, including a read that
360        // returned nothing: a zero-row read still consumed latency, and dropping it
361        // would bias the distribution toward the rows-returning reads.
362        obs::record_histogram(
363            catalog::READ_DURATION,
364            acc.started.elapsed().as_secs_f64(),
365            attrs,
366        );
367
368        // The four read PHASES (issue #1707): ONE sample per phase per completed
369        // operation, from the counters the pipeline threads accumulated into.
370        //
371        // A phase is emitted iff it RAN — `phases.entered(phase)` — and NOT iff it
372        // accumulated nanos (issue #1707, roborev job 145). The two are different
373        // questions, and gating on the duration answered the wrong one: it reported
374        // "ran but measured zero" as "did not run".
375        //
376        // Absence carries load-bearing meaning here that it does not carry for
377        // `read.duration` above: no `decompress` series means the SSTable is
378        // UNCOMPRESSED, no `merge` series means a SINGLE GENERATION. Under the old
379        // `nanos > 0` gate a phase that genuinely ran and measured zero was
380        // indistinguishable from one that never ran, so the metric asserted the
381        // opposite of the truth.
382        //
383        // That is not hypothetical for MERGE. `timed_merge_excluding_recv_wait`
384        // saturates to 0 when the recv-wait it subtracts exceeds the step's wall
385        // time — documented, tested, and the honest thing to do — so a real
386        // multi-generation merge whose producer starved records 0 nanos and was
387        // skipped, telling the operator "single generation". The honesty mechanism
388        // manufactured the false statement.
389        //
390        // So `0.0` now MEANS something precise: the phase ran and measured zero
391        // (too fast for the clock, or a merge whose whole wall time was recv-wait).
392        // It is no longer "a measurement that was never taken", because entry is
393        // tracked separately from duration. Absence means exactly what the docs
394        // say — the phase DID NOT RUN — and a zero-valued sample is a real
395        // observation, not a fabrication.
396        //
397        // ATTRIBUTE-FREE, deliberately, and NOT `attrs`: this family is declared
398        // "**Attributes**: none" by `catalog_read_phase` and carries an empty
399        // `attributes` in every `operator_docs_annotations_read_phase` row, so
400        // emitting `cqlite.sstable.format` here would make the emission and the
401        // declaration disagree — two statements of one fact, one of them wrong.
402        // The declaration is the one to keep: the merge phase is format-agnostic
403        // (it spans generations), so a per-format phase dimension could not be
404        // honestly populated across the family anyway. `read.duration` above keeps
405        // `attrs` — its format attribute IS declared.
406        //
407        // PARTIAL-SNAPSHOT CAVEAT (issue #1707): the surrounding prose says "ONE
408        // sample per phase per COMPLETED scan", and completion here means THIS
409        // METER completed — `finish()` runs when the stream is dropped. The
410        // detached feed/parse tasks hold their own `Arc<ReadPhaseTimings>` clone
411        // and keep accumulating into it after that, so an ABANDONED scan (a `LIMIT`
412        // the consumer stopped reading, a dropped stream) emits a PARTIAL snapshot
413        // of an operation still in flight, not a final total. That is the same
414        // shape `read.duration` already has (it measures until the drop, not until
415        // the pipeline quiesces) and is why the emission is here rather than behind
416        // a join: waiting for the detached tasks would make an abandoned scan's
417        // metric arrive late, or never.
418        let phase_attrs: &[(&'static str, AttrValue)] = &[];
419        for (phase, name) in [
420            (ReadPhase::Io, catalog::READ_PHASE_IO),
421            (ReadPhase::Decompress, catalog::READ_PHASE_DECOMPRESS),
422            (ReadPhase::Decode, catalog::READ_PHASE_DECODE),
423            (ReadPhase::Merge, catalog::READ_PHASE_MERGE),
424        ] {
425            // ONE synchronized read of the (entry bit, counter) pair — never an
426            // `entered()` then a separate `nanos()`. This runs CONCURRENTLY with
427            // the still-accumulating detached threads described just above, and
428            // reading the bit before the counter without the acquire/release
429            // pairing inside `snapshot` would let a fresh entry bit be paired with
430            // a stale zero counter, publishing a fabricated `0.0` (roborev job
431            // 149). See `ReadPhaseTimings::snapshot` for which atomic carries
432            // which ordering.
433            if let Some(nanos) = acc.phases.snapshot(phase) {
434                obs::record_histogram(name, Duration::from_nanos(nanos).as_secs_f64(), phase_attrs);
435            }
436        }
437    }
438}
