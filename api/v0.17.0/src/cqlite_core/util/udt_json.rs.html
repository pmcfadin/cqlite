1//! One rule for rendering a UDT as JSON: **its declared fields and nothing else**.
2//!
3//! # Why this exists (issue #3629, parent class #3504)
4//!
5//! Two JSON renderers — `cqlite-cli`'s per-cell JSON rendering (then
6//! `JSONWriter::value_to_json`, now `JsonCell::from_value`) and `cqlite-core`'s
7//! `impl ToJson for Value` — each used to `insert("_type", …)`
8//! into the SAME `serde_json` object that then received the UDT's own declared
9//! fields. That makes type identity (our control data) and the user's field names
10//! (their data) share ONE channel, which is a defect twice over:
11//!
12//! * a UDT that DECLARES a field named `_type` — legal CQL via a quoted
13//!   identifier — silently OVERWRITES the marker, so the type name is
14//!   unrecoverable and the collision is invisible; and
15//! * every UDT that declares no such field carries a key Cassandra never wrote,
16//!   so the output diverges from `sstabledump` for ordinary data.
17//!
18//! # The reference rule, and its PRIMARY SOURCE
19//!
20//! Authority is Cassandra, read at the pinned tag — not CQLite's own code:
21//! `cassandra-5.0.8:src/java/org/apache/cassandra/db/marshal/UserType.java:261`
22//! (`toJSONString`) builds `{"<field>": <value>, …}` by iterating
23//! `for (int i = 0; i < types.size(); i++)` over `stringFieldNames` ALONE. It
24//! emits **no type key and no keyspace key**, and where a field's buffer is
25//! absent it appends the literal `null` (line 280). So "declared fields, nothing
26//! else, `null` for an absent one" is Cassandra's rule, not a CQLite convention.
27//!
28//! Corroborated by `sstabledump` on the committed Cassandra-written fixture
29//! `test-data/fixtures/issue_3504/`, whose non-colliding `p` cell dumps as
30//! `{"label": …, "real_field": 7}` — and whose `id 3` `c` cell dumps
31//! `"_type": null`, which line 280 says is the CORRECT rendering of a null
32//! FIELD and not a residue of the removed marker.
33//!
34//! `crate::util::value_fmt::ValueFormatter::format_udt` (the table/CSV display
35//! path) already followed that rule. This helper is the same rule, for JSON.
36//!
37//! # Why it is generic over the field renderer
38//!
39//! The two callers deliberately render field VALUES by DIFFERENT rules — 11 arms
40//! differ (blobs/uuids/inet as CLI hex vs core base64, timestamps as human
41//! strings vs raw integers, maps as `[{key,value}]` vs a Display-keyed object).
42//! `decimal` and `varint` are two of those 11 and were divergent BEFORE #3644 (a
43//! quoted display string against core's `{scale, unscaled: <base64>}` and a
44//! base64 string); #3644 changed the KIND of the CLI side — an unquoted JSON
45//! number — without changing the count. Converging the whole writer would be
46//! wrong, so only the UDT arm is shared and each caller keeps its own field-value
47//! renderer.
48//!
49//! Call sites (both must stay on this rule):
50//! * `cqlite-cli/src/output/json_cell.rs` — `JsonCell::from_value`, through
51//!   [`udt_render_fields`] (its cell type is not a `serde_json::Value`, so it
52//!   shares the RULE rather than the return type)
53//! * `cqlite-core/src/query/result.rs` — `impl ToJson for Value`, through
54//!   [`udt_to_json_object`], which is itself a thin adapter over
55//!   [`udt_render_fields`]
56//!
57//! Coverage: `cqlite-cli/tests/issue_3629_cli_udt_json_namespace.rs` and
58//! `cqlite-core/tests/issue_3629_core_tojson_udt_namespace.rs` (independent per
59//! site, so the two copies cannot silently diverge again).
60
61use serde_json::{Map, Value as JsonValue};
62
63use crate::types::{UdtValue, Value};

65/// Render `udt` as a JSON object holding its DECLARED FIELDS AND NOTHING ELSE.
66///
67/// * Field declaration order is preserved (`serde_json` is built with
68///   `preserve_order`).
69/// * A field whose value is `None` renders as JSON `null`: a null-valued field is
70///   still a declared field, and the null is the user's data.
71/// * `udt.type_name` / `udt.keyspace` are deliberately NOT emitted. `--format
72///   json` has no metadata channel, and inventing a key inside the field
73///   namespace is the defect this helper exists to remove.
74///
75/// `render_field` renders each present field value by the CALLER's own rules.
76pub fn udt_to_json_object<F>(udt: &UdtValue, render_field: F) -> JsonValue
77where
78    F: Fn(&Value) -> JsonValue,
79{
80    let mut object = Map::with_capacity(udt.fields.len());
81    udt_render_fields(
82        udt,
83        render_field,
84        || JsonValue::Null,
85        |name, rendered: JsonValue| {
86            object.insert(name.to_string(), rendered);
87        },
88    );
89    JsonValue::Object(object)
90}

92/// The SAME rule as [`udt_to_json_object`], for a caller whose rendered field is
93/// not a [`JsonValue`].
94///
95/// `cqlite-cli`'s JSON egress renders a `decimal`/`varint` as a RAW JSON number
96/// fragment, which `serde_json::Value` cannot hold without `arbitrary_precision`
97/// (see `cqlite-cli/src/output/json_cell.rs`), so its field renderer produces its
98/// own cell type. Sharing the rule rather than the return type is what keeps
99/// "declared fields, nothing else, `null` for an absent one" in ONE place: this
100/// function IS the rule and [`udt_to_json_object`] is a thin adapter over it.
101///
102/// `absent` BUILDS the caller's spelling of JSON `null`, emitted for a field
103/// whose value is `None` — a null-valued field is still a declared field. It is a
104/// constructor rather than a value so the cell type need not be `Clone`
105/// (`cqlite-cli`'s carries a `Box`).
106pub fn udt_render_fields<T, F, A, E>(udt: &UdtValue, render_field: F, absent: A, mut emit: E)
107where
108    F: Fn(&Value) -> T,
109    A: Fn() -> T,
110    E: FnMut(&str, T),
111{
112    for field in &udt.fields {
113        let rendered = match &field.value {
114            Some(value) => render_field(value),
115            None => absent(),
116        };
117        emit(&field.name, rendered);
118    }
119}
