1//! TEST-ONLY fault injection for the producer boundaries that used to collapse a
2//! dead producer into a clean end of input: the query row stream's two (issue
3//! #3106), the k-way MERGE's shared row-forward funnel (issue #3120), and every
4//! spawned task on the multi-generation streaming-scan path (issue #3124).
5//!
6//! # Why this exists
7//!
8//! The query row stream ([`crate::storage::sstable::reader::QueryRowStream`]) is
9//! fed by a detached producer thread over a bounded channel, and on the full-ring
10//! arm that thread is in turn fed by an INNER `tokio` task over a second channel.
11//! Before issue #3106 BOTH boundaries collapsed a channel DISCONNECT into a clean
12//! end of stream, so a producer that UNWOUND (a panic anywhere in the walk/decode,
13//! rather than an `Err` return) dropped its sender without a terminal message and
14//! the request completed SUCCESSFULLY with a silently truncated result set. The
15//! fix makes completion explicit at both boundaries; this module is how a test
16//! PROVES that, deterministically, without waiting for a real decode bug to
17//! unwind.
18//!
19//! Independent seams, one per boundary:
20//!
21//! * [`arm_query_row_producer_panic`] → the OUTER boundary: the query-row producer
22//!   THREAD panics at a batch handoff ([`ProducerFault::before_batch_handoff`],
23//!   consulted in `query_rows::emit_rows`).
24//! * [`arm_inner_scan_task_panic`] → the INNER boundary: the batched-scan `tokio`
25//!   TASK panics ([`inner_scan_task_checkpoint`]). ONE checkpoint site, in that
26//!   task's cursor-open prelude
27//!   (`data_access::joined_scan_stream::SSTableReader::open_batched_scan_cursor`),
28//!   which sits ABOVE the `requires_chunk_stitching()` branch and is therefore
29//!   reached whatever on-disk format the reader has — a checkpoint inside either
30//!   branch would fire only for that branch's formats and could silently not fire.
31//!   This is the arm a `do_get` with NO token filter takes, so it is the issue's
32//!   own repro; killing the task drops its sender with no terminator, which the
33//!   query-row thread used to read as "the scan finished".
34//! * [`arm_scan_task_panic`] → the generalisation of the second seam to EVERY
35//!   spawned scan task on the ≠1-generation (query-engine full scan) path (issue
36//!   #3124): the fan-out k-way merge task, a per-reader per-row sub-scan, the
37//!   windowed forwarder, and the cross-generation RECONCILING merge task — see
38//!   [`ScanTaskSite`]. Each had a DISCARDED `JoinHandle`
39//!   and a consumer that read channel-close as end-of-scan, i.e. the #3106 defect
40//!   on the multi-generation path. An arm is keyed by `(site, scope)`, not scope
41//!   alone, because one scan traverses several of these checkpoints.
42//! * [`arm_merge_producer_panic`] → the K-WAY MERGE boundary (issue #3120): a
43//!   merge producer THREAD panics at a row forward
44//!   ([`MergeProducerFault::before_row_forward`], consulted in
45//!   `write_engine::merge::from_readers::forward_row`). That is the `emit`
46//!   callback BOTH `stream_all_partitions_for_compaction` and
47//!   `..._for_query` invoke, and it sits in `write_engine/merge` ABOVE any
48//!   reader format branch — so unlike a checkpoint inside the reader there is no
49//!   `requires_chunk_stitching()`-style bypass that could make the fault silently
50//!   not fire, and ONE funnel covers BOTH producer shapes (path-based compaction
51//!   and shared-reader warm query).
52//!
53//!   Its registry is SEPARATE from the query-row one ([`arm_merge_producer_panic`]
54//!   vs [`arm_query_row_producer_panic`]) on purpose: a shared registry would let
55//!   a merge producer consume an arm a query-row test registered (and vice versa),
56//!   which is exactly the cross-consumption class the per-reader scoping below
57//!   exists to eliminate.
58//!
59//! # Every arm is SCOPED to one reader — no test can take another's (roborev)
60//!
61//! An arm is registered against a `scope` STRING, and a checkpoint fires only when
62//! the scanning reader's `Data.db` PATH contains that scope. This is the
63//! structural replacement for the earlier "process-global, caller serializes"
64//! convention, which was unsound in the `cqlite-core` lib test binary: the in-`src`
65//! panic tests compile into the SAME binary as thousands of other tests and
66//! libtest runs them in parallel, so a concurrent test's scan could consume the arm
67//! and let a panic-injection test pass for the wrong reason (a doc comment asking
68//! callers to serialize is exactly the mitigation that failed).
69//!
70//! Two properties make it structural rather than conventional:
71//!
72//! * **Scoped consumption.** A scan whose path does not match leaves the arm
73//!   registered, so it cannot consume a foreign arm even by racing. A test scopes
74//!   to its own `TempDir` path (unique per run) or to its own `keyspace/table`.
75//! * **A registry, not a slot.** Arms live in a `Vec`, so two concurrently armed
76//!   tests coexist; neither can clobber the other's arm by arming second. Each
77//!   guard removes its OWN entry (by id) on drop.
78//!
79//! Matching is by substring so a caller can scope to a directory (`keyspace/table`)
80//! without knowing the generated SSTable filename. An arm that matches nothing is
81//! simply never taken — the arming test then fails LOUDLY (it sees no error), which
82//! is the correct failure direction.
83//!
84//! # Why this is not a production knob (no-heuristics safe)
85//!
86//! * Everything that can arm a fault is `#[cfg(any(test, feature =
87//!   "producer-fault-injection"))]`. In a default build the arming API does not
88//!   exist, the registries do not exist, [`ProducerFault`] is a zero-sized struct
89//!   with no fields, and both checkpoints compile to empty functions that never
90//!   even evaluate their scope closure — so a production scan does not pay the
91//!   `PathBuf` clone. The production build is byte-identical to one without this
92//!   module's body, and the module itself is `pub(crate)` there.
93//! * No environment variable, config field or on-disk byte pattern can arm it: the
94//!   only way in is a Rust call to an arming function that does not exist in
95//!   production builds. So it cannot influence a decoding decision (issue #28)
96//!   even accidentally.
97//! * `cqlite-flight` enables the feature from its `[dev-dependencies]` (the same
98//!   convention `arrow-shape-corpus` / `test-util` already use), so the shipped
99//!   Flight binary never links it.
100//!
101//! # One seam injects an `Err`, not a panic (issue #3154)
102//!
103//! [`arm_merge_construction_error`] (child module `construction`) makes
104//! `KWayMerger::new` REPORT a chosen error variant on the cross-generation merge
105//! path, proving the narrowed fallback classification: an I/O or corruption failure
106//! must propagate, while a merger-ineligible unsupported-format failure must still
107//! degrade to the documented concat. See that module's doc.

133/// Producer-fault state captured ONCE when a query row stream is opened, then
134/// owned by that stream's producer thread.
135///
136/// A zero-sized, no-op struct in a production build (see the module doc).
137#[derive(Debug, Default)]
138pub(crate) struct ProducerFault {
139    /// Batches this producer may still hand to the consumer before it panics.
140    /// `None` = no fault armed (always the case in production).
141    #[cfg(any(test, feature = "producer-fault-injection"))]
142    panic_after_batches: Option<u64>,
143}
144
145impl ProducerFault {
146    /// Take the OUTER arm registered for this reader, if any (never any, in
147    /// production — `scope_of` is not even called).
148    ///
149    /// `scope_of` is lazy precisely so the production build pays nothing: it
150    /// clones a `PathBuf` only when the arming surface is compiled in.
151    pub(crate) fn capture_for(scope_of: impl FnOnce() -> std::path::PathBuf) -> Self {
152        #[cfg(not(any(test, feature = "producer-fault-injection")))]
153        let _ = scope_of;
154        Self {
155            #[cfg(any(test, feature = "producer-fault-injection"))]
156            panic_after_batches: armed::take_outer(&scope_of().to_string_lossy()),
157        }
158    }
159
160    /// Consulted by the producer THREAD immediately BEFORE it hands a batch to
161    /// the consumer — the single batch-handoff funnel both walk arms go through,
162    /// so an injected fault is observed identically on either.
163    ///
164    /// Panics ON PURPOSE once the armed batch budget is exhausted; that panic is
165    /// the fault being injected, and it is what the producer's `catch_unwind`
166    /// must convert into a terminal error instead of a silent truncation.
167    /// Compiles to an empty function in a production build.
168    pub(crate) fn before_batch_handoff(&mut self) {
169        #[cfg(any(test, feature = "producer-fault-injection"))]
170        if let Some(remaining) = self.panic_after_batches.as_mut() {
171            if *remaining == 0 {
172                panic!("{}", INJECTED_PANIC_MESSAGE);
173            }
174            *remaining -= 1;
175        }
176    }
177
178    /// Build an OUTER fault state directly, WITHOUT touching the arm registry —
179    /// so a unit test of this module's own logic needs no scope and can never
180    /// race, or be raced by, a sibling test.
181    #[cfg(test)]
182    fn for_test(panic_after_batches: u64) -> Self {
183        Self {
184            panic_after_batches: Some(panic_after_batches),
185        }
186    }
187}

257/// Which spawned scan task a checkpoint belongs to (issue #3124).
258///
259/// Part of an arm's key, not just documentation: the four #3124 boundaries sit on
260/// ONE code path, so a single fan-out scan runs through the merge task, each
261/// per-reader sub-scan and (on a compressed reader) the windowed forwarder. Keyed by
262/// scope ALONE, a test arming the boundary it means to prove would have its arm
263/// consumed by whichever checkpoint the scan reached first, and would then pass
264/// while the boundary under test was never exercised.
265///
266/// Exists in production builds too (it is a checkpoint PARAMETER), where every
267/// checkpoint compiles to an empty function that never inspects it.
268#[derive(Debug, Clone, Copy, PartialEq, Eq)]
269pub enum ScanTaskSite {
270    /// The BATCHED scan's driver task, at its cursor-open prelude
271    /// (`open_batched_scan_cursor`) — the issue-#3106 inner boundary.
272    InnerBatchedScan,
273    /// A PER-ROW `scan_stream_admitted` sub-scan task, at its prelude (issue #3124
274    /// site 2). Each generation of a fan-out merge runs one of these.
275    PerRowScan,
276    /// The fan-out k-way MERGE task of `SSTableManager::scan_stream` (issue #3124
277    /// site 1) — the multi-generation path's top-level producer.
278    ///
279    /// Constructed only on the non-`tombstones` path: a `tombstones` build routes
280    /// `scan_stream` through the materializing `scan`, so there is no fan-out merge
281    /// task there and this variant is legitimately unconstructed in that config.
282    #[cfg_attr(feature = "tombstones", allow(dead_code))]
283    FanoutMerge,
284    /// The windowed scan's FORWARDER task (issue #3124 site 4), which adapts the
285    /// blocking parse half's batches to the caller's surface. Reached only by
286    /// chunk-stitching (compressed) readers.
287    WindowedForwarder,
288    /// The CROSS-GENERATION reconciling merge task of
289    /// `generation_merge::stream_generations_for_read` (issue #3124 site 5), at its
290    /// prelude — i.e. inside the `KWayMerger::new` construction window, BEFORE the
291    /// task signals readiness.
292    ///
293    /// Deliberately its own site rather than sharing [`Self::FanoutMerge`]: that is
294    /// the schema-less lazy token-order CONCAT, this is the authoritative RECONCILING
295    /// merge a multi-generation read with a schema takes, and the whole point of the
296    /// site is that a death here must NOT be answered by silently substituting the
297    /// concat (roborev on #3124).
298    ///
299    /// # Gated to exactly where the site EXISTS
300    ///
301    /// `generation_merge` is a `write-support` module (it drives the write engine's
302    /// `KWayMerger`) and its streaming entry point is additionally
303    /// `cfg(not(tombstones))` — a `tombstones` build routes `scan_stream` through the
304    /// materializing `scan`. So this checkpoint exists in exactly one configuration,
305    /// and the variant is `#[cfg]`'d to match it rather than kept everywhere behind an
306    /// `allow(dead_code)`: in a read-only (`--no-default-features`) build there is no
307    /// cross-generation merge task to arm, and a variant nothing can ever construct
308    /// there would be a lie about the seam's coverage. Its only two references — the
309    /// checkpoint call and the end-to-end pin in
310    /// `scan_stream_fanout_panic_tests.rs` — carry this same triple already.
311    ///
312    /// ([`Self::FanoutMerge`] cannot use a `#[cfg]` here: this module's own always-
313    /// compiled unit tests name it, so under `--all-features` (i.e. `tombstones` on)
314    /// cfg'ing it away would break those tests rather than silence a lint.)
315    #[cfg(all(feature = "write-support", not(feature = "tombstones")))]
316    CrossGenerationMerge,
317}

319/// Consulted at a spawned scan task's checkpoint so an armed fault unwinds THAT
320/// task — reproducing exactly the condition every one of these boundaries used to
321/// read as "the scan finished": the task's sender drops with no error and no
322/// terminator.
323///
324/// Panics ON PURPOSE when an arm for this SITE, scoped to THIS reader, is
325/// registered, taking that arm so exactly one task dies. Compiles to an empty
326/// function — which never calls `scope_of` — in a production build.
327#[inline]
328pub(crate) fn scan_task_checkpoint(
329    site: ScanTaskSite,
330    scope_of: impl FnOnce() -> std::path::PathBuf,
331) {
332    #[cfg(not(any(test, feature = "producer-fault-injection")))]
333    {
334        let _ = site;
335        let _ = scope_of;
336    }
337    #[cfg(any(test, feature = "producer-fault-injection"))]
338    armed::take_task_and_panic(site, &scope_of().to_string_lossy());
339}

350/// A checkpoint scope CAPTURED for a task that will run later, elsewhere (issue
351/// #3124).
352///
353/// [`scan_task_checkpoint`] takes a lazy closure because its callers hold the reader
354/// right there. Two #3124 sites do not: the fan-out merge task and the windowed
355/// forwarder are `tokio::spawn`ed with an environment that must OWN whatever they
356/// check, and the forwarder is spawned from a function with no reader in scope. This
357/// type is that owned scope — and it is a ZERO-SIZED, no-op struct in a production
358/// build, so a production scan clones no `PathBuf` and the spawned task's
359/// environment grows by nothing.
360#[derive(Debug, Clone, Default)]
361pub(crate) struct FaultScope {
362    #[cfg(any(test, feature = "producer-fault-injection"))]
363    path: std::path::PathBuf,
364}
365
366impl FaultScope {
367    /// Capture the scope a later-spawned task will check against. `of` is called
368    /// only when the arming surface is compiled in.
369    pub(crate) fn capture(of: impl FnOnce() -> std::path::PathBuf) -> Self {
370        #[cfg(not(any(test, feature = "producer-fault-injection")))]
371        let _ = of;
372        Self {
373            #[cfg(any(test, feature = "producer-fault-injection"))]
374            path: of(),
375        }
376    }
377
378    /// The captured scope's checkpoint for `site`. Empty function in production.
379    #[inline]
380    pub(crate) fn checkpoint(&self, site: ScanTaskSite) {
381        #[cfg(not(any(test, feature = "producer-fault-injection")))]
382        let _ = site;
383        #[cfg(any(test, feature = "producer-fault-injection"))]
384        armed::take_task_and_panic(site, &self.path.to_string_lossy());
385    }
386}

406/// The panic message both checkpoints raise. Exported so a test can (a) assert
407/// the forwarded error carries it and (b) suppress exactly this panic in its

409#[cfg(any(test, feature = "producer-fault-injection"))]

413#[cfg(any(test, feature = "producer-fault-injection"))]
414mod armed {
415    use std::sync::atomic::{AtomicU64, Ordering};
416
417    use parking_lot::Mutex;
418
419    /// One registered OUTER arm.
420    struct OuterArm {
421        id: u64,
422        scope: String,
423        after_batches: u64,
424    }
425
426    /// One registered TASK arm: a scope PLUS the checkpoint site it applies to
427    /// (issue #3124). The site is part of the key, so arming the fan-out merge over
428    /// a fixture cannot be consumed by that same fixture's per-reader sub-scan — the
429    /// four #3124 sites sit on ONE code path and every scan runs through several of
430    /// them, so a scope-only key would let a test prove the wrong boundary.
431    struct TaskArm {
432        id: u64,
433        scope: String,
434        site: super::ScanTaskSite,
435    }
436
437    /// One registered MERGE arm (issue #3120). Shaped like [`OuterArm`] (it has a
438    /// row budget) but in its OWN registry, so a merge producer can never consume
439    /// a query-row test's arm — see the module doc.
440    ///
441    /// `write-support`-gated for the same reason [`super::MergeProducerFault`] is:
442    /// with no k-way merge compiled there is no producer thread to arm, so the
443    /// whole MERGE registry would be dead.
444    #[cfg(feature = "write-support")]
445    struct MergeArm {
446        id: u64,
447        scope: String,
448        after_rows: u64,
449    }
450
451    /// Registered arms. A `Vec`, not a slot: concurrently armed tests coexist and
452    /// cannot clobber one another (see the module doc). Every critical section
453    /// below is a few comparisons long and NEVER spans an `.await`, so no guard is
454    /// ever held across a suspension point.
455    static OUTER_ARMS: Mutex<Vec<OuterArm>> = Mutex::new(Vec::new());
456    static TASK_ARMS: Mutex<Vec<TaskArm>> = Mutex::new(Vec::new());
457    #[cfg(feature = "write-support")]
458    static MERGE_ARMS: Mutex<Vec<MergeArm>> = Mutex::new(Vec::new());
459
460    /// Distinguishes two arms with the same scope, so a guard removes exactly its
461    /// own registration.
462    static NEXT_ARM_ID: AtomicU64 = AtomicU64::new(0);
463
464    /// `pub(super)` so the sibling [`construction`](super::construction) registry
465    /// shares ONE id space with these three, rather than minting a second counter
466    /// whose ids could collide with theirs in a debugger or a log.
467    pub(super) fn next_id() -> u64 {
468        NEXT_ARM_ID.fetch_add(1, Ordering::SeqCst)
469    }
470
471    /// Shortest scope an arm may register with.
472    ///
473    /// The match is a substring test, so an empty (or near-empty) scope matches
474    /// EVERY reader path and silently restores the process-global behaviour the
475    /// scoping exists to eliminate — invisibly, which is the worst failure
476    /// direction. Enforced rather than documented, since "callers are careful" is
477    /// exactly the mitigation that already failed once here (roborev, #3106). Any
478    /// real scope — a `TempDir` path or a `keyspace/table` pair — clears this by an
479    /// order of magnitude.
480    const MIN_SCOPE_LEN: usize = 8;
481
482    /// Fail LOUDLY on a scope that would match everything. `pub(super)` so every
483    /// registry — including the sibling [`construction`](super::construction) one —
484    /// enforces the SAME minimum rather than re-deriving it.
485    pub(super) fn check_scope(scope: &str) {
486        debug_assert!(
487            scope.len() >= MIN_SCOPE_LEN,
488            "producer-fault scope {scope:?} is shorter than {MIN_SCOPE_LEN} chars: a \
489             substring that loose matches every reader path, which silently reverts \
490             the arm to process-global (issue #3106) — scope to a TempDir path or a \
491             keyspace/table instead"
492        );
493    }
494
495    pub(super) fn arm_outer(scope: &str, after_batches: u64) -> u64 {
496        check_scope(scope);
497        let id = next_id();
498        OUTER_ARMS.lock().push(OuterArm {
499            id,
500            scope: scope.to_string(),
501            after_batches,
502        });
503        id
504    }

507        OUTER_ARMS.lock().retain(|arm| arm.id != id);
508    }

510    /// Take the arm whose scope this reader path matches, if any. A non-matching
511    /// path leaves every arm registered — which is what makes a foreign scan
512    /// unable to consume someone else's arm.
513    pub(super) fn take_outer(path: &str) -> Option<u64> {
514        let mut arms = OUTER_ARMS.lock();
515        let index = arms
516            .iter()
517            .position(|arm| path.contains(arm.scope.as_str()))?;
518        Some(arms.remove(index).after_batches)
519    }

523        check_scope(scope);
524        let id = next_id();

526            id,
527            scope: scope.to_string(),
528            after_rows,
529        });
530        id

538    /// Take the MERGE arm whose scope this run's reader path matches, if any. A
539    /// non-matching path leaves every arm registered — which is what stops one
540    /// run of a K-input merge from consuming the arm meant for another (a
541    /// TempDir-wide scope would kill whichever producer reached its first row
542    /// first: a nondeterministic victim AND a nondeterministic rows-through
543    /// count).
544    #[cfg(feature = "write-support")]
545    pub(super) fn take_merge(path: &str) -> Option<u64> {
546        let mut arms = MERGE_ARMS.lock();
547        let index = arms
548            .iter()
549            .position(|arm| path.contains(arm.scope.as_str()))?;
550        Some(arms.remove(index).after_rows)
551    }

553    pub(super) fn arm_task(scope: &str, site: super::ScanTaskSite) -> u64 {
554        check_scope(scope);
555        let id = next_id();
556        TASK_ARMS.lock().push(TaskArm {
557            id,
558            scope: scope.to_string(),
559            site,
560        });
561        id
562    }

564    pub(super) fn disarm_task(id: u64) {
565        TASK_ARMS.lock().retain(|arm| arm.id != id);
566    }

568    /// TAKE the arm registered for THIS site and scoped to this reader, then panic.
569    /// Taken (not merely read) and the lock RELEASED before the panic, so the unwind
570    /// cannot re-enter and a retry/sibling scan is never hit by the same arm.
571    ///
572    /// Both parts of the key must match: an arm registered for another site is left
573    /// registered even when the path matches (issue #3124), so a checkpoint upstream
574    /// of the one under test cannot consume it.
575    pub(super) fn take_task_and_panic(site: super::ScanTaskSite, path: &str) {
576        let armed = {
577            let mut arms = TASK_ARMS.lock();
578            match arms
579                .iter()
580                .position(|arm| arm.site == site && path.contains(arm.scope.as_str()))
581            {
582                Some(index) => {
583                    arms.remove(index);
584                    true
585                }
586                None => false,
587            }
588        };
589        if armed {
590            panic!("{}", super::INJECTED_PANIC_MESSAGE);
591        }
592    }
593}
