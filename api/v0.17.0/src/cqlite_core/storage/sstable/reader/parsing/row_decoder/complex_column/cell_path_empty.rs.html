1//! The EMPTY-BUFFER ADMISSION GATE for a multicell collection's CELL PATH, and
2//! the SET path's decode entry point (issues #3747, #3805, #4106).
3//!
4//! # ONE gate, because Cassandra asks ONE question
5//! A zero-length cell path is the EMPTY component, never "no component". Whether
6//! that component is LEGAL DATA or CORRUPTION is decided by `validateCellPath`,
7//! and at `cassandra-5.0.8` that is a single line for every collection kind:
8//! `schema/ColumnMetadata.java:457-467` calls
9//! `((CollectionType)type).nameComparator().validate(path.get(0))`, where
10//! `nameComparator()` is the KEYS type of a `MapType`
11//! (`db/marshal/MapType.java`) and the ELEMENTS type of a `SetType`
12//! (`db/marshal/SetType.java:101-104`). The FRAMING half is the same object too:
13//! one `CollectionType.cellPathSerializer` (`db/marshal/CollectionType.java:55`,
14//! `:361-382`) serializes every collection's cell path as
15//! `ByteBufferUtil.writeWithVIntLength(path.get(0))`, so a zero-length path is
16//! expressible and MEANS empty. Hence one gate here rather than a per-collection
17//! opinion able to drift.
18//!
19//! # THE GATE IS THE TAG TABLE, NOT A WIDTH TABLE
20//! The admission is [`EmptyValueType::for_cql_type`] — the ONE place the
21//! legal/corruption line is drawn, on Cassandra's `validate()` rather than on
22//! decodability. A `Some` tag means that family's serializer accepts the empty
23//! buffer AND maps it to null (see that function's membership rule), so the
24//! component is PRESENT, TYPED and MEANINGLESS-VALUED. Because the gate is drawn
25//! on `validate()` and not on decodability it is CORRECT to consult it without
26//! regard to what the decoder would have done, which is why it is consulted for
27//! EVERY empty cell path and BEFORE the decode.
28//!
29//! That placement is the whole content of roborev job 449 finding C (#4079): a
30//! gate consulted only in the decoder's `Err` arm cannot reach a family whose
31//! decoder ACCEPTS the empty buffer, so `varint` and `inet` — both ADMITTED by
32//! the tag table — kept a SECOND spelling of the empty buffer (`Varint(b"")` /
33//! `Inet(b"")`) beside the canonical `Value::Empty(tag)`.
34//!
35//! An earlier revision of the map gate asked the WIDTH table instead
36//! (`allowed.contains(&0)`). Those are two authorities answering two DIFFERENT
37//! questions and they disagree on exactly one family: `decimal` is
38//! VARIABLE-width (Cassandra accepts `0` or `>= 4`), a width table cannot
39//! express `{0} ∪ [4, ∞)`, so `allowed.contains(&0)` was FALSE and a LEGAL empty
40//! `decimal` component was refused — while `for_cql_type` admits it from
41//! `DecimalSerializer.java:31-34,58-63`, whose own message reads *"Expected 0 or
42//! at least 4 bytes"* (#3805 REQ-3805-02).
43//!
44//! # WHAT THE GATE DOES *NOT* REACH — the bound, MEASURED not reasoned
45//!  * `text`/`ascii`/`varchar`/`blob`: `for_cql_type` is `None`, because an empty
46//!    buffer is a legal, MEANINGFUL value there
47//!    (`serializers/AbstractTextSerializer.java:72-77`,
48//!    `serializers/BytesSerializer.java:57-62` override `isNull` to say so). They
49//!    keep `Text(b"")`/`Blob(b"")`.
50//!  * `tinyint`/`smallint`/`date`/`time`: `for_cql_type` is `None` (bare `!= N`
51//!    validate — corruption on Cassandra's own terms), so the gate declines and
52//!    the refusal is the width check's (map) or the decoder's own (set).
53//!  * `duration`, every composite (`list`/`set`/`map`/`tuple`/UDT/
54//!    `frozen<collection>`) and `custom`: `for_cql_type` is `None`, so they fall
55//!    through to the decode and keep their existing outcome — an `Err` for
56//!    `duration` and the collections, a structural decode for `tuple`, an opaque
57//!    blob for an unresolvable UDT name.
58//!
59//! Both halves — the table's answer AND the decode result — are asserted by
60//! `regression_3747_empty_map_key_tests` and
61//! `regression_4106_empty_set_member_tests`, so a widening of the table cannot
62//! silently widen either decoder.
63//!
64//! # ONE ADMISSION, TWO RESOLUTIONS — THE SEAM, stated (#4106, roborev job 449 B1)
65//! Two reviewers reported adjacent facts on this file that only LOOK
66//! contradictory. Both are right, about different things:
67//!
68//!  * the marshal TABLE is shared, so "the gate's classifier and the decoder
69//!    cannot disagree on the marshal spelling" holds:
70//!    [`Self::native_marshal_to_cql_type`] is the crate's one marshal-name
71//!    authority and `primitive_marshal_to_cql_short` (which the decoder consults)
72//!    is a projection of it;
73//!  * the ENTRY CONDITION differs, and THAT is where read and write diverged.
74//!    Every consumer handed an ISOLATED COMPONENT NAME consults the table only
75//!    when the string already `contains("org.apache.cassandra.db.marshal.")` —
76//!    [`Self::cell_path_key_cql_type`] and the value decoder
77//!    (`raw_value/reporting.rs`) both spell it that way, and they must, because a
78//!    bare name out of context is ambiguous (`#3612` round 9 finding 2 removed
79//!    the package-synthesising alternative: it made a foreign
80//!    `com.acme.CustomBytesType` match `BytesType`, which is name-pattern
81//!    inference #28 forbids).
82//!
83//! So the ADMISSION is one function ([`Self::cell_path_empty_admits`]) and the
84//! RESOLUTION of the component TYPE is per-route — because Cassandra's own type
85//! SELECTION is per-route:
86//!
87//!  * a SET's element type is derived from the column's declared type and from
88//!    nothing else, so the set route resolves it from the COMPLETE declared type
89//!    via the shared `cell_path_component::resolve_declared_cell_path_type` — the
90//!    same function the WRITER uses, so the two agree by construction. This is
91//!    finding B1's fix: `org.apache.cassandra.db.marshal.SetType(Int32Type)`
92//!    (package on the OUTER name, bare inner element name — a legal `TypeParser`
93//!    spelling, `TypeParser.java:450`) was ACCEPTED by the writer and refused by
94//!    the reader, whose string split had discarded the marshal context before the
95//!    classifier ever saw it;
96//!  * a MAP's key type has a committed marshal-over-schema PRECEDENCE rule
97//!    (`map_key_type_for_decode`, #3612 R7/R8: the marshal form wins when it is
98//!    UDT-bearing, and Cassandra's `SerializationHeader.getType` is the authority
99//!    for that), so the string the decoder uses is NOT always derived from
100//!    `column.data_type` and resolving from `column.data_type` would OVERRIDE the
101//!    header in exactly the case that rule resolves in the header's favour. The
102//!    map route therefore keeps classifying the string the precedence rule
103//!    picked. **The same bare-inner-name asymmetry is therefore still reachable
104//!    on the MAP route** — `org.apache.cassandra.db.marshal.MapType(Int32Type,
105//!    Int32Type)` — and it is NOT silently fixed here; it is named, and it needs
106//!    the precedence rule to report WHICH container it picked from before it can
107//!    be closed the same way. Every real `SerializationHeader` writes fully
108//!    qualified names, so the reachable spelling is the hand-written/
109//!    `TypeParser`-legal one.

111use super::*;
112use crate::storage::sstable::cell_path_component::{
113    resolve_declared_cell_path_type, CellPathComponent,
114};
115use crate::types::EmptyValueType;
116
117impl V5CompressedLegacyParser {
118    /// **THE ADMISSION** — the ONE place the legal/corruption line is drawn for a
119    /// zero-length cell path, on an already-RESOLVED component type.
120    ///
121    /// Both routes below end here, so a widening of the tag table widens both at
122    /// once and neither can hold a per-family opinion of its own. What differs
123    /// between the routes is only how the component type is NAMED; see the
124    /// module header's "ONE ADMISSION, TWO RESOLUTIONS" section for why that
125    /// half cannot be shared.
126    pub(super) fn cell_path_empty_admits(component_type: &CqlType) -> Option<EmptyValueType> {
127        EmptyValueType::for_cql_type(component_type)
128    }
129
130    /// The typed sentinel a zero-length cell path denotes for a MAP KEY of
131    /// DECLARED type `type_str`, or `None` when no authority admits an empty
132    /// buffer there.
133    ///
134    /// `type_str` is the string `map_key_type_for_decode` picked (schema short
135    /// form, or the marshal form when it is UDT-bearing), so it is an ISOLATED
136    /// COMPONENT NAME and is normalized by [`Self::cell_path_key_cql_type`] —
137    /// the classifier for that shape. The admission is
138    /// [`Self::cell_path_empty_admits`]. Nothing per-family is decided here.
139    ///
140    /// See the module header for why this route cannot resolve from the COMPLETE
141    /// declared type the way the set route does, and for the residual
142    /// bare-inner-marshal-name asymmetry that leaves.
143    pub(super) fn cell_path_empty_sentinel(&self, type_str: &str) -> Option<EmptyValueType> {
144        self.cell_path_key_cql_type(type_str)
145            .as_ref()
146            .and_then(Self::cell_path_empty_admits)
147    }
148
149    /// The typed sentinel a zero-length cell path denotes for the ELEMENT of a
150    /// multicell set whose COLUMN is declared `set_data_type`, or `None` when no
151    /// authority admits an empty buffer there.
152    ///
153    /// **Resolved from the COMPLETE declared type, never from the split-out
154    /// element name** (#4106, roborev job 449 finding B1). The set branch derives
155    /// its element type from `column.data_type` and from nothing else, so
156    /// resolving the element from `column.data_type` is resolving THE SAME
157    /// DECLARATION — it restores the marshal context that
158    /// `extract_collection_element_type`'s string split discards, and it does so
159    /// through `cell_path_component::resolve_declared_cell_path_type`, the very
160    /// function the WRITER's admission uses. Read and write therefore agree on
161    /// every declared string by construction rather than by care.
162    ///
163    /// There is deliberately NO fallback to [`Self::cell_path_key_cql_type`] on
164    /// the split-out name. A fallback would re-admit exactly the disagreements
165    /// this shares a resolver to prevent: `set<frozen<int>>` (not legal CQL)
166    /// resolves to `Frozen(Int)` here and is REFUSED, which is what the writer
167    /// does with it — a fallback would peel the `frozen<>` and admit `Int` on the
168    /// read side only.
169    pub(super) fn set_element_empty_sentinel(&self, set_data_type: &str) -> Option<EmptyValueType> {
170        resolve_declared_cell_path_type(set_data_type, CellPathComponent::SetElement)
171            .as_ref()
172            .and_then(Self::cell_path_empty_admits)
173    }
174
175    /// Decode a MULTICELL SET's cell path — which IS the member (`cql3/Sets.java:407`
176    /// writes the element as the cell path and `ByteBufferUtil.EMPTY_BYTE_BUFFER`
177    /// as the cell value).
178    ///
179    /// ISSUE #4106. A ZERO-LENGTH path is the EMPTY MEMBER, so it goes through the
180    /// shared admission gate above; everything else takes the SAME
181    /// [`Self::parse_value_from_raw_bytes`] it always did. The guard this replaces
182    /// (`!path_bytes.is_empty()`) produced `None` and DROPPED the member, so a
183    /// `SELECT` returned a set one member short with no error and no log line —
184    /// the identical defect #3747 removed for map keys, and the reason the gate
185    /// lives in one place for both.
186    ///
187    /// # SCOPE: the fixed-width / full-consumption checks are NOT extended here
188    /// The MAP cell path additionally validates widths and full consumption
189    /// ([`Self::parse_cell_path_key_reporting`], issue #3612), and that module's
190    /// header records that widening those to the set/frozen routes was out of
191    /// #3612's scope. It stays out of #4106's: a NON-EMPTY member keeps its exact
192    /// pre-existing decode, and only the empty buffer — which the guard meant
193    /// reached NO authority at all — is newly admitted.
194    ///
195    /// Errors PROPAGATE (#3811, roborev F1): mapping them to a dropped member is
196    /// strictly worse than a refusal, because a dropped member leaves no trace.
197    ///
198    /// # A CELL-PATH COMPONENT IS NEVER `null`, so a `Null` decode is a REFUSAL
199    /// The shared value decoder's oracle for an empty buffer is Cassandra's
200    /// `deserialize()`, which maps it to `null` UNIFORMLY for all twelve
201    /// fixed-width scalars (issue #3847 — see
202    /// [`super::super::raw_value::fixed_width`]'s header and its pinned oracle).
203    /// That is the right answer for a VALUE and an impossible one for a cell-path
204    /// COMPONENT: Cassandra has no null map key and no null set member —
205    /// `cql3/Sets.java:407` writes the element INTO the path and cannot express
206    /// one, and `validateCellPath` (`schema/ColumnMetadata.java:457-467`)
207    /// validates the component with the element type's `validate()`, which for
208    /// `tinyint`/`smallint`/`date`/`time` is a bare `!= N` that THROWS on the
209    /// empty buffer. So when the admission gate declines AND the decoder answers
210    /// `Null`, no authority admits these bytes and the member is REFUSED.
211    ///
212    /// This is the same composition `cell_path_key.rs` uses one route over (it
213    /// substitutes its own answer keyed on THIS DECODER'S ANSWER, never on a
214    /// width table), and it lands on the same OUTCOME the map route already has
215    /// for the same declared type: an empty `tinyint` map key is refused there by
216    /// the width check, on `cell_path_key`'s committed error-budget rule — `Err`
217    /// only where Cassandra's own `validate`/`split` throws.
218    ///
219    /// MEASURED, not derived: the families this branch actually reaches are
220    /// exactly those four (`regression_4106_empty_set_member_tests`'s refusal and
221    /// trichotomy cases pin it). Nothing per-family is decided here — the branch
222    /// is keyed on the decoder's answer, so it cannot drift from the tag table.
223    ///
224    /// # TWO type strings, and each is used for the ONE thing it can answer
225    /// `set_data_type` is the COLUMN's complete declared type and is what the
226    /// admission is resolved from ([`Self::set_element_empty_sentinel`]) — see
227    /// the module header's "ONE ADMISSION, TWO RESOLUTIONS" section for why the
228    /// split-out element name cannot answer that question for the marshal
229    /// spelling. `element_type` is that split-out name and is what the VALUE
230    /// DECODER is handed, unchanged: a NON-EMPTY member keeps its exact
231    /// pre-existing decode, and widening the decoder's own entry condition is
232    /// out of #4106's scope (a bare-inner-name marshal element still decodes to
233    /// an opaque blob there, exactly as it did before this change — that is the
234    /// decoder's pre-existing `contains(package)` guard in
235    /// `raw_value/reporting.rs`, not something introduced or fixed here).
236    pub(super) fn decode_set_cell_path_member(
237        &self,
238        path_bytes: &[u8],
239        set_data_type: &str,
240        element_type: &str,
241        column_name: &str,
242    ) -> Result<Value> {
243        if path_bytes.is_empty() {
244            if let Some(tag) = self.set_element_empty_sentinel(set_data_type) {
245                return Ok(Value::Empty(tag));
246            }
247        }
248        let decoded = self.parse_value_from_raw_bytes(path_bytes, element_type, column_name, 0)?;
249        if path_bytes.is_empty() && matches!(Self::peeled_for_inspection(&decoded), Value::Null) {
250            return Err(Error::corruption(format!(
251                "Set member '{column_name}' of type '{element_type}': a zero-length \
252                 cell path decodes to no value for this type, and Cassandra's own \
253                 `validateCellPath` rejects it (issue #4106)"
254            )));
255        }
256        Ok(decoded)
257    }
