1//! Decoding a MULTICELL collection cell's CELL PATH as a map KEY (issue #3612).
2//!
3//! A non-frozen `map<K, V>` is multicell: each entry is its own cell and the KEY
4//! is carried in that cell's CellPath. Cassandra frames a CellPath as
5//! `[VInt length][bare serialized key]`
6//! (`CollectionType.CollectionPathSerializer`); the caller in
7//! [`super::complex_column`] has already stripped the VInt, so the slice reaching
8//! this module IS the serialized key and carries NO length prefix of its own.
9//!
10//! Historically this site carried its OWN type ladder — an allowlist of six
11//! scalar families with a `Value::Blob` default — so a COMPOSITE key
12//! (`frozen<udt>`, `tuple<…>`, a frozen collection) and roughly ten further
13//! scalar families surfaced as raw bytes, while the FROZEN spelling of the very
14//! same map decoded structurally. The fix is to delegate to
15//! [`super::V5CompressedLegacyParser::parse_value_from_raw_bytes`] — the
16//! structural decoder the SET branch already used for a set member's cell path,
17//! whose convention ("the entire slice IS the value") is exactly this one, and
18//! whose framing for a tuple/UDT (`[i32 BE len][bytes]` per component, `-1` =
19//! null, per Cassandra's `TupleType.buildValue`) is byte-identical to a
20//! composite CellPath's.
21//!
22//! Two properties this module owns, because delegation alone would lose them:
23//!
24//! 1. **The ORIGINAL-CASE type string is forwarded.**
25//!    `primitive_marshal_to_cql_short` matches marshal suffixes CASE-SENSITIVELY
26//!    (`s.ends_with("Int32Type")`), so lowercasing before delegation would fail
27//!    every marshal-form normalization and land straight back in an opaque blob —
28//!    which is precisely the no-schema `Statistics.db` path, where the key type
29//!    arrives in marshal form.
30//!
31//! 2. **Fixed-width keys are validated against the widths CASSANDRA accepts.**
32//!    `parse_value_from_raw_bytes` rejects only UNDER-width input (`< N`) because
33//!    its other callers hand it element bytes already bounded by an outer length
34//!    prefix, so trailing bytes cannot occur. A CellPath has no such outer bound
35//!    here: the whole slice is the key, so an over-long slice is corruption and
36//!    must not be decoded from its prefix.
37//!
38//!    The authority is `org.apache.cassandra.serializers.*.validate`, read at the
39//!    pinned `cassandra-5.0.8` tag (there is no clone on the build hosts; read via
40//!    `git show cassandra-5.0.8:src/java/org/apache/cassandra/serializers/<X>.java`
41//!    or the raw tag URL). **It is NOT a uniform `!= N`** — an earlier revision of
42//!    this header claimed that and was WRONG, which is why the rule is written out
43//!    per type here and mirrored literally by `cql_short_allowed_widths`:
44//!
45//!    * **`N` or `0`** (`size != N && !isEmpty` → an EMPTY buffer is LEGAL):
46//!      `Int32Serializer` 4, `LongSerializer` 8, `FloatSerializer` 4,
47//!      `DoubleSerializer` 8, `UUIDSerializer` 16, `TimestampSerializer` 8, and
48//!      `CounterSerializer` (which `extends LongSerializer`) 8.
49//!    * **strict `!= N`** (no empty buffer): `ShortSerializer` 2,
50//!      `ByteSerializer` 1, `SimpleDateSerializer` 4, `TimeSerializer` 8.
51//!    * **`size > 1`**, i.e. 0 or 1: `BooleanSerializer`.
52//!    * **`InetAddressSerializer`** RETURNS EARLY on empty
53//!      (`if (accessor.isEmpty(value)) return;`) and otherwise delegates to
54//!      `InetAddress.getByAddress`, so 0, 4 or 16. It is an `N`-or-`0` type, NOT
55//!      a strict one — an earlier revision of this header called it "the fifth
56//!      strict case" on the strength of a `grep` whose output line had run the
57//!      `isEmpty` test together with the `throw` from the
58//!      `catch (UnknownHostException)` block below it. Read the whole method, not
59//!      a grep of its `if`s.
60//!
61//!    #3612 encoded the `0` allowances as a FIDELITY fix with no behaviour change,
62//!    because the caller then decoded only a NON-EMPTY `path_bytes` — while warning
63//!    that "correct only because the caller filters" was one file from breaking.
64//!
65//!    **#3747 removed that filter, so these `0` rows are now load-bearing.** The
66//!    filter WAS the defect #3612 described: a legal empty `text`/`blob` key was
67//!    DROPPED from the `Value::Map`. The caller now decodes every cell path, so this
68//!    table decides an empty key's fate and the empty-key tests are reached by a real
69//!    read (UNIT-ONLY labels gone). Where it ADMITS `0` but no `Value` can carry it,
70//!    the decode below preserves the entry OPAQUELY; a typed one is **#3805**'s.
71//!
72//! # When this site may return `Err` — and why the line is drawn at Cassandra
73//!
74//! MEASURED through the public surface (issue #3612 review round 1): an `Err`
75//! from here does NOT reach the caller of a `SELECT`. It propagates out of
76//! `parse_complex_column`, and row assembly then SWALLOWS it — `row_data.rs`'s
77//! complex-column `match` has an `Err(e) => { tracing::debug!(…); break; }` arm
78//! (the ONLY handler, shared by both the user-facing read and the
79//! compaction/elements-out read, which are just the two arms producing
80//! `parse_result`). `break` leaves the column loop, so the failing column AND
81//! EVERY LATER ON-DISK COLUMN silently vanish from the row. Reproduced with a
82//! real `SELECT` over the committed Cassandra fixture: declaring `cm` as
83//! `map<int,int>` against its 70-byte on-disk UDT cell path returned exit 0 and
84//! `"cm": null, "tm": null` with every other column intact.
85//!
86//! A silently TRUNCATED ROW is more destructive than one wrongly-typed value, so
87//! this site does NOT invent error classes. The rule, and it is a rule:
88//!
89//! * **`Err` only where Cassandra's own `validate`/`split` THROWS** — a wrong
90//!   fixed width, a non-4/16-byte `inet`, or trailing bytes after a composite's
91//!   components. Those inputs are corrupt on Cassandra's own terms, so refusing
92//!   them adds no availability risk for data Cassandra would have read.
93//! * **NEVER `Err` merely because CQLITE cannot model the declared type.**
94//!   Cassandra reads such a key fine; only this reader cannot. That case returns
95//!   the opaque `Value::Blob` the shared decoder produced and reports it to the
96//!   caller, which `warn!`s once per column per row naming the column, the
97//!   declared type and how many entries were affected — so the row stays whole and
98//!   the gap is visible in the log rather than in a missing column.
99//!
100//! The swallow itself is a PRE-EXISTING defect of row assembly, not of this
101//! module, and is tracked separately (see the PR for #3612).
102//!
103//! ## The undecodable-key signal is REPORTED to the caller; nothing here `warn!`s
104//!
105//! There is no `warn!` in this module. [`Self::parse_cell_path_key_reporting`]
106//! runs ONCE PER MAP ENTRY and only SETS an `opaque_out` flag; `complex_column`'s
107//! map branch counts the entries whose key came back opaque and emits at most ONE
108//! line per column per ROW, carrying that count as `affected_entries`. WHY that is
109//! the right cardinality is stated ONCE, on `parse_cell_path_key_reporting`'s own
110//! doc comment, and is deliberately not restated here — an earlier revision of
111//! this header argued the OPPOSITE (that caller-side aggregation was "deliberately
112//! NOT taken"), outlived the change that took it, and contradicted that doc
113//! comment. One statement, at the site that owns the signal — and, since the
114//! prose was what drifted, the cardinality itself is now PINNED by a test:
115//! `warn_cardinality_tests` (declared at the foot of this file) asserts that two
116//! undecodable entries produce exactly ONE record carrying `affected_entries: 2`.
117//!
118//! What is recorded here, because the aggregate does not answer it, is a DIFFERENT
119//! question: the per-row line is not additionally DEDUPLICATED across rows, and
120//! neither available place to hold "already warned" state is worth its cost.
121//!
122//! * **Per reader instance.** There is no natural home — `V5CompressedLegacyParser`
123//!   is plain owned data with no interior mutability and the decode entry point
124//!   takes `&self`, so this needs a new `Mutex`/`RefCell` field touched on the hot
125//!   decode path. And it would not even work: the instance is built PER BLOCK
126//!   (`parsing/block_entries.rs`'s `parse_block_entries_at_now`, called per block
127//!   from the scan stream) and per point read, so the dedupe window is one block,
128//!   not one scan — a constant factor, for a lock.
129//! * **A process-lifetime `static` latch** (`Once`/`AtomicBool`) is worse than the
130//!   repetition, not merely insufficient: it would suppress the warning for a
131//!   DIFFERENT table read later in the same process, turning a noisy disclosure
132//!   into a missing one.
133//!
134//! # Decoder enumeration and exactness disposition (issue #3612 round 2)
135//!
136//! Enumerated by following `parse_value_from_raw_bytes`'s `match` rather than
137//! from anyone's list: **24 top-level arms**, plus the registry-bare-name UDT
138//! sub-path inside the final `other` arm — **25 reachable decode paths**. Every
139//! one is EXACT here, by exactly one of three mechanisms:
140//!
141//! | reachable decoder | how it is made exact |
142//! |---|---|
143//! | text / ascii / varchar (+3 marshal aliases) | whole slice by construction (UTF-8 validated over all of `data`) |
144//! | blob / bytes | whole slice by construction |
145//! | varint, inet | whole slice by construction (borrowed entire) |
146//! | decimal | whole slice by construction (`scale` = `data[..4]`, unscaled = `data[4..]`) |
147//! | int, bigint/counter, boolean, uuid/timeuuid, float, double, smallint, tinyint, timestamp, date, time | caller's ALLOWED-width table, per type, mirroring Cassandra's serializers (stronger than a consumption compare) |
148//! | inet (widths) | same table, `[0, 4, 16]` — `N`-or-`0`, two non-empty widths |
149//! | frozen list (`parse_frozen_list_value_raw`) | reported offset, was DISCARDED — now checked |
150//! | frozen set (`parse_frozen_set_value_raw`) | reported offset, was DISCARDED — now checked |
151//! | frozen map (`parse_frozen_map_value_raw`) | reported offset, was DISCARDED — now checked |
152//! | tuple (`parse_tuple_elements_raw`) | reported `&mut offset`, was DISCARDED — now checked |
153//! | UDT, marshal + registry-bare-name (`parse_raw_type_value`, whose UDT work is TWO inline field loops in `raw_type_value.rs` — the marshal one and the registry-bare one — not a call to `parse_udt_value`) | reported offset, was DISCARDED — now checked |
154//! | `frozen<T>` / `FrozenType(T)` | recursion for the VALUE; exactness is the inner arm's, and for a fixed-width inner it comes from the width table, which is why that table peels frozen first (B1) |
155//! | duration | the SHARED decoder's own assert, one layer down: its `"duration"` arm reports where the third VInt ended, so this module no longer walks the framing itself (#3631 unification) |
156//! | unknown type → opaque `Value::Blob` | whole slice by construction; also raises the caller-aggregated opaque-key signal (the `warn!` is the caller's — see above) |
157//!
158//! ## Nested consumption: THREE OF FOUR CLASSES ARE NOW REFUSED
159//!
160//! An earlier revision of this header carried a broad residual — "nested
161//! consumption is unchecked at every level below the first" — naming four classes:
162//! fixed-width scalars, nested tuples/UDTs, nested collections and `duration`. The
163//! first three of those are now REFUSED, so that heading is stated here in the PAST
164//! TENSE and only `duration` survives, as a DECIDED disposition rather than a gap.
165//!
166//! The tightening landed as **#3811** (`parse_value_from_raw_bytes` gained a
167//! consumption channel: it is a thin wrapper over
168//! `parse_value_from_raw_bytes_reporting` plus a consumption assert, so every
169//! bounded caller of the short name inherits the rule) and the UNIFICATION #3811
170//! asked for landed as **#3631**: there is ONE `require_fully_consumed`, in
171//! `typed_value.rs`, which every layer names, and this module's `duration`
172//! consumption special-case is GONE with it — the shared decoder's own assert
173//! reaches a trailing byte first (see `decode_reporting_consumption` below).
174//! What this module still owns is the fixed-width ALLOWED-width table, which is
175//! cell-path-specific and has no equivalent on the value side.
176//!
177//! The refusals are pinned by name in
178//! `row_decoder/raw_value/issue_3811_consumption_demo_tests.rs`:
179//!
180//! | class, as the old residual named it | now refused, by these tests |
181//! |---|---|
182//! | fixed-width scalars decoding from a prefix (a 5-byte `int`) | `bounded_int_over_width_is_refused` (control: `bounded_int_exact_decodes_ok`) |
183//! | nested tuples and UDTs leaving extra components unread | `bounded_tuple_with_trailing_byte_is_refused` (control: `bounded_tuple_exact_decodes_ok`); `nested_udt_trailing_garbage_is_refused` (control: `nested_udt_exact_decodes_ok`), plus its twins `structural_nested_udt_trailing_garbage_is_refused` and `inline_udt_trailing_garbage_is_refused` |
184//! | nested collections stopping at the declared count | `bounded_list_with_trailing_byte_is_refused` and `bounded_set_with_trailing_byte_is_refused` (control: `bounded_list_exact_decodes_ok`) |
185//!
186//! Consequently the collapse the old residual led with is GONE: measured on this
187//! tree, a `frozen<list<int>>` cell path of `[count=1][len=5][5B]` (13 bytes) is now
188//! REFUSED ("decoded only 4 of 5 byte(s)" — the NESTED element's width), while the
189//! well-formed `[count=1][len=4][4B]` (12 bytes) still decodes to
190//! `Frozen(List([Integer(7)]))`. The two no longer decode to one key, so the map
191//! entry a Python read used to lose to that collision is not lost any more. (The
192//! old header carried a "SYMPTOM: A PYTHON READ CAN SILENTLY LOSE A MAP ENTRY"
193//! section for that collapse; it described behaviour that no longer occurs and is
194//! deleted rather than kept as a war story.)
195//!
196//! A GENUINELY SHORT encoding stays LEGAL and that is deliberate: `TupleType.split`
197//! rule 1 permits omitted trailing components, which leaves `consumed == len` and is
198//! accepted. Cassandra cannot drop a UDT field (`AlterTypeStatement` at
199//! `cassandra-5.0.8` offers only `AddField`, `RenameFields`, `AlterField`), so
200//! schema evolution yields exactly these short encodings — refusing them would break
201//! ordinary evolved data.
202//!
203//! ### `duration` IS tolerated — parity-correct, decided under #3778 Option A
204//!
205//! The fourth class survives, at TWO sites, and only one of them is nested:
206//!
207//! * `raw_type_value.rs`'s `"duration"` arm — a duration NESTED inside a frozen
208//!   composite (its errors read `Frozen element '{}'`). The third `parse_vint` binds
209//!   `_remaining` and DISCARDS it, then `offset += duration_len` advances by the
210//!   DECLARED length.
211//! * `cell_value_scalar.rs`'s `CellKind::Duration` arm — a plain top-level CELL,
212//!   NOT nested. Leftover bytes emit one `warn!("… has {} extra bytes after
213//!   parsing")` and the value is returned.
214//!
215//! **Cassandra tolerates the same bytes**, which is why this is not a defect. Read
216//! at the pinned tag: `serializers/DurationSerializer.java` `deserialize` reads three
217//! VInts and returns, with no consumption check, and its `validate` (`:80-105`)
218//! enforces only `size >= 3` ("Expected at least 3 bytes for a duration (%d)"), the
219//! months/days 32-bit bounds and the same-sign rule — no upper bound.
220//! `grep -n "remaining\|hasRemaining\|limit()"` over that file plus
221//! `db/marshal/DurationType.java` gives ZERO hits. `TupleType.split` rule 4 refuses
222//! trailing bytes at the TUPLE FRAMING level, not inside one element's declared
223//! length.
224//!
225//! So this is a **DECIDED disposition, not an open gap**: the #3778 lead ruling took
226//! Option A (keep the tolerance, pin it, declare it) and explicitly REFUSED Option B
227//! (refuse the bytes), which would have converted reads Cassandra performs
228//! successfully into hard CQLite failures with no oracle supporting the strictness.
229//! An earlier revision of this header called the disposition open and tracked it as
230//! #3723; the deciding issue is **#3778**.
231//!
232//! The residual it leaves, accepted deliberately: two byte strings differing ONLY in
233//! trailing bytes inside `duration_len` decode to ONE, EQUAL `Value::Duration`. That
234//! is pinned at both sites by `row_decoder/issue_3778_duration_parity_tests.rs`
235//! (`two_encodings_differing_only_in_trailing_bytes_decode_equal_nested` and
236//! `…_cell`), whose header carries the oracle so a future reader does not "fix" it.
237//! That file also pins the ASYMMETRY: the third duration arm, `raw_value`'s bounded
238//! one, REFUSES the same input via `require_fully_consumed` — stricter than the
239//! oracle, filed as follow-up **#4038** (direction: relax to match the oracle) and
240//! deliberately unchanged here.
241//!
242//! None of this is patched with a second framing walk here: a call-site validator
243//! that must know about every decoder is precisely the shape this module replaced.
244//!
245//! # Presenting the key EXACTLY as the FROZEN spelling does (issue #3612, R3-F2/R7)
246//!
247//! **This is now true for every composite subject the corpus has, and it is
248//! achieved in ONE place, and that is the point of the current shape.**
249//!
250//! **`marshal_element::map_key_type_for_decode` is the single rule**, called by the
251//! MULTICELL map reader (`complex_column`) and the FROZEN map reader
252//! (`cell_value_complex`). Both hand the SAME key-type string to the SAME decoder,
253//! so their `Value` keys are equal by construction. Nothing in THIS file adjusts a
254//! key's presentation any more; the checks below borrow a peeled VIEW
255//! (`peeled_for_inspection`) and return the decoded value untouched.
256//!
257//! It got here in two steps, and the first was insufficient in a way worth keeping
258//! on the record:
259//!
260//! * **R7** made the multicell branch prefer the authoritative MARSHAL key type
261//!   (`prefer_udt_marshal_element`, #1340), fixing UDT and tuple keys, and paired
262//!   it with a value-level wrapper fixup on the multicell side only.
263//! * **Round 8** found that fixup was the instance fix, not the class fix: a
264//!   multicell `map<frozen<set<frozen<U>>>, int>` supplies
265//!   `FrozenType(SetType(UserType(..)))` while the frozen spelling supplies
266//!   `SetType(UserType(..))`, giving `Frozen(Set(Udt))` against `Set(Udt)` — the
267//!   same defect one nesting level down. Two readers producing two presentations
268//!   of one value is a CONSOLIDATION problem, so the fixup was deleted and the
269//!   normalization moved into the shared rule, where it strips the redundant outer
270//!   `FrozenType` from a MARSHAL key only. The strip is a NO-OP on the frozen
271//!   reader (Cassandra omits that marker inside a frozen collection), which is why
272//!   wiring both sides changes only the multicell side's output.
273//!
274//! Why the marker differs at all is Cassandra's own metadata: a MULTICELL map key
275//! must be explicitly frozen, so its marshal keeps `FrozenType`, while everything
276//! inside a FROZEN collection is already frozen, so the inner marker is omitted.
277//!
278//! Measured parity, per subject, unpeeled (`cqlite-core/tests/issue_3612_multicell_map_composite_key.rs`
279//! for the fixture-backed subjects; `cell_path_key_tests.rs` for the set-keyed one,
280//! which no fixture in the corpus supplies):
281//!
282//! | subject (multicell vs frozen) | before | after |
283//! |---|---|---|
284//! | `cm` vs `fcm` (UDT key) | `Udt` == `Udt` | unchanged, still equal |
285//! | `tm` vs `ftm` (UDT key) | `Udt` == `Udt` | unchanged, still equal |
286//! | `m_tuple_udt` vs `f_map_tuple_udt` (TUPLE key) | `Frozen(Tuple[Frozen(Udt),Int])` vs `Tuple[Udt,Int]` — **UNEQUAL** (fixed in R7) | `Tuple[Udt,Int]` both — **EQUAL, equal hash** |
287//! | set-of-UDT key (no fixture; unit-tested from the two marshal spellings) | `Frozen(Set[Udt])` vs `Set[Udt]` — **UNEQUAL** (round 8) | `Set[Udt]` both — **EQUAL, equal hash** |
288//!
289//! No subject remains non-parity. Value equality is asserted wherever the fixture
290//! stores the SAME logical key in both spellings (`cm`/`fcm`, `tm`/`ftm`, and
291//! `m_tuple_udt` id=3); the other tuple rows hold deliberately different data, so
292//! they are covered by `Value`-nesting equality, which is the property that
293//! generalises.
294//!
295//! # The asymmetry across the three cell-path/key readers (issue #3612)
296//!
297//! THIS PASSAGE IS THE SINGLE STATEMENT OF THE CROSS-READER COMPARISON.
298//! `read_assembly.rs` CITES it rather than paraphrasing: three paraphrases there were
299//! false, each one written while fixing the last (rounds 1-3 of #3612 review).
300//!
301//! For a key type CQLite models nowhere, TWO of the three serve an opaque `Value::Blob`:
302//! this multicell path (plus the caller-aggregated `warn!`) and the frozen-map reader
303//! (`parse_frozen_map_value`, via `read_frozen_element`). The THIRD — the multi-generation
304//! MERGED read — FAILS CLOSED instead, returning `Error::unsupported_format` from
305//! `composite_collection_unsupported` before any ordering decision is reached; serving an
306//! opaque blob there was deliberately abandoned. So there IS an availability difference
307//! between the single-generation readers and the merged read, tracked by issue #2339.
308//!
309//! For a key type CQLite DOES model (`tuple<…>`, a nested collection, a resolvable UDT)
310//! the divergence is WIDER, not narrower: the single-generation readers decode it
311//! STRUCTURALLY while the merged read still FAILS CLOSED. So #2339 is MERGE-side work,
312//! and nothing on this path waits on it.
313//!
314//! (`key_is_opaque_composite` IS that check's predicate: both guard sites — set element,
315//! map key — test it and return `composite_collection_unsupported`. Its only other consumer
316//! (its own `Frozen` arm recurses) is `sort_elements_by_cell_path`'s raw-byte ordering arm,
317//! DEFENSIVE only because the guard fires first. An earlier revision cited the predicate for
318//! "NO availability difference" — right symbol, conclusion exactly backwards.)
319//!
320//! They DIVERGE on CORRUPTION: only this path validates fixed widths and full
321//! consumption, so a multicell key with a wrong width or trailing bytes is
322//! REFUSED here (and, until the row-assembly swallow is fixed, that manifests as
323//! a truncated row) while the frozen spelling of the same map would decode it
324//! from a prefix. That asymmetry is intentional — this is the one site where the
325//! whole slice is known to BE the key — but it is not symmetric, and widening it
326//! to the frozen/set routes is out of #3612's scope.

330impl V5CompressedLegacyParser {
331    /// Parse a MULTICELL map's cell-path key, DISCARDING the undecodable-key
332    /// signal; see [`Self::parse_cell_path_key_reporting`], which is the
333    /// production entry point and carries the contract.
334    ///
335    /// TEST-ONLY, and gated so `-D dead-code` says so honestly: the only production
336    /// caller (`complex_column`'s map branch) takes the reporting form, because it
337    /// aggregates the signal across a row's entries. This wrapper exists solely to
338    /// keep this module's unit call sites on the simpler signature; an
339    /// `#[allow(dead_code)]` would have silenced a true statement instead.
340    #[cfg(test)]
341    pub(super) fn parse_cell_path_key(
342        &self,
343        data: &[u8],
344        type_str: &str,
345        column_name: &str,
346    ) -> Result<Value> {
347        let mut opaque = false;
348        self.parse_cell_path_key_reporting(data, type_str, column_name, &mut opaque)
349    }
350
351    /// Decode a MULTICELL map's cell-path key and REPORT whether it surfaced as
352    /// opaque bytes.
353    ///
354    /// `data` is the bare serialized key (the CellPath's VInt length prefix is
355    /// already stripped by the caller). `type_str` is the map's declared KEY type
356    /// in whatever spelling the authoritative source provided — a CQL short form
357    /// from the schema (`frozen<collide>`, `int`) or a Cassandra marshal form from
358    /// `Statistics.db` (`org.apache.cassandra.db.marshal.UserType(…)`) — and is
359    /// forwarded WITH ITS CASE INTACT (see the module header).
360    ///
361    /// `opaque_out` is set when the declared type is one this reader cannot model,
362    /// so the caller can aggregate. It is a caller-side signal rather than a
363    /// `warn!` here because this function runs ONCE PER MAP ENTRY: a scan of a
364    /// table with an unmodellable key type would emit `entries x rows` identical
365    /// lines, which floods the log, can exhaust log storage, and destroys the one
366    /// number an operator actually wants — HOW MANY entries were affected
367    /// (roborev round 8, finding 2). The caller emits at most one line per column
368    /// per row, carrying that count; the message's content is unchanged.
369    pub(super) fn parse_cell_path_key_reporting(
370        &self,
371        data: &[u8],
372        type_str: &str,
373        column_name: &str,
374        opaque_out: &mut bool,
375    ) -> Result<Value> {
376        let allowed = self.cell_path_key_allowed_widths(type_str);
377        if !allowed.is_empty() && !allowed.contains(&data.len()) {
378            return Err(Error::corruption(format!(
379                "Map key '{}' of type '{}' requires exactly {} bytes, got {}",
380                column_name,
381                type_str,
382                allowed
383                    .iter()
384                    .map(|w| w.to_string())
385                    .collect::<Vec<_>>()
386                    .join(" or "),
387                data.len()
388            )));
389        }
390        // ═══ THE EMPTY-BUFFER ADMISSION GATE ═══
391        //
392        // Consulted for EVERY empty cell path, BEFORE the decode — never only on
393        // a decode FAILURE. The gate, its Cassandra derivation, its placement
394        // (roborev job 449 finding C / #4079), why it is the TAG table and not
395        // the WIDTH table, and the exact set of families it does NOT reach all
396        // live in ONE place: `cell_path_empty`'s module header. It is shared with
397        // the SET member route (#4106), because `validateCellPath` decides both
398        // with one line. Do not restate any of it here.
399        //
400        // `opaque_out` stays UNSET on the typed branch: the flag exists to
401        // diagnose a key this reader CANNOT MODEL, and it now can. Leaving it set
402        // would emit a `warn!` per column per row for correct data, which is the
403        // misleading-diagnostic half of #3612.
404        if data.is_empty() {
405            if let Some(tag) = self.cell_path_empty_sentinel(type_str) {
406                return Ok(Value::Empty(tag));
407            }
408        }
409        // ONE decode, which also REPORTS what it consumed (see
410        // `decode_reporting_consumption`).
411        let (decoded, consumed) =
412            match self.decode_reporting_consumption(data, type_str, column_name, 0) {
413                Ok(v) => v,
414                // #3747's DOOR 1 — an empty buffer the ADMISSION GATE above did
415                // NOT admit. (DOOR 2 is the decode-succeeded-with-`Null` case
416                // below; the two labels are the file's own cross-reference and
417                // both are kept.) Behaviour here is EXACTLY what it was before
418                // #3805 slice 2, which is what makes the gate a strict ADDITION
419                // rather than a widening:
420                //   * the WIDTH table admitted the empty buffer but no sentinel
421                //     speaks for the family -> the pre-existing opaque policy.
422                //     Unreachable today (every `0`-admitting width family has a
423                //     tag, MEASURED) and kept because the width table and the tag
424                //     table are two authorities that could diverge again.
425                //   * otherwise -> the decoder's OWN error, verbatim. That is what
426                //     keeps `duration` (`for_cql_type` -> `None`, empty key `Err`,
427                //     MEASURED) and every composite refused instead of silently
428                //     becoming an opaque blob.
429                Err(_) if data.is_empty() && allowed.contains(&0) => {
430                    *opaque_out = true;
431                    return Ok(Value::blob(Vec::new()));
432                }
433                Err(e) => return Err(e),
434            };
435        // A PEELED VIEW FOR THE CHECKS ONLY — the value itself is returned exactly
436        // as the shared decoder produced it (see the return, and the module header's
437        // parity section). A `frozen<absent_udt>` key can come back as
438        // `Frozen(Blob)`, so the opaque-value test below must look THROUGH any
439        // wrapper or it silently stops diagnosing every frozen-spelled undecodable
440        // key. Borrowing rather than rebinding is what keeps the inspection from
441        // becoming a presentation change, which is the defect roborev round 8 found
442        // one nesting level down.
443        let probe = Self::peeled_for_inspection(&decoded);
444        // #3747's DOOR 2: the decode SUCCEEDED with `Null`. Keyed on the PEELED
445        // answer, never the width table (`inet` admits 0 and decodes) and never a
446        // byte length. Full argument + the four defects it caused: `frozen_map`.
447        if data.is_empty() && matches!(probe, Value::Null) {
448            *opaque_out = true;
449            return Ok(Value::blob(Vec::new()));
450        }
451        // THE EXACTNESS RULE. For a cell path the whole slice IS the key, so a
452        // decoder that stopped short read a PREFIX and two distinct byte strings
453        // would collapse to one logical key. Where the decoder can say how far it
454        // got, require it to have reached the end.
455        //
456        // This one comparison subsumes three separate behaviours, which is why it
457        // replaced the hand-rolled framing validator that preceded it (issue #3612
458        // review round 2): trailing bytes after the components (`pos < len`) are
459        // REFUSED; a partial 1-3 byte component-length header (also `pos < len`,
460        // because the decoders treat it as "trailing fields omitted" and do NOT
461        // advance past it) is REFUSED; and a genuinely SHORT encoding, whose
462        // omitted components leave `pos == len`, is ACCEPTED — which is exactly
463        // Cassandra 5.0.8 `TupleType.split`'s pair of rules (`if (position ==
464        // length) return copyOfRange(...)` and `if (position < length) throw`).
465        if let Some(consumed) = consumed {
466            if consumed != data.len() {
467                return Err(Error::corruption(format!(
468                    "Map key '{}' of type '{}' decoded only {} of {} byte(s); the whole \
469                     cell path must be the key (trailing bytes, or a partial trailing \
470                     component header, are corruption)",
471                    column_name,
472                    type_str,
473                    consumed,
474                    data.len()
475                )));
476            }
477        }
478        // The declared type is one this reader cannot model, so the shared
479        // decoder handed back the raw bytes. Report it to the caller — which
480        // `warn!`s once per column per row with the count — but do NOT return
481        // `Err`: an `Err` here is swallowed by row assembly into a silently
482        // truncated row (see the module header's error-budget rule), which is
483        // more destructive than the opaque value, and Cassandra itself reads
484        // such a key without complaint. Raising the signal only HERE is what
485        // distinguishes this from a key DECLARED `blob`, which is a correct
486        // decode and stays silent — the misleading-diagnostic half of #3612.
487        if matches!(probe, Value::Blob(_)) && !self.cell_path_key_declares_blob(type_str) {
488            *opaque_out = true;
489        }
490        // Returned EXACTLY as the shared decoder produced it. There is deliberately
491        // no presentation fixup here any more: both map readers now receive the same
492        // key-type string from `map_key_type_for_decode`, so they decode to the same
493        // `Value` by construction. A fixup on this side was how round 3 achieved
494        // parity for UDT keys and how it missed collection keys.
495        Ok(decoded)
496    }

498    /// Decode a cell-path key AND report how many bytes the decode consumed.
499    ///
500    /// `Ok((value, Some(n)))` — the decoder reported that it consumed `n` bytes.
501    /// `Ok((value, None))`    — the arm consumes the WHOLE slice by construction,
502    ///                          so there is nothing to compare (see below).
503    ///
504    /// # Why this exists rather than a post-hoc framing validator
505    /// Round 1 of review added a hand-rolled walk over the component framing to
506    /// catch trailing bytes. Round 2 found two more holes in the SAME class —
507    /// frozen list/set/map keys and `duration`, plus a partial trailing header —
508    /// because a validator at the call site has to know about every decoder, and
509    /// this one knew about two. Every composite decoder ALREADY reports a consumed
510    /// offset, which `parse_value_from_raw_bytes` used to DISCARD (`let (val, _)`)
511    /// until #3811 gave it a reporting twin; the correct shape is to keep that
512    /// offset instead of re-deriving it.
513    ///
514    /// # The `None` arms are exact, not unchecked
515    /// `None` is returned only where the arm's contract IS "the entire slice is the
516    /// value": text/ascii/varchar (validated UTF-8 over all of `data`), blob/bytes,
517    /// varint and inet (each borrows the whole slice), and decimal (scale from
518    /// `data[..4]`, unscaled from `data[4..]`). Fixed-width scalars also return
519    /// `None`, and for them exactness comes from the caller's ALLOWED-width table
520    /// instead. Finding B1 was that a `frozen<int>` reached this `None` with no
521    /// width pinned anywhere, and it was answered by making that table peel the
522    /// frozen wrapper; #4104 answers it upstream instead, by REFUSING the spelling
523    /// at both metadata entry points, so the table no longer peels (see
524    /// `cell_path_key_allowed_widths`). The opaque `Value::Blob` default likewise
525    /// borrows all of `data`.
526    ///
527    /// # Dispatch must mirror `parse_value_from_raw_bytes`
528    /// The guards below are the same predicates, in the same ORDER (frozen before
529    /// UDT, because `is_udt_type` is a substring match that also matches
530    /// `FrozenType(UserType(..))`).
531    ///
532    /// ## ADDING AN ARM THERE IS A MANUAL OBLIGATION HERE — no test enforces it
533    /// `cell_path_key_tests::every_composite_cell_path_key_spelling_is_consumption_checked`
534    /// runs a HAND-CURATED list and requires each spelling to refuse a trailing byte,
535    /// so it catches an arm BROKEN OR REMOVED here (its `cases.len()` pin catches a
536    /// case dropped from the list). It cannot catch the OPPOSITE direction — a
537    /// composite arm added to `parse_value_from_raw_bytes` and not here falls through
538    /// to the `None` "whole slice by construction" default and prefix-decodes
539    /// SILENTLY. An earlier revision of this doc claimed the guard did catch it.
540    /// Deriving it is FEASIBLE and is simply NOT DONE HERE — the reason is scope, not
541    /// impossibility. A scan pairing `parse_value_from_raw_bytes`'s `starts_with` literals
542    /// with this file's would match all ten (five inline in both files, five as the `const`s
543    /// below), but it needs a scanner that locates a fn body in another module's source, and
544    /// the one NON-literal arm — `other if is_udt_type(other)` — carries
545    /// no literal for it to pair, so it would stay uncovered either way.
546    fn decode_reporting_consumption(
547        &self,
548        data: &[u8],
549        type_str: &str,
550        column_name: &str,
551        depth: usize,
552    ) -> Result<(Value, Option<usize>)> {
553        if depth > MAX_TYPE_NESTING_DEPTH {
554            return Err(Error::corruption(format!(
555                "Map key '{}': type nesting depth {} exceeds maximum {}",
556                column_name, depth, MAX_TYPE_NESTING_DEPTH
557            )));
558        }
559        let lower = type_str.to_ascii_lowercase();
560        // Full literals rather than `format!("{M}…")`: this runs once per map
561        // ENTRY per row, and the six allocations were pure waste on a hot path.
562        const M_FROZEN: &str = "org.apache.cassandra.db.marshal.frozentype(";
563        const M_LIST: &str = "org.apache.cassandra.db.marshal.listtype(";
564        const M_SET: &str = "org.apache.cassandra.db.marshal.settype(";
565        const M_MAP: &str = "org.apache.cassandra.db.marshal.maptype(";
566        const M_TUPLE: &str = "org.apache.cassandra.db.marshal.tupletype(";
567
568        // frozen<T> / FrozenType(T): recurse on the inner type, then RE-WRAP,
569        // mirroring `parse_value_from_raw_bytes`'s frozen arm
570        // (`Ok(Value::Frozen(Box::new(inner)))`) exactly.
571        //
572        // The re-wrap is REQUIRED, and its absence used to be masked. This
573        // dispatcher previously returned the bare inner value because the
574        // cell-path key entry point peeled and re-applied a wrapper of its own; with
575        // that fixup deleted (roborev round 8), not wrapping here would make a
576        // SCHEMA-form key diverge from the frozen reader in the opposite direction —
577        // `frozen<set<int>>` reaches BOTH readers unchanged (its marshal is not
578        // UDT-bearing, so `map_key_type_for_decode` keeps the schema form), and the
579        // frozen reader renders it `Frozen(Set)`. Mirroring the reference decoder is
580        // what keeps the two equal in the schema case, exactly as the shared rule's
581        // strip does in the marshal case.
582        //
583        // Deliberately BEFORE the UDT arm: `is_udt_type` is a substring match that
584        // also matches `FrozenType(UserType(..))`.
585        if lower.starts_with("frozen<") || lower.starts_with(M_FROZEN) {
586            let inner = self.extract_frozen_inner_type(type_str)?;
587            let (value, consumed) =
588                self.decode_reporting_consumption(data, &inner, column_name, depth + 1)?;
589            return Ok((Value::Frozen(Box::new(value)), consumed));
590        }
591
592        if lower.starts_with("list<") || lower.starts_with(M_LIST) {
593            let elem = self.extract_collection_element_type(type_str, "list")?;
594            let (val, off) =
595                self.parse_frozen_list_value_raw(data, 0, &elem, column_name, depth + 1)?;
596            return Ok((val, Some(off)));
597        }
598        if lower.starts_with("set<") || lower.starts_with(M_SET) {
599            let elem = self.extract_collection_element_type(type_str, "set")?;
600            let (val, off) =
601                self.parse_frozen_set_value_raw(data, 0, &elem, column_name, depth + 1)?;
602            return Ok((val, Some(off)));
603        }
604        if lower.starts_with("map<") || lower.starts_with(M_MAP) {
605            let (k, v) = self.extract_map_types(type_str)?;
606            let (val, off) =
607                self.parse_frozen_map_value_raw(data, 0, &k, &v, column_name, depth + 1)?;
608            return Ok((val, Some(off)));
609        }
610        if lower.starts_with("tuple<") || lower.starts_with(M_TUPLE) {
611            let element_types = self.extract_tuple_element_types(type_str)?;
612            if element_types.is_empty() {
613                return Err(Error::schema(format!(
614                    "Map key '{}': empty tuple type '{}'",
615                    column_name, type_str
616                )));
617            }
618            let mut off = 0usize;
619            let elements = self.parse_tuple_elements_raw(
620                data,
621                &mut off,
622                data.len(),
623                &element_types,
624                column_name,
625                depth + 1,
626            )?;
627            return Ok((Value::Tuple(elements), Some(off)));
628        }
629        // UDT: both the marshal `UserType(..)` form and a registry-resolved bare
630        // name route through `parse_raw_type_value`, which reports the offset after
631        // the last field it consumed — including the "trailing fields omitted"
632        // early exit, which is what makes a partial trailing header visible here.
633        if Self::is_udt_type(type_str)
634            // ORIGINAL case, not `lower`: the callee re-looks-up with `type_str`
635            // and `get_udt` is a deliberately case-SENSITIVE map get, so a
636            // lowercased probe here would make this guard fire on keys the callee
637            // cannot resolve (and miss ones it can).
638            || self
639                .udt_registry
640                .as_ref()
641                .is_some_and(|r| r.get_udt_qualified(&self.keyspace, type_str).is_some())
642        {
643            let (val, off) = self.parse_raw_type_value(data, 0, type_str, column_name, depth)?;
644            return Ok((val, Some(off)));
645        }
646        // `duration`'s own three-VInt walk USED to live here, and was live only
647        // while `parse_value_from_raw_bytes` discarded the count its arm already
648        // had. #3811 made the short name assert `consumed == data.len()` and made
649        // that arm report where the third VInt ended, so the callee refuses a
650        // trailing byte one layer down and the walk here could never fire — dead
651        // code that only appeared to do the work. Folded out under #3631's
652        // ONE-implementation ruling (recorded beside `require_fully_consumed`);
653        // both layers refuse in the shared "decoded only N of M byte(s)" class, so
654        // `cell_path_key_tests`'s pinned assertions are unaffected. Everything
655        // reaching here consumes the whole slice by construction (see above) or is
656        // enforced by the callee: nothing left to compare.
657        Ok((
658            self.parse_value_from_raw_bytes(data, type_str, column_name, depth)?,
659            None,
660        ))
661    }

663    /// The declared KEY type as a [`CqlType`], or `None` when this module's own
664    /// classifiers cannot name it.
665    ///
666    /// Composed from the TWO normalizers already in this decode path — no third
667    /// parser, because a second opinion about a type spelling is the drift this
668    /// module's header calls out by name:
669    ///
670    ///   * a MARSHAL name goes through [`Self::native_marshal_to_cql_type`] — the
671    ///     crate's one marshal-class-to-[`CqlType`] table, and the very table
672    ///     `primitive_marshal_to_cql_short` (which the width classifier consults)
673    ///     is built on. It enforces the package rule, so `com.acme.Int32Type` is
674    ///     `None` here rather than silently CQL `int`.
675    ///   * everything else is a CQL short form and goes through
676    ///     [`CqlType::parse`], the crate's one CQL-type-string parser
677    ///     (case-insensitive, like the decoder's own lowercased matching).
678    ///
679    /// `CqlType::parse` cannot fail for a bare unrecognised name — it yields
680    /// `CqlType::Custom`, for which `EmptyValueType::for_cql_type` is `None` — so
681    /// an unmodelled type reaches the caller's opaque fallback rather than a
682    /// guessed family (#28).
683    /// # NO FROZEN PEEL — the frozen-scalar spelling is REFUSED UPSTREAM (#4104)
684    /// This used to peel `frozen<…>`/`FrozenType(…)` before classifying, and the
685    /// peel could only ever change the answer for a frozen SCALAR: for every LEGAL
686    /// frozen inner the peeled and unpeeled strings classify identically (a peeled
687    /// `set<int>`/`SetType(…)`/`address_type` has no empty-buffer tag, and neither
688    /// does `Frozen(..)`). A frozen scalar is not declarable CQL
689    /// (`CQL3Type.Raw::freeze()` throws — `cassandra-5.0.8:src/java/org/apache/
690    /// cassandra/cql3/CQL3Type.java:647-651`) and both metadata entry points now
691    /// refuse it, so the peel was dead. `cell_path_key_tests_frozen` pins the
692    /// reachability claim that makes it dead.
693    ///
694    /// `pub(super)` is #4106's, not this issue's: `cell_path_empty.rs` calls this
695    /// from a SIBLING module (`daadfced3`), so the visibility must survive the
696    /// peel removal — the rebase conflict here was visibility-vs-body, and both
697    /// sides win their own half.
698    pub(super) fn cell_path_key_cql_type(&self, type_str: &str) -> Option<CqlType> {
699        if type_str.contains("org.apache.cassandra.db.marshal.") {
700            return Self::native_marshal_to_cql_type(type_str);
701        }
702        CqlType::parse(type_str).ok()
703    }

705    /// Whether `type_str` DECLARES a blob key, i.e. whether `Value::Blob` is the
706    /// CORRECT decode result rather than the shared opaque default.
707    ///
708    /// The distinction cannot be made from the RESULT — a declared `blob` key and
709    /// an undecodable key both yield `Value::Blob` — so it is made from the
710    /// DECLARED type.
711    ///
712    /// # NO FROZEN PEEL — `frozen<blob>` is REFUSED UPSTREAM (#4104)
713    /// This used to peel `frozen<…>`/`FrozenType(…)` so that `frozen<blob>` was
714    /// recognised as a declared blob. `frozen<blob>` is not declarable CQL — a
715    /// blob is a `RawType`, which does not override the throwing base
716    /// `CQL3Type.Raw::freeze()` (`cassandra-5.0.8:src/java/org/apache/cassandra/
717    /// cql3/CQL3Type.java:647-651`) — and both metadata entry points now refuse it,
718    /// so the peel was dead: no LEGAL frozen inner (collection, tuple, UDT) is a
719    /// blob, so peeling one could never change this answer either.
720    pub(super) fn cell_path_key_declares_blob(&self, type_str: &str) -> bool {
721        // CQL spells a CUSTOM type as a SINGLE-QUOTED marshal class name
722        // (`'org.apache.cassandra.db.marshal.BytesType'`), so strip the quotes.
723        let t = type_str.trim().trim_matches('\'').trim();
724
725        // EXACT NAMES ONLY — never a suffix match, and never a synthesised package
726        // prefix (issue #3612, roborev round 9 finding 2).
727        //
728        // This used to ask `primitive_marshal_to_cql_short`, whose match is
729        // `s.ends_with("BytesType")`, and for a bare name it PREFIXED the canonical
730        // package first: `format!("org.apache.cassandra.db.marshal.{t}")`. That
731        // defeated the guard every other consumer relies on. `parse_value_from_raw_
732        // bytes` (raw_value.rs) and `cell_path_key_allowed_widths` both consult the
733        // normalizer ONLY when the name already `contains` the Cassandra package, so
734        // a foreign `com.acme.CustomBytesType` never reaches the suffix matcher and
735        // correctly decodes to an opaque `Value::Blob`. Synthesising the prefix here
736        // made that same name look like `BytesType`, so this function reported "a
737        // declared blob" and SUPPRESSED the warning — silencing the diagnostic in
738        // precisely the case it exists for, an unmodelled custom type.
739        //
740        // Deciding a type's identity from a name SUFFIX is inference from a name
741        // pattern, which #28 forbids; a closed set of exact names is not.
742        //
743        // Marshal names are matched CASE-SENSITIVELY on purpose: the decoder's own
744        // normalizer is case-sensitive, so `bytestype` does NOT decode as a blob and
745        // must NOT be reported as a declared one, or the two would disagree. The CQL
746        // short forms are case-INSENSITIVE because the decoder lowercases before
747        // matching them.
748        const CANONICAL_BLOB_MARSHAL: &str = "org.apache.cassandra.db.marshal.BytesType";
749        const BARE_BLOB_MARSHAL: &str = "BytesType";
750        if t == CANONICAL_BLOB_MARSHAL || t == BARE_BLOB_MARSHAL {
751            return true;
752        }
753        matches!(t.to_ascii_lowercase().as_str(), "blob" | "bytes")
754    }

756    /// A BORROWED view of `value` with any `Value::Frozen` wrappers seen through,
757    /// for INSPECTION ONLY.
758    ///
759    /// Deliberately takes and returns a reference: the checks in
760    /// [`Self::parse_cell_path_key_reporting`] must look through a wrapper, and the
761    /// returned value
762    /// must NOT be changed by having done so. The previous owned version rebound
763    /// `decoded`, which turned an inspection into a presentation change and is the
764    /// shape of roborev round 8's finding — parity is now the shared key-type
765    /// rule's job (`map_key_type_for_decode`), never this function's.
766    pub(crate) fn peeled_for_inspection(value: &Value) -> &Value {
767        let mut v = value;
768        while let Value::Frozen(inner) = v {
769            v = inner;
770        }
771        v
772    }

774    /// The EXACT byte width a fixed-width cell-path key must have, or `None` for
775    /// a variable-width / composite type (where the whole slice is consumed and
776    /// no width invariant applies).
777    ///
778    /// Accepts both spellings of the type. A marshal form is normalized through
779    /// the CASE-SENSITIVE [`Self::primitive_marshal_to_cql_short`], which returns
780    /// `None` for anything parameterised (`UserType(…)`, `TupleType(…)`,
781    /// `FrozenType(…)`, collections), so a composite key is never width-checked.
782    /// The byte widths a fixed-width cell-path key MAY have. Empty slice =
783    /// variable width (no invariant). A SLICE rather than one `usize` because
784    /// several families admit more than one width: every `N`-or-`0` type admits
785    /// the empty buffer, and `inet` admits 4 (IPv4) or 16 (IPv6) as well.
786    ///
787    /// # NO FROZEN PEEL — the frozen-scalar spelling is REFUSED UPSTREAM (#4104)
788    /// This used to peel `frozen<…>` before classifying, and finding B1 is why: a
789    /// RAW `frozen<int>` took the "contains `'<'` => variable width" branch, the
790    /// dispatcher's frozen arm recursed on `"int"`, matched no composite guard and
791    /// reported `None` consumption — so a 5-byte `frozen<int>` cell path decoded
792    /// `Value::Integer` from `data[0..4]` with no width check, no consumption check
793    /// and no `warn!`.
794    ///
795    /// B1 was answered by peeling because at the time "`frozen<int>` is not legal
796    /// CQL" was correctly rejected as a DEFENCE — a spelling handled in one helper
797    /// cannot be assumed impossible in another. #4104 makes it a REFUSAL instead of
798    /// a defence: `CQL3Type.Raw::freeze()` throws for every non-collection/tuple/UDT
799    /// (`cassandra-5.0.8:src/java/org/apache/cassandra/cql3/CQL3Type.java:647-651`),
800    /// and BOTH metadata entry points now reject the spelling, so it cannot arrive
801    /// here at all — pinned by `cell_path_key_tests_frozen`. The peel is dead for
802    /// every LEGAL frozen inner too: peeled or not, `frozen<set<int>>`,
803    /// `FrozenType(SetType(..))` and `frozen<address_type>` all classify as
804    /// variable-width.
805    fn cell_path_key_allowed_widths(&self, type_str: &str) -> &'static [usize] {
806        let type_str: &str = type_str.trim();
807        let short: &str = if type_str.contains("org.apache.cassandra.db.marshal.") {
808            match Self::primitive_marshal_to_cql_short(type_str) {
809                Some(s) => s,
810                None => return &[],
811            }
812        } else if type_str.contains('<') || type_str.contains('(') {
813            // A CQL-short composite (`frozen<…>`, `tuple<…>`, `map<…>`): variable width.
814            return &[];
815        } else {
816            // A CQL short form. `parse_value_from_raw_bytes` matches on the
817            // LOWERCASED spelling, so normalize the same way here or a `"Int"`
818            // from a hand-written schema would skip the check it then decodes under.
819            return Self::cql_short_allowed_widths(&type_str.to_ascii_lowercase());
820        };
821        Self::cql_short_allowed_widths(short)
822    }

824    /// The allowed widths of a canonical lowercase CQL short form.
825    ///
826    /// Kept as a single table so the marshal and short-form routes cannot drift
827    /// into two different opinions about a family's width.
828    fn cql_short_allowed_widths(short: &str) -> &'static [usize] {
829        match short {
830            // --- `N` OR `0`: `size != N && !isEmpty` throws, so EMPTY is legal ---
831            "int" | "float" => &[0, 4],
832            "bigint" | "counter" | "double" | "timestamp" => &[0, 8],
833            "uuid" | "timeuuid" => &[0, 16],
834            // `BooleanSerializer` is spelled `size > 1`, i.e. 0 or 1.
835            "boolean" => &[0, 1],
836            // --- STRICT `!= N`: these four admit no empty buffer ---
837            "tinyint" | "byte" => &[1],
838            "smallint" | "short" => &[2],
839            "date" => &[4],
840            "time" => &[8],
841            // `InetAddressSerializer.validate` RETURNS EARLY on empty and
842            // otherwise delegates to `InetAddress.getByAddress`, which takes a 4-
843            // or 16-byte address. So `inet` belongs to the `N`-or-`0` family, with
844            // TWO non-empty widths.
845            "inet" => &[0, 4, 16],
846            // Variable-width by definition: text/ascii/varchar, blob/bytes,
847            // varint, decimal, duration — plus every composite.
848            _ => &[],
849        }
850    }
851}
