1//! Issue #3847 — which byte widths a fixed-width CQL scalar admits on the
2//! `raw_value` READ path, and what an EMPTY buffer means there.
3//!
4//! # SCOPE: this is ONE OF TWO independent tables. It is NOT the only one.
5//!
6//! An earlier revision of this header called it "the ONE place" and said the UDT
7//! field decoders were reconciled TO it. **That was true of this branch before it
8//! merged `origin/main`, and it is false now** (roborev job 149). #3631/PR#3820
9//! moved the UDT field decoders to `row_decoder/typed_value.rs`, which answers the
10//! same question from its OWN table:
11//! `typed_value/scalar_rules.rs::empty_is_a_value`. So the repository currently has
12//! **two independent answers** to "what does an empty buffer mean for this type":
13//!
14//! | path | authority |
15//! |---|---|
16//! | `parse_value_from_raw_bytes` (`raw_value/reporting.rs`) | THIS module |
17//! | typed / UDT field decode (`typed_value.rs`) | `typed_value/scalar_rules.rs::empty_is_a_value` |
18//!
19//! **The drift risk is therefore REAL and NOT prevented by this module** — stating
20//! that plainly, because the previous wording advertised a guarantee that no longer
21//! exists, and a false claim of drift-prevention is worse than an acknowledged gap:
22//! it tells the next reader to stop looking. The two agree TODAY on the shape that
23//! matters (empty ⇒ null at consumed `0` for the fixed-width family); nothing
24//! enforces that they keep agreeing.
25//!
26//! Unifying them is deliberately NOT done here. It would mean editing
27//! `typed_value/` — code #3631 landed hours ago — under an issue whose subject is
28//! the `raw_value` path, and #3847's corpus census measured only this path. It is
29//! proposed as a follow-up on the issue thread (`REQ-3847-04`).
30//!
31//! # The oracle, and why it is `deserialize()` and not `validate()`
32//!
33//! `docs/round-artifacts/issue-3847-cassandra-oracle.md`, read at the pinned
34//! `cassandra-5.0.8` tag. A bounded value decoder is a READ path, so its
35//! Cassandra analogue is `TypeSerializer.deserialize`, and on that side the rule
36//! is **uniform, 12 of 12, with no per-type exceptions**: an EMPTY buffer
37//! deserializes to `null` for `int`, `bigint`/`counter`, `boolean`, `uuid`,
38//! `timeuuid`, `float`, `double`, `smallint`, `tinyint`, `timestamp`, `date` and
39//! `time` alike.
40//!
41//! `validate()` is NOT this path's oracle. It is not uniform — `smallint`,
42//! `tinyint`, `date` and `time` reject the empty buffer there — but it gates what
43//! may be WRITTEN, not what must be READ, and all four of those still
44//! *deserialize* empty to `null`. Reading is the permissive side of Cassandra's
45//! contract, and CQLite's reader must match Cassandra's reader.
46//!
47//! Corroboration from the other direction: `BooleanSerializer.serialize(null)`
48//! returns `ByteBufferUtil.EMPTY_BYTE_BUFFER`. Empty **is** the on-the-wire
49//! spelling of `null` for a fixed-width scalar, so a reader that refuses it
50//! cannot read data Cassandra legitimately writes.
51//!
52//! # Scope: BOUNDED decoders only, and that is not a shortcut
53//!
54//! Only a decoder handed an EXACTLY-bounded slice can observe an empty buffer at
55//! all: the length that says "zero bytes" has to come from somewhere. That is the
56//! case for a frozen collection element, a tuple/UDT component and a cell-path
57//! key, all of which carry an explicit component length. It is NOT the case for
58//! the offset-advancing cell/clustering decoders (`cell_value_scalar.rs`,
59//! `raw_type_value.rs`, `row_framing.rs`), where a fixed-width value is written
60//! with NO length prefix at all (`AbstractType.valueLengthIfFixed`) — an empty
61//! fixed-width value is not expressible there, for Cassandra either, so those
62//! families are out of scope rather than merely unvisited.
63//!
64//! # The five UDT framing sites, which had three different answers
65//!
66//! A UDT field's length header decides whether a field is absent (`-1`), present
67//! and empty (`0`) or present with bytes. Five sites route the `0`:
68//! `parse_udt_value`, `parse_nested_udt_from_registry`, `parse_inline_udt_value`
69//! and `raw_type_value.rs`'s two UDT arms (marshal/inline and registry-resolved).
70//! All five hand it to the SAME delegate today,
71//! `typed_value.rs::parse_simple_udt_field_value_at`, with an explicit `&[]`, and
72//! all five answer `null`. They did not always: before #3847 `parse_udt_value` and
73//! `raw_type_value.rs`'s marshal/inline arm routed through
74//! `create_empty_value_for_type` — a function since DELETED (#3631/PR#3820) — and
75//! answered "empty BLOB", while the other three answered `Err`.
76//! An `Err` there was the worse of the two, because `row_data.rs` `break`s its
77//! column loop on a failing column, so the failing column AND every later one
78//! silently became null.
79//!
80//! # THE CELL-PATH KEY: this rule REACHES it by delegation, and the key path
81//! # answers for itself
82//!
83//! `complex_column/cell_path_key.rs` has a separate WIDTH-ADMISSIBILITY table whose
84//! oracle is `validate()`: it admits `{n, 0}` for the eight permissive families but
85//! only `{n}` for `smallint`, `tinyint`, `date` and `time`, and the stricter table
86//! wins for those four. That much is unchanged.
87//!
88//! **TWO CLAIMS THAT USED TO STAND HERE WERE FALSE, and each cost something:**
89//!
90//! 1. *"No READ reaches an empty cell path — the multicell map caller filters
91//!    `path_bytes.is_empty()` — so the divergence is unit-observable only, a
92//!    residual and not a defect."* **#3747 REMOVED that caller guard on purpose**
93//!    (and #4106 removed the SET branch's identical one, for the identical
94//!    reason: a zero-length cell path is the EMPTY component, not its absence);
95//!    its tests now carry `!! REACHABILITY: THE EMPTY-KEY CASES BELOW ARE NOW
96//!    REACHED BY A REAL READ`. A stale reachability argument is the worst kind of
97//!    comment: it reads as a licence to stop looking.
98//! 2. *"This rule is about VALUES and does not reach the key path."* **It reaches it
99//!    by DELEGATION** — `cell_path_key.rs` decodes through
100//!    `parse_value_from_raw_bytes`. Widening this rule therefore changed KEY
101//!    decoding, and it was not a residual: #3747's opaque policy sat on the
102//!    decoder's `Err` branch and stopped firing once the decode began SUCCEEDING
103//!    with `Null`, so `an_empty_key_of_an_n_or_zero_type_is_preserved_opaquely`
104//!    FAILED in the gate of record. Grepping `cell_path_key.rs` for this module's
105//!    symbols found nothing and looked like proof of no coupling; the coupling is
106//!    through the shared decoder, not through a name.
107//!
108//! **What is true now:** `{n, 0}` -> `null` is the rule for a VALUE. A KEY cannot
109//! take that answer — Cassandra has no null map key — so `cell_path_key.rs` applies
110//! #3747's empty -> OPAQUE answer (empty blob plus `opaque_out`) for itself, KEYED ON
111//! THIS DECODER'S ANSWER: it delegates, and when an empty buffer comes back `Null` it
112//! substitutes the opaque key. It does NOT inherit this rule, and it no longer depends
113//! on the decode FAILING (the door #3847 shut).
114//!
115//! **A third correction, from the fix round itself:** the first attempt put that check
116//! BEFORE the delegation, gated on the key table admitting width 0. That is too broad
117//! and broke `inet`, which admits `[0, 4, 16]` and whose empty buffer decodes to a real
118//! `Value::Inet(empty)` (`InetAddressSerializer.validate` returns early on empty). The
119//! width table says what is ADMISSIBLE; only the decode says whether a value could be
120//! PRODUCED — so the policy has to read the answer, not the table. Three false
121//! statements have now stood in this one header; each was a claim about code that had
122//! moved underneath it.
123//!
124//! # Why this rule lives under `raw_value`
125//!
126//! Its sole caller is `raw_value/reporting.rs` (the `parse_value_from_raw_bytes`
127//! path, #3847's named subject). It was ALSO used by this branch's own UDT field
128//! decoders until the `origin/main` merge; #3631 superseded those with
129//! `typed_value.rs`, so the UDT half is no longer this module's business — see the
130//! SCOPE note at the top. It is a child of
131//! `raw_value` rather than a sibling registered in `mod.rs` because `mod.rs` is
132//! over the campsite file-size ratchet ceiling and cannot take a new line
133//! (epic #1116).

135/// An ADMISSIBLE fixed-width slice, and which of the two admissible shapes it is.
136///
137/// Inadmissibility is deliberately NOT a variant: each caller family formats its
138/// own corruption message (they differ, and their wording is asserted by existing
139/// tests), so the classifiers below report it as `None`.
140#[derive(Debug, Clone, Copy, PartialEq, Eq)]
141pub(in crate::storage::sstable::reader::parsing::row_decoder) enum FixedWidthCell {
142    /// The EMPTY buffer — Cassandra's on-the-wire spelling of `null`.
143    ///
144    /// The caller MUST decode it to [`crate::types::Value::Null`] and, where it
145    /// reports consumption, report **`0`** — never the type's width `n`. Reporting
146    /// `n` here would make the caller's fully-consumed assert refuse the very
147    /// value this classification admits (that composition is the whole substance
148    /// of #3847: relaxing the width guard alone is a defect, not the fix).
149    Null,
150    /// A non-empty slice wide enough for the type: `data.len() >= n`, from
151    /// [`admissible_at_least`] — the sole remaining classifier. The caller may read
152    /// the type's first `n` bytes.
153    ///
154    /// An `admissible_exactly` sibling existed while this branch carried its own UDT
155    /// field decoders; #3631 superseded those with `row_decoder/typed_value.rs`, so it
156    /// was removed with them rather than left as an uncalled function. Referencing it
157    /// here would be a broken intra-doc link (roborev job 147).
158    Bytes,
159}
160
161/// Accepted widths `{0} ∪ {w : w >= n}`.
162///
163/// For a caller that reports its consumption and inherits a fully-consumed
164/// assert: an over-width slice is admitted here and refused THERE, because the
165/// arm reports `n` and leaves the tail unconsumed. The composed accepted set is
166/// `{n, 0}`, which is Cassandra's.
167pub(in crate::storage::sstable::reader::parsing::row_decoder) fn admissible_at_least(
168    data: &[u8],
169    n: usize,
170) -> Option<FixedWidthCell> {
171    if data.is_empty() {
172        Some(FixedWidthCell::Null)
173    } else if data.len() >= n {
174        Some(FixedWidthCell::Bytes)
175    } else {
176        None
177    }
178}
