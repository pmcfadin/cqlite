1//! Issue #1640 (Epic K, finding **K1**): the single V5CompressedLegacy
2//! partition/row emit driver.
3//!
4//! The parser performance audit (`docs/reports/parser-performance-audit-2026-07-01.md`)
5//! found the partition/row emit skeleton — partition-header parse →
6//! END_OF_PARTITION / range-tombstone-marker checks → row-body decode →
7//! boundary peek → `ParseStep` advance / `flush_and_emitted!` — duplicated
8//! across five emit functions, with the subtle issue-#932 row-write-timestamp
9//! coexistence decision hand-copied into the two sliding-window loops. "This is
10//! how parity regressions are manufactured": a future tombstone fix must land in
11//! N places or the paths silently diverge.
12//!
13//! This module owns:
14//! - [`row_write_timestamp`] — the ONE issue-#932 row-write-timestamp decision.
15//! - [`SlidingPartitionPolicy`] / [`MarkerOutcome`] /
16//!   [`V5CompressedLegacyParser::drive_partition_sliding`] — the ONE bounded
17//!   sliding-window partition skeleton, driven by policy hooks that capture the
18//!   per-consumer differences (streaming-scan timestamps vs per-element
19//!   compaction rows).
20//!
21//! K1 is the HEAD of the K-emit chain: K2 (#1641 non-allocating boundary peek),
22//! K3 (#1642 positional row emit), K4 (#1643 `Arc` key handles) are separate
23//! lanes and are NOT folded in here.

34/// Issue #932 (K1): the single row-write-timestamp coexistence decision.
35///
36/// A `HAS_DELETION` row may ALSO carry a liveness timestamp (surviving cells
37/// written strictly after the row deletion). Prefer that liveness timestamp as
38/// the row timestamp so those cells inherit it and are NOT shadowed by the older
39/// row deletion during reconcile; fall back to `markedForDeleteAt` only for a
40/// PURE row tombstone (which has no `HAS_TIMESTAMP`). `0` when the row carries
41/// neither a liveness timestamp nor a deletion.
42///
43/// Formerly hand-copied into `parse_one_partition_with_timestamps`
44/// (`block_emit_windowed.rs`) and `parse_one_partition_for_compaction`
45/// (`compaction.rs`); centralized here so the decision lives in exactly one
46/// place (audit finding K1).
47pub(super) fn row_write_timestamp(row_header_opt: &Option<RowHeader>) -> i64 {
48    let row_tombstone = row_header_opt.as_ref().filter(|h| h.is_row_tombstone());
49    row_header_opt
50        .as_ref()
51        .and_then(|h| h.timestamp)
52        .or_else(|| row_tombstone.map(|h| h.row_tombstone_deletion_time()))
53        .unwrap_or(0)
54}

56/// How the driver should advance after a policy handled a range-tombstone marker.
57///
58/// `Unparseable` and `Refused` are two of the three states ONE signal used to
59/// conflate (issue #3721), and the distinction between them is a FRAMING one,
60/// decided from state the caller already holds — never a severity judgement and
61/// never a byte pattern:
62///
63/// * `Unparseable` — the marker could not be PARSED, so there is no resume
64///   offset, and the cause is PRESERVED: `NeedMore` on a non-final chunk (a
65///   refill may still complete the marker) and the preserved error propagated on
66///   the FINAL chunk, where no refill is coming and completing the partition
67///   would report success with the marker — and every later row — missing.
68///
69///   The third state, `Stop`, is GONE (roborev job 78). It expressed "this parse
70///   failure IS a framing terminator", which let the FINAL chunk complete the
71///   partition SUCCESSFULLY without the marker: a silently truncated `SELECT` on
72///   the read path, and a dropped tombstone in WRITTEN output on the compaction
73///   path (roborev job 16). Both policies produced it and the meaning was wrong
74///   for both, so the variant is REMOVED rather than left available — a variant a
75///   future policy can reach for is how this defect came to be written twice. See
76///   `range_marker_error`'s module docs for the two facts that settle it and the
77///   Cassandra authority.
78/// * `Refused` — the marker WAS parsed (a resume offset exists and the partition
79///   body continues there) and the policy cannot represent it. Corruption with a
80///   valid resume point, which no refill can fix; reporting it as `Stop` truncated
81///   the partition and returned `Ok`. Both policies produce it: the timestamps
82///   policy when the read-side shadow FSM refuses a bound kind, and the compaction
83///   policy for an unrecognised bound kind of its own (#3808) — where a SKIP is
84///   worse still, because that policy's rows are written to a new SSTable.
85pub(super) enum MarkerOutcome {
86    /// The marker was consumed; continue the row loop at this offset.
87    Advanced(usize),
88    /// The marker could not be PARSED — no resume offset exists — and the parse
89    /// error is carried here rather than discarded (issue #3721).
90    ///
91    /// The driver, which is the only holder of the chunking state, then decides
92    /// on a FRAMING fact and never on a byte pattern:
93    ///
94    /// * **non-final chunk** — the marker body may simply straddle the window
95    ///   boundary, which is the one explanation a refill can fix, so this is
96    ///   `NeedMore` — the behaviour the removed `Stop` variant had on a non-final
97    ///   chunk, the one half of its meaning that was right;
98    /// * **final chunk** — no further bytes can arrive, so "cannot parse this
99    ///   marker" is corrupt or truncated data and NOT a boundary. The preserved
100    ///   cause is propagated instead of being converted into a successful
101    ///   partition completion.
102    ///
103    /// EVERY policy produces this from its marker-PARSE-failure arm, and the harm
104    /// it prevents is NOT scoped to written output:
105    ///
106    /// * `timestamp_policy` — the USER-FACING read. Completing the partition here
107    ///   returns `Ok` with the tombstone and every later row of the partition
108    ///   missing, and nothing downstream rejects it (`block_emit`'s
109    ///   `partition_complete` flag gates only the #3095 static-only emission). A
110    ///   silently truncated `SELECT` is this issue's PRIMARY harm (roborev job 78).
111    /// * `compaction::CompactionPolicy` — the same omission in output that is
112    ///   WRITTEN, so the rows the dropped tombstone shadowed come back durably, on
113    ///   disk (roborev job 16) — the same harm as the unrecognised bound kind
114    ///   [`MarkerOutcome::Refused`] covers (#3808), for a parse failure instead of
115    ///   an unrepresentable kind.
116    Unparseable(Error),
117    /// The marker was PARSED but cannot be represented faithfully (issue #3721):
118    /// corruption at a known resume point. Propagated to the caller of the read —
119    /// see [`super::range_marker_error::range_marker_refused`].
120    Refused(Error),
121}

123/// Issue #3809 (Finding 1) — the DISCRIMINATED outcome of a data-row policy hook.
124///
125/// # Why one `Err` channel was not enough
126///
127/// Issue #3782 gave [`SlidingPartitionPolicy::on_data_row`] an error channel
128/// meaning *the row FAILED TO DECODE*, and made the DRIVER — never the policy —
129/// decide tolerance from its authoritative `at_final_chunk`: at the final chunk no
130/// further bytes can arrive, so the failure is truncation/corruption and is
131/// refused; mid-window it is the ordinary straddling-row case and is answered with
132/// `NeedMore`. That is exactly right for its subject, which is a
133/// BYTES-AVAILABILITY question.
134///
135/// Issue #3809 needs the opposite disposition for a different subject. Its
136/// clustering-identity check
137/// (`CompactionRowData::require_tombstone_clustering_identity`) fires only AFTER
138/// the row DECODED successfully: a row deletion reached the builder having
139/// recovered fewer clustering values than its table declares, so emitting it would
140/// hand the merge a deletion that identifies no row. **No amount of refilling can
141/// make a short clustering become full-arity**, so "maybe more bytes will arrive"
142/// is not merely unhelpful there, it is semantically inapplicable — and on every
143/// entry point that declares [`BufferExtent::Window`](super::BufferExtent::Window)
144/// (the point and promoted readers, the block-by-block scans, the windowed emit)
145/// `at_final_chunk` is `false`, so a single undiscriminated `Err` channel would
146/// convert the refusal into a refill request and silently truncate the read: the
147/// very tolerant-tail data loss both issues exist to remove.
148///
149/// # Why a distinct OUTCOME rather than a kind test at the driver
150///
151/// Two shapes were available. A kind test at the driver (`if err.is_refusal()`)
152/// would need a discriminable marker on [`crate::error::Error`], i.e. either a new
153/// public variant — a public-surface change nothing in this repo detects the drift
154/// of (#3366), and one that would retitle #3809's deliberately-chosen
155/// `Corruption` telemetry bucket — or a message-text test, which the no-heuristics
156/// mandate (#28) forbids outright.
157///
158/// A distinct outcome fits this trait instead, for three reasons:
159///
160/// * This module ALREADY owns a policy-outcome enum of exactly this shape
161///   ([`MarkerOutcome`]), where the policy reports what it found and the driver
162///   decides how to advance.
163/// * It makes the data-losing default UNREPRESENTABLE, which is the argument
164///   [`BufferExtent`](super::BufferExtent) itself is built on. Had the hook kept a
165///   `Result`, a future `?` inside a policy body — the most natural thing to write
166///   — would route a refusal into the TOLERATED channel silently, and that is the
167///   defaulted-flag defect #3782 removed, reintroduced one layer up. With no
168///   `Result` in the signature, `?` does not compile and every failure site must
169///   NAME which of the two it is.
170/// * Both dispositions stay literally true and are readable side by side, so the
171///   trait no longer carries two contracts on one channel.
172///
173/// The cost is stated rather than hidden: a policy that acquires a genuine
174/// plumbing error (neither a decode failure nor a refusal) has no `Err` to return
175/// and must classify it. No policy has one today — all three route a
176/// `parse_row_data_*` `Result` and nothing else — and being forced to choose is
177/// the point.
178#[derive(Debug)]
179pub(super) enum DataRowOutcome {
180    /// The row decoded and was handled; continue the row loop at this offset.
181    Decoded(usize),
182    /// The policy DECLINES the row with no error to report. Unchanged pre-#3782
183    /// behaviour: end-of-partition on the final chunk, else `NeedMore`.
184    ///
185    /// `dead_code`-EXPECTED, and the reason is worth recording rather than
186    /// silencing: NO production policy declines TODAY. Both classify their one
187    /// failure since #3782 (`DecodeFailed`), so the decline path is reached only by
188    /// the driver's `StubPolicy` test harness. That was
189    /// already true on `main` and merely INVISIBLE there, because the hook returned
190    /// `Option<usize>` and `None` is a std variant no lint can call unconstructed.
191    /// It is kept because the DRIVER's disposition of it is load-bearing contract —
192    /// distinct from both failures, pinned by test (f) — and deleting the variant
193    /// would delete that behaviour along with its test.
194    ///
195    /// `#[expect]` rather than `#[allow]` so the allowance is SELF-RETIRING: an
196    /// `expect` that is never triggered is itself a `-D warnings` error, so this
197    /// reds the moment a policy DOES start constructing the variant — i.e. exactly
198    /// when the reason recorded above stops being true.
199    ///
200    /// The `cfg_attr` predicate is REQUIRED and was measured, not guessed: with no
201    /// attribute at all, `dead_code` fires in three of the four configurations and
202    /// stays SILENT in exactly one — cqlite-core's own `--lib` test build WITH
203    /// `write-support`, where the `StubPolicy` harness (itself `write-support`-gated)
204    /// is the sole constructor. A bare `#[expect(dead_code)]` is therefore
205    /// UNFULFILLED there and FAILS the gate of record's `core-tests`
206    /// (`-D unfulfilled-lint-expectations`, implied by `-D warnings`) — measured.
207    /// So the expectation is asserted precisely where the variant IS unconstructed,
208    /// which also makes the predicate a second statement of the reason above: if the
209    /// harness ever stops being the only (or a `write-support`-gated) constructor,
210    /// this reds too, naming the lint rather than failing silently.
211    #[cfg_attr(
212        not(all(test, feature = "write-support")),
213        expect(
214            dead_code,
215            reason = "no production policy declines today; constructed only by the \
216                      driver's StubPolicy test harness, whose disposition of it is \
217                      pinned by test (f)"
218        )
219    )]
220    Declined,
221    /// The row FAILED TO DECODE, with the decoder's error preserved (issue #3782).
222    /// A BYTES-AVAILABILITY answer: the policy does NOT decide tolerance, the
223    /// driver does, from `at_final_chunk` — refused at a proven-complete buffer,
224    /// tolerated as a straddling row mid-window.
225    DecodeFailed(Error),
226    /// The row DECODED but MUST NOT be emitted (issue #3809): a semantic refusal.
227    /// The driver propagates it UNCONDITIONALLY — `at_final_chunk` is not
228    /// consulted, because the question is not about bytes and refilling the window
229    /// cannot change the answer.
230    Refused(Error),
231}

233/// Per-consumer policy for the bounded sliding-window partition skeleton
234/// (issue #1640, K1). The driver owns the framing; each policy owns exactly the
235/// three behaviours that differ between the streaming-scan timestamps path and
236/// the per-element compaction path.
237///
238/// Both policies buffer emitted rows into the driver-owned `pending` vec (never
239/// forwarding directly), so a mid-partition `NeedMore` re-parse cannot double-
240/// emit (issue #827): `pending` is flushed only when the partition is confirmed
241/// complete.
242pub(super) trait SlidingPartitionPolicy {
243    /// The row carrier this policy emits.
244    type Row;
245
246    /// Called once, after the partition header is parsed, before the row loop.
247    /// `partition_deletion` is the header's `Option<(markedForDeleteAt µs,
248    /// localDeletionTime s)>`. The timestamps policy opens a read-side shadow
249    /// here (when shadowing); the compaction policy pushes a synthetic
250    /// partition-delete row for a partition tombstone (issue #1072).
251    fn on_partition_open(
252        &mut self,
253        partition_key: RowKey,
254        partition_deletion: Option<(i64, i32)>,
255        schema: &TableSchema,
256        pending: &mut Vec<Self::Row>,
257    );
258
259    /// Handle a range-tombstone marker at `offset`. The timestamps policy feeds
260    /// the range-tombstone FSM (or skips on a physical read); the compaction
261    /// policy pairs bound markers into `RangeMarker` rows (issue #933).
262    fn on_range_marker(
263        &mut self,
264        data: &[u8],
265        offset: usize,
266        schema: &TableSchema,
267        pending: &mut Vec<Self::Row>,
268    ) -> MarkerOutcome;
269
270    /// Decode and handle one data row at `offset`, pushing any emitted row into
271    /// `pending`. Reports which of FOUR things happened via [`DataRowOutcome`];
272    /// the distinction between the last two is load-bearing and is the ONE place
273    /// issue #3782's contract and issue #3809's are reconciled.
274    ///
275    /// * [`DataRowOutcome::Decoded(next_offset)`](DataRowOutcome::Decoded) — the
276    ///   row decoded; continue at `next_offset`.
277    /// * [`DataRowOutcome::Declined`] — the policy declines the row with no error
278    ///   to report. The driver treats it exactly as it always has:
279    ///   end-of-partition on the final chunk, else `NeedMore`.
280    /// * [`DataRowOutcome::DecodeFailed(e)`](DataRowOutcome::DecodeFailed) — the
281    ///   row FAILED TO DECODE, with `e` preserved (issue #3782) — typically a
282    ///   COLUMN inside it ([`crate::Error::ColumnDecode`], #3721). Serving the row
283    ///   without that column, or ending the partition early, are both silent data
284    ///   loss. The policy does NOT decide tolerance; the DRIVER does, from
285    ///   `at_final_chunk`.
286    /// * [`DataRowOutcome::Refused(e)`](DataRowOutcome::Refused) — the row DECODED
287    ///   and must not be emitted (issue #3809). The driver propagates `e`
288    ///   UNCONDITIONALLY and never consults `at_final_chunk`.
289    ///
290    /// # Which failures the driver may tolerate under a [`BufferExtent::Window`],
291    /// and why the line is drawn at SEMANTICS rather than byte availability
292    ///
293    /// A `Window` caller (the point and promoted readers, the block-by-block
294    /// scans, the windowed emit) drives this loop with `at_final_chunk == false`,
295    /// where a `DecodeFailed` becomes `ParseStep::NeedMore` — the straddling-row
296    /// refill protocol those readers depend on. That is CORRECT for `DecodeFailed`
297    /// and ONLY for it: the question a decode failure asks is *were all this row's
298    /// bytes present?*, more bytes can still arrive, and the answer may genuinely
299    /// change on the next chunk. Measured over 42 well-formed corpus tables
300    /// (10913 rows) that path fires 614 times, ALL with
301    /// `at_final_chunk == false`.
302    ///
303    /// A `Refused` outcome asks nothing about bytes. The decode already returned
304    /// `Ok`; the row is fully framed and structurally complete, and the policy has
305    /// judged its CONTENT unrepresentable — a row deletion that recovered fewer
306    /// clustering values than its table declares, and so identifies no row
307    /// (`CompactionRowData::require_tombstone_clustering_identity`, #3809). No
308    /// amount of refilling can make a short clustering become full-arity, so
309    /// "maybe more bytes will arrive" is not a weaker answer there, it is an
310    /// INAPPLICABLE one — and answering it that way would turn the refusal into a
311    /// refill request on every `Window` entry point, silently truncating the read.
312    /// A refusal is therefore NEVER tolerated, at any extent.
313    ///
314    /// Before #3782 this returned `Option<usize>`, so a decode error and "no row
315    /// here" were the same value and every error was silently swallowed as
316    /// end-of-partition — which is #3721's defect at this layer, and the same
317    /// contract both issues arrived at independently. Before #3809 the two FAILURES were the same value, so a
318    /// refusal inherited the decode failure's tolerance. There is deliberately no
319    /// `Result` in the signature: a `?` inside a policy body is the most natural
320    /// thing to write and would route a refusal into the tolerated channel
321    /// silently — the data-losing default [`BufferExtent`] exists to make
322    /// unrepresentable. Each failure site must NAME which one it is.
323    fn on_data_row(
324        &mut self,
325        data: &[u8],
326        offset: usize,
327        schema: &TableSchema,
328        reader: &crate::storage::sstable::reader::types::SSTableReader,
329        resolution: &RowColumnResolution,
330        pending: &mut Vec<Self::Row>,
331    ) -> DataRowOutcome;
332
333    /// Called once per partition, AFTER its last row, on every `Emitted` return —
334    /// immediately before `pending` is flushed to the external emit. A
335    /// mid-partition `NeedMore` discards `pending` and never calls this, so a row
336    /// pushed here can never be emitted twice.
337    ///
338    /// `complete` distinguishes the two ways a partition parse ends (issue #3095,
339    /// reconciling this hook with `block_emit*`'s own `partition_complete` guard):
340    /// * `true` — the parse observed a STRUCTURAL end: the `END_OF_PARTITION`
341    ///   marker, or the next partition's header. A well-formed SSTable always ends
342    ///   a partition body this way.
343    /// * `false` — the parse ran out of buffer on the FINAL chunk, hit an
344    ///   unrepresentable range marker, or a policy declined a row. The partition
345    ///   body was only partially observed (truncated/corrupt), so "this partition
346    ///   yielded no clustering row" is NOT knowable.
347    ///
348    /// Since #3782 a row DECODE ERROR at the final chunk no longer reaches here at
349    /// all, and since #3809 nor does a row REFUSAL at any extent: the driver
350    /// returns that error instead of flushing a partial partition. The three
351    /// `complete == false` cases above are unchanged.
352    ///
353    /// Exists for Cassandra's static-content-on-an-empty-partition rule
354    /// (`SelectStatement.processPartition()`, issue #3095): a partition whose
355    /// static row is live but which yielded NO clustering row returns exactly one
356    /// result row, and "yielded no clustering row" is only knowable at a
357    /// structurally-confirmed partition end. Defaults to a no-op so a policy with
358    /// no partition-level output (the compaction policy) is unaffected.
359    fn on_partition_close(
360        &mut self,
361        _schema: &TableSchema,
362        _pending: &mut Vec<Self::Row>,
363        _complete: bool,
364    ) {
365    }
366}

368impl V5CompressedLegacyParser {
369    /// The single bounded sliding-window partition skeleton (issue #1640, K1).
370    ///
371    /// Parses exactly ONE partition from the front of `data`, driving the
372    /// per-consumer `policy` hooks, and reports how the parse terminated via
373    /// [`ParseStep`] — identical `Emitted`/`NeedMore`/`Done` semantics to the
374    /// pre-K1 `parse_one_partition_with_timestamps` /
375    /// `parse_one_partition_for_compaction` bodies this replaces.
376    ///
377    /// `at_final_chunk` flips a mid-partition parse failure between a refill
378    /// request (`NeedMore`) and a terminal flush, exactly as before — with two
379    /// exceptions, both of which return the error to the caller:
380    /// * a row DECODE ERROR at the FINAL chunk (issue #3782: no further bytes can
381    ///   arrive, so it is data loss, not framing);
382    /// * a row REFUSAL at ANY extent (issue #3809: the row decoded and its content
383    ///   is unrepresentable, so `at_final_chunk` is not consulted at all).
384    pub(super) fn drive_partition_sliding<P, F>(
385        &self,
386        data: &[u8],
387        schema: &TableSchema,
388        reader: &crate::storage::sstable::reader::types::SSTableReader,
389        at_final_chunk: bool,
390        policy: &mut P,
391        mut emit: F,
392    ) -> Result<ParseStep>
393    where
394        P: SlidingPartitionPolicy,
395        F: FnMut(P::Row) -> Result<std::ops::ControlFlow<()>>,
396    {
397        if data.is_empty() {
398            return Ok(ParseStep::Done);
399        }
400
401        // Issue #3928 / #1741: the header arm — readiness classification, the
402        // real parse, and (at the final chunk) the REFUSAL that replaced the
403        // silent byte resync — is shared with the row-granular streaming driver
404        // (`header_arm.rs`). `?` propagates the refusal; the three tolerant
405        // answers are translated into THIS driver's advance vocabulary here.
406        let (partition_key, mut offset, partition_deletion) =
407            match self.driver_partition_header(data, at_final_chunk)? {
408                DriverHeader::Parsed(key, after_header, deletion) => (key, after_header, deletion),
409                DriverHeader::Done => return Ok(ParseStep::Done),
410                DriverHeader::NeedMore => return Ok(ParseStep::NeedMore),
411                DriverHeader::Resync => return Ok(ParseStep::Emitted(1)),
412            };
413
414        // Issue #1046: per-PARTITION resolution build (this driver is re-entered
415        // once per partition by the sliding-window caller; allocations scale with
416        // partition count, not row count). Borrows header strings + schema.
417        let resolution = RowColumnResolution::build(schema, reader);
418
419        // Finding 1 (#827): buffer this partition's rows locally and forward them
420        // to the external `emit` only once the partition is CONFIRMED complete (an
421        // `Emitted` return). A mid-partition `NeedMore` discards `pending` so the
422        // caller can refill and re-parse from the partition start without
423        // double-emitting already-buffered rows. Bounded by ONE partition's rows.
424        let mut pending: Vec<P::Row> = Vec::new();
425
426        policy.on_partition_open(partition_key, partition_deletion, schema, &mut pending);
427
428        // Flush the buffered rows, honouring an early `Break`, and report the
429        // bytes consumed for this (complete) partition so the caller drains
430        // correctly.
431        // `$complete` records whether the parse observed a STRUCTURAL partition end
432        // (END_OF_PARTITION / the next partition header) rather than simply running
433        // out of buffer or failing to parse — see `on_partition_close`. Never called
434        // on `NeedMore`, so a row a policy appends here cannot be emitted twice.
435        macro_rules! flush_and_emitted {
436            ($consumed:expr, $complete:expr) => {{
437                policy.on_partition_close(schema, &mut pending, $complete);
438                for row in pending.drain(..) {
439                    match emit(row)? {
440                        std::ops::ControlFlow::Continue(()) => {}
441                        std::ops::ControlFlow::Break(()) => break,
442                    }
443                }
444                Ok(ParseStep::Emitted($consumed))
445            }};
446        }
447
448        loop {
449            // END_OF_PARTITION (0x01): partition complete, consume the marker.
450            if offset < data.len() && Self::is_end_of_partition(data[offset]) {
451                offset += 1;
452                // STRUCTURAL end: the END_OF_PARTITION marker.
453                return flush_and_emitted!(offset, true);
454            }
455
456            // Consumed everything but never saw END_OF_PARTITION: the partition
457            // may continue in the next chunk. On NeedMore flush NOTHING (drop the
458            // buffered rows) so the caller can refill and re-parse from the start.
459            if offset >= data.len() {
460                if at_final_chunk {
461                    // Buffer exhausted with NO END_OF_PARTITION: truncated body.
462                    return flush_and_emitted!(offset, false);
463                }
464                return Ok(ParseStep::NeedMore);
465            }
466
467            if Self::is_range_tombstone_marker(data[offset]) {
468                match policy.on_range_marker(data, offset, schema, &mut pending) {
469                    MarkerOutcome::Advanced(next_offset) => {
470                        offset = next_offset;
471                        continue;
472                    }
473                    // Issue #3721 (roborev jobs 16 + 78): a marker parse failure.
474                    // A non-final chunk may simply have cut the marker body in
475                    // half, so a refill is still the right answer; the FINAL chunk
476                    // has nothing left to arrive, so completing the partition here
477                    // would report success with a tombstone missing. Propagate the
478                    // preserved cause instead.
479                    MarkerOutcome::Unparseable(cause) => {
480                        if at_final_chunk {
481                            return Err(range_marker_error::unparseable_marker_at_final_chunk(
482                                cause,
483                            ));
484                        }
485                        return Ok(ParseStep::NeedMore);
486                    }
487                    // Issue #3721: the marker parsed and the body continues past
488                    // it, so no refill can help and truncating the partition would
489                    // report `Ok` with rows missing. Propagate.
490                    MarkerOutcome::Refused(e) => return Err(e),
491                }
492            }
493
494            match policy.on_data_row(data, offset, schema, reader, &resolution, &mut pending) {
495                // Issue #3809: a REFUSAL bypasses `at_final_chunk` entirely. The
496                // row DECODED; the policy judged its CONTENT unrepresentable, which
497                // is not a question about byte availability, so no refill can
498                // change the answer. Tolerating it here would convert the refusal
499                // into `NeedMore` on every `BufferExtent::Window` entry point —
500                // the tolerant-tail truncation both #3782 and #3809 remove.
501                DataRowOutcome::Refused(e) => return Err(e),
502                // Issue #3782: for a DECODE FAILURE the DRIVER decides tolerance,
503                // never the policy, and `at_final_chunk` is the discriminator — an
504                // authoritative property of the sliding window, not a guess about
505                // the bytes.
506                //
507                // At the final chunk NO FURTHER BYTES CAN ARRIVE, so a decode
508                // error can never be a row straddling a chunk boundary: it is
509                // truncation or corruption, and both are DATA LOSS. Swallowing
510                // it made a corrupt clustering value read 23 of 100 rows and
511                // made compaction emit 102 rows while LOSING 2 real partitions
512                // and FABRICATING 3 — a loss compaction would then write back
513                // to disk, invisible to any count-based check.
514                //
515                // Mid-stream the SAME error is the ordinary straddling-row case
516                // and stays tolerant. Measured over 42 well-formed corpus
517                // tables (10913 rows) the tolerant path fires 614 times, ALL of
518                // them with `at_final_chunk == false` and ZERO with `true`, so
519                // refusing here costs no well-formed read.
520                DataRowOutcome::DecodeFailed(e) => {
521                    if at_final_chunk {
522                        return Err(e);
523                    }
524                    return Ok(ParseStep::NeedMore);
525                }
526                DataRowOutcome::Decoded(next_offset) => {
527                    offset = next_offset;
528                    if offset >= data.len() {
529                        // End of the buffer without an explicit END_OF_PARTITION:
530                        // the partition may continue in the next chunk.
531                        if at_final_chunk {
532                            return flush_and_emitted!(offset, false);
533                        }
534                        return Ok(ParseStep::NeedMore);
535                    }
536                    if self.peek_is_partition_header(data, offset) {
537                        // STRUCTURAL end: the next partition's header.
538                        return flush_and_emitted!(offset, true);
539                    }
540                }
541                DataRowOutcome::Declined => {
542                    // The policy DECLINED the row with no error to report (#3782:
543                    // an actual decode error takes the `DecodeFailed` arm above,
544                    // #3809: a refusal the `Refused` arm). Mid-stream that may be a
545                    // row straddling the chunk boundary, so request more bytes
546                    // unless this is the final chunk (where it is end-of-partition).
547                    if at_final_chunk {
548                        // Body only partly observed.
549                        return flush_and_emitted!(offset, false);
550                    }
551                    return Ok(ParseStep::NeedMore);
552                }
553            }
554        }
555    }
556}
