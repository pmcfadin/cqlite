1//! Warm/shared-reader k-way merge construction (issue #2346).
2//!
3//! The path-based [`KWayMerger::new`]/[`KWayMerger::new_cancellable`] family
4//! (`mod.rs`) opens a fresh [`SSTableReader`] per input INSIDE its own detached
5//! producer thread — necessary for the compaction/write-engine callers, whose
6//! inputs may be deleted once the merge (and thus every producer thread) has
7//! finished (issue #591). A cached-reader caller — the intended consumer is a
8//! future Flight warm-handle registry (epic #2310) — instead wants to hand the
9//! merger ALREADY-OPEN, possibly-SHARED `Arc<SSTableReader>`s it keeps parsed
10//! across requests, paying the reader-open + Index/Summary/Statistics/bloom
11//! parse cost once per SSTable generation instead of once per request.
12//!
13//! [`KWayMerger::new_from_readers`] is that seam. It reuses every other piece
14//! of the k-way merge (heap, reconciliation, LWW tie-break by run index)
15//! byte-identically — only WHO opens/owns the `SSTableReader` differs from the
16//! path-based constructors.
17//!
18//! ## Delegation (no behavioural drift between the two producer shapes)
19//!
20//! [`drive_compaction_stream`] is the single streaming-emit helper BOTH producer
21//! thread shapes call: the path-based `SSTableRowIteratorAdapter::producer_thread`
22//! (private to `producer_iter`; unchanged opening/threading behaviour — still one fresh reader
23//! opened per thread, in parallel, exactly as before this issue) and the new
24//! [`SSTableRowIteratorAdapter::open_from_reader`]'s producer thread (this file,
25//! never opens a reader). Factoring the conversion/backpressure/
26//! cancellation-by-variant logic into one function means the two shapes cannot
27//! silently diverge.
28//!
29//! `KWayMerger::new_with_gc_and_registry_cancellable` (the path-based
30//! constructor) is intentionally NOT rewritten to open readers eagerly and then
31//! call [`KWayMerger::new_from_readers`] — that would move every input's open
32//! from N-parallel-producer-threads to one serial pass on the calling thread,
33//! a real latency regression for a multi-SSTable merge with no benefit (the
34//! path-based caller never has a reader to share in the first place). The
35//! shared code is the STREAMING logic, not the opening timing.
36//!
37//! ## File-lifetime / open-config contract for caller-supplied readers
38//!
39//! The path-based adapter forces `use_mmap = false` + `DiskAccessMode::Buffered`
40//! specifically because compaction inputs may be deleted by
41//! `finalize_merge_async` once every producer thread has finished (issue #591) —
42//! a reader opened any other way could hold a dangling mapping. A reader passed
43//! into [`SSTableRowIteratorAdapter::open_from_reader`] is opened by the CALLER
44//! (not by this seam), so that safety property is the CALLER's responsibility:
45//! the backing `Data.db` MUST NOT be deleted while any `Arc<SSTableReader>`
46//! clone (including ones held by other concurrent runs, or by a cache) is still
47//! alive. This is a materially different contract from the path-based adapter's
48//! self-contained guarantee, so it is called out explicitly rather than
49//! silently inherited. A read-only warm-handle cache that never deletes/replaces
50//! a generation's `Data.db` out from under a live `Arc` (evicting only its OWN
51//! reference, per #1749's fail-closed model) satisfies this trivially.
52//!
53//! ## CLOSED — a dead producer is an ERROR, never end-of-input (issue #3120)
54//!
55//! Neither producer-thread shape used to send an explicit terminator, and
56//! `SSTableRowIteratorAdapter::next` (`producer_iter`) mapped a channel DISCONNECT
57//! onto `None` = "this run is exhausted". So a producer thread that UNWOUND made
58//! its run look finished, and the merge completed successfully having merged only
59//! the rows that reached the channel — a silently short read result, or a short
60//! rewritten SSTable on the compaction path (silent data loss at rest). The query
61//! row stream's version of this defect was fixed in issue #3106; this is the same
62//! treatment for the merge:
63//!
64//! * The channel item is [`MergeMsg`](super::producer_msg::MergeMsg), whose
65//!   TERMINATORS make completion an observed fact — see that module's header for
66//!   the full protocol rationale.
67//! * BOTH producer thread bodies run under `catch_unwind` and send EXACTLY ONE
68//!   terminal message on EVERY exit path, with the BLOCKING `SyncSender::send`
69//!   (a `try_send` that dropped the terminator would recreate the ambiguity).
70//! * [`forward_row`] no longer sends a row-conversion failure as a mid-walk
71//!   channel message while RETURNING `Continue`. A non-terminal `Err` in the DATA
72//!   slot, after which the walk keeps going, is precisely the shape that lets a
73//!   later genuine dead-producer disconnect revert to a clean end-of-input. It
74//!   now RETURNS the `Err` out of the emit callback and the thread body emits the
75//!   single terminal `Failed`. Behaviour delta: the walk stops at the FIRST
76//!   row-conversion failure instead of continuing. The outcome observed by the
77//!   merge is unchanged, because `RunReader::refill_buffer` already returned that
78//!   `Err` to its caller immediately.
79//!
80//! UDT registry: [`SSTableRowIteratorAdapter::open`] (path-based) can call
81//! `reader.set_udt_registry(..)` because it just opened its OWN exclusive
82//! reader. `open_from_reader` CANNOT — the reader is shared (`Arc`), so no
83//! `&mut self` is available. A caller needing UDT-aware decode over a shared
84//! reader must open it WITH the registry already resolved (before wrapping it
85//! in `Arc`); `open_from_reader` takes no `udt_registry` parameter for this
86//! reason (an accepted-but-silently-ignored parameter would be a correctness
87//! trap).

107/// Drive `reader`'s compaction stream into `sender`, converting each row via
108/// [`SSTableRowIteratorAdapter::build_merge_entry`].
109///
110/// Shared by BOTH producer-thread shapes (see the module doc): the path-based
111/// adapter (which opens its own reader per thread) and the shared-reader
112/// adapter this module adds. `scan_cancel` is the PER-CALL token
113/// [`SSTableReader::stream_all_partitions_for_compaction`] now takes (issue
114/// #2346) — never a field mutated onto `reader`, so two concurrent calls over
115/// the SAME shared reader (two different producer threads, each with its own
116/// token) cancel independently.
117#[allow(clippy::too_many_arguments)]
118pub(super) async fn drive_compaction_stream(
119    reader: &SSTableReader,
120    run_index: usize,
121    schema: &TableSchema,
122    scan_cancel: &ScanCancel,
123    sender: &SyncSender<MergeMsg>,
124    local_sent: &AtomicI64,
125    // Issue #2820: the merge-scoped adaptive ROW capacity this run's channel was
126    // budgeted (`egress_budget`'s snapshot). It bounds the BATCH size too — a
127    // batch ceiling independent of it would make the #2765 throttle inert on
128    // resident memory. See `egress_batch::batch_limit_ceiling`.
129    rows_cap: usize,
130    fault: &mut MergeProducerFault,
131) -> Result<()> {
132    let mut batcher = EgressBatcher::new(sender, local_sent, rows_cap);
133    let walk = reader
134        .stream_all_partitions_for_compaction(Some(schema), scan_cancel, |compaction_row| {
135            forward_row(run_index, compaction_row, schema, &mut batcher, fault)
136        })
137        .await;
138    finish_batched_walk(walk, &mut batcher)
139}

141/// Flush the pending tail of a batched walk on EVERY exit path, then report the
142/// walk's own outcome (issue #2820).
143///
144/// LOAD-BEARING, and the one thing batching can silently get wrong: the caller
145/// (a producer thread body) sends its single terminator immediately after this
146/// returns, so a row still sitting in the accumulator when `Done` goes out is a
147/// row the merge never sees — issue #3120's silent-short-read / short-rewritten-
148/// SSTable class, reintroduced through the back door and invisible to any test
149/// that only counts rows on a fixture whose size happens to be a batch multiple.
150///
151/// The tail is flushed on the ERROR path too, not just the clean one: the
152/// terminator is queued BEHIND every data message, so the consumer still sees
153/// those rows before the failure, and flushing can only ever deliver MORE of what
154/// the producer already read. The walk's `Err` always wins — a flush that finds
155/// the consumer gone (`Break`) is not an error, there is simply nobody left to
156/// hand rows to.
157fn finish_batched_walk(walk: Result<()>, batcher: &mut EgressBatcher<'_>) -> Result<()> {
158    let _ = batcher.flush();
159    walk
160}

162/// Warm query-serve sibling of [`drive_compaction_stream`] (issue #2412 §C /
163/// #2413 Option A): drives the reader's Summary-guided query stream
164/// ([`SSTableReader::stream_all_partitions_for_query`]) with an optional token
165/// pushdown, instead of the full-ring compaction stream.
166///
167/// A SEPARATE helper (not a flag on `drive_compaction_stream`) precisely because
168/// the two must NOT drift toward each other: the path-based/compaction thread
169/// (`mod.rs`) keeps its byte-parity full-ring materialising walk unchanged, while
170/// ONLY the warm reader-based producer takes the streaming + token-scoped path.
171/// The row conversion + batched backpressure (`forward_row` into one
172/// `EgressBatcher`, then [`finish_batched_walk`]) is still shared, so the emit
173/// contract — including the pre-terminator tail flush — cannot diverge.
174#[allow(clippy::too_many_arguments)]
175pub(super) async fn drive_query_stream(
176    reader: &SSTableReader,
177    run_index: usize,
178    schema: &TableSchema,
179    scan_cancel: &ScanCancel,
180    token_bound: Option<crate::storage::sstable::reader::ScanTokenBound>,
181    sender: &SyncSender<MergeMsg>,
182    local_sent: &AtomicI64,
183    // Issue #2820: see `drive_compaction_stream`'s `rows_cap`.
184    rows_cap: usize,
185    fault: &mut MergeProducerFault,
186) -> Result<()> {
187    let mut batcher = EgressBatcher::new(sender, local_sent, rows_cap);
188    let walk = reader
189        .stream_all_partitions_for_query(Some(schema), scan_cancel, token_bound, |compaction_row| {
190            forward_row(run_index, compaction_row, schema, &mut batcher, fault)
191        })
192        .await;
193    finish_batched_walk(walk, &mut batcher)
194}

196/// Convert one streamed row into a [`MergeEntry`] and accumulate it into
197/// `batcher`, signalling `Break` when the consumer has dropped the channel.
198/// Shared by BOTH [`drive_compaction_stream`] and [`drive_query_stream`] so their
199/// emit contract is defined in exactly one place.
200///
201/// Issue #2820: this used to `send` ONE channel message per ROW — measured at
202/// 49.9% of single-stream CPU, ~94% of it kernel park/wake. It now hands the
203/// entry to [`EgressBatcher`], which sends one message per BATCH; the caller
204/// flushes the tail before its terminator (see [`finish_batched_walk`]).
205///
206/// A row-conversion failure is RETURNED as `Err` (issue #3120), never sent as a
207/// channel message: only the thread body may put a terminator on the channel, and
208/// it sends EXACTLY ONE. The pre-#3120 code sent an `Err` here and returned
209/// `Continue`, i.e. a non-terminal error in the DATA slot after which the walk kept
210/// going — the shape that lets a later genuine dead-producer disconnect revert to a
211/// clean end-of-input. The outcome seen by the merge is unchanged: `RunReader::
212/// refill_buffer` already propagated that `Err` to its caller immediately.
213///
214/// The egress-depth (issue #2419) and `local_sent` (roborev job 1733)
215/// accounting lives in [`EgressBatcher::flush`], per successful batch send and in
216/// ENTRIES — see `channel_depth`'s module doc for why the unit must stay entries
217/// on both sides.
218fn forward_row(
219    run_index: usize,
220    compaction_row: crate::storage::sstable::reader::CompactionRow,
221    schema: &TableSchema,
222    batcher: &mut EgressBatcher<'_>,
223    fault: &mut MergeProducerFault,
224) -> Result<std::ops::ControlFlow<()>> {
225    // TEST-ONLY (issue #3120): an empty function in a production build. This is
226    // the ONE emit funnel both stream shapes go through, and it sits ABOVE any
227    // reader format branch, so a fault armed here cannot silently fail to fire
228    // for a particular on-disk format.
229    fault.before_row_forward();
230    let entry = SSTableRowIteratorAdapter::build_merge_entry(run_index, compaction_row, schema)?;
231    Ok(batcher.push(entry))
232}

234impl SSTableRowIteratorAdapter {
235    /// Open a streaming run over an ALREADY-OPEN, possibly-SHARED
236    /// [`SSTableReader`] (issue #2346), instead of opening a fresh reader from a
237    /// path ([`SSTableRowIteratorAdapter::open`]).
238    ///
239    /// Still spawns a dedicated producer thread (preserving the O(M)
240    /// thread-per-input / bounded-channel backpressure architecture — issues
241    /// #827/#2316) but never opens/owns a reader itself; it drives the
242    /// caller-supplied `Arc<SSTableReader>` directly via
243    /// [`drive_compaction_stream`]. See the module doc for the file-lifetime
244    /// and UDT-registry contract differences from the path-based `open`.
245    ///
246    /// `channel_capacity` (issue #2765) is the merge-scoped adaptive egress
247    /// capacity snapshotted ONCE by the `KWayMerger` constructor and shared by
248    /// every source channel of that merge.
249    pub(crate) fn open_from_reader(
250        reader: Arc<SSTableReader>,
251        run_index: usize,
252        schema: &TableSchema,
253        scan_cancel: ScanCancel,
254        token_bound: Option<crate::storage::sstable::reader::ScanTokenBound>,
255        channel_capacity: usize,
256    ) -> Result<Self> {
257        let schema = schema.clone();
258        // Held on the adapter for cancel-aware recv + Drop teardown (issue #2361).
259        let adapter_cancel = scan_cancel.clone();
260        // Issue #2820: `channel_capacity` is a ROW budget (`egress_budget`'s whole
261        // vocabulary is rows); the channel carries BATCHES, so it is converted to a
262        // MESSAGE capacity here. Passing the row budget straight through would
263        // budget 256 BATCHES = 65_536 entries per source — a 256x resident-row
264        // blow-up. See `egress_batch::message_capacity_for_rows`.
265        let message_capacity = egress_batch::message_capacity_for_rows(channel_capacity);
266        let (sender, receiver) = std::sync::mpsc::sync_channel(message_capacity);
267        // Issue #2419 roborev job 1733: this adapter's own sent-count, shared
268        // with the producer thread — see `SSTableRowIteratorAdapter`'s field doc.
269        let sent_count = Arc::new(AtomicI64::new(0));
270        let producer_sent_count = sent_count.clone();
271
272        // Issue #2316: account this producer on the live-thread gauge BEFORE
273        // spawning (see `SSTableRowIteratorAdapter::open`'s identical rationale).
274        producer_gauge::spawned();
275
276        // Issue #2819: thread-locals are NOT inherited across a spawn, so the
277        // flight per-request sub-phase sink is propagated EXPLICITLY — capture it
278        // on the CALLING (merge consumer) thread here and re-install it at the top
279        // of the producer thread below, so this scan's page-in/decompress (which
280        // run synchronously ON the producer thread — `stream_all_partitions_for_query`
281        // → `compressed_offset.rs` / `compaction.rs`) reach the request's
282        // accumulator. A deeper `spawn_blocking` feed thread (the windowed-scan
283        // page-in) is NOT reached by this single-hop propagation and is not
284        // covered. `None` (no-op) for every non-flight caller.
285        let subphase_sink = crate::observability::stream_subphase::current();
286        // Issue #1707: the read-PHASE sink is propagated the SAME way and for the
287        // same reason. `generation_merge::stream_generations_for_read` installs it on
288        // the merge/CONSUMER thread, but the chunk decode of a cross-generation read
289        // happens HERE, on this per-input producer thread — so without this
290        // capture/install pair the route recorded `merge` and nothing else. It reaches
291        // the shared chunk-decode plane (`reader::chunk_source`), so DECOMPRESS is
292        // measured through it; the io seam is a separate matter, see
293        // `observability::read_phase`'s coverage boundary. `None` (no-op) for an
294        // unmetered caller.
295        let read_phase_sink = crate::observability::read_phase::current();
296        // Issue #3120: whatever fault a test armed FOR THIS INPUT is captured HERE
297        // (never re-read mid-walk) and owned by the producer thread. Always empty —
298        // and a zero-sized no-op whose scope closure is never called — in a
299        // production build.
300        let fault = MergeProducerFault::capture_for(|| reader.file_path());
301        let producer = match std::thread::Builder::new().spawn(move || {
302            let _subphase_guard = crate::observability::stream_subphase::install(subphase_sink);
303            let _read_phase_guard = crate::observability::read_phase::install(read_phase_sink);
304            Self::producer_thread_from_reader(
305                reader,
306                run_index,
307                schema,
308                scan_cancel,
309                token_bound,
310                sender,
311                producer_sent_count,
312                channel_capacity,
313                fault,
314            );
315        }) {
316            Ok(handle) => handle,
317            Err(e) => {
318                producer_gauge::rollback();
319                return Err(Error::Storage(format!(
320                    "streaming producer (shared reader): failed to spawn thread: {}",
321                    e
322                )));
323            }
324        };
325
326        Ok(Self {
327            receiver: Some(receiver),
328            producer: Some(producer),
329            scan_cancel: adapter_cancel,
330            sent_count,
331            received_count: 0,
332            held: Vec::new().into_iter(),
333            // Issue #3120: no terminator observed yet. `None` (end of input) is
334            // reachable ONLY from a `Done`-proven `RunState::Finished`.
335            state: RunState::Streaming,
336            #[cfg(test)]
337            egress_channel_capacity: message_capacity,
338            #[cfg(test)]
339            egress_rows_capacity: channel_capacity,
340        })
341    }
342
343    /// Body of the shared-reader producer thread (issue #2346).
344    ///
345    /// Unlike `Self::producer_thread` (path-based, private to `producer_iter`),
346    /// this NEVER opens a
347    /// reader — it drives the caller-supplied `Arc<SSTableReader>` directly via
348    /// [`drive_compaction_stream`], reusing the exact
349    /// conversion/backpressure/cancellation-by-variant semantics. Still owns a
350    /// dedicated `current_thread` runtime (issue #2316: zero extra worker
351    /// threads) so the async `stream_all_partitions_for_compaction` call can
352    /// run without a nested-runtime panic.
353    ///
354    /// Sends EXACTLY ONE terminal [`MergeMsg`] on EVERY exit path (issue #3120),
355    /// so the consumer never has to infer completion from a channel disconnect —
356    /// see the module header. `catch_unwind` covers the unwinding path; the
357    /// `Done` terminator covers every other way this thread could stop.
358    #[allow(clippy::too_many_arguments)]
359    fn producer_thread_from_reader(
360        reader: Arc<SSTableReader>,
361        run_index: usize,
362        schema: TableSchema,
363        scan_cancel: ScanCancel,
364        token_bound: Option<crate::storage::sstable::reader::ScanTokenBound>,
365        sender: SyncSender<MergeMsg>,
366        sent_count: Arc<AtomicI64>,
367        // Issue #2820: the ROW capacity that bounds this run's batch size.
368        rows_cap: usize,
369        mut fault: MergeProducerFault,
370    ) {
371        let _thread_guard = producer_gauge::ProducerThreadGuard;
372        // Issue #3120: the terminal sender lives OUTSIDE the `catch_unwind`
373        // closure, so an unwind cannot drop it before the terminator is sent.
374        let terminal_sender = sender.clone();
375
376        // Issue #3120: an UNWINDING walk must not look like a finished one.
377        // `AssertUnwindSafe` is sound here because nothing the closure touched is
378        // observed after an unwind: the reader `Arc`, schema, cancel token and
379        // per-row fault state are dropped, and the only thing used afterwards is
380        // `terminal_sender` — an mpsc `SyncSender`, which has no
381        // poisoning/broken-invariant state. `sent_count` is an atomic whose value
382        // stays meaningful (it counts sends that already succeeded), and `Drop`
383        // reads it only after joining this thread.
384        let outcome = std::panic::catch_unwind(std::panic::AssertUnwindSafe(|| -> Result<()> {
385            let rt = tokio::runtime::Builder::new_current_thread()
386                .enable_all()
387                .build()
388                .map_err(|e| {
389                    Error::Storage(format!(
390                        "streaming producer (shared reader): failed to create runtime: {}",
391                        e
392                    ))
393                })?;
394            rt.block_on(drive_query_stream(
395                &reader,
396                run_index,
397                &schema,
398                &scan_cancel,
399                token_bound,
400                &sender,
401                sent_count.as_ref(),
402                rows_cap,
403                &mut fault,
404            ))
405        }));
406
407        // EXACTLY ONE terminal message, on every exit path. `Cancelled` is
408        // preserved distinctly (issue #2264) by `MergeProducerError::from`.
409        let terminal = match outcome {
410            Ok(Ok(())) => MergeMsg::Done,
411            Ok(Err(e)) => MergeMsg::Failed(MergeProducerError::from(e)),
412            Err(panic) => MergeMsg::Failed(panicked_producer_error(panic.as_ref())),
413        };
414        // The BLOCKING `send`, never `try_send`: dropping the terminator because
415        // the bounded channel happened to be full would recreate exactly the
416        // ambiguity this protocol removes. A failed send means the consumer is
417        // already gone, which is fine — nobody is left to mislead.
418        let _ = terminal_sender.send(terminal);
419        // Channel closed naturally when `sender` is dropped here.
420    }
421}

423impl KWayMerger {
424    /// Build a k-way merger over already-open, possibly-SHARED `SSTableReader`s
425    /// (issue #2346): a warm-handle cache can hand this constructor `Arc`
426    /// clones of readers it keeps parsed across requests, instead of the
427    /// per-request path-based open ([`KWayMerger::new_cancellable`]).
428    ///
429    /// `readers` must be ordered newest-to-oldest generation (run index = LWW
430    /// tie-break rank), exactly as the path-based constructors' `input_paths`
431    /// are. Reconciliation is byte-identical to the path-based merge — only WHO
432    /// opens/owns the `SSTableReader` differs.
433    ///
434    /// `token_bound` (issue #2412 §C / #2413 Option A): when `Some`, each reader's
435    /// Summary-guided walk is scoped to the split's `(start, end]` token range so
436    /// out-of-range partition bodies are never read; `None` walks the full ring.
437    /// Compaction never uses this seam, so it keeps full-ring parity walks.
438    ///
439    /// UDT-registry guard (issue #2346, WS1 #2345): this seam takes NO
440    /// `udt_registry` parameter (see the module doc — a shared `Arc` reader has
441    /// no `&mut self` for `set_udt_registry`). Each caller-supplied reader MUST
442    /// therefore be opened WITH its UDT registry already resolved BEFORE it is
443    /// wrapped in `Arc`. Wiring that resolution into the warm-handle registry
444    /// caller is WS1 #2345's responsibility — if a warm caller opens a
445    /// UDT-bearing table's reader WITHOUT the registry, frozen/nested UDT cells
446    /// silently decode as `Blob` (the #1234 data-loss class), NOT an error. The
447    /// merge layer cannot detect this here; #2345 owns that end-to-end guarantee.
448    pub fn new_from_readers(
449        readers: Vec<Arc<SSTableReader>>,
450        schema: &TableSchema,
451        scan_cancel: ScanCancel,
452        token_bound: Option<crate::storage::sstable::reader::ScanTokenBound>,
453    ) -> Result<Self> {
454        if readers.is_empty() {
455            return Err(Error::InvalidInput(
456                "K-way merge requires at least one input reader".to_string(),
457            ));
458        }
459        schema.validate_dropped_columns()?;
460        // Issue #3058: explicit "the k-way merge arm was taken" marker (see
461        // `storage::read_path_probe`), recorded once per constructed merger.
462        crate::storage::read_path_probe::record_merger_built();
463
464        // Issue #2765: register this k-way merge ONCE and snapshot the adaptive
465        // per-channel egress capacity shared by every source channel below.
466        let (channel_capacity, egress_slot) = egress_budget::begin_merge();
467
468        let mut runs = Vec::with_capacity(readers.len());
469        for (run_index, reader) in readers.into_iter().enumerate() {
470            let adapter = SSTableRowIteratorAdapter::open_from_reader(
471                reader,
472                run_index,
473                schema,
474                scan_cancel.clone(),
475                token_bound,
476                channel_capacity,
477            )?;
478            runs.push(RunReader::new(
479                Box::new(adapter) as Box<dyn SSTableRowIterator>
480            ));
481        }
482
483        Ok(Self {
484            runs,
485            heap: std::collections::BinaryHeap::new(),
486            current_partition: None,
487            schema: schema.clone(),
488            // Issue #1668, stage 5c-i: see the field doc in `mod.rs`.
489            schema_arc: Arc::new(schema.clone()),
490            gc_before_secs: None,
491            now_secs: None,
492            purge_safe: false,
493            max_purgeable_timestamp: None,
494            _egress_slot: Some(egress_slot),
495        })
496    }
