1//! Heap-size estimation for one `MergeEntry` (issue #2820, roborev round 2).
2//!
3//! # Why this is not a wildcard match any more
4//!
5//! Two budgets are denominated in this estimate: `RunReader`'s read-ahead buffer
6//! (`RunReader::DEFAULT_BUFFER_SIZE`, pre-dating #2820) and the egress batcher's
7//! `BATCH_EMIT_BYTES_MERGE` byte budget (#2820). The previous estimator ended in
8//! `_ => 32, // Default estimate for complex types`, so every nested `Value` —
9//! `List`, `Set`, `Map`, `Tuple`, `Udt`, `Frozen`, `Json`, `Tombstone` — was
10//! counted as 32 bytes however large it actually was. A batch of large nested
11//! payloads could therefore hold hundreds of megabytes and never reach a 1 MiB
12//! threshold: the byte bound was bypassable for exactly the row shapes most
13//! likely to be large, and BOTH budgets were affected.
14//!
15//! Worse than the undercount itself, the wildcard **failed open for variants
16//! nobody had considered**: a new `Value` variant inherited 32 bytes silently,
17//! with no compile error and no failing test. The match over `Value` here is
18//! therefore **EXHAUSTIVE — there is no `_` arm, and none may be added**. A new
19//! `Value` variant is a compile error at this site, which forces whoever adds it
20//! to decide its size (the same reasoning that holds the `channel_depth`
21//! entry-unit invariant up, one module over).
22//!
23//! # Bounded, non-recursive traversal (the #1625 precedent)
24//!
25//! Nesting is walked with an explicit worklist rather than recursion — a
26//! `Value` graph is attacker-shaped data, and a recursive walk over it is a
27//! stack-overflow primitive. Because traversal state is not on the call stack
28//! there is no depth cap, so a large scalar buried arbitrarily deep is counted
29//! at its real size instead of collapsing to a floor. Worst-case WORK is bounded
30//! instead, by node count: past [`MAX_ESTIMATE_NODES`] the estimate **fails
31//! CLOSED**, returning `usize::MAX`.
32//!
33//! Failing closed is the only safe direction for both consumers, and both take
34//! it correctly: the batcher's `pending_bytes.saturating_add(..)` immediately
35//! exceeds any budget and flushes, and `RunReader::refill_buffer` stops
36//! read-ahead after the current entry. An unmeasurable size must never take the
37//! permissive branch (a 32-byte guess for an arbitrarily large nested value is
38//! exactly that shape).
39//!
40//! # Every container costs THREE things (roborev round 4)
41//!
42//! The undercount above was the first of three instances of ONE class:
43//! *a container's ELEMENT ALLOCATION is not counted, only its header and its
44//! element payloads.* The three were the `_ => 32` wildcard, `range_deletion`'s
45//! uncounted `ClusteringKey` bounds, and `add_clustering_key`'s uncounted
46//! `Vec<(String, Value)>` element array (a `(String, Value)` slot is ~8x the
47//! payload of a `BigInt` clustering component, so a wide scalar clustering key
48//! underestimated by roughly the whole array).
49//!
50//! So every container this module walks is accounted in three parts:
51//!
52//! 1. its **header** — `size_of::<Vec<_>>()` etc., or already inside the
53//!    enclosing `size_of` when the container is an inline field;
54//! 2. its **element array** — `capacity() × size_of::<Element>()`, via
55//!    [`SizeAcc::add_element_array`]. `capacity()`, not `len()`: capacity is
56//!    what is allocated, and over-counting is the safe direction. `Element` is
57//!    the container's own slot type — `(Value, Value)` for a `Map`,
58//!    `UdtField` for a UDT, `(String, Value)` for a clustering key;
59//! 3. each element's own **heap payload** — the `String`/`Bytes` bytes, and
60//!    nested `Value`s via the worklist.
61//!
62//! A field that owns heap through something other than a `Vec` needs the same
63//! three-part treatment: `RowKey`'s `Arc<[u8]>` bounds inside a
64//! `Value::Tombstone` are counted as [`ARC_CONTROL_BLOCK`] + bytes, having
65//! previously been swallowed by a flat `size_of + 16`.
66//!
67//! # Unit convention
68//!
69//! Bytes of heap *owned by* the entry, plus the entry's own `size_of`. The
70//! per-variant scalar figures are carried over from the previous estimator
71//! VERBATIM, so this change is strictly additive: an entry with no nested value
72//! and no range deletion estimates byte-identically to before, which is why the
73//! #827 flat-payload memory fixture cannot move. It is an ESTIMATE (container
74//! overheads are approximated, and a nested element's inline slot is counted by
75//! both its parent's slot arithmetic and its own arm), and every approximation
76//! errs LARGE — the safe direction for a budget.

89/// Upper bound on value nodes one entry's estimate may visit before it fails
90/// closed (`usize::MAX`). Matches `Memtable::MAX_ESTIMATE_NODES` (issue #1625):
91/// far beyond any legitimate row's node count, yet keeps the walk cheap.
92#[cfg(feature = "write-support")]
93pub(super) const MAX_ESTIMATE_NODES: usize = 1_000_000;
94
95/// Bytes of `Arc` control block (strong + weak counters) in front of an
96/// `Arc<[u8]>`'s payload — the allocation a `RowKey` owns beyond its bytes.
97#[cfg(feature = "write-support")]
98const ARC_CONTROL_BLOCK: usize = 2 * size_of::<usize>();

100/// Estimate the heap bytes one `MergeEntry` occupies.
101///
102/// Covers every variable-sized field of `MergeEntry`: partition key bytes, the
103/// clustering key's element array plus column names and values, live cells
104/// (column name, value, cell path), complex-deletion markers, and — new in
105/// #2820 — the clustering bounds carried by `range_deletion`, whose
106/// `ClusteringKey` columns were not counted at all. The remaining fields
107/// (`run_index`, `timestamp`, `row_deletion`, `partition_deletion`,
108/// `row_liveness`) are fixed-size and already inside `size_of::<MergeEntry>()`
109/// (`row_liveness` is `Copy` and owns no heap).
110///
111/// Container accounting follows the three-part rule in the module doc
112/// (header + element array + element payloads).
113#[cfg(feature = "write-support")]
114pub(super) fn estimate_entry_size(entry: &MergeEntry) -> usize {
115    let mut acc = SizeAcc::new(size_of::<MergeEntry>());
116
117    acc.add(entry.key.key.len());
118
119    if let Some(ck) = entry.clustering_key.as_ref() {
120        acc.add_clustering_key(ck);
121    }
122
123    match &entry.row_data {
124        RowData::Live { cells } => {
125            for cell in cells {
126                acc.add(size_of::<super::model::CellData>());
127                acc.add(cell.column.len());
128                // Epic #899: per-element cells carry cell-path bytes; count them
129                // so the streaming buffer's memory accounting stays accurate
130                // against the 128 MiB bound (#827).
131                acc.add(cell.cell_path.as_ref().map_or(0, |p| p.len()));
132                acc.add_value(&cell.value);
133            }
134        }
135        RowData::Tombstone { .. } => acc.add(16),
136    }
137
138    // Epic #899: complex-deletion markers carried on the entry also occupy
139    // memory; account for their column-name + fixed-size fields.
140    for cd in &entry.complex_deletions {
141        acc.add(size_of::<super::model::ComplexDeletion>());
142        acc.add(cd.column.len());
143    }
144
145    // Issue #2820: a range tombstone's bounds own `ClusteringKey` columns —
146    // unbounded heap that the previous estimator ignored entirely.
147    if let Some(rt) = entry.range_deletion.as_ref() {
148        for bound in [&rt.start, &rt.end] {
149            match bound {
150                ClusteringBound::Inclusive(ck) | ClusteringBound::Exclusive(ck) => {
151                    acc.add_clustering_key(ck)
152                }
153                ClusteringBound::Bottom | ClusteringBound::Top => {}
154            }
155        }
156    }
157
158    acc.finish()
159}

161/// Saturating byte accumulator with a shared node budget across every value
162/// walked for ONE entry (so an entry made of many medium collections is bounded
163/// the same way a single huge one is).
164#[cfg(feature = "write-support")]
165struct SizeAcc {
166    total: usize,
167    visited: usize,
168    /// Set once the node budget is exhausted; makes [`Self::finish`] fail closed.
169    exhausted: bool,
170}
171
172#[cfg(feature = "write-support")]
173impl SizeAcc {
174    fn new(base: usize) -> Self {
175        Self {
176            total: base,
177            visited: 0,
178            exhausted: false,
179        }
180    }
181
182    fn add(&mut self, bytes: usize) {
183        self.total = self.total.saturating_add(bytes);
184    }
185
186    /// `ClusteringKey.columns: Vec<(String, Value)>` — header, ELEMENT ARRAY,
187    /// then each element's own heap payload (issue #2820, roborev round 4).
188    ///
189    /// The element array is the half that was missing: a `(String, Value)` slot
190    /// is `size_of::<String>()` + `size_of::<Value>()` bytes, ~8x the 8-byte
191    /// payload of a `BigInt` component, so a row with many small clustering
192    /// components underestimated by roughly the whole array — bypassing both
193    /// the batch byte budget and read-ahead. Sized from `capacity()`, not
194    /// `len()`: capacity is what is actually allocated, and over-counting is
195    /// the safe direction for a budget.
196    fn add_clustering_key(&mut self, ck: &ClusteringKey) {
197        self.add(size_of::<Vec<(String, Value)>>());
198        self.add_element_array(ck.columns.capacity(), size_of::<(String, Value)>());
199        for (name, value) in &ck.columns {
200            self.add(name.len());
201            self.add_value(value);
202        }
203    }
204
205    /// `count` element slots of `elem_size` bytes each — the heap array a
206    /// container owns, distinct from its header and from the elements' own
207    /// payloads. Saturating in BOTH operations: an attacker-shaped `capacity`
208    /// must not wrap the product (and `usize::MAX` makes `+`/`*` a debug panic).
209    fn add_element_array(&mut self, count: usize, elem_size: usize) {
210        self.add(count.saturating_mul(elem_size));
211    }
212
213    /// The measured estimate, or `usize::MAX` when the node budget was exhausted.
214    fn finish(self) -> usize {
215        if self.exhausted {
216            usize::MAX
217        } else {
218            self.total
219        }
220    }
221
222    /// Would enqueuing `incoming` more children push this entry's total node
223    /// count past the cap? Checked BEFORE enqueuing, so a single flat collection
224    /// with far more than [`MAX_ESTIMATE_NODES`] elements fails closed WITHOUT
225    /// first growing the worklist proportional to its element count (#1625).
226    fn would_exceed_cap(&self, pending: usize, incoming: usize) -> bool {
227        self.visited
228            .saturating_add(pending)
229            .saturating_add(incoming)
230            > MAX_ESTIMATE_NODES
231    }
232
233    /// Walk one `Value` iteratively, adding its heap bytes.
234    ///
235    /// The match is EXHAUSTIVE by design (module doc): no `_` arm, so a new
236    /// `Value` variant fails the build here rather than silently inheriting a
237    /// permissive size.
238    fn add_value(&mut self, value: &Value) {
239        // Stack-backed worklist: 32 inline slots cover normal rows, so the hot
240        // path walks with zero heap allocation; only deep/wide values spill.
241        let mut worklist: SmallVec<[&Value; 32]> = SmallVec::new();
242        worklist.push(value);
243
244        while let Some(v) = worklist.pop() {
245            self.visited += 1;
246            if self.visited > MAX_ESTIMATE_NODES {
247                self.exhausted = true;
248                return;
249            }
250
251            match v {
252                Value::Null => {}
253                // Zero HEAP bytes: the sentinel's payload is the empty buffer
254                // and its 1-byte type tag is inline in the `Value` slot, which
255                // this estimator counts through the enclosing container
256                // (issue #3805).
257                Value::Empty(_) => {}
258                Value::Boolean(_) | Value::TinyInt(_) => self.add(1),
259                Value::SmallInt(_) => self.add(2),
260                Value::Integer(_) | Value::Float32(_) | Value::Date(_) => self.add(4),
261                Value::BigInt(_)
262                | Value::Counter(_)
263                | Value::Timestamp(_)
264                | Value::Time(_)
265                | Value::Float(_) => self.add(8),
266                Value::Uuid(_) => self.add(16),
267                Value::Duration { .. } => self.add(20),
268                Value::Text(s) => self.add(s.len().saturating_add(size_of::<String>())),
269                Value::Blob(b) | Value::Inet(b) | Value::Varint(b) => {
270                    self.add(b.len().saturating_add(size_of::<Vec<u8>>()))
271                }
272                Value::Decimal { unscaled, .. } => self.add(
273                    unscaled
274                        .len()
275                        .saturating_add(4)
276                        .saturating_add(size_of::<Vec<u8>>()),
277                ),
278                Value::Tombstone(info) => {
279                    // Base figure carried over VERBATIM so a tombstone with no
280                    // range bounds estimates byte-identically to before.
281                    self.add(size_of::<crate::types::TombstoneInfo>().saturating_add(16));
282                    // Issue #2820 (roborev round 4): the `RowKey(Arc<[u8]>)`
283                    // range bounds own UNBOUNDED bytes the flat figure above
284                    // ignored — the same class as the clustering-key array.
285                    for bound in [&info.range_start, &info.range_end] {
286                        if let Some(rk) = bound.as_ref() {
287                            self.add(rk.0.len().saturating_add(ARC_CONTROL_BLOCK));
288                        }
289                    }
290                }
291                Value::Json(json) => {
292                    self.add(size_of::<serde_json::Value>());
293                    self.add_json(json);
294                    if self.exhausted {
295                        return;
296                    }
297                }
298                Value::List(items) | Value::Set(items) | Value::Tuple(items) => {
299                    self.add(size_of::<Vec<Value>>());
300                    self.add_element_array(items.capacity(), size_of::<Value>());
301                    if self.would_exceed_cap(worklist.len(), items.len()) {
302                        self.exhausted = true;
303                        return;
304                    }
305                    worklist.extend(items.iter());
306                }
307                Value::Map(entries) => {
308                    self.add(size_of::<Vec<(Value, Value)>>());
309                    self.add_element_array(entries.capacity(), size_of::<(Value, Value)>());
310                    // Each entry enqueues both a key and a value.
311                    let incoming = entries.len().saturating_mul(2);
312                    if self.would_exceed_cap(worklist.len(), incoming) {
313                        self.exhausted = true;
314                        return;
315                    }
316                    for (k, val) in entries {
317                        worklist.push(k);
318                        worklist.push(val);
319                    }
320                }
321                Value::Udt(udt) => {
322                    self.add(size_of::<crate::types::UdtValue>());
323                    self.add(udt.type_name.len());
324                    self.add(udt.keyspace.len());
325                    self.add_element_array(
326                        udt.fields.capacity(),
327                        size_of::<crate::types::UdtField>(),
328                    );
329                    if self.would_exceed_cap(worklist.len(), udt.fields.len()) {
330                        self.exhausted = true;
331                        return;
332                    }
333                    for field in &udt.fields {
334                        self.add(field.name.len());
335                        if let Some(fv) = field.value.as_ref() {
336                            worklist.push(fv);
337                        }
338                    }
339                }
340                Value::Frozen(inner) => {
341                    self.add(size_of::<Value>());
342                    if self.would_exceed_cap(worklist.len(), 1) {
343                        self.exhausted = true;
344                        return;
345                    }
346                    worklist.push(inner);
347                }
348            }
349        }
350    }
351
352    /// Walk a JSON document iteratively, on the SAME node budget.
353    ///
354    /// Deliberately not `json.to_string().len()` (what `Memtable`'s estimator
355    /// does): serialising an arbitrarily large document to measure it allocates
356    /// the very memory this estimate exists to bound.
357    fn add_json(&mut self, root: &serde_json::Value) {
358        let mut worklist: SmallVec<[&serde_json::Value; 32]> = SmallVec::new();
359        worklist.push(root);
360
361        while let Some(v) = worklist.pop() {
362            self.visited += 1;
363            if self.visited > MAX_ESTIMATE_NODES {
364                self.exhausted = true;
365                return;
366            }
367
368            match v {
369                serde_json::Value::Null => self.add(4),
370                serde_json::Value::Bool(_) => self.add(5),
371                serde_json::Value::Number(_) => self.add(size_of::<serde_json::Number>()),
372                serde_json::Value::String(s) => {
373                    self.add(s.len().saturating_add(size_of::<String>()))
374                }
375                serde_json::Value::Array(items) => {
376                    self.add(size_of::<Vec<serde_json::Value>>());
377                    self.add_element_array(items.capacity(), size_of::<serde_json::Value>());
378                    if self.would_exceed_cap(worklist.len(), items.len()) {
379                        self.exhausted = true;
380                        return;
381                    }
382                    worklist.extend(items.iter());
383                }
384                serde_json::Value::Object(map) => {
385                    self.add(size_of::<serde_json::Map<String, serde_json::Value>>());
386                    if self.would_exceed_cap(worklist.len(), map.len()) {
387                        self.exhausted = true;
388                        return;
389                    }
390                    for (k, val) in map {
391                        self.add(k.len().saturating_add(size_of::<String>()));
392                        self.add(size_of::<serde_json::Value>());
393                        worklist.push(val);
394                    }
395                }
396            }
397        }
398    }
