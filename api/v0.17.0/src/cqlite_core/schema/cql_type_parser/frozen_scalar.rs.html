1//! `frozen<T>` IS NOT DECLARABLE OVER A SCALAR — the one rule, both spellings
2//! (issue #4104).
3//!
4//! # SCOPE OF THE CLAIM — read this before trusting the title
5//!
6//! "Both spellings" means the two METADATA ENTRY POINTS (CQL type string,
7//! SerializationHeader marshal string), NOT "every syntactic position". The title
8//! states a rule, not a totality proof; a guarantee this module does not deliver
9//! would be its own defect (roborev job 116, finding 2).
10//!
11//! The one position #4104 DECLARED as not covered — a frozen scalar nested in a
12//! VECTOR ELEMENT, `frozen<vector<frozen<int>, 3>>` — is now covered, and NOT by
13//! anything this module does. #4149 gave `CqlType` a `Vector(element, dimension)`
14//! variant whose parser recurses into the element through `parse_with_depth`, which
15//! re-enters the CQL gate below; the refusal reaches that position for free. Pinned
16//! by `a_frozen_scalar_in_a_vector_element_is_refused_since_4149`. Issue #4154 stays
17//! open for the audit of the remaining positions — this note records one position
18//! closing, not the whole issue. The MARSHAL half still checks a head class only and
19//! descends into nothing; its bound is declared on
20//! [`FROZEN_WRAPPABLE_MARSHAL_SIMPLE_NAMES`].
21//!
22//! # THE TWO HALVES ARE TWO QUESTIONS, AND THEIR ACCEPT SETS DIFFER (#4158 review)
23//!
24//! The CQL half asks "is `frozen<T>` DECLARABLE?" (Cassandra's grammar); the marshal
25//! half asks "could Cassandra have WRITTEN `FrozenType(T)` into this header?"
26//! (Cassandra's writer). `vector` and `tuple` answer YES to the first and NO to the
27//! second — both are freezable CQL, and neither is ever printed inside a
28//! `FrozenType(` wrapper. Expecting ONE accept set for both is what let the read gate
29//! admit `FrozenType(VectorType(..))` while the same PR's writer proved that string
30//! impossible. Derivations: [`frozen_inner_supports_freezing`] (grammar) and
31//! [`FROZEN_WRAPPABLE_MARSHAL_SIMPLE_NAMES`] (writer).
32//!
33//! # The oracle is Cassandra's GRAMMAR, not its bytes
34//!
35//! `CQL3Type.Raw::freeze()` is the BASE implementation and it does nothing but
36//! throw (`cassandra-5.0.8:src/java/org/apache/cassandra/cql3/CQL3Type.java:647-651`):
37//!
38//! ```text
39//!         public Raw freeze()
40//!         {
41//!             String message = String.format("frozen<> is only allowed on collections, tuples, and user-defined types (got %s)", this);
42//!             throw new InvalidRequestException(message);
43//!         }
44//! ```
45//!
46//! and the grammar routes EVERY `frozen<…>` through it
47//! (`cassandra-5.0.8:src/antlr/Parser.g:1853-1860`):
48//!
49//! ```text
50//!     | K_FROZEN '<' f=comparatorType '>'
51//!       {
52//!         try {
53//!             $t = f.freeze();
54//!         } catch (InvalidRequestException e) {
55//!             addRecognitionError(e.getMessage());
56//!         }
57//!       }
58//! ```
59//!
60//! Only four subclasses override it — `RawCollection` (`:773`, list/set/map),
61//! `RawVector` (`:916`), `RawUT` (`:958`) and `RawTuple` (`:1037`). Everything
62//! else, `RawType` (every native scalar) and a `STRING_LITERAL` custom class
63//! included, reaches the base and is a recognition error.
64//!
65//! Three consequences, and they are the whole content of this module:
66//!
67//! 1. no Cassandra table can carry a `frozen<scalar>` column, map key, collection
68//!    element or UDT field;
69//! 2. no Cassandra-written `Statistics.db` SerializationHeader can spell
70//!    `FrozenType(Int32Type)`;
71//! 3. **there are no Cassandra-written bytes for this input, BY CONSTRUCTION** — so
72//!    under the no-heuristics mandate (#28) CQLite must not invent a decode result
73//!    for it. Two lanes did invent one, in opposite directions (`Value::blob(b"")`
74//!    on #3847/PR #4017, `Value::Empty(Int)` on #3805/PR #4033); the lead's
75//!    `REQ-3805-14` ruling deleted BOTH pins and sent the refusal here.
76//!
77//! # Corroborated on the real corpus, and the recipe is reproducible
78//!
79//! Every `FrozenType(` occurrence in the fetched corpus was censused
80//! (310 `Statistics.db`/`Data.db` files under `/data/datasets`, i.e. every one the
81//! box holds) and the inner head was one of exactly four classes — `MapType` (25),
82//! `ListType` (16), `UserType` (10), `SetType` (9); no scalar, ever. Reproduce with:
83//!
84//! ```text
85//! python3 - <<'EOF'
86//! import re, os, collections
87//! pat = re.compile(rb'FrozenType\(([A-Za-z0-9_.]+)')
88//! c = collections.Counter()
89//! for root, _, files in os.walk(os.environ['CQLITE_DATASETS_ROOT']):
90//!     for f in files:
91//!         if f.endswith(('Statistics.db', 'Data.db')):
92//!             for m in pat.finditer(open(os.path.join(root, f), 'rb').read()):
93//!                 c[m.group(1).decode('ascii', 'replace')] += 1
94//! print(c.most_common())
95//! EOF
96//! ```
97//!
98//! That is CORROBORATION and not the oracle: an absence measured over one corpus
99//! could never establish an impossibility, which is why the grammar above does.
100//!
101//! # Where the two gates are, and why there are exactly two
102//!
103//! A declared type reaches CQLite through exactly two metadata entry points, and
104//! this module is called from both:
105//!
106//! * the CQL type-string parser, [`CqlType::parse`] — via
107//!   [`frozen_inner_supports_freezing`] + [`refuse_frozen_scalar_cql`];
108//! * the `Statistics.db` SerializationHeader type parser — via
109//!   [`validate_marshal_frozen`], called from the one choke point every header
110//!   type string passes through
111//!   (`parser::enhanced_statistics_parser::marshal_type::convert_marshal_type_to_cql_checked`).
112//!
113//! **No DECODE path gains a frozen-scalar branch**, and that is deliberate: the
114//! refusal belongs upstream of decode, at the metadata boundary, so that no decoder
115//! ever has to hold an opinion about bytes that cannot exist.

156/// Whether a PARSED inner type may legally carry a `frozen<>` wrapper.
157///
158/// The membership set is Cassandra's override set, mapped onto [`CqlType`]:
159/// `RawCollection` -> [`CqlType::List`]/[`CqlType::Set`]/[`CqlType::Map`],
160/// `RawTuple` -> [`CqlType::Tuple`], `RawUT` -> [`CqlType::Udt`], and an
161/// already-frozen inner ([`CqlType::Frozen`]) because `RawCollection::freeze`
162/// (`CQL3Type.java:773-786`) freezes an already-frozen collection to itself.
163///
164/// [`CqlType::Custom`] carries TWO things `CqlType::parse` cannot model, and both
165/// are legally freezable, so the arm decides between them by SPELLING:
166///
167///   * a UDT REFERENCE. `CqlType::parse` has no UDT registry, so a bare
168///     `frozen<address_type>` lands in `Custom` and refusing it would refuse every
169///     real frozen UDT. Admitted when the name is a plausible UDT identifier
170///     ([`is_udt_identifier`]).
171///   * a VECTOR — and as of #4149 this half is UNREACHABLE FROM
172///     [`CqlType::parse`], which is stated here rather than quietly left to rot.
173///     When #4104 wrote it, `CqlType` had no `Vector` variant and every
174///     `vector<..>` spelling landed in `Custom`. #4149 added
175///     `CqlType::Vector(element, dimension)` and sited its arm BEFORE the
176///     UDT/primitive fall-through, so today `CqlType::parse` resolves a
177///     `vector<..>` spelling to either `CqlType::Vector` (well-formed) or an
178///     `Err` (malformed) — never to a `Custom`. Derivation: for
179///     [`is_vector_spelling`] to answer `true` the text before the first `<` must
180///     trim to exactly `vector`, which is precisely the shape
181///     `schema::vector_type::cql_vector_kind` classifies as `Args` or
182///     `Malformed`, and BOTH are handled upstream of this arm.
183///
184///     It is KEPT, not deleted, because this function is a `pub(crate)`
185///     membership predicate over an ARBITRARY [`CqlType`] value and
186///     `Custom("vector<float, 3>")` is still representable. Deleting the carve-out
187///     would make the predicate answer `false` there while the
188///     [`CqlType::Vector`] arm answers `true` for the same declared type — one
189///     rule with two answers, which is the exact divergence class this module
190///     exists to prevent. The two AGREE today: a well-formed spelling is `true`
191///     either way, and a malformed one is refused either way (by this predicate
192///     via `Custom`, or by `cql_vector_kind` before the predicate is reached).
193///
194///     THE FULL DERIVATION, FACTORY TO GRAMMAR, at the pinned tag — it answers the
195///     CQL question, so it lives here and not on the writer-side
196///     [`FROZEN_WRAPPABLE_MARSHAL_SIMPLE_NAMES`]:
197///       1. `Parser.g:1916-1919` — `vector_type : K_VECTOR '<' comparatorType ','
198///          INTEGER '>' { $vt = CQL3Type.Raw.vector(t1, ...); }`
199///       2. `CQL3Type.java:705-708` — `public static Raw vector(..) { return new
200///          RawVector(t, dimension); }`
201///       3. `CQL3Type.java:885` — `private static class RawVector extends Raw`
202///       4. `CQL3Type.java:915-919` — `@Override public Raw freeze() { return this; }`
203///          — it DOES override, and RETURNS rather than throws (`:909-913`
204///          `supportsFreezing() -> true`; `:897-901` `isVector() -> true`; base
205///          `:632-635` `isImplicitlyFrozen() -> isTuple() || isVector()`).
206///       5. `Parser.g:1851` puts `vector_type` in `comparatorType`, and `:1853-1860`
207///          routes `K_FROZEN '<' comparatorType '>'` through `freeze()` — so
208///          `frozen<vector<float, 3>>` raises no `InvalidRequestException` and no
209///          recognition error.
210///
211///     Its HEADER spelling is nonetheless the BARE `VectorType(FloatType , 3)`:
212///     `VectorType.toString` prints no wrapper (`VectorType.java:339-342`).
213///
214/// Everything else in `Custom` is refused, which keeps the quoted custom-class
215/// spelling (`frozen<'org.apache.cassandra.db.marshal.Int32Type'>`) out — Cassandra
216/// routes that through `CQL3Type.Raw.from(new CQL3Type.Custom(..))`, i.e. a
217/// `RawType`, i.e. the throwing base (`Parser.g:1861-1864`).
218///
219/// Every native scalar is `false`. This function is the ONLY membership statement;
220/// the enumeration is exhaustive with no `_` arm on purpose, so a new [`CqlType`]
221/// variant cannot silently inherit either answer.
222pub(crate) fn frozen_inner_supports_freezing(inner: &CqlType) -> bool {
223    match inner {
224        // Cassandra's four `freeze()` overrides, plus the already-frozen case.
225        CqlType::List(_) | CqlType::Set(_) | CqlType::Map(_, _) => true,
226        CqlType::Tuple(_) => true,
227        CqlType::Udt(_, _) => true,
228        CqlType::Frozen(_) => true,
229        // `RawVector` is Cassandra's FIFTH `freeze()` override, and it RETURNS
230        // `this` rather than throwing (`CQL3Type.java:915-919`, with
231        // `supportsFreezing() -> true` at `:909-913`), so `frozen<vector<float, 3>>`
232        // IS declarable CQL and must not be refused.
233        //
234        // WHY THIS ARM IS NEW rather than always having been here: before #4149
235        // `CqlType` had NO `Vector` variant, so `frozen<vector<float, 3>>` parsed to
236        // `Frozen(Custom("vector<float, 3>"))` and the permission was granted by the
237        // `Custom` arm's [`is_vector_spelling`] carve-out below. #4149 added
238        // `CqlType::Vector(element, dimension)`, so the same spelling now parses to
239        // `Frozen(Vector(Float, 3))` and the ONE rule has to be expressed on the new
240        // variant too — otherwise this gate would refuse declarable CQL, which is a
241        // worse defect than the hole it exists to close.
242        //
243        // Unconditional, and that is Cassandra's answer too: `RawVector::freeze`
244        // returns `this` whatever the parameters, so freezability is a HEAD-CLASS
245        // question here — as it is on the marshal side, though over a DIFFERENT set
246        // ([`FROZEN_WRAPPABLE_MARSHAL_SIMPLE_NAMES`] answers what the WRITER prints,
247        // and it prints no wrapper around a vector). A
248        // `CqlType::Vector` value can only exist because `schema::vector_type`
249        // already validated its element and dimension (the CQL parser errors on a
250        // malformed one BEFORE this predicate is reached), so there is nothing left
251        // for a freezability gate to re-check.
252        CqlType::Vector(_, _) => true,
253        CqlType::Custom(name) => {
254            let name = name.strip_prefix("udt:").unwrap_or(name.as_str());
255            is_udt_identifier(name) || is_vector_spelling(name)
256        }
257        // `RawType` — every native scalar reaches the throwing base.
258        CqlType::Boolean
259        | CqlType::TinyInt
260        | CqlType::SmallInt
261        | CqlType::Int
262        | CqlType::BigInt
263        | CqlType::Counter
264        | CqlType::Float
265        | CqlType::Double
266        | CqlType::Decimal
267        | CqlType::Text
268        | CqlType::Ascii
269        | CqlType::Varchar
270        | CqlType::Blob
271        | CqlType::Timestamp
272        | CqlType::Date
273        | CqlType::Time
274        | CqlType::Uuid
275        | CqlType::TimeUuid
276        | CqlType::Inet
277        | CqlType::Duration
278        | CqlType::Varint => false,
279    }
280}

282/// Whether a `Custom` type name is a COMPLETE, DECLARABLE `vector<element,
283/// dimension>` spelling.
284///
285/// # A HEAD-KEYWORD MATCH IS NOT ENOUGH, and that was roborev job 108's finding
286/// This checked only that the text before the first `<` was `vector`, so
287/// `frozen<vector<int>>` (no dimension), `frozen<vector<>>` (no arguments) and
288/// `frozen<vector<int, nope>>` (dimension not an integer) were all granted
289/// freezability. None of them is declarable CQL, so that was a permissive
290/// fall-through GRANTING A PERMISSION CASSANDRA DOES NOT — the same
291/// no-heuristics defect as an invented decode result, pointed the other way.
292///
293/// The `Custom` arm needs the spelling to be a vector because the SPELLING is all
294/// it has: `CqlType` has no `Vector` variant, so a vector and an unparseable
295/// string are the same value. A spelling that never becomes a `RawVector` never
296/// reaches `RawVector::freeze` either, so it must be refused here.
297///
298/// # THE ACCEPTED GRAMMAR, DERIVED AT THE PINNED TAG
299///
300/// ```text
301/// Parser.g:1916-1919
302///   vector_type returns [CQL3Type.Raw vt]
303///       : K_VECTOR '<' t1=comparatorType ','  d=INTEGER '>'
304///           { $vt = CQL3Type.Raw.vector(t1, Integer.parseInt($d.text)); }
305///       ;
306/// Lexer.g:337-339
307///   INTEGER : '-'? DIGIT+ ;
308/// VectorType.java:86-92
309///   private VectorType(AbstractType<T> elementType, int dimension) {
310///       ...
311///       if (dimension <= 0)
312///           throw new InvalidRequestException("vectors may only have positive dimensions; given %d");
313/// ```
314///
315/// So, exactly: the head keyword `vector`; EXACTLY TWO top-level arguments (the
316/// element may itself contain commas, e.g. `vector<map<int, text>, 3>`); a
317/// non-empty element; and a dimension that is a bare DIGIT string (`INTEGER`
318/// permits a leading `-` and nothing else — no `+`, no separators, no radix),
319/// fits a Java `int` (`Integer.parseInt` throws beyond it), and is `> 0`
320/// (`VectorType`'s constructor). Rust's `parse::<i32>()` reproduces the `int`
321/// bound exactly and RETURNS `Err` rather than saturating; requiring all-digits
322/// first is what excludes the `-`/`+` spellings `parse` would otherwise accept.
323///
324/// # UNREACHABLE FROM `CqlType::parse` SINCE #4149
325/// This predicate is retained for the reasons given on
326/// [`frozen_inner_supports_freezing`]'s `Custom` arm (it must keep answering
327/// consistently for a representable `Custom("vector<..>")`), but no `CqlType::parse`
328/// input reaches it any more: #4149's vector arm resolves every `vector<..>`
329/// spelling to `CqlType::Vector` or an `Err` before the `Custom` fall-through.
330/// Consequences worth stating, because both were true when this was written and are
331/// no longer:
332///  * **The ELEMENT is now inspected** — by #4149's `parse_with_depth` recursion,
333///    not here — so `frozen<vector<frozen<int>, 3>>` is refused. That closes the
334///    position #4104 declared out of scope (issue #4154 stays open for the rest).
335///    This predicate STILL does not inspect the element, and that no longer matters
336///    on the parse path; it is why the predicate must not be the only gate.
337///  * Re-entering `CqlType::parse` from HERE remains the wrong fix, and #4149 did
338///    not do it: a fresh `parse` call restarts at depth 0, so
339///    `frozen<vector<frozen<vector<…` would recurse unbounded past
340///    `MAX_NESTING_DEPTH` (issue #1690's stack-overflow hazard). #4149 threads the
341///    EXISTING depth instead.
342///
343/// # ONE FURTHER BOUND, DECLARED RATHER THAN IMPLIED
344///  * **The MARSHAL half does not validate arity/dimension** — see
345///    [`FROZEN_WRAPPABLE_MARSHAL_SIMPLE_NAMES`], which is a head-CLASS lookup over names
346///    a Cassandra WRITER produced, not a spelling proxy.
347fn is_vector_spelling(name: &str) -> bool {
348    let Some((head, rest)) = name.split_once('<') else {
349        return false;
350    };
351    if !head.trim().eq_ignore_ascii_case("vector") {
352        return false;
353    }
354    let Some(inner) = rest.strip_suffix('>') else {
355        return false;
356    };
357    // An EMPTY argument is a CQL syntax error at whatever depth it occurs, and the
358    // shared splitter FILTERS empty segments — so `vector<int, , 3>` would
359    // otherwise split to two parts and pass. Refuse the shape directly: no legal
360    // type string carries a leading, trailing or doubled comma at any depth, so
361    // this cannot over-refuse.
362    let squeezed: String = inner.chars().filter(|c| !c.is_whitespace()).collect();
363    if squeezed.starts_with(',') || squeezed.ends_with(',') || squeezed.contains(",,") {
364        return false;
365    }
366    // THE SHARED SPLITTER, reused rather than re-implemented: it is the parent
367    // module's own `<>`-depth walk (and it already refuses unbalanced nesting), so
368    // this predicate cannot form a second opinion about where an argument ends.
369    let Ok(parts) = CqlType::split_top_level_types(inner) else {
370        return false;
371    };
372    let [element, dimension] = parts[..] else {
373        return false;
374    };
375    !element.trim().is_empty() && is_vector_dimension(dimension.trim())
376}

378/// Whether `d` is a dimension `Integer.parseInt` would accept and `VectorType`'s
379/// constructor would keep: a bare digit string, inside Java `int`, strictly `> 0`.
380///
381/// `is_ascii_digit` FIRST, and it is load-bearing: `str::parse::<i32>` accepts a
382/// leading `+` that `Lexer.g:337-339`'s `INTEGER` does not, and would accept the
383/// `-` spellings `VectorType.java:89-90` throws on. Digits-only settles both, and
384/// leaves `parse` to do only the one thing Java's does — enforce the `int` bound,
385/// by returning `Err` instead of saturating.
386fn is_vector_dimension(d: &str) -> bool {
387    !d.is_empty() && d.bytes().all(|b| b.is_ascii_digit()) && d.parse::<i32>().is_ok_and(|n| n > 0)
388}

399/// The MARSHAL simple names that can appear as the IMMEDIATE inner of a
400/// `FrozenType(` in a header Apache Cassandra WROTE.
401///
402/// # THE TWO GATES ANSWER TWO DIFFERENT QUESTIONS, AND HERE THEY MUST DIVERGE
403///
404/// The CQL half ([`frozen_inner_supports_freezing`]) answers a GRAMMAR question —
405/// would `CQL3Type.Raw::freeze()` accept `frozen<T>`? This half answers a WRITER
406/// question — can `AbstractType::toString()` ever PRINT `FrozenType(` around this
407/// class? A type can be freezable in CQL and never carry the wrapper on disk, and
408/// `vector` and `tuple` are exactly that: `frozen<vector<float, 3>>` and
409/// `frozen<tuple<int, text>>` are declarable (accepted on the CQL side) while
410/// `FrozenType(VectorType(..))` and `FrozenType(TupleType(..))` are refused here,
411/// because those BYTES cannot exist. Reading this set as "the freezable types"
412/// is what made the two halves of #4158 contradict each other.
413///
414/// # DERIVED AT THE PINNED TAG, WHOLE-TREE — the set is FOUR, not seven
415///
416/// The SerializationHeader records `type.toString()` verbatim
417/// (`serializers/AbstractTypeSerializer.java:36-39`, the serializer
418/// `SerializationHeader.Serializer` holds at `SerializationHeader.java:389`), and
419/// the literal `FrozenType(` is printed at exactly FOUR sites in the whole of
420/// `cassandra-5.0.8/src/java` — the `includeFrozenType = !ignoreFreezing &&
421/// !isMultiCell()` branch of `ListType.java:195-206`, `SetType.java:185-196`,
422/// `MapType.java:310-320` and `UserType.java:436-447`:
423///
424/// ```text
425/// $ grep -rn 'FrozenType.class.getName()' cassandra-5.0.8/src/java
426/// .../db/marshal/ListType.java:201        .../db/marshal/MapType.java:316
427/// .../db/marshal/SetType.java:191         .../db/marshal/UserType.java:442
428/// ```
429///
430/// (the only other whole-tree hit for the class NAME,
431/// `cql3/functions/types/DataTypeClassNameParser.java:49`, is a client-side
432/// PARSER constant and prints nothing). Everything else inherits
433/// `AbstractType::toString(boolean) { return this.toString(); }`
434/// (`AbstractType.java:466-469`), so it can never be wrapped:
435///
436///  * `TupleType.toString()` is `getClass().getName() +
437///    stringifyTypeParameters(types, true)` (`TupleType.java:557-560`) — no
438///    wrapper, and it forces `ignoreFreezing` on its own components;
439///  * `VectorType.toString(ignoreFreezing)` is `getClass().getName() +
440///    stringifyVectorParameters(elementType, ignoreFreezing, dimension)`
441///    (`VectorType.java:339-342`) — no wrapper either, so a frozen vector is
442///    written as the BARE `VectorType(FloatType , 3)`;
443///  * a NESTED `FrozenType(FrozenType(..))` is unprintable: each of the four
444///    wrapping types passes `ignoreFreezing || !isMultiCell` down to its own
445///    parameters (`ListType.java:203`, `SetType.java:193`, `MapType.java:317`,
446///    `UserType.java:444`), so anything under a wrapper is printed with
447///    `ignoreFreezing = true` and prints no wrapper of its own. A frozen
448///    collection nested in a MULTICELL parent still wraps — that is the corpus's
449///    `MapType(FrozenType(SetType(..)),..)` shape, and it is one level of
450///    wrapping, not two.
451///
452/// This is the SAME four-name set the WRITE path derives independently, for the
453/// same reason (`stats_writer::marshal::FREEZE_WRAPPED_HEADS`, #4158) — the read
454/// gate and the writer must not hold two opinions about what is possible.
455///
456/// Corroborated, never established, by the corpus: `MapType` 25, `ListType` 16,
457/// `UserType` 10, `SetType` 9 over 144 `Statistics.db` — no `TupleType`, no
458/// `VectorType`, no nesting (recipe in this module's header). Because a NARROWING
459/// can over-refuse where a widening cannot,
460/// `frozen_scalar_tests::the_header_gate_never_refuses_a_frozentype_cassandra_wrote`
461/// re-derives the accept set from the Cassandra-written bytes themselves.
462///
463/// # THIS IS A HEAD-CLASS LOOKUP AND CHECKS NO ARGUMENTS — deliberately
464/// Unlike the CQL side's [`is_vector_spelling`], which must validate the whole
465/// `vector<..>` spelling because the spelling is its only evidence that a `Custom`
466/// IS a vector, these names arrive from a marshal string a Cassandra WRITER
467/// produced, and the wrapper question they answer is decided by the class alone:
468/// `MapType.toString` prints the wrapper whatever its key and value types are.
469/// Validating a parameter list belongs to the marshal type parser, not to this
470/// gate. Stated so the asymmetry reads as a decision rather than an oversight.
471const FROZEN_WRAPPABLE_MARSHAL_SIMPLE_NAMES: &[&str] =
472    &["ListType", "SetType", "MapType", "UserType"];
473
474/// The canonical Cassandra marshal package. A `FrozenType` inner head must be
475/// either a BARE simple name or this package's — the same package rule
476/// `row_decoder::udt::marshal_name` enforces, and for the same reason: a
477/// third-party `com.acme.SetType` is not Cassandra's `SetType` and must not be
478/// read as if it were (#28, roborev job 76).
479const MARSHAL_PACKAGE: &str = "org.apache.cassandra.db.marshal.";
480
481/// Refuse a `Statistics.db` SerializationHeader type string that freezes a
482/// non-freezable type, ANYWHERE inside it — fail-closed.
483///
484/// Scans EVERY `FrozenType(` occurrence rather than only a leading one, because a
485/// header type string nests: the frozen wrapper can sit on a map key
486/// (`MapType(FrozenType(Int32Type),Int32Type)`), on a collection element, or on a
487/// UDT field (`UserType(ks,name,f:FrozenType(Int32Type))`) — and the UDT case is
488/// exactly the one a leading-prefix check would miss, since
489/// `convert_marshal_type_to_cql` returns a `UserType`-bearing string verbatim
490/// without descending into it.
491///
492/// Fail-closed in every direction: an EMPTY inner (`FrozenType()`), an unbalanced
493/// parenthesis, a non-canonical package and an unrecognised head are each refused
494/// rather than allowed through.
495///
496/// # THE SCAN'S BOUND, STATED RATHER THAN IMPLIED
497/// The marker is a plain substring search for `FrozenType(`, so it assumes the
498/// marshal grammar in which a `(` follows only a CLASS NAME. That holds for
499/// everything Cassandra writes: a keyspace or UDT name cannot contain `(`, and a
500/// UDT's FIELD names are hex-encoded. It is NOT proven for a third-party CUSTOM
501/// class free to put arbitrary text inside its own parameters — such a class would
502/// have to embed the literal `FrozenType(` to be affected, and the outcome would be
503/// a refusal (fail-closed), never a silent misread. The `FrozenType(` marker itself is matched
504/// case-insensitively (as `extract_frozen_inner_type` does), and the inner head is
505/// compared case-insensitively against the table above for the same reason: a
506/// spelling this crate would not decode as `SetType` must not be admitted as one.
507pub(crate) fn validate_marshal_frozen(marshal: &str) -> Result<()> {
508    const MARKER: &str = "frozentype(";
509    let lower = marshal.to_ascii_lowercase();
510    let mut search_from = 0usize;
511    while let Some(rel) = lower[search_from..].find(MARKER) {
512        let open = search_from + rel + MARKER.len();
513        // Advance past THIS marker whatever the outcome, so a nested
514        // `FrozenType(FrozenType(..))` is inspected at both levels and the loop
515        // always makes progress.
516        search_from = open;
517        let inner = balanced_inner(&marshal[open..]).ok_or_else(|| {
518            Error::schema(format!(
519                "unreadable SerializationHeader type '{marshal}': a FrozenType(…) has no \
520                 matching close parenthesis, so what it freezes cannot be checked — {CITATION}"
521            ))
522        })?;
523        let inner = inner.trim();
524        if !marshal_head_takes_frozen_wrapper(inner) {
525            return Err(Error::schema(format!(
526                "SerializationHeader type '{marshal}' is not writable by Cassandra: it spells \
527                 FrozenType({inner}), and no Cassandra writer prints a FrozenType(…) wrapper \
528                 around '{inner}' — {WRITER_CITATION}. The companion CQL rule, which \
529                 decides what is DECLARABLE rather than what is written: {CITATION}"
530            )));
531        }
532    }
533    Ok(())
534}

536/// The content of a parenthesised group whose opening `(` has already been
537/// consumed, or `None` if the parentheses do not balance.
538fn balanced_inner(after_open: &str) -> Option<&str> {
539    let mut depth = 1usize;
540    for (idx, ch) in after_open.char_indices() {
541        match ch {
542            '(' => depth += 1,
543            ')' => {
544                depth -= 1;
545                if depth == 0 {
546                    return Some(&after_open[..idx]);
547                }
548            }
549            _ => {}
550        }
551    }
552    None
553}

555/// Whether a MARSHAL type string's head class overrides `freeze()`.
556///
557/// The leading `[` and `(` the header sometimes prefixes a comparator with are
558/// stripped first, mirroring `convert_marshal_type_to_cql`'s own
559/// `strip_wrapping_parens` (roborev jobs 43/48): a normalization one reader applies
560/// and another does not is how two readers form two opinions about one string.
561fn marshal_head_takes_frozen_wrapper(inner: &str) -> bool {
562    let inner = inner.trim().trim_start_matches(['[', '(']).trim_start();
563    // The head is everything before the first `(` (a parameterised class) or the
564    // whole string (a bare class name).
565    let head = match inner.find('(') {
566        Some(i) => &inner[..i],
567        None => inner,
568    }
569    .trim();
570    // THE PACKAGE RULE. A bare simple name, or the canonical package — nothing else.
571    let simple = if let Some(rest) = head.strip_prefix(MARSHAL_PACKAGE) {
572        rest
573    } else if head.contains('.') {
574        return false;
575    } else {
576        head
577    };
578    FROZEN_WRAPPABLE_MARSHAL_SIMPLE_NAMES
579        .iter()
580        .any(|n| n.eq_ignore_ascii_case(simple))
581}
