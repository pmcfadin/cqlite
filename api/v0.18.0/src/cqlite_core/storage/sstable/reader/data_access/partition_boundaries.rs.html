1//! Partition-BOUNDARY enumeration over `Data.db` (issue #1103; rewritten
2//! streaming + boundary-keyed for issue #4197 roborev job 124).
3//!
4//! One job: report, in on-disk order, where every partition STARTS in the
5//! decompressed data section and which raw partition key its header carries —
6//! the `(data_position, raw_key)` domain `Index.db` and the BTI
7//! `Partitions.db` trie encode. Two consumers:
8//!
9//! * the verifier's BTI identity cross-check (`verify.rs`), which resolves a
10//!   trie leaf's payload back to a raw key through this map, and
11//! * `cqlite rebuild` (`write_engine::rebuild::boundaries`), which has no
12//!   authoritative boundary source to trust at all — regenerating `Index.db`
13//!   is the whole point of the tool.
14//!
15//! # Two properties this module exists to hold (roborev job 124)
16//!
17//! 1. **Bounded memory.** The walk rides the EXISTING streaming compaction
18//!    driver ([`SSTableReader::stream_all_partitions_for_compaction`]) instead
19//!    of `stitch_all_chunks`, so the decompressed data section is NEVER fully
20//!    resident: peak is one chunk + one in-flight structure (the driver
21//!    advances its window cursor per ROW — issue #2299), plus the returned
22//!    boundary vector itself. The pre-#4197 implementation materialised the
23//!    whole section into one `Vec<u8>` first, which made
24//!    `rebuild_components`'s peak heap O(file size) while spec R6 claimed
25//!    O(one partition).
26//! 2. **Boundary-keyed, never key-keyed.** Each enumerated entry is one
27//!    on-disk partition HEADER. The pre-#4197 implementation deduped by raw
28//!    partition key (`HashSet<Vec<u8>>`), so a `Data.db` carrying the same key
29//!    at two different offsets — the corruption Cassandra's `Verifier` reports
30//!    as "Key out of order" for a non-increasing `(token, key)` step — was
31//!    silently UNDER-enumerated rather than refused. That is exactly the
32//!    hazard `partition_verify_scan` already documents fixing under issue
33//!    #1282; this module keys on the boundary for the same reason. The
34//!    duplicate is surfaced to the caller, which decides: `rebuild` refuses
35//!    (`RefusalReason::DataCorrupt`), the verifier's multiset compare reports
36//!    the mismatch.
37//!
38//! # What the boundary signal IS
39//!
40//! Not a byte-pattern search (issue #28, spec R2.3): the streaming driver
41//! tells us. [`CompactionPartitionState::header_parsed`] flips `false -> true`
42//! exactly when `stream_partition_body_incremental` has decoded one partition
43//! HEADER, and that header began at the window-front offset recorded before
44//! the call. That offset is the same `partition_start` the buffered
45//! `parse_block_for_compaction_emit_with_offset` reports, so both paths define
46//! the boundary in one place.
47//!
48//! One deliberate behavioural delta from the buffered predecessor: it recorded
49//! a partition only once a ROW of it was emitted, so a partition consisting of
50//! a header plus an END_OF_PARTITION marker and nothing else was not
51//! enumerated at all. A header on disk IS a partition (Cassandra's `Index.db`
52//! carries an entry for it), so it is now enumerated. Consumers already handle
53//! a partition that reconciles to no rows — `rebuild`'s pass 2 skips it
54//! (`decode_one_partition` → `Ok(None)`), which is why its key-range
55//! population is drawn from the pass-2 call site alone (issue #4197 F6).
56

63/// The partition-boundary observer threaded through the streaming compaction
64/// driver (`data_access::compaction`), plus the driver's running LOGICAL offset
65/// bookkeeping.
66///
67/// `front` is the absolute offset, in the DECOMPRESSED data section, of the
68/// driver window's front byte — i.e. the total number of bytes the driver has
69/// consumed so far. It is maintained whether or not a `sink` is installed (the
70/// cost is one add per consumed structure), because the whole point is that the
71/// offset is derived from the driver's own confirmed consumption rather than
72/// re-derived by a second walk.
73///
74/// `sink` is `None` for an ordinary compaction stream (the k-way merge producer
75/// wants rows, not boundaries) and `Some` only for the boundary walk below.
76pub(crate) struct PartitionBoundaryObserver<'a> {
77    front: u64,
78    #[allow(clippy::type_complexity)]
79    sink: Option<&'a mut (dyn FnMut(u64, &RowKey) -> Result<()> + Send + 'a)>,
80}
81
82impl<'a> PartitionBoundaryObserver<'a> {
83    /// An observer that tracks the logical front offset but reports no
84    /// boundaries — the ordinary compaction-stream case.
85    pub(crate) fn inactive() -> Self {
86        Self {
87            front: 0,
88            sink: None,
89        }
90    }
91
92    /// An observer that reports every partition boundary to `sink` as
93    /// `(data_position, raw_partition_key)`.
94    pub(crate) fn reporting(
95        sink: &'a mut (dyn FnMut(u64, &RowKey) -> Result<()> + Send + 'a),
96    ) -> Self {
97        Self {
98            front: 0,
99            sink: Some(sink),
100        }
101    }
102
103    /// Whether a caller is actually collecting boundaries.
104    ///
105    /// The driver consults this to route a boundary walk AWAY from its
106    /// non-stitching (index-walk) fallback branch, which resolves rows through
107    /// `Index.db`/the Summary and so reports no decompressed-data-section
108    /// partition offset at all — and this is the one caller that is
109    /// REGENERATING `Index.db`, so inventing one is not an option (issue #28).
110    /// A reporting observer therefore always takes the window-drain path, which
111    /// reads the SAME chunk sequence `stitch_all_chunks` does (for an
112    /// uncompressed reader `read_next_block` yields raw blocks and
113    /// `compression_reader` is `None`, so the bytes pass straight through) —
114    /// exactly how this walk decoded that format before it was made streaming,
115    /// only without the whole section resident.
116    ///
117    /// Empirically load-bearing, not defensive: the committed real Cassandra
118    /// 5.0 `test_basic.uncompressed_table` fixture reaches that fallback
119    /// (`requires_chunk_stitching()` is false for it — measured, against
120    /// `compaction_stream_loses_cell_metadata`'s doc comment, which reads as
121    /// though no real `nb` SSTable can), so a boundary walk that followed it
122    /// REFUSED a healthy file with `UnsupportedFormat` until this routing was
123    /// added.
124    pub(crate) fn is_reporting(&self) -> bool {
125        self.sink.is_some()
126    }
127
128    /// The logical offset of the driver window's front byte — the start offset
129    /// of whatever structure the driver is about to parse.
130    pub(crate) fn front(&self) -> u64 {
131        self.front
132    }
133
134    /// Consume `n` bytes from the driver's window, advancing the logical front
135    /// by the number of bytes the window ACTUALLY consumed.
136    ///
137    /// Reads the clamped amount back out of the window rather than trusting
138    /// `n`: [`WindowCursor::consume`] clamps to the remaining length, so a
139    /// decoder reporting `consumed > remaining` must not be allowed to push the
140    /// logical offset past the bytes the driver really walked (every later
141    /// boundary would then be reported at a wrong absolute offset).
142    pub(crate) fn consume(&mut self, window: &mut WindowCursor, n: usize) {
143        let before = window.len();
144        window.consume(n);
145        self.front += (before - window.len()) as u64;
146    }
147
148    /// Report one confirmed partition boundary, if a caller is collecting.
149    pub(crate) fn note_partition_start(&mut self, start: u64, key: &RowKey) -> Result<()> {
150        if let Some(sink) = self.sink.as_mut() {
151            sink(start, key)?;
152        }
153        Ok(())
154    }
155
156    /// The `false -> true` header-parsed transition check the driver runs after
157    /// every `stream_partition_body_incremental` call: when `was_header_parsed`
158    /// was `false` and the state now reports a parsed header, a partition
159    /// started at `start` carrying `state`'s key.
160    pub(crate) fn note_if_partition_started(
161        &mut self,
162        was_header_parsed: bool,
163        start: u64,
164        state: &CompactionPartitionState,
165    ) -> Result<()> {
166        if !was_header_parsed && state.header_parsed() {
167            self.note_partition_start(start, state.partition_key())?;
168        }
169        Ok(())
170    }
171}

173impl SSTableReader {
174    /// Return every on-disk partition's `(data_position, raw_partition_key)`
175    /// in on-disk order, where `data_position` is the partition's start offset
176    /// in the DECOMPRESSED data section (issue #1103).
177    ///
178    /// `data_position` is exactly the value a BTI `Partitions.db` leaf encodes
179    /// as
180    /// [`BtiPartitionLocation::DataOffset`](crate::storage::sstable::bti::parser::BtiPartitionLocation::DataOffset)
181    /// (and the `data_position` recovered from a `RowsOffset` entry via
182    /// [`resolve_rows_db_entry`](crate::storage::sstable::bti::parser::resolve_rows_db_entry)),
183    /// and the offset `Index.db` records for the partition. The verifier's BTI
184    /// cross-check resolves each leaf PAYLOAD back to its raw partition key
185    /// through this map, so it catches a corruption that keeps the emitted trie
186    /// prefix but rewrites the payload to point at a DIFFERENT partition.
187    ///
188    /// # One entry per BOUNDARY, not per distinct key
189    ///
190    /// The returned keys are NOT deduplicated: a `Data.db` in which the same
191    /// partition key appears at two different offsets yields two entries, in
192    /// on-disk order. That is a corruption (Cassandra's `Verifier` flags a
193    /// non-increasing `(token, key)` step), and the caller is the right place
194    /// to classify it — `rebuild` refuses with
195    /// `RefusalReason::DataCorrupt`, the verifier's multiset compare reports
196    /// the mismatch. Deduplicating here, as this function did before issue
197    /// #4197's roborev round, silently DROPPED the second occurrence and
198    /// under-enumerated the file (the same hazard
199    /// [`SSTableReader::partition_verify_scan`] documents fixing under issue
200    /// #1282).
201    ///
202    /// # Memory
203    ///
204    /// Streaming: bounded by one chunk + one in-flight structure + the
205    /// returned vector, never by the size of the data section (spec R6). See
206    /// the module doc.
207    ///
208    /// `schema`, when supplied, takes priority over the reader's own
209    /// header-derived resolution (`get_table_schema`'s "Strategy 0"; issue
210    /// #4197). This matters whenever the reader's usual fallbacks cannot
211    /// resolve one on their own — e.g. `cqlite rebuild` walking boundaries
212    /// while the sibling `Statistics.db` (the source `get_table_schema`'s
213    /// header-derived Strategy 1 reads from at OPEN time) is itself the
214    /// component being regenerated, or is temporarily relocated for repair-
215    /// field recovery (spec R4.2). Every pre-existing caller passes `None`
216    /// and is unaffected.
217    pub async fn distinct_partition_keys_with_positions(
218        &self,
219        schema: Option<&crate::schema::TableSchema>,
220    ) -> Result<Vec<(u64, Vec<u8>)>> {
221        let mut result: Vec<(u64, Vec<u8>)> = Vec::new();
222        {
223            let mut sink = |start: u64, key: &RowKey| -> Result<()> {
224                result.push((start, key.as_bytes().to_vec()));
225                Ok(())
226            };
227            // The rows themselves are irrelevant here — each one is dropped as
228            // soon as the driver hands it over, which is what keeps the walk's
229            // peak bounded by a single structure. Decoding them is not wasted
230            // work that could be skipped: it is how the driver establishes
231            // where the NEXT structure (and so the next partition header)
232            // begins, and it is the same decode that proves `Data.db` is
233            // structurally sound (rebuild spec R5).
234            self.stream_all_partitions_for_compaction_observed(
235                schema,
236                &self.scan_cancel,
237                PartitionBoundaryObserver::reporting(&mut sink),
238                |_row| Ok(std::ops::ControlFlow::Continue(())),
239            )
240            .await?;
241        }
242        Ok(result)
243    }
