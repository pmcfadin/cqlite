1//! Sliding-window stitch+parse driver for the user-facing streaming scan
2//! (issue #1143).
3//!
4//! # Design (issue #1143 regression fix)
5//!
6//! The V5CompressedLegacy full scan must reconcile two goals that PR #1156
7//! treated as mutually exclusive:
8//!
9//!   1. **Bounded heap.** Keep only a sliding `window: Vec<u8>` of decompressed
10//!      bytes (peak `max_partition_size + one_chunk`), not an O(file) stitched
11//!      buffer per scan. (PR #1156's contribution — KEPT.)
12//!   2. **CPU off the async worker pool.** Decompress +
13//!      `parse_one_partition_with_timestamps` are CPU-bound; running them inline
14//!      on the small async worker pool (as PR #1156 did, relying on
15//!      `yield_now()`) lets a scan starve everything else scheduled there
16//!      (writer flush/compaction in production), halving reader throughput under
17//!      concurrent write load. The pre-#1156 path ran the whole parse under a
18//!      dedicated `spawn_blocking` thread — restore that.
19//!
20//! Both are achievable together. This driver splits the work across THREE stages
21//! of one bounded pipeline (issue #1143 contention fix):
22//!
23//!   - **Async I/O half** (`run_scan_stream_windowed`): the only thing that must
24//!     touch the async runtime is the chunk read (`read_next_block().await`
25//!     awaits the per-scan cursor's async file lock). It does ONLY I/O: read the
26//!     next raw compressed chunk and hand it to the parse half over a small
27//!     bounded channel (`raw` channel, capacity [`RAW_CHUNK_CHANNEL_CAP`] = 8 so
28//!     the I/O half can read ahead instead of ping-ponging on every chunk).
29//!   - **Blocking parse half** (`drain_scan_window_blocking`): a single
30//!     `spawn_blocking` task owns the parser, the schema, and the sliding
31//!     window. It pulls raw chunks with `blocking_recv`, decompresses, appends to
32//!     the window, drains every confirmed partition, and accumulates surviving
33//!     `(RowKey, ScanRow)` entries into a BATCH of up to [`BATCH_EMIT_ROWS`], which
34//!     it hands across the blocking→async seam via `tx.blocking_send` as ONE
35//!     `Vec` item. ALL decompress+parse CPU runs here, off the async worker pool.
36//!     Batching is the key contention fix: PR #1156 `blocking_send`'d one row at
37//!     a time, so a `SELECT *` full scan woke the consuming async task O(rows)
38//!     times across the blocking-pool ↔ async-worker boundary; samply attributed
39//!     ~31.5% of read wall time under `mixed.read_while_write` conc=8 to that one
40//!     `parking_lot` condvar. Batching amortizes the wake ~`BATCH_EMIT_ROWS`×.
41//!     To keep that win WITHOUT regressing incremental delivery, the pending
42//!     batch is flushed at a BOUNDED CADENCE — at each chunk/window drain
43//!     boundary (after the per-chunk drain returns NeedMore / empties the
44//!     window) as well as on reaching `BATCH_EMIT_ROWS` — so a sparse or
45//!     sub-`BATCH_EMIT_ROWS` scan (e.g. a `LIMIT`) still delivers its confirmed
46//!     rows promptly instead of waiting for the whole scan to finish. The wake
47//!     rate is thus ~one-per-chunk (plus one-per-full-batch in dense windows),
48//!     far below PR #1156's one-per-row.
49//!   - **Async forwarder task** (in `run_scan_stream_windowed`): flattens each
50//!     `Vec` batch back into the caller's per-item `tx`, preserving the public
51//!     `scan_stream` contract (item type, order, backpressure) unchanged. Runs on
52//!     the async runtime concurrently with the I/O half (both are needed at once;
53//!     running them sequentially would deadlock), so its wakes are cheap
54//!     async-worker wakes, not blocking-pool condvar wakes.
55//!
56//! ## Backpressure (preserved end-to-end)
57//!
58//! A slow consumer blocks the forwarder's `tx.send().await`, which stops draining
59//! the bounded batch channel, which blocks the parse half's `tx.blocking_send`,
60//! which stops the parse loop, which stops draining the `raw` channel, which
61//! (being bounded) blocks `raw_tx.send().await` in the I/O half, which stops
62//! reading from disk. Nothing buffers the whole file; live heap stays
63//! `window + RAW_CHUNK_CHANNEL_CAP` raw chunks + at most
64//! [`MAX_INFLIGHT_BATCH_ROWS`] buffered rows ahead of the caller.
65//!
66//! ## Worst-case resident rows (issue #1143, roborev)
67//!
68//! Be honest and COMPLETE: against a stalled consumer the resident `(RowKey, ScanRow)`
69//! count is the SUM of three inherent terms, not one constant —
70//! `buffer_size + max_partition_size + MAX_INFLIGHT_BATCH_ROWS`:
71//!
72//! - **`buffer_size`** — the public per-item channel, sized from the caller's
73//!   `StreamingConfig::buffer_size`.
74//! - **`max_partition_size`** — INHERENT to any row-materializing partition scan and
75//!   PRE-DATES this change: `drain_scan_window` parses one CONFIRMED partition fully
76//!   into a reused `scratch: Vec<(RowKey, ScanRow)>` before batching (the parser's `FnMut`
77//!   emit is synchronous, so a partition's rows cannot stream out mid-parse), so if
78//!   `blocking_send` stalls mid-iteration the producer still owns that Vec's
79//!   not-yet-batched tail. This is the pre-existing #1156 windowed-scan heap term
80//!   (heap was always `~max_partition_size + one_chunk`); this PR neither introduced
81//!   it nor restructures emission to observe backpressure mid-partition — that is a
82//!   separate #1156 redesign, deliberately out of scope here.
83//! - **`MAX_INFLIGHT_BATCH_ROWS`** — the *additional* bound this PR's batching adds:
84//!   a SECOND in-flight pool NOT sized by `buffer_size`. The bounded batch channel
85//!   (`BATCH_CHANNEL_CAP` batches), the one batch the forwarder `recv()`'d and is
86//!   flattening, AND the one batch the producer is parked-in-`blocking_send` holding
87//!   can ALL be live at once — even when `buffer_size == 1`: a deliberate, BOUNDED
88//!   read-ahead, the price of amortizing the blocking->async wake. It bounds the
89//!   BATCHING subsystem ALONE; it does NOT — and is not claimed to — cover the
90//!   `max_partition_size` term. The public `scan_stream` doc states the full
91//!   three-term sum so callers know the true worst case.
92//!
93//! ## Cancellation (issue #1143 finding 2)
94//!
95//! The outer scan runs inside the `tokio::spawn` in `scan_stream`; if that task
96//! is dropped/cancelled at an `await`, the parse task's `JoinHandle` (held in
97//! `run_scan_stream_windowed`) is dropped too. Dropping a `spawn_blocking`
98//! `JoinHandle` DETACHES the task — it does NOT abort it (there is no portable
99//! way to interrupt a running blocking thread). The detached parse task keeps
100//! running: `raw_rx.blocking_recv()` observes the dropped `raw_tx`, and because a
101//! clean cancellation leaves `io_failed == false`, it proceeds to a final drain
102//! and `tx.blocking_send`s its trailing batch into the batch channel.
103//!
104//! This is harmless in practice and needs no abort machinery: on cancellation
105//! the consumer drops the `mpsc::Receiver` (`rx`) returned by `scan_stream`, so
106//! the forwarder's next `fwd_tx.send` fails, the forwarder returns and drops the
107//! batch receiver, so the parse half's next `tx.blocking_send` fails
108//! (`*broke = true`), the parse loop returns immediately, and the task — and the
109//! `reader: Arc<Self>` it holds — are released. The only window in which it can
110//! still emit is when a batch was already in flight AND the consumer's `rx` has
111//! not yet dropped, i.e. the consumer is still reading; those rows are valid scan
112//! output, not garbage. Worst case the task lingers for one partition's parse
113//! before its `blocking_send` fails, keeping `Arc<Self>` alive only that long.
114//! Pre-#1156 the parse ran inline on the cancellable async task, so this detach
115//! window is new to the offload split; it is bounded and self-terminating, so we
116//! document it rather than add abort plumbing.
117//!
118//! ## Parity
119//!
120//! The emitted set/order is byte-identical to the prior inline driver: same
121//! schema resolution, same incompressible-chunk raw fallback, same
122//! `table_ids_match` / key-range / `filter_tombstone` filters, same
123//! NeedMore/Done straddle handling and final-chunk semantics, same
124//! `READ_SCAN_WINDOW_REFILL` counter. The only change is WHERE the CPU runs.

136/// Bound on the raw-compressed-chunk channel feeding the blocking parse task.
137///
138/// This is the I/O-half → parse-half hand-off depth. It must stay small enough
139/// to bound live heap (combined with the sliding window: live heap is
140/// `max_partition_size + (RAW_CHUNK_CHANNEL_CAP + 1) * one_chunk`), but a value
141/// of 2 (PR #1156's original) makes the two halves ping-pong: the I/O half fills
142/// the channel, parks on `raw_tx.send().await`, and is unparked again after the
143/// parse half drains essentially every chunk. Under concurrent write load (issue
144/// #1143, `mixed.read_while_write` conc=8) samply showed ~42% of read wall time
145/// parked on futexes, dominated by this channel's park/unpark, roughly doubling
146/// read p99 vs the pre-windowing baseline.
147///
148/// Raising the depth to 8 lets the I/O half read ahead up to 8 compressed chunks
149/// before it has to park, amortizing the wake round-trips ~4x while preserving
150/// the bounded-heap intent of PR #1156. The chunks are RAW COMPRESSED data
151/// (~`one_chunk` = the SSTable's compression chunk length, typically 16–64 KiB),
152/// so the added buffer is at most `(8 - 2) * one_chunk` ≈ 384 KiB per scan at
153/// 64 KiB chunks. At the issue #1143 concurrency of 8 readers that is < 3 MiB of
154/// channel buffers total — negligible against the < 128 MiB budget, and far
155/// smaller than the O(file) stitch buffer PR #1156 eliminated. Backpressure is
156/// unchanged: a full channel still blocks the I/O half, which still blocks disk
157/// reads, so nothing buffers the whole file.
158const RAW_CHUNK_CHANNEL_CAP: usize = 8;
159
160/// Number of surviving `(RowKey, ScanRow)` entries the blocking parse half buffers
161/// before it hands a batch across the blocking→async seam.
162///
163/// PR #1156's blocking parse half `blocking_send`s ONE row at a time into the
164/// async consumer's channel. Each such send parks/unparks across the
165/// blocking-pool ↔ async-worker boundary (a `parking_lot` condvar wake under
166/// tokio's blocking pool). For a `SELECT *` full scan that is O(rows) wakes per
167/// scan — and samply attributed ~31.5% of read wall time to that one condvar
168/// under `mixed.read_while_write` conc=8 (issue #1143). The cap-bump on the
169/// raw-chunk channel alone did not move read p99 in the external harness, because
170/// the cost is dominated by THIS per-row cross-thread wake, not the chunk hand-off.
171///
172/// Batching `BATCH_EMIT_ROWS` rows into a single `Vec` item amortizes that wake
173/// ~`BATCH_EMIT_ROWS`× (one wake per batch instead of one per row) while keeping
174/// the bounded-heap and backpressure guarantees: a batch holds at most this many
175/// `(RowKey, ScanRow)` already-owned entries (the same entries the prior code held
176/// transiently in `scratch`), and the batch channel is bounded
177/// ([`BATCH_CHANNEL_CAP`]) so a slow consumer still stops the parse loop, which
178/// still stops draining raw chunks, which still stops disk reads. Order is
179/// preserved (entries are pushed and drained FIFO, batches sent in order). A
180/// modest value keeps the per-batch heap small; tiny / sparse result sets do not
181/// wait for a full batch because the pending tail is flushed at every chunk/window
182/// drain boundary (and at stream end), preserving incremental first-row delivery.
183const BATCH_EMIT_ROWS: usize = 256;
184
185/// Bound on the batched-row channel feeding the async forwarder. Small: the
186/// forwarder flattens batches into the public per-item channel roughly as fast as
187/// the parse half produces them. Live heap on this channel is at most
188/// `BATCH_CHANNEL_CAP * BATCH_EMIT_ROWS` entries; with the defaults that is
189/// ~512 small `(RowKey, ScanRow)` entries — negligible against the <128MB budget.
190const BATCH_CHANNEL_CAP: usize = 2;
191
192/// Documented bound on the rows the windowed scan's BATCHING SUBSYSTEM may hold in
193/// flight ahead of the caller, INDEPENDENT of `scan_stream`'s `buffer_size`
194/// (roborev finding, issue #1143).
195///
196/// # Scope (read this first)
197///
198/// This bounds the BATCHING subsystem ALONE — the pending `batch`, the bounded batch
199/// channel, and the parked-in-`blocking_send` batch — the *additional* in-flight pool
200/// issue-#1143 batching adds, NOT sized by `buffer_size`. It is NOT the whole-pipeline
201/// resident-row bound: the complete worst case (module doc) is
202/// `buffer_size + max_partition_size + MAX_INFLIGHT_BATCH_ROWS`, and this constant
203/// does NOT cover the inherent pre-existing-#1156 `max_partition_size` term (the one
204/// confirmed partition `drain_scan_window` materializes in `scratch` before
205/// batching). It is named/tested so a future `BATCH_EMIT_ROWS`/`BATCH_CHANNEL_CAP`
206/// tweak cannot silently let batching run arbitrarily far ahead of a stalled consumer.
207///
208/// # The bound (batching subsystem)
209///
210/// When the public consumer is stalled, THREE full batches coexist in flight — not
211/// two (each up to `BATCH_EMIT_ROWS` rows):
212///   1. **Forwarder-held.** The async forwarder `recv()`'d one batch and is blocked
213///      flattening it into the caller's full `tx`; it has LEFT the batch channel.
214///   2. **Channel-resident.** The bounded batch channel is FULL —
215///      `BATCH_CHANNEL_CAP` items — because the forwarder (stuck on (1)) stopped draining.
216///   3. **Producer-blocked.** The `spawn_blocking` parse half assembled its NEXT
217///      full batch and is PARKED in `tx.blocking_send`, still OWNING it because the
218///      channel (full, per (2)) has no slot — `blocking_send` moves the value only
219///      on success, so a parked send holds a third, distinct batch.
220///
221/// All three coexist at one instant; the pending tail in `drain_scan_window` is NOT
222/// a fourth — once it REACHES `BATCH_EMIT_ROWS` it BECOMES (3) via `blocking_send`,
223/// and a producer parked in that send accumulates no further tail. So bounding by
224/// `(BATCH_CHANNEL_CAP + 2) * BATCH_EMIT_ROWS` covers channel + forwarder-held (+1)
225/// + producer-blocked-in-send (+1).
226///
227/// With the defaults (`256 * 4 = 1024`) this equals — never exceeds — every real
228/// caller's `buffer_size` (`StreamingConfig::buffer_size` defaults to 1024, the
229/// text preset is 512 ≤ this), keeping this batching term comparable to the
230/// channel term — yet the bound is a CONSTANT, not `buffer_size`-scaled, so it
231/// holds even for `buffer_size = 1`. (The full resident-row worst case adds the
232/// `max_partition_size` term on top; see the module doc.)
233///
234/// [`tests::batch_inflight_rows_are_bounded_independent_of_buffer_size`] asserts
235/// the batching subsystem's runtime worst case never exceeds this; any sizing
236/// change that breaks the bound must update this constant AND keep that test green.
237pub(super) const MAX_INFLIGHT_BATCH_ROWS: usize = (BATCH_CHANNEL_CAP + 2) * BATCH_EMIT_ROWS;

239/// Decide whether the blocking parse half should run its terminal
240/// (`at_final_chunk = true`) drain once the raw-chunk stream has ended.
241///
242/// The terminal drain parses the trailing window AS IF it were a complete final
243/// partition (it collapses `NeedMore` → `Done`). That is correct only on a CLEAN
244/// EOF. If the I/O half stopped on a mid-stream read error it sets `io_failed`
245/// before dropping the raw-chunk sender, so the trailing window is a TRUNCATED
246/// fragment; running the terminal drain on it would emit a spurious/garbage
247/// partition through `tx` BEFORE the caller surfaces the I/O `Err` (issue #1143
248/// finding 2). Skipping it makes a truncated/corrupt stream yield ONLY the error.
249///
250/// Pulled out as a tiny pure function so the drain-skip decision is unit-tested
251/// directly (issue #1143 finding 1): a future refactor that drops the flag,
252/// flips the load, or reorders the store-before-`drop(raw_tx)` must fail
253/// [`tests::terminal_drain_skipped_iff_io_failed`].
254#[inline]
255fn should_run_terminal_drain(io_failed: bool) -> bool {
256    !io_failed
257}
258
259/// Flush any rows already buffered in `batch` to the batched-row channel as one
260/// item, draining `batch`. Used at EVERY error-exit of the blocking parse half
261/// so confirmed rows produced before a mid-stream parse/decompress error are
262/// delivered to the consumer ahead of the terminal `Err` — matching the
263/// pre-#1156 per-row send contract (the consumer must see all confirmed rows up
264/// to the failure, not just the earlier full batches).
265///
266/// Returns the send result; the caller propagates the original error regardless
267/// (a failed flush means the consumer already dropped `rx`, so there is nobody
268/// left to receive the rows OR the error — the scan is terminating either way).
269/// A no-op when `batch` is empty. Roborev finding (issue #1143): the batching
270/// change must not silently drop confirmed-up-to-error rows.
271#[inline]
272fn flush_pending(
273    batch: &mut Vec<(RowKey, ScanRow)>,
274    tx: &mpsc::Sender<Result<Vec<(RowKey, ScanRow)>>>,
275) {
276    if !batch.is_empty() {
277        let _ = tx.blocking_send(Ok(std::mem::take(batch)));
278    }
279}
280
281/// Finish the blocking parse half: deliver the rows still pending in `batch` and
282/// return the drain outcome to the caller.
283///
284/// This is the load-bearing error-flush seam (roborev finding, issue #1143).
285/// `drained` is the result of the fallible parse loop + terminal drain:
286///
287///   - `Err(e)`: a mid-stream decompress/parse error. FLUSH `batch` first so the
288///     consumer receives every confirmed-up-to-error row ahead of the terminal
289///     `Err` — matching the pre-batching per-row send contract — THEN propagate
290///     `e`. Removing this flush silently drops the confirmed-but-unflushed pending
291///     rows on an error, which is exactly the regression
292///     [`tests::finish_blocking_drain_flushes_pending_before_error`] pins.
293///   - `Ok(())` and the consumer is still attached (`!broke`): flush the trailing
294///     partial batch so the last rows reach the consumer.
295///   - `Ok(())` but `broke` (consumer dropped): nothing to deliver — drop `batch`.
296///
297/// Pulled out of [`SSTableReader::drain_scan_window_blocking`] so the error-path
298/// flush is unit-tested in isolation with a genuinely NON-EMPTY pending batch. In
299/// the live driver the in-stream per-chunk flush usually empties `batch` at a
300/// chunk boundary BEFORE a separate-chunk decompress error fires, which would make
301/// an end-to-end "corrupt trailing chunk" test vacuous; testing this seam directly
302/// guarantees the error flush is exercised and FAILS if it is removed.
303fn finish_blocking_drain(
304    drained: Result<()>,
305    batch: &mut Vec<(RowKey, ScanRow)>,
306    broke: bool,
307    tx: &mpsc::Sender<Result<Vec<(RowKey, ScanRow)>>>,
308) -> Result<()> {
309    match drained {
310        Err(e) => {
311            flush_pending(batch, tx);
312            Err(e)
313        }
314        Ok(()) => {
315            if !broke {
316                flush_pending(batch, tx);
317            }
318            Ok(())
319        }
320    }
321}

323/// Inputs the blocking parse half needs that the I/O half resolves once up front
324/// (so the blocking task does not have to touch the async runtime).
325struct WindowParseCtx {
326    table_id: TableId,
327    start_key: Option<RowKey>,
328    end_key: Option<RowKey>,
329    schema: Option<crate::schema::TableSchema>,
330    /// Cassandra stores a chunk RAW when its compressed length would meet or
331    /// exceed this (Bug #639, epic #970, issue #1104); honour the same rule as
332    /// `stitch_all_chunks` so the windowed path decodes identically.
333    max_compressed_length: usize,
334}
335
336impl SSTableReader {
337    /// Async I/O half of the windowed streaming scan (issue #1143).
338    ///
339    /// Reads raw compressed chunks from `cursor` and forwards them to a single
340    /// `spawn_blocking` parse task ([`drain_scan_window_blocking`]) over a
341    /// bounded channel; the parse task owns all decompress+parse CPU and emits
342    /// results through `tx`. See the module docs for the full rationale.
343    ///
344    /// Precondition: `cursor`'s file is seeked to the start of the data section.
345    pub(super) async fn run_scan_stream_windowed(
346        self: Arc<Self>,
347        table_id: TableId,
348        start_key: Option<RowKey>,
349        end_key: Option<RowKey>,
350        schema: Option<crate::schema::TableSchema>,
351        cursor: &ScanCursor,
352        tx: &mpsc::Sender<Result<(RowKey, ScanRow)>>,
353    ) -> Result<()> {
354        // Resolve everything the parser needs ONCE, here on the async side, so
355        // the blocking task never touches the async runtime. Schema resolution
356        // matches the previous `parse_stitched_stream` resolution exactly.
357        let ctx = WindowParseCtx {
358            table_id,
359            start_key,
360            end_key,
361            schema: schema.or_else(|| self.get_table_schema(None)),
362            max_compressed_length: self
363                .compression_info
364                .as_ref()
365                .map(|ci| ci.max_compressed_length as usize)
366                .unwrap_or(usize::MAX),
367        };
368
369        // Raw-chunk pipe: I/O half -> blocking parse half (bounded for heap +
370        // backpressure). Output backpressure rides on the batch channel inside
371        // the task.
372        let (raw_tx, raw_rx) = mpsc::channel::<Vec<u8>>(RAW_CHUNK_CHANNEL_CAP);
373        // Batched-row pipe: blocking parse half -> async forwarder task. The
374        // parse half buffers up to `BATCH_EMIT_ROWS` surviving entries per item so
375        // the expensive blocking→async wake happens once per batch instead of once
376        // per row (issue #1143). The forwarder task flattens each batch into the
377        // caller's per-item `tx`, preserving the public stream contract.
378        let (batch_tx, batch_rx) =
379            mpsc::channel::<Result<Vec<(RowKey, ScanRow)>>>(BATCH_CHANNEL_CAP);
380        // The batching subsystem (this bounded channel + the forwarder-held batch +
381        // the producer's parked-in-send batch) holds at most `MAX_INFLIGHT_BATCH_ROWS`
382        // confirmed rows ahead of a stalled caller, INDEPENDENT of `scan_stream`'s
383        // `buffer_size` (roborev finding, issue #1143). The assert ties the runtime
384        // channel sizing to that named bound so a capacity change cannot exceed it.
385        debug_assert!(
386            (BATCH_CHANNEL_CAP + 2) * BATCH_EMIT_ROWS <= MAX_INFLIGHT_BATCH_ROWS,
387            "batch channel sizing must stay within the documented MAX_INFLIGHT_BATCH_ROWS bound \
388             (channel-resident BATCH_CHANNEL_CAP + forwarder-held 1 + producer-blocked-in-send 1)"
389        );
390        // Distinguishes a clean EOF (sender dropped after `Ok(None)`) from a
391        // mid-stream read error (sender dropped after `Err`). On error the parse
392        // half must NOT run its `at_final_chunk = true` terminal drain — a
393        // truncated/partial trailing window would otherwise emit a spurious
394        // partition through `tx` BEFORE this function returns the `Err` (issue
395        // #1143 finding 2; the pre-#1156 path `?`-propagated the read error and
396        // never ran a final drain). Set before `raw_tx` is dropped so the parse
397        // half observes it via the channel-close happens-before.
398        let io_failed = Arc::new(AtomicBool::new(false));
399        let reader = Arc::clone(&self);
400        let task_io_failed = Arc::clone(&io_failed);
401        let parse_task = tokio::task::spawn_blocking(move || {
402            reader.drain_scan_window_blocking(ctx, raw_rx, batch_tx, task_io_failed)
403        });
404
405        // Forwarder task: flatten batched rows from the blocking parse half into
406        // the caller's per-item `tx`. Runs CONCURRENTLY with the I/O feed loop
407        // below — both are needed at once (the I/O loop produces the raw chunks
408        // the parse half consumes; the parse half produces the batches this task
409        // drains), so running them sequentially would deadlock. On the async
410        // runtime, so its wakes are cheap async-worker wakes, not blocking-pool
411        // condvar wakes.
412        //
413        // Backpressure: a slow consumer blocks `fwd_tx.send().await` here, which
414        // stops draining `batch_rx`, which (being bounded) blocks the parse half's
415        // `blocking_send`, which stops the parse loop and ultimately disk reads —
416        // the exact end-to-end backpressure shape PR #1156 had, just batched. If
417        // the consumer drops `tx`, the send fails, this task returns and drops
418        // `batch_rx`; the parse half's next `blocking_send` then fails so it
419        // terminates (`*broke = true`).
420        let fwd_tx = tx.clone();
421        let forwarder = tokio::spawn(async move {
422            let mut batch_rx = batch_rx;
423            while let Some(batch) = batch_rx.recv().await {
424                match batch {
425                    Ok(rows) => {
426                        for entry in rows {
427                            if fwd_tx.send(Ok(entry)).await.is_err() {
428                                return; // consumer dropped
429                            }
430                        }
431                    }
432                    Err(e) => {
433                        // The parse half surfaced an error mid-stream; forward it
434                        // as a terminal stream item and stop. The parse half also
435                        // returns the same error via its `Result`, joined below.
436                        let _ = fwd_tx.send(Err(e)).await;
437                        return;
438                    }
439                }
440            }
441        });
442
443        // Feed raw compressed chunks to the parse task. The bounded `raw_tx`
444        // applies backpressure all the way back to disk reads when the consumer
445        // (and thus the parse task) falls behind.
446        let mut io_err: Option<Error> = None;
447        loop {
448            match self.read_next_block(cursor).await {
449                Ok(Some(chunk)) => {
450                    if raw_tx.send(chunk).await.is_err() {
451                        // Parse task ended early (consumer dropped or parse
452                        // error). Stop reading; the task's result is canonical.
453                        break;
454                    }
455                }
456                Ok(None) => break, // EOF
457                Err(e) => {
458                    // Tell the parse half to SKIP the terminal final drain: the
459                    // stream is truncated, so the trailing window is partial and
460                    // must not be emitted. The store is sequenced before the
461                    // `drop(raw_tx)` the parse half synchronizes on.
462                    io_failed.store(true, Ordering::SeqCst);
463                    io_err = Some(e);
464                    break;
465                }
466            }
467        }
468        // Drop the sender so the blocking task sees EOF and runs its final drain
469        // (only if `io_failed` is still false — see the parse half).
470        drop(raw_tx);
471
472        // Join the parse task; its Result is the scan's Result. An I/O error
473        // takes precedence (the task only saw a truncated stream). The parse task
474        // owns `batch_tx`; when it returns, `batch_tx` drops, so the forwarder's
475        // `batch_rx.recv()` will observe channel close after the last batch.
476        let parse_result = match parse_task.await {
477            Ok(r) => r,
478            Err(join_err) => Err(Error::corruption(format!(
479                "run_scan_stream_windowed: parse task failed: {join_err}"
480            ))),
481        };
482        // Then await the forwarder so every batched row reaches the consumer
483        // before this function returns (the public stream must not drop the
484        // trailing batch). The forwarder cannot fail the scan — it only flattens
485        // already-produced rows — so a join error there is non-fatal; the parse
486        // task's `Result` plus `io_err` remain canonical.
487        let _ = forwarder.await;
488        if let Some(e) = io_err {
489            return Err(e);
490        }
491        parse_result
492    }
493
494    /// Blocking parse half of the windowed streaming scan (issue #1143).
495    ///
496    /// Runs entirely on a `spawn_blocking` thread — NEVER on an async worker.
497    /// Owns the sliding `window` (a [`WindowCursor`], issue #1589); for each raw chunk pulled from
498    /// `raw_rx` it applies the incompressible-raw fallback or decompresses,
499    /// appends to the window, and drains every confirmed partition via
500    /// [`drain_scan_window`]. On a CLEAN `raw_rx` close (I/O EOF) it runs a final
501    /// drain with `at_final_chunk = true`; on a close caused by a mid-stream read
502    /// error (`io_failed` set by the I/O half before it dropped the sender) it
503    /// SKIPS that terminal drain so a truncated window cannot emit a spurious
504    /// trailing partition (issue #1143 finding 2). Surviving `(RowKey, ScanRow)`
505    /// entries are accumulated into batches of up to [`BATCH_EMIT_ROWS`] and sent
506    /// through `tx` (a `Vec`-batched channel) with `blocking_send`, mirroring the
507    /// pre-#1156 `parse_stitched_stream` backpressure but amortizing the
508    /// blocking→async wake one-per-batch instead of one-per-row (issue #1143).
509    ///
510    /// On a mid-stream decompress/parse `Err`, any rows already buffered in the
511    /// pending batch are flushed to `tx` BEFORE the error is propagated (via
512    /// [`flush_pending`]), so the consumer receives every confirmed-up-to-error
513    /// row ahead of the terminal `Err` — preserving the pre-batching per-row
514    /// send contract (roborev finding, issue #1143).
515    fn drain_scan_window_blocking(
516        &self,
517        ctx: WindowParseCtx,
518        mut raw_rx: mpsc::Receiver<Vec<u8>>,
519        tx: mpsc::Sender<Result<Vec<(RowKey, ScanRow)>>>,
520        io_failed: Arc<AtomicBool>,
521    ) -> Result<()> {
522        use crate::storage::sstable::compression::Compression;
523
524        // Issue #1741: single-gen full-scan read path applies SELECT-semantic
525        // read shadowing (partition/range tombstone + TTL), so build the parser
526        // with read_shadowing = true.
527        let parser = self.build_v5_parser(true);
528        // Sliding front-cursor window (issue #1589): compacts once per refill.
529        let mut window = WindowCursor::new();
530        let mut broke = false;
531        let mut chunk_count = 0usize;
532        // Pending surviving rows not yet handed to the forwarder. Flushed as a
533        // single batch item when it reaches `BATCH_EMIT_ROWS`, and once more at
534        // stream end (the partial tail). Bounded by `BATCH_EMIT_ROWS` + one
535        // partition's worth of rows, so it stays within the sliding-window heap
536        // bound.
537        let mut batch: Vec<(RowKey, ScanRow)> = Vec::with_capacity(BATCH_EMIT_ROWS);
538        // Reused scratch buffer for ONE confirmed partition's surviving
539        // `(RowKey, ScanRow)` entries. Hoisted OUT of the per-partition loop in
540        // [`drain_scan_window`] (issue #1333, follow-up to #1046) and passed by
541        // `&mut` so it is allocated ONCE for the whole scan and `.clear()`-reused
542        // per partition. `clear()` drops the prior partition's entries but PRESERVES
543        // capacity, so a warmed buffer performs ZERO per-partition backing
544        // allocations — the #1046 "buffers should be reused, do not allocate as we
545        // iterate" mandate, extended to the per-partition scratch. Its peak size is
546        // still bounded by one partition's rows (`max_partition_size`), the same
547        // bound the transient per-partition `Vec::new()` had.
548        let mut scratch: Vec<(RowKey, ScanRow)> = Vec::new();
549
550        // The parse loop + terminal drain are fallible; on ANY `Err` we must
551        // first deliver the rows already buffered in `batch` (confirmed rows
552        // produced before the failure) so the consumer sees them ahead of the
553        // terminal error — the pre-#1156 per-row send delivered every
554        // confirmed-up-to-error row, and batching must preserve that (roborev
555        // finding, issue #1143). Run the fallible work in a closure and flush
556        // `batch` before propagating any error it returns.
557        let drained: Result<()> = (|| {
558            while let Some(compressed_chunk) = raw_rx.blocking_recv() {
559                // Shared decompressed-chunk cache (issue #1567). The I/O half feeds
560                // chunks from the data-section start (chunk 0) in order, so
561                // `chunk_count` is the ABSOLUTE chunk index — a stable cache key in
562                // the windowed-scan namespace. Incompressible raw-passthrough chunks
563                // (`len >= max_compressed_length`) skip the decompressor already, so
564                // there is nothing to memoize; they are NOT cached (documented D-choice,
565                // task 4.4). On a compressible chunk the cache is consulted before
566                // decompress: a hit skips the decompressor (and the counter).
567                if compressed_chunk.len() >= ctx.max_compressed_length {
568                    window.refill(&compressed_chunk);
569                } else if let Some(compression_reader) = &self.compression_reader {
570                    let key = self
571                        .chunk_cache_key(super::data_access::NS_WINDOWED_CHUNK, chunk_count as u64);
572                    let chunk: std::sync::Arc<[u8]> = match self.chunk_cache.get(&key) {
573                        Some(hit) => hit,
574                        None => {
575                            let compression = Compression::new(*compression_reader.algorithm())?;
576                            let d = compression.decompress(&compressed_chunk).map_err(|e| {
577                                Error::corruption(format!(
578                                    "drain_scan_window_blocking: Failed to decompress chunk {}: {}",
579                                    chunk_count, e
580                                ))
581                            })?;
582                            super::data_access::DECOMPRESS_CALLS
583                                .fetch_add(1, std::sync::atomic::Ordering::Relaxed);
584                            self.chunk_cache.insert(key, d)
585                        }
586                    };
587                    window.refill(&chunk);
588                } else {
589                    window.refill(&compressed_chunk);
590                }
591                chunk_count += 1;
592
593                // Not the final chunk yet: drain confirmed partitions; NeedMore
594                // means "await more bytes" (a partition straddles this boundary).
595                self.drain_scan_window(
596                    &parser,
597                    &ctx,
598                    &mut window,
599                    false,
600                    &tx,
601                    &mut batch,
602                    &mut scratch,
603                    &mut broke,
604                )?;
605                if broke {
606                    return Ok(());
607                }
608
609                // Per-chunk flush cadence (roborev finding, issue #1143). The
610                // drain above stopped because no further partition can be
611                // confirmed until the NEXT raw chunk arrives (NeedMore / empty
612                // window), so any rows still buffered in `batch` are FULLY
613                // confirmed — they will not be amended or joined by a same-chunk
614                // partition. Flushing the pending tail here (a no-op when empty)
615                // restores `scan_stream`'s incremental-delivery contract and
616                // first-row latency for sparse / sub-`BATCH_EMIT_ROWS` result
617                // sets, which the pure-batching change regressed (those emitted
618                // nothing until full scan completion). Dense windows still hit
619                // the full-batch flush inside `drain_scan_window`, so we wake the
620                // forwarder at most ~once per chunk PLUS once per full batch —
621                // far below PR #1156's one-wake-per-ROW, preserving the perf win.
622                if !batch.is_empty() {
623                    if tx.blocking_send(Ok(std::mem::take(&mut batch))).is_err() {
624                        broke = true; // consumer dropped
625                        return Ok(());
626                    }
627                    batch.reserve(BATCH_EMIT_ROWS);
628                }
629            }
630
631            // Stream end. On a CLEAN EOF run the final drain — a trailing
632            // partition with no END_OF_PARTITION marker is now terminal (Done),
633            // not a refill request that will never come. But if the I/O half
634            // stopped on a read ERROR (`io_failed`), the trailing window is a
635            // truncated fragment of a partition; running `at_final_chunk = true`
636            // here would parse and emit it as if complete, surfacing a
637            // partial/garbage row BEFORE the caller returns the I/O `Err`. Skip
638            // the final drain so a truncated/corrupt stream yields ONLY the error
639            // (issue #1143 finding 2). The store in the I/O half happens-before
640            // the `drop(raw_tx)` that ended `blocking_recv`, so this load
641            // observes it.
642            if !broke && should_run_terminal_drain(io_failed.load(Ordering::SeqCst)) {
643                self.drain_scan_window(
644                    &parser,
645                    &ctx,
646                    &mut window,
647                    true,
648                    &tx,
649                    &mut batch,
650                    &mut scratch,
651                    &mut broke,
652                )?;
653            }
654            Ok(())
655        })();
656
657        // Finish: deliver any rows still in `batch` and propagate the drain
658        // outcome. On `Err`, the pending rows are flushed BEFORE the error so the
659        // consumer sees every confirmed-up-to-error row ahead of the terminal Err
660        // (roborev finding, issue #1143); on success the trailing partial batch is
661        // flushed (unless the consumer already dropped, `broke`). Extracted so the
662        // error-path flush is unit-tested directly with a NON-EMPTY pending batch
663        // (`tests::finish_blocking_drain_flushes_pending_before_error`) — that test
664        // fails if the error flush is dropped, keeping the guard non-vacuous even
665        // though the in-stream per-chunk flush usually empties `batch` first.
666        finish_blocking_drain(drained, &mut batch, broke, &tx)?;
667
668        // Test-only probe (issue #1143 regression guard): record the thread that
669        // ran the parse so a guard test can prove it was NOT an async worker.
670        // Compiled ONLY under the non-default `scan-offload-probe` feature; a
671        // true no-op (not even referenced) in normal/release builds.
672        #[cfg(feature = "scan-offload-probe")]
673        probe::record_parse_thread();
674
675        log::debug!(
676            "drain_scan_window_blocking: drained {} chunks (final window {} bytes)",
677            chunk_count,
678            window.len()
679        );
680        Ok(())
681    }
682
683    /// Drain every confirmed partition from the front of the sliding `window`,
684    /// accumulating each surviving `(RowKey, ScanRow)` into `batch` and flushing a
685    /// full `BATCH_EMIT_ROWS`-sized batch through `tx` (issue #1143).
686    ///
687    /// Synchronous (runs on the `spawn_blocking` thread). Drives
688    /// [`parse_one_partition_with_timestamps`], drops the per-row timestamp, and
689    /// applies the same `table_ids_match` + key-range + `filter_tombstone`
690    /// filters the prior driver applied. After each `Emitted(consumed)` the
691    /// consumed prefix is removed, keeping the window's peak bounded by
692    /// `max_partition_size + one_chunk`. Rows are pushed onto `batch` in scan
693    /// order; whenever `batch` reaches `BATCH_EMIT_ROWS` it is flushed as ONE
694    /// channel item (amortizing the blocking→async wake). The trailing partial
695    /// batch is flushed by the caller at stream end. Stops at `NeedMore` / `Done`
696    /// (await the next chunk / genuine end) or when the consumer is dropped
697    /// (`*broke`).
698    #[allow(clippy::too_many_arguments)]
699    fn drain_scan_window(
700        &self,
701        parser: &crate::storage::sstable::reader::parsing::V5CompressedLegacyParser,
702        ctx: &WindowParseCtx,
703        window: &mut WindowCursor,
704        at_final_chunk: bool,
705        tx: &mpsc::Sender<Result<Vec<(RowKey, ScanRow)>>>,
706        batch: &mut Vec<(RowKey, ScanRow)>,
707        scratch: &mut Vec<(RowKey, ScanRow)>,
708        broke: &mut bool,
709    ) -> Result<()> {
710        use crate::storage::sstable::reader::parsing::ParseStep;
711
712        loop {
713            if *broke || window.is_empty() {
714                return Ok(());
715            }
716
717            // Buffer this partition's surviving entries in the caller's REUSED
718            // `scratch` buffer, then forward them via `blocking_send` AFTER the
719            // parser returns. `parse_one_partition_with_timestamps` takes a
720            // synchronous `FnMut` emit, so we cannot send inside it; a partition's
721            // rows are bounded by `max_partition_size`, so this stays within the
722            // window bound. `clear()` drops the previous partition's entries but
723            // PRESERVES the backing capacity, so after warmup this loop performs
724            // NO per-partition allocation for `scratch` (issue #1333, follow-up to
725            // #1046). NeedMore/Done leave `scratch` empty (the parser only invokes
726            // the emit closure on a CONFIRMED `Emitted`), so nothing leaks across
727            // partitions. Issue #1334: entries carry the `ScanRow` row carrier.
728            scratch.clear();
729            // Snapshot the (retained) capacity BEFORE this partition's pushes so
730            // the offload probe can count how many times `scratch` actually grows
731            // its backing store across the whole scan — the direct signal that the
732            // buffer is reused, not reallocated per partition (issue #1333 guard).
733            #[cfg(feature = "scan-offload-probe")]
734            let scratch_cap_before = scratch.capacity();
735            let step = parser.parse_one_partition_with_timestamps(
736                window.as_slice(),
737                ctx.schema.as_ref(),
738                self,
739                at_final_chunk,
740                &mut |(entry_table_id, key, value, _ts)| {
741                    // Key-range + tombstone filters match the previous
742                    // `parse_stitched_stream`; the `table_ids_match` guard is the
743                    // ADDITIONAL filter the non-stitching `scan_stream` branch
744                    // also applies (a no-op for single-table SSTables).
745                    if !table_ids_match(&entry_table_id, &ctx.table_id) {
746                        return Ok(std::ops::ControlFlow::Continue(()));
747                    }
748                    if let Some(start) = ctx.start_key.as_ref() {
749                        if &key < start {
750                            return Ok(std::ops::ControlFlow::Continue(()));
751                        }
752                    }
753                    if let Some(end) = ctx.end_key.as_ref() {
754                        if &key > end {
755                            return Ok(std::ops::ControlFlow::Continue(()));
756                        }
757                    }
758                    // Suppress row tombstones from user-facing scan output (#505).
759                    if !self.filter_tombstone(&value) {
760                        return Ok(std::ops::ControlFlow::Continue(()));
761                    }
762                    scratch.push((key, value));
763                    Ok(std::ops::ControlFlow::Continue(()))
764                },
765            )?;
766
767            // Record whether this partition forced `scratch` to (re)allocate its
768            // backing store. With the hoist this happens only while the buffer
769            // grows to its high-water mark (a small bounded number of times per
770            // scan); if the buffer were freshly allocated per partition it would
771            // grow from empty EVERY partition, so the count would scale with
772            // partition count — exactly what the #1333 guard asserts it does not.
773            #[cfg(feature = "scan-offload-probe")]
774            probe::note_scratch_capacity(scratch_cap_before, scratch.capacity());
775
776            match step {
777                ParseStep::Emitted(consumed) => {
778                    let take = if consumed == 0 { 1 } else { consumed };
779                    // Advance the cursor (no memmove); `consume` clamps to remaining.
780                    window.consume(take);
781                    // Accumulate this partition's surviving entries in scan order,
782                    // flushing a full batch as ONE channel item whenever it
783                    // reaches `BATCH_EMIT_ROWS`. `blocking_send` carries the same
784                    // backpressure as the prior per-row send (this runs on a
785                    // spawn_blocking thread) but wakes the async forwarder once per
786                    // batch instead of once per row (issue #1143).
787                    for entry in scratch.drain(..) {
788                        batch.push(entry);
789                        if batch.len() >= BATCH_EMIT_ROWS {
790                            let full =
791                                std::mem::replace(batch, Vec::with_capacity(BATCH_EMIT_ROWS));
792                            if tx.blocking_send(Ok(full)).is_err() {
793                                *broke = true; // consumer dropped
794                                return Ok(());
795                            }
796                        }
797                    }
798                }
799                // NeedMore: the partition straddles this chunk boundary. The
800                // per-partition parser buffers a partition's rows internally and
801                // only invokes our emit closure on a CONFIRMED `Emitted` return,
802                // so on `NeedMore` our `scratch` buffer is empty — nothing was
803                // forwarded and nothing is dropped. The caller appends the next
804                // chunk and we re-parse this partition from its start, so no row
805                // is duplicated or lost across the boundary. Record the straddle
806                // (issue #1143) so the boundary re-parse path is observable; it is
807                // suppressed at the final chunk (parser collapses NeedMore→Done).
808                ParseStep::NeedMore => {
809                    crate::observability::add_counter(
810                        crate::observability::catalog::READ_SCAN_WINDOW_REFILL,
811                        1,
812                        &[],
813                    );
814                    return Ok(());
815                }
816                // Done: genuine end of partitions / terminal truncation.
817                ParseStep::Done => return Ok(()),
818            }
819        }
820    }
821}
