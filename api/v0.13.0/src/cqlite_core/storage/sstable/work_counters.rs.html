1//! Process-global read-work counters for partition-targeted lookups
2//! (Issue #958, Epic #951).
3//!
4//! # Why this exists
5//!
6//! #949 added a partition-targeted lookup ([`SSTableManager::scan_partition`])
7//! that prunes the SSTable set via the bloom filter / BTI trie before parsing,
8//! so a `WHERE pk = ?` over a table backed by *N* SSTables touches only the
9//! handful of candidates that can hold the key — not all *N*. Correct result
10//! rows do not prove that pruning happened: a regression could quietly revert to
11//! "open and scan every SSTable, then filter in memory" and still return the
12//! right answer.
13//!
14//! These counters make the *work* observable so a CI test can fail the moment a
15//! single-partition read starts scaling with the total SSTable count. They
16//! mirror the [`scan_for_key_call_count`](crate::storage::sstable::SSTableReader::scan_for_key_call_count)
17//! probe (issue #831) and the access-path probe (issue #960): a process-global
18//! atomic with [`reset`]/getter accessors, observable from an integration test
19//! without parsing logs and from the streaming path's spawned task.
20//!
21//! # What each counter counts
22//!
23//! - [`sstables_scanned`] — incremented **once per candidate SSTable reader that
24//!   `scan_partition` actually parses** for a partition-targeted lookup. After
25//!   bloom/BTI pruning drops the SSTables that cannot hold the key, every
26//!   surviving candidate whose `Data.db` is parsed (whether through the
27//!   cross-generation k-way merge or the per-reader concat fallback) bumps this
28//!   by one. It is the O(candidates) signal: for a key living in one SSTable it
29//!   must stay near 1 (plus any bloom false-positives), never grow to N. It is
30//!   **not** incremented on the full-scan path — only the targeted lookup is
31//!   instrumented, which is exactly the path #949/#958 protect.
32//!
33//! - [`partitions_parsed`] — incremented **once per partition row a
34//!   partition-targeted lookup returns** (after retaining only the target key /
35//!   the merge emits the partition). For a single-partition point lookup this is
36//!   0 (absent key) or the number of rows that partition holds; it never scales
37//!   with the table's total partition count, which a full scan would.
38//!
39//! - [`chunks_decompressed`] — incremented **once per compression chunk the
40//!   single-candidate seek path actually decompresses** while buffering the
41//!   target partition's bytes (Issue #953 / #951). Where `partitions_decoded`
42//!   proves we returned only one partition, this proves the seek bounded its
43//!   *decompression I/O* to that partition's chunk span rather than reading the
44//!   whole `Data.db` to EOF. A head-of-file point lookup must NOT decompress the
45//!   tail chunks of a large SSTable: a regression that stitches to EOF (the bug
46//!   the bound replaces) bumps this by the file's whole chunk count, which the
47//!   `issue_953` bound test catches even though `partitions_decoded` stays 1.
48//!   Incremented at the seek's single decompression site
49//!   (`SSTableReader::bti_pull_decompressed_chunk`), so every chunk the seek
50//!   materializes — BIG (`nb`, bounded by the `Index.db` size) or BTI (`da`,
51//!   bounded by the next-partition boundary) — is counted exactly once. The
52//!   whole-section `stitch_all_chunks` fallback does **not** bump it (it is the
53//!   unbounded path the seek avoids when chunk targeting is possible).
54//!
55//! - [`partitions_decoded`] — incremented **once per partition actually decoded
56//!   out of `Data.db`** by the single-candidate *seek* path (Issue #953). Where
57//!   `sstables_scanned` proves we touched few SSTables, this proves that *within*
58//!   a touched SSTable we did not decode every partition: the seek resolves the
59//!   target partition's `Data.db` offset (via the BTI trie or `Index.db`) and
60//!   decodes only that one partition, so this stays O(1) for a point lookup. A
61//!   regression that reverts the single-candidate path to a full parse-then-retain
62//!   would bump this by the SSTable's whole partition count (~N), failing the
63//!   `issue_953` bound. It is incremented at the per-partition decode site of the
64//!   seek (`SSTableReader::scan_single_partition` → the emit closure that captures
65//!   a complete partition), NOT at the result-count boundary. The full-scan +
66//!   retain fallback does **not** bump it (it is the unoptimized path the seek
67//!   replaces); a candidate that cannot be seeked therefore reads 0 here, which is
68//!   why the test asserts a *small upper bound* (decode happened cheaply) rather
69//!   than an exact equality.
70//!
71//! # Cost
72//!
73//! Each increment is a single `Relaxed` atomic add on the cold per-lookup
74//! boundary (once per candidate / once per returned partition), never inside an
75//! inner byte-decoding loop, so the hot path is unaffected. The counters are not
76//! gated behind `cfg(test)` because integration tests in `tests/` compile
77//! against the library crate without its `test` cfg (same rationale as
78//! `SCAN_FOR_KEY_CALLS`).
79
80use std::sync::atomic::{AtomicU64, Ordering};

82/// The five read-work counters as one value.
83///
84/// Production code shares a single process-global instance ([`COUNTERS`]) reached
85/// through the free functions below; the increment sites and integration probes
86/// all operate on that instance. Bundling the atomics in a struct also lets a
87/// unit test exercise the add/get/reset contract against a *local* instance,
88/// immune to other tests concurrently mutating the global (issue #1071) — the
89/// global is shared with read-path code that any parallel test can drive.
90struct Counters {
91    /// Candidate SSTables actually parsed by a partition-targeted lookup.
92    sstables_scanned: AtomicU64,
93    /// Partitions a partition-targeted lookup has returned.
94    partitions_parsed: AtomicU64,
95    /// Partitions DECODED from `Data.db` by the single-candidate seek (Issue #953).
96    partitions_decoded: AtomicU64,
97    /// Compression chunks DECOMPRESSED by the single-candidate seek (Issue #953 / #951).
98    chunks_decompressed: AtomicU64,
99    /// Individual rows DECODED within a partition by the seek path (Issue #954).
100    rows_decoded: AtomicU64,
101    /// Promoted-index blocks DECODED back-to-front by the BIG reverse partition
102    /// iterator (Issue #1184). One per block the reverse walk visits.
103    reverse_blocks_decoded: AtomicU64,
104    /// Peak number of decoded rows held in a SINGLE block buffer by the BIG
105    /// reverse iterator (Issue #1184) — the per-iteration memory high-water mark.
106    /// A regression that materialises the whole partition before reversing pushes
107    /// this to the partition's full row count instead of one block's worth.
108    reverse_peak_block_rows: AtomicU64,
109    /// Full re-reads of a finished `Data.db` performed to compute checksums
110    /// (Issue #1663). Bumped once each time the re-read CRC oracle
111    /// (`crc_writer::build_crc_bytes`) or the digest re-read
112    /// (`SSTableWriter::compute_crc32`) OPENS `Data.db`. The streaming write path
113    /// accumulates both checksums as it writes, so a non-empty
114    /// `SSTableWriter::finish()` must leave this at 0; a regression that
115    /// reintroduces the finish-time double re-read bumps it (2 on the old path).
116    data_db_checksum_full_reads: AtomicU64,
117}

119impl Counters {
120    const fn new() -> Self {
121        Self {
122            sstables_scanned: AtomicU64::new(0),
123            partitions_parsed: AtomicU64::new(0),
124            partitions_decoded: AtomicU64::new(0),
125            chunks_decompressed: AtomicU64::new(0),
126            rows_decoded: AtomicU64::new(0),
127            reverse_blocks_decoded: AtomicU64::new(0),
128            reverse_peak_block_rows: AtomicU64::new(0),
129            data_db_checksum_full_reads: AtomicU64::new(0),
130        }
131    }
132
133    #[cfg(not(feature = "tombstones"))]
134    fn add_sstables_scanned(&self, count: u64) {
135        self.sstables_scanned.fetch_add(count, Ordering::Relaxed);
136    }
137
138    #[cfg(not(feature = "tombstones"))]
139    fn add_partitions_parsed(&self, count: u64) {
140        self.partitions_parsed.fetch_add(count, Ordering::Relaxed);
141    }
142
143    #[cfg(not(feature = "tombstones"))]
144    fn add_partition_decoded(&self) {
145        self.partitions_decoded.fetch_add(1, Ordering::Relaxed);
146    }
147
148    #[cfg(not(feature = "tombstones"))]
149    fn add_chunk_decompressed(&self) {
150        self.chunks_decompressed.fetch_add(1, Ordering::Relaxed);
151    }
152
153    #[cfg(not(feature = "tombstones"))]
154    fn add_rows_decoded(&self, count: u64) {
155        self.rows_decoded.fetch_add(count, Ordering::Relaxed);
156    }
157
158    #[cfg(not(feature = "tombstones"))]
159    fn add_reverse_block_decoded(&self) {
160        self.reverse_blocks_decoded.fetch_add(1, Ordering::Relaxed);
161    }
162
163    #[cfg(not(feature = "tombstones"))]
164    fn observe_reverse_block_rows(&self, rows: u64) {
165        self.reverse_peak_block_rows
166            .fetch_max(rows, Ordering::Relaxed);
167    }
168
169    #[cfg(feature = "write-support")]
170    fn add_data_db_checksum_full_read(&self) {
171        self.data_db_checksum_full_reads
172            .fetch_add(1, Ordering::Relaxed);
173    }
174
175    fn data_db_checksum_full_reads(&self) -> u64 {
176        self.data_db_checksum_full_reads.load(Ordering::Relaxed)
177    }
178
179    fn reverse_blocks_decoded(&self) -> u64 {
180        self.reverse_blocks_decoded.load(Ordering::Relaxed)
181    }
182
183    fn reverse_peak_block_rows(&self) -> u64 {
184        self.reverse_peak_block_rows.load(Ordering::Relaxed)
185    }
186
187    fn sstables_scanned(&self) -> u64 {
188        self.sstables_scanned.load(Ordering::Relaxed)
189    }
190
191    fn partitions_parsed(&self) -> u64 {
192        self.partitions_parsed.load(Ordering::Relaxed)
193    }
194
195    fn partitions_decoded(&self) -> u64 {
196        self.partitions_decoded.load(Ordering::Relaxed)
197    }
198
199    fn chunks_decompressed(&self) -> u64 {
200        self.chunks_decompressed.load(Ordering::Relaxed)
201    }
202
203    fn rows_decoded(&self) -> u64 {
204        self.rows_decoded.load(Ordering::Relaxed)
205    }
206
207    fn reset(&self) {
208        self.sstables_scanned.store(0, Ordering::Relaxed);
209        self.partitions_parsed.store(0, Ordering::Relaxed);
210        self.partitions_decoded.store(0, Ordering::Relaxed);
211        self.chunks_decompressed.store(0, Ordering::Relaxed);
212        self.rows_decoded.store(0, Ordering::Relaxed);
213        self.reverse_blocks_decoded.store(0, Ordering::Relaxed);
214        self.reverse_peak_block_rows.store(0, Ordering::Relaxed);
215        self.data_db_checksum_full_reads.store(0, Ordering::Relaxed);
216    }
217}

219/// The process-global counters every read-path increment site and integration
220/// probe shares. Unit tests that assert absolute values use a local
221/// [`Counters`] instead (issue #1071).
222static COUNTERS: Counters = Counters::new();
223
224/// Record that `count` candidate SSTables were parsed by a partition-targeted
225/// lookup. Called once per `scan_partition` invocation with the number of
226/// surviving (post-prune) candidates whose `Data.db` is parsed.
227///
228/// Only the default (`not(tombstones)`) build has the bloom/BTI-pruning
229/// `scan_partition`; the `tombstones` build serves a single-partition read by a
230/// full scan + filter and has no candidate set to count, so the mutators are
231/// compiled only for the build whose pruning they instrument. The getters and
232/// [`reset`] remain available in every build for the test API.
233#[cfg(not(feature = "tombstones"))]
234pub(crate) fn add_sstables_scanned(count: u64) {
235    COUNTERS.add_sstables_scanned(count);
236}
237
238/// Record that `count` partitions were returned by a partition-targeted lookup.
239#[cfg(not(feature = "tombstones"))]
240pub(crate) fn add_partitions_parsed(count: u64) {
241    COUNTERS.add_partitions_parsed(count);
242}
243
244/// Record that one partition was DECODED from `Data.db` by the single-candidate
245/// seek path (Issue #953). Called once per complete partition the seek decodes
246/// at the resolved offset — exactly one for a point lookup that hits, zero for a
247/// verified-absent key.
248///
249/// Gated on `not(tombstones)` like the other mutators: the seek path
250/// (`SSTableReader::scan_single_partition`) is only reachable from the default
251/// build's `scan_partition`; under `tombstones` the full-scan fallback never
252/// seeks, so the counter stays at 0 and the mutator would be dead code.
253#[cfg(not(feature = "tombstones"))]
254pub(crate) fn add_partition_decoded() {
255    COUNTERS.add_partition_decoded();
256}
257
258/// Record that one compression chunk was DECOMPRESSED by the single-candidate
259/// seek path (Issue #953 / #951). Called once per chunk the seek materializes
260/// into its decompressed window while buffering the target partition; the bound
261/// (BIG `Index.db` size, BTI next-partition boundary) stops the loop so this
262/// stays O(partition chunk span), never the file's whole chunk count.
263///
264/// Gated on `not(tombstones)` like the other seek-path mutators: only the
265/// default build reaches the seek (`bti_pull_decompressed_chunk`); under
266/// `tombstones` the full-scan fallback never seeks, so the counter stays 0.
267#[cfg(not(feature = "tombstones"))]
268pub(crate) fn add_chunk_decompressed() {
269    COUNTERS.add_chunk_decompressed();
270}
271
272/// Record that one row was DECODED from `Data.db` within a partition by the
273/// single-candidate seek path (Issue #954). Called once per row the partition
274/// decoder actually parses out of the (clustering-narrowed) byte window — the
275/// row-granularity signal that proves a `WHERE pk = ? AND ck </>/= ?` slice
276/// query decodes O(matched rows + index block slack), not the whole partition.
277///
278/// Where [`add_partition_decoded`] counts WHICH partition was touched (1 for a
279/// hit), this counts HOW MANY of its clustering rows were parsed: a regression
280/// that reverts the clustering seek to a full-partition decode bumps this by the
281/// partition's whole row count, failing the `issue_954` bound even though
282/// `partitions_decoded` stays 1.
283///
284/// Gated on `not(tombstones)` like the other seek-path mutators: only the
285/// default build reaches the seek; under `tombstones` the full-scan fallback
286/// never seeks, so the counter stays 0.
287#[cfg(not(feature = "tombstones"))]
288pub(crate) fn add_rows_decoded(count: u64) {
289    COUNTERS.add_rows_decoded(count);
290}
291
292/// Record that the BIG reverse partition iterator decoded one promoted-index
293/// block (Issue #1184). Called once per block the back-to-front walk visits, so
294/// a test can prove the reverse scan is block-driven (count == block count) and
295/// not a post-fetch in-memory `sort_by` over a single full-partition read.
296#[cfg(not(feature = "tombstones"))]
297pub(crate) fn add_reverse_block_decoded() {
298    COUNTERS.add_reverse_block_decoded();
299}

301/// Observe the row count of ONE block buffer the reverse iterator just decoded
302/// (Issue #1184); keeps the running peak. A test asserts the peak stays bounded
303/// to a single block, proving per-iteration memory is O(block), not O(partition).
304#[cfg(not(feature = "tombstones"))]
305pub(crate) fn observe_reverse_block_rows(rows: u64) {
306    COUNTERS.observe_reverse_block_rows(rows);
307}

309/// Record one full re-read of a finished `Data.db` performed to compute
310/// checksums (Issue #1663). Called once at each site that OPENS `Data.db` to
311/// checksum it: the re-read CRC oracle (`crc_writer::build_crc_bytes`) and the
312/// digest re-read (`SSTableWriter::compute_crc32`).
313///
314/// Gated on `write-support` because both increment sites live in the writer,
315/// which is only compiled with that feature; the getter and [`reset`] are
316/// available in every build for the test API.
317#[cfg(feature = "write-support")]
318pub fn add_data_db_checksum_full_read() {
319    COUNTERS.add_data_db_checksum_full_read();
320}

322/// Number of full `Data.db` re-reads performed for checksum computation since
323/// the last [`reset`] (Issue #1663).
324///
325/// The streaming write path accumulates the whole-file digest and the per-chunk
326/// `CRC.db` values as it writes, so a non-empty `SSTableWriter::finish()` must
327/// leave this at 0. A regression that reintroduces the finish-time double
328/// re-read (one for `Digest.crc32`, one for `CRC.db`) bumps it to 2, failing the
329/// issue-#1663 work guard.
330pub fn data_db_checksum_full_reads() -> u64 {
331    COUNTERS.data_db_checksum_full_reads()
332}

334/// Number of candidate SSTables parsed by partition-targeted lookups since the
335/// last [`reset`].
336///
337/// Tests assert this stays O(candidates) — near 1 for a key in a single SSTable
338/// (plus a small allowance for bloom false-positives) — so a regression that
339/// reopens every SSTable for a single-partition read fails CI.
340pub fn sstables_scanned() -> u64 {
341    COUNTERS.sstables_scanned()
342}

344/// Number of partitions returned by partition-targeted lookups since the last
345/// [`reset`].
346pub fn partitions_parsed() -> u64 {
347    COUNTERS.partitions_parsed()
348}

350/// Number of partitions DECODED from `Data.db` by the single-candidate seek path
351/// since the last [`reset`] (Issue #953).
352///
353/// Tests assert this stays O(1) for a point lookup — a small bound, near 1 for a
354/// hit — so a regression that reverts the single-candidate path to a full parse
355/// (decoding every partition in the SSTable, then retaining one) fails CI.
356pub fn partitions_decoded() -> u64 {
357    COUNTERS.partitions_decoded()
358}

360/// Number of compression chunks DECOMPRESSED by the single-candidate seek path
361/// since the last [`reset`] (Issue #953 / #951).
362///
363/// Tests assert this stays bounded by the target partition's chunk span — a
364/// small constant for a point lookup — so a regression that stitches the
365/// `Data.db` section to EOF (decompressing every chunk after the target,
366/// including the whole tail of a large file for a head-of-file lookup) fails the
367/// `issue_953` bound, even though `partitions_decoded` would still read 1.
368pub fn chunks_decompressed() -> u64 {
369    COUNTERS.chunks_decompressed()
370}
371
372/// Number of individual partition rows DECODED from `Data.db` by the
373/// single-candidate seek path since the last [`reset`] (Issue #954).
374///
375/// Tests assert this stays bounded by the requested clustering slice (plus one
376/// index block of block-granularity slack) for a `WHERE pk = ? AND ck </>/= ?`
377/// query — proving the within-partition seek decodes O(slice), not the whole
378/// partition. A regression that decodes every clustering row of the partition
379/// (then post-filters) bumps this by the partition's full row count and fails
380/// the bound, even though `partitions_decoded` would still read 1.
381pub fn rows_decoded() -> u64 {
382    COUNTERS.rows_decoded()
383}

385/// Number of promoted-index blocks the BIG reverse partition iterator decoded
386/// back-to-front since the last [`reset`] (Issue #1184). For a wide partition
387/// this equals the partition's block count; a regression to a forward
388/// full-partition read + in-memory sort leaves it at 0.
389pub fn reverse_blocks_decoded() -> u64 {

391}

393/// Peak rows held in a single reverse-iterator block buffer since the last
394/// [`reset`] (Issue #1184). Tests assert this stays bounded to one block's worth
395/// of rows — far below the partition total — proving bounded per-iteration memory.
396pub fn reverse_peak_block_rows() -> u64 {

400/// Clear all five process-global counters. Integration tests call this before a
401/// query so a stale value from an earlier query cannot satisfy a later
402/// assertion. Because the global is shared, an integration test that asserts on
403/// it must run without a concurrent query on another thread (the integration
404/// tests serialize their own setup); the in-crate unit test sidesteps this
405/// entirely by asserting against a local [`Counters`] instance (issue #1071).
406pub fn reset() {
407    COUNTERS.reset();
408}

410#[cfg(all(test, not(feature = "tombstones")))]
411mod tests {
412    use super::*;
413
414    // Exercises the add/get/reset contract against a *local* [`Counters`] rather
415    // than the process-global instance reached through the free functions. The
416    // global is shared with read-path increment sites that any concurrent test
417    // in this binary can drive, so absolute-value assertions on it race
418    // nondeterministically (issue #1071). A local instance is owned by this test
419    // alone, so the exact-equality checks below are deterministic.
420    #[test]
421    fn counters_round_trip() {
422        let c = Counters::new();
423        c.reset();
424        assert_eq!(c.sstables_scanned(), 0);
425        assert_eq!(c.partitions_parsed(), 0);
426        assert_eq!(c.partitions_decoded(), 0);
427        assert_eq!(c.chunks_decompressed(), 0);
428        assert_eq!(c.rows_decoded(), 0);
429        c.add_sstables_scanned(2);
430        c.add_partitions_parsed(5);
431        c.add_partition_decoded();
432        c.add_partition_decoded();
433        c.add_chunk_decompressed();
434        c.add_chunk_decompressed();
435        c.add_chunk_decompressed();
436        c.add_rows_decoded(7);
437        assert_eq!(c.sstables_scanned(), 2);
438        assert_eq!(c.partitions_parsed(), 5);
439        assert_eq!(c.partitions_decoded(), 2);
440        assert_eq!(c.chunks_decompressed(), 3);
441        assert_eq!(c.rows_decoded(), 7);
442        c.reset();
443        assert_eq!(c.sstables_scanned(), 0);
444        assert_eq!(c.partitions_parsed(), 0);
445        assert_eq!(c.partitions_decoded(), 0);
446        assert_eq!(c.chunks_decompressed(), 0);
447        assert_eq!(c.rows_decoded(), 0);
448    }
