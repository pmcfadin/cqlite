1//! Async-to-sync bridge for the write engine's blocking helpers (Issue #587,
2//! #1670).
3//!
4//! `block_on_async` runs an async future to completion from a synchronous
5//! context, safely whether or not a Tokio runtime is already running on the
6//! current thread. It is the shared bridge for `SSTableRowIteratorAdapter` (the
7//! k-way merge readers), `WriteEngine::flush_internal`, and
8//! `WriteEngine::finalize_merge_blocking`.
9//!
10//! ## Why not `Handle::block_on`?
11//!
12//! When this bridge is reached from a thread that is already driving a Tokio
13//! runtime — anything under `#[tokio::main]` or `#[tokio::test]`, which is how
14//! the CLI (`maintenance`, `export-sstable --compact`) and any async caller
15//! reach compaction — `Handle::current().block_on()` panics with *"Cannot start
16//! a runtime from within a runtime"* (Issue #587). Compaction only reaches the
17//! bridge once a merge has input SSTables to read, which is why STCS worked in
18//! isolation but blew up from async callers.
19//!
20//! `tokio::task::block_in_place` is not a general fix either: it panics on a
21//! current-thread runtime (e.g. the default `#[tokio::test]` flavor).
22//!
23//! ## Strategy
24//!
25//! A single long-lived bridge runtime is built lazily on first *successful* use
26//! and reused for every subsequent call (Issue #1670) — previously a fresh
27//! `Runtime::new()` was constructed and torn down on *every* flush/maintenance
28//! step. A transient build failure is NOT cached: the error is returned to the
29//! caller and the next call retries, so one bad build never disables the bridge
30//! for the process lifetime. The cached runtime is a **multi-thread** runtime (worker threads =
31//! CPU count) with all drivers (I/O, time, blocking pool) enabled — the same
32//! flavor `Runtime::new()` built before #1670. This is deliberate: concurrent
33//! flush/compaction each bridge through `block_on_async`, and a single shared
34//! `current_thread` runtime would serialize those concurrent `block_on` calls
35//! (and any internal task fan-out within one future), regressing
36//! concurrent-flush/compaction throughput vs main. A multi-thread runtime
37//! preserves main's parallelism semantics: N threads can each drive a
38//! `block_on` on the shared runtime and its worker pool services them in
39//! parallel.
40//!
41//! - **No runtime on the current thread** (`Handle::try_current()` is `Err`):
42//!   block on the cached runtime directly. A panic in the future unwinds to the
43//!   caller (catchable via `catch_unwind`; the host does not abort) exactly as
44//!   before, and the cached runtime remains usable afterward (Tokio restores
45//!   its scheduler core on unwind).
46//! - **Already inside a runtime** (`Ok`): a nested `block_on` on this thread
47//!   would panic, so the future is handed to a dedicated scoped thread that
48//!   drives the *cached* runtime (a `&'static Runtime` is `Send`, so the scoped
49//!   thread can call `block_on` on it while the caller's runtime keeps its own
50//!   thread). The thread is free to block because it is not driving the
51//!   caller's runtime, so this works for both the multi-thread and
52//!   current-thread runtime flavors. `std::thread::scope` (rather than
53//!   `std::thread::spawn`) lets the future borrow from the caller's stack —
54//!   `flush_internal`/`finalize_merge_blocking` pass futures that borrow
55//!   `&mut self` — so it need not be `'static`. The scoped-thread `join()`
56//!   catches a panic in the future and surfaces it as `Error::Storage`
57//!   (Issue #587 panic-safety), instead of unwinding across the FFI/host.
58//!
59//! The future and its output must be `Send` because they cross a thread
60//! boundary in the in-runtime case.

71/// Process-wide cached bridge runtime. Built once on first *successful* use and
72/// reused for the life of the process (Issue #1670). Tests that create and drop
73/// many `WriteEngine`s reuse this single runtime — a process-global runtime that
74/// outlives every engine is intentional and harmless.
75///
76/// The cell holds ONLY a successfully-built [`Runtime`] (not a
77/// `Result<Runtime, _>`). A transient build failure (e.g. thread-spawn/resource
78/// exhaustion in [`tokio::runtime::Builder::build`]) returns an error to the
79/// caller WITHOUT populating this cell, so the next call retries — a failed
80/// build never poisons the cache for the process lifetime. Builds are serialized
81/// by [`BRIDGE_BUILD_LOCK`] with a double-check so a successful build still
82/// happens at most once even under a concurrent first-access race.
83#[cfg(feature = "write-support")]
84static BRIDGE_RUNTIME: OnceLock<Runtime> = OnceLock::new();
85
86/// Serializes bridge-runtime construction so that (a) at most one build is
87/// in-flight at a time and (b) a successful build populates [`BRIDGE_RUNTIME`]
88/// exactly once even when multiple threads miss the fast path simultaneously.
89/// A single lock acquisition per bridge call is negligible next to the ~290µs a
90/// per-call `Runtime::new()` cost before #1670.
91#[cfg(feature = "write-support")]
92static BRIDGE_BUILD_LOCK: Mutex<()> = Mutex::new(());
93
94/// Number of times the cached bridge runtime has actually been constructed.
95///
96/// Incremented immediately before each real `Runtime` build (under the build
97/// lock), so it counts actual build *attempts* — not `block_on_async` calls.
98/// With the cache it is `<= 1` for the life of the process once a build
99/// succeeds; before Issue #1670 (a `Runtime::new()` per call) it grew by one on
100/// every `block_on_async` invocation. A retried build after a transient failure
101/// increments it again — the intended, observable retry behavior.
102#[cfg(feature = "write-support")]
103static RUNTIME_BUILD_COUNT: AtomicU64 = AtomicU64::new(0);
104
105/// Return the cached bridge runtime, building it on first use.
106///
107/// A failed build returns `Err` WITHOUT caching anything, so the next call
108/// retries (no permanent poison — the regression fixed for Issue #1670). Builds
109/// are serialized by [`BRIDGE_BUILD_LOCK`] with a re-check under the lock, so a
110/// successful build happens at most once even if many threads miss the fast
111/// path at the same instant.
112#[cfg(feature = "write-support")]
113fn bridge_runtime() -> Result<&'static Runtime> {
114    get_or_build_once(&BRIDGE_RUNTIME, &BRIDGE_BUILD_LOCK, || {
115        RUNTIME_BUILD_COUNT.fetch_add(1, Ordering::Relaxed);
116        // Multi-thread flavor (worker threads = CPU count), matching main's
117        // `Runtime::new()` semantics so concurrent `block_on_async` calls and
118        // in-future task fan-out run in parallel rather than being serialized by
119        // a shared single-threaded scheduler (Issue #1670).
120        tokio::runtime::Builder::new_multi_thread()
121            .enable_all()
122            .build()
123            .map_err(|e| Error::Storage(format!("Failed to create tokio runtime: {}", e)))
124    })
125}

127/// Return the value cached in `cell`, building it via `build` on the first miss.
128///
129/// The store-only-on-success cache contract (Issue #1670 robustness fix):
130/// - Fast path returns the cached value with no locking once populated.
131/// - On a miss, `lock` serializes construction and a re-check avoids a double
132///   build under a concurrent first-access race, so a successful build happens
133///   **at most once**.
134/// - If `build` returns `Err`, the error is propagated and `cell` stays EMPTY,
135///   so a later call retries — a transient failure never permanently poisons
136///   the cache.
137#[cfg(feature = "write-support")]
138fn get_or_build_once<T, F>(
139    cell: &'static OnceLock<T>,
140    lock: &Mutex<()>,
141    build: F,
142) -> Result<&'static T>
143where
144    F: FnOnce() -> Result<T>,
145{
146    // Fast path: already built and cached.
147    if let Some(v) = cell.get() {
148        return Ok(v);
149    }
150    // Slow path: serialize construction so at most one build runs at a time.
151    let _guard = lock
152        .lock()
153        .map_err(|_| Error::Storage("bridge runtime build lock poisoned".to_string()))?;
154    // Re-check under the lock: another thread may have built while we waited.
155    if let Some(v) = cell.get() {
156        return Ok(v);
157    }
158    // On `Err` we return here WITHOUT touching `cell`, so it stays empty and the
159    // next call retries the build (no permanent poison).
160    let v = build()?;
161    // Only reached on success. We hold the lock and re-checked emptiness above,
162    // so `set` succeeds; store then return the stored ref.
163    if cell.set(v).is_err() {
164        return Err(Error::Storage(
165            "bridge runtime unexpectedly already set".to_string(),
166        ));
167    }
168    cell.get()
169        .ok_or_else(|| Error::Storage("bridge runtime missing after successful set".to_string()))
170}

172/// Run an async future to completion from a synchronous context, safely whether
173/// or not a Tokio runtime is already running on the current thread. See the
174/// module docs for the full strategy and Issue #587 / #1670 rationale.
175#[cfg(feature = "write-support")]
176pub(crate) fn block_on_async<F, T>(future: F) -> Result<T>
177where
178    F: std::future::Future<Output = Result<T>> + Send,
179    T: Send,
180{
181    let rt = bridge_runtime()?;
182    match tokio::runtime::Handle::try_current() {
183        // Already inside a runtime: a nested `block_on` on this thread would
184        // panic. Drive the cached runtime from a scoped thread instead; its
185        // `join()` also catches a panic in the future (Issue #587).
186        Ok(_) => std::thread::scope(|scope| {
187            scope
188                .spawn(|| rt.block_on(future))
189                .join()
190                .map_err(|_| Error::Storage("async-to-sync bridge thread panicked".to_string()))?
191        }),
192        // No runtime on this thread: block on the cached runtime directly.
193        Err(_) => rt.block_on(future),
194    }
195}

201    /// Read the current construction count (test-only accessor).
202    fn runtime_build_count() -> u64 {
203        RUNTIME_BUILD_COUNT.load(Ordering::Relaxed)
204    }

206    /// Issue #1670 TDD: N `block_on_async` calls must construct the runtime at
207    /// most ONCE (it is cached), exercising BOTH the no-runtime path and the
208    /// in-runtime (scoped-thread) path. On main (a `Runtime::new()` per call at
209    /// the old lines 367/377) this count would equal the number of calls
210    /// (`>= N`, here 16), so the `<= 1` assertion is red-on-main.
211    #[test]
212    fn runtime_is_constructed_at_most_once_across_many_calls() {
213        // No-runtime path: N direct calls.
214        for i in 0..8u64 {
215            let out: Result<u64> = block_on_async(async move { Ok(i) });
216            assert_eq!(out.expect("no-runtime call succeeds"), i);
217        }
218
219        // In-runtime path: N calls from inside an ambient runtime (each hits the
220        // scoped-thread branch).
221        let ambient = tokio::runtime::Runtime::new().expect("ambient runtime");
222        ambient.block_on(async {
223            assert!(tokio::runtime::Handle::try_current().is_ok());
224            for i in 100..108u64 {
225                let out: Result<u64> = block_on_async(async move { Ok(i) });
226                assert_eq!(out.expect("in-runtime call succeeds"), i);
227            }
228        });
229
230        assert!(
231            runtime_build_count() <= 1,
232            "bridge runtime constructed {} times across 16 calls; expected <= 1 (cached)",
233            runtime_build_count()
234        );
235    }

237    /// Issue #1670: concurrent `block_on_async` calls from many OS threads on
238    /// the single shared runtime must all complete correctly and must NOT
239    /// serialize. Each future spawns inner tasks (task fan-out) and awaits a
240    /// short timer; a multi-thread runtime services them on its worker pool in
241    /// parallel. A shared `current_thread` runtime would serialize both the
242    /// top-level `block_on` calls and the inner fan-out — so this both proves
243    /// thread-safety of the shared handle and guards the multi-thread flavor.
244    #[test]
245    fn concurrent_block_on_from_many_threads_is_safe_and_parallel() {
246        use std::sync::Arc;
247
248        const THREADS: usize = 8;
249        // Prime the cache from the no-runtime path so all worker threads reuse
250        // one runtime rather than racing to build it.
251        let _: Result<u64> = block_on_async(async { Ok(0u64) });
252        let build_before = runtime_build_count();
253
254        let barrier = Arc::new(std::sync::Barrier::new(THREADS));
255        let start = std::time::Instant::now();
256        let handles: Vec<_> = (0..THREADS)
257            .map(|i| {
258                let barrier = Arc::clone(&barrier);
259                std::thread::spawn(move || {
260                    barrier.wait();
261                    block_on_async(async move {
262                        // Inner task fan-out: joined concurrently on the shared
263                        // worker pool, then a short timer to keep each future
264                        // in-flight while its peers run.
265                        let a = tokio::spawn(async move { i });
266                        let b = tokio::spawn(async move { i * 2 });
267                        tokio::time::sleep(std::time::Duration::from_millis(100)).await;
268                        let (a, b) = (
269                            a.await.map_err(|e| Error::Storage(e.to_string()))?,
270                            b.await.map_err(|e| Error::Storage(e.to_string()))?,
271                        );
272                        Ok::<u64, Error>((a + b) as u64)
273                    })
274                })
275            })
276            .collect();
277
278        for (i, h) in handles.into_iter().enumerate() {
279            let got = h
280                .join()
281                .expect("worker thread did not panic")
282                .expect("concurrent block_on_async succeeds");
283            assert_eq!(got, (i * 3) as u64, "wrong result on thread {i}");
284        }
285
286        // All THREADS futures sleep 100ms and ran concurrently on the shared
287        // runtime; if they were serialized (a single-threaded scheduler) the
288        // wall time would approach THREADS * 100ms. A generous ceiling well
289        // below that proves non-serialization without being flake-prone.
290        let elapsed = start.elapsed();
291        assert!(
292            elapsed < std::time::Duration::from_millis(100 * THREADS as u64 / 2),
293            "concurrent calls appear serialized: {elapsed:?} for {THREADS} x 100ms sleeps"
294        );
295        // Still the single cached runtime — no per-thread rebuild.
296        assert_eq!(
297            runtime_build_count(),
298            build_before,
299            "shared runtime was rebuilt under concurrent load"
300        );
301    }

303    /// Issue #587 panic-safety, in-runtime path: a panic in the future must be

306    #[test]
307    fn in_runtime_future_panic_returns_err_not_abort() {
308        let ambient = tokio::runtime::Runtime::new().expect("ambient runtime");
309        ambient.block_on(async {
310            let result: Result<u64> = block_on_async(async {
311                panic!("boom in future (in-runtime path)");
312                #[allow(unreachable_code)]
313                Ok(0u64)
314            });
315            match result {
316                Err(Error::Storage(msg)) => {
317                    assert!(msg.contains("panicked"), "unexpected message: {msg}")
318                }
319                other => panic!("expected Err(Storage(..)), got {other:?}"),
320            }
321        });
322    }

324    /// Issue #1670 robustness: a FAILED build must NOT poison the cache — the
325    /// next call retries and can succeed. Exercised on the isolated
326    /// `get_or_build_once` helper (its own `OnceLock`/`Mutex`) so the property is
327    /// tested without brittle global state or a way to force a real tokio build
328    /// to fail. This is the regression roborev flagged: a permanently-cached
329    /// `Err` would disable the bridge for the whole process.
330    #[test]
331    fn failed_build_does_not_poison_cache_and_retries() {
332        use std::sync::atomic::AtomicU32;
333
334        static CELL: OnceLock<u32> = OnceLock::new();
335        static LOCK: Mutex<()> = Mutex::new(());
336        static ATTEMPTS: AtomicU32 = AtomicU32::new(0);
337
338        // First call: the builder fails. The cell must stay empty (not poisoned).
339        let first: Result<&'static u32> = get_or_build_once(&CELL, &LOCK, || {
340            ATTEMPTS.fetch_add(1, Ordering::Relaxed);
341            Err(Error::Storage("transient build failure".to_string()))
342        });
343        assert!(first.is_err(), "first build should surface the error");
344        assert!(
345            CELL.get().is_none(),
346            "failed build must leave the cache empty (no poison)"
347        );
348
349        // Second call: the builder succeeds and the value is cached.
350        let second: Result<&'static u32> = get_or_build_once(&CELL, &LOCK, || {
351            ATTEMPTS.fetch_add(1, Ordering::Relaxed);
352            Ok(42u32)
353        });
354        assert_eq!(*second.expect("retry after failure succeeds"), 42);
355        assert_eq!(CELL.get(), Some(&42), "successful build is cached");
356
357        // Third call: fast path, no further build attempts.
358        let third: Result<&'static u32> =
359            get_or_build_once(&CELL, &LOCK, || panic!("must not rebuild after success"));
360        assert_eq!(*third.expect("cached value returned"), 42);
361
362        // Exactly two build attempts: one failed, one succeeded — proving the
363        // retry happened and the success was not rebuilt.
364        assert_eq!(ATTEMPTS.load(Ordering::Relaxed), 2);
365    }

367    /// Issue #587 panic-safety, no-runtime path: a panic in the future unwinds
368    /// to the caller (the direct-block-on branch does NOT convert it to `Err`),
369    /// but it is catchable via `catch_unwind` — the host does not abort — and
370    /// the cached runtime stays usable afterward. This preserves the exact
371    /// pre-#1670 semantics of the direct branch.
372    #[test]
373    fn no_runtime_future_panic_is_catchable_and_runtime_survives() {
374        assert!(
375            tokio::runtime::Handle::try_current().is_err(),
376            "test must run without an ambient runtime"
377        );
378        let caught = std::panic::catch_unwind(|| {
379            let _: Result<u64> = block_on_async(async {
380                panic!("boom in future (no-runtime path)");
381                #[allow(unreachable_code)]
382                Ok(0u64)
383            });
384        });
385        assert!(
386            caught.is_err(),
387            "panic should be catchable, host must survive"
388        );
389
390        // Cached runtime is still usable after the unwind.
391        let after: Result<u64> = block_on_async(async { Ok(42u64) });
392        assert_eq!(after.expect("runtime usable after panic"), 42);
393    }
