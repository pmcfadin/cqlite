1//! One format-tagged partition-location façade (issue #1599 / G3).
2//!
3//! Every point read resolves a partition's uncompressed `Data.db` offset through a
4//! SINGLE entry point, [`SSTableReader::locate`], rather than each read path
5//! re-implementing the "range-check → presence → offset" sequence. The façade is
6//! deliberately THIN: it composes the already-verified primitives
7//! ([`partition_key_out_of_range`](SSTableReader::partition_key_out_of_range),
8//! [`lookup_partition_with_index`](SSTableReader::lookup_partition_with_index),
9//! [`lookup_partition_via_bti_trie`](SSTableReader::lookup_partition_via_bti_trie))
10//! so the B4 key→offset cache, the C5 range short-circuit, and the per-format
11//! presence ordering keep exactly one implementation each. No behavior changes: the
12//! offsets, negatives, and error classification are byte-identical to the legacy
13//! per-path calls the migration replaces.
14//!
15//! ## Two ordering carve-outs (behavior-preserving; see the amended G3 spec)
16//!
17//! 1. **C5 stays a PRE-DISPATCH guard in `get_with_resolution`** (ahead of the BIG
18//!    bloom pre-check), preserving today's `C5 → bloom → index` order for BIG.
19//!    `partition_key_out_of_range` is ONE implementation reached both from that
20//!    guard AND as `locate`'s step 1. An out-of-range POINT read returns at the
21//!    guard, so `locate` is never reached for it and C5 is never double-recorded.
22//!    A DIRECT `locate` call (e.g. the parity test, or a future locate-first caller)
23//!    still records the short-circuit exactly once as step 1.
24//! 2. **The BIG candidate-prune stays BLOOM-based**, NOT routed through `locate`: a
25//!    BIG `Index.db` miss is not a definitive absent (#1572 truncated-index
26//!    invariant), so pruning on an index miss would drop a candidate that actually
27//!    holds the partition. The BTI candidate-prune instead calls
28//!    [`SSTableReader::might_contain_partition_encoded`] (issue #2163): it shares
29//!    the SAME trie resolution `locate` uses AND emits
30//!    `cqlite.read.sstables_pruned{format=bti}` on a definitive trie-miss — the
31//!    single site where a BTI SSTable is excluded from a multi-generation read.
32//!    `locate` itself never emits that counter, so a caller that prunes via
33//!    `might_contain_partition_encoded` and then reads via `locate` never
34//!    double-emits.
35
36use super::SSTableReader;
37use crate::Result;
38
39impl SSTableReader {
40    /// Resolve `partition_key` to its uncompressed `Data.db` offset (and size, where
41    /// the format records one) through the one format-tagged façade.
42    ///
43    /// Returns:
44    /// - `Ok(Some((offset, size)))` — the partition's uncompressed data-section
45    ///   offset. `size` is the Index.db-recorded partition size for BIG, and `0` for
46    ///   BTI (the trie records no size). Callers keep treating `size == 0` as "parse
47    ///   forward from the offset, do not range-read".
48    /// - `Ok(None)` — absent: out of the authoritative `[first_key, last_key]` bound
49    ///   (C5), a BTI trie miss (definitive absence), or a BIG `Index.db` miss (which
50    ///   the BIG point path treats as inconclusive and re-checks via a scan; see the
51    ///   carve-out above — an index miss is NOT a definitive absent).
52    /// - `Err(_)` — the same typed `Error::Corruption` the underlying legacy path
53    ///   raises (a corrupt trie, a `RowsOffset` with no `Rows.db`, etc.).
54    ///
55    /// Resolution order:
56    /// 1. **C5 range short-circuit** (step 1): if `partition_key` provably sorts
57    ///    outside this SSTable's authoritative Summary bound, record one
58    ///    `RANGE_SHORT_CIRCUITS` and return absence before any presence work. A no-op
59    ///    when no bound exists (BTI / no Summary).
60    /// 2. **Format dispatch**: BTI (`da`) walks the `Partitions.db` trie; BIG
61    ///    (`nb`/uncompressed) probes the raw-key `Index.db` map. Both reuse the B4
62    ///    key-offset cache and their existing presence-counter emissions.
63    pub async fn locate(&self, partition_key: &[u8]) -> Result<Option<(u64, u32)>> {
64        // Step 1: C5 authoritative range short-circuit (single implementation shared
65        // with the `get_with_resolution` pre-dispatch guard). No-op for BTI / no
66        // Summary. See the module carve-out: a point read never reaches here for an
67        // out-of-range key (the guard returns first), so this only records C5 for a
68        // direct `locate` caller.
69        if self.partition_key_out_of_range(partition_key) {
70            crate::storage::sstable::read_work_counters::record_range_short_circuit();
71            return Ok(None);
72        }
73
74        // Step 2: per-format presence + offset resolution.
75        if self.is_bti() {
76            // BTI: the Partitions.db trie is the authoritative presence oracle and
77            // records no partition size, so the façade reports size == 0.
78            return Ok(self
79                .lookup_partition_via_bti_trie(partition_key)?
80                .map(|offset| (offset, 0)));
81        }
82        // BIG: the raw-key Index.db map resolves (offset, size).
83        self.lookup_partition_with_index(partition_key).await
84    }
85}
