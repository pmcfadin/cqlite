1//! Full-`Index.db` partition enumeration for BIG SSTables (issue #2302).
2//!
3//! `iterate_all_partitions` (in the sibling `partition_lookup` module) historically
4//! walked only the SPARSE `Summary.db` samples (≈1-in-128 partitions) and passed
5//! `data_size = 0` to the partition parser — `Index.db` never stores a partition
6//! size — so it read zero bytes per entry, resolved zero partitions, and SILENTLY
7//! fell back to a full `sequential_scan` on EVERY read, even with complete valid
8//! components. This module enumerates EVERY partition via the full `Index.db`
9//! offset table instead, bounding each partition by the successor entry's offset
10//! (the last by the data-section end) — authoritative on-disk structure, no size
11//! guessing (issue #28).
12//!
13//! Lives in `data_access` so it reuses that module's `pub(super)` helpers
14//! (`build_v5_parser`, `read_compressed_offset_window`, `sort_by_token_order`)
15//! without widening their visibility.
16//!
17//! ## Every `Ok(None)` / `Ok(Some(...))` exit, exhaustively (roborev jobs 1609, 1610)
18//!
19//! | Site | Condition | Classification | Loud/Quiet |
20//! |------|-----------|-----------------|------------|
21//! | entries empty | zero-entry Index.db — UNREACHABLE as a valid empty SSTable (`IndexReader::open` rejects a zero-byte file, and any non-empty buffer parsing to zero entries leaves unparsed trailing bytes ⇒ `is_fully_parsed()` false); reached only via a corrupt-from-byte-zero / structurally-unusable index (roborev job 1615, see the site) | incomplete `Ok(None)` | loud (caller WARNs) |
22//! | entries non-empty + data section empty | structurally inconsistent | incomplete `Ok(None)` | loud |
23//! | `!index_reader.is_fully_parsed()` | mid-entry-truncated Index.db (Signal A) | incomplete `Ok(None)` | loud |
24//! | `partition_key.is_empty()` | entry carries a present-but-zero-length key — legal Cassandra shape, but `key_len == 0` is unsafe to read back through the shared row/partition scanner on EITHER path (job 1610, see the call-site comment) | incomplete `Ok(None)` | loud |
25//! | `lookup_partition_with_index` misses | index/probe disagreement | incomplete `Ok(None)` | loud |
26//! | `next_offset <= data_offset` | non-ascending offsets | incomplete `Ok(None)` | loud |
27//! | `u32::try_from(span)` fails | partition span overflows `u32` | incomplete `Ok(None)` | loud |
28//! | `partition_slice_fully_consumed` false (Signal B) | dropped trailing entries, a corrupt/truncated partition body (any entry, empty or non-empty result), OR (job 1610) a slice truncated exactly at a parseable row boundary with no CONFIRMED end-of-partition terminator | incomplete `Ok(None)` | loud |
29//! | loop completes for every entry | every partition proven structurally complete (full byte coverage AND a confirmed terminator) | complete `Ok(Some(rows))` | quiet |

31use super::super::SSTableReader;
32use super::model::sort_by_token_order;
33use crate::types::ScanRow;
34use crate::{Result, RowKey};
35
36impl SSTableReader {
37    /// Enumerate every partition of a BIG SSTable through the FULL `Index.db`
38    /// partition-offset table (issue #2302), one index-random-read per partition.
39    ///
40    /// Each `Index.db` entry stores a partition's start offset (relative to the data
41    /// section) but NOT its byte size. The exclusive end of partition `i` is the
42    /// start of partition `i+1` (entries are token-ordered, matching Data.db physical
43    /// order); the LAST partition ends at the data-section end. Every real probe
44    /// increments `INDEX_PROBES` via
45    /// [`lookup_partition_with_index`](SSTableReader::lookup_partition_with_index).
46    ///
47    /// Both compression modes are handled: the offsets are in the uncompressed
48    /// data-section domain, so an uncompressed reader reads the raw file slice
49    /// (CRC-verified) while a compressed reader maps the slice to its covering
50    /// compression chunk(s) and decompresses them
51    /// ([`read_compressed_offset_window`](SSTableReader::read_compressed_offset_window)).
52    ///
53    /// A partition that decodes SUCCESSFULLY to zero live rows (legitimately
54    /// all-shadowed / all-TTL-expired / all-tombstoned, or a pure partition-delete)
55    /// contributes zero rows and the walk CONTINUES — it is NOT a decode failure, so
56    /// one fully-shadowed partition in an otherwise-healthy SSTable never demotes the
57    /// whole read to a sequential scan. This is proven authoritative (never a guess,
58    /// issue #28) BEFORE the shadowed decode even runs: see
59    /// [`partition_slice_fully_consumed`](Self::partition_slice_fully_consumed).
60    ///
61    /// Returns (see the module-level exit table for the exhaustive enumeration):
62    /// - `Ok(Some(rows))` — every index entry resolved to a structurally decodable
63    ///   partition (or the SSTable is genuinely, provably empty); the rows are
64    ///   token-ordered + tombstone-filtered, matching `sequential_scan`.
65    /// - `Ok(None)` — the index/data section could not be proven complete or
66    ///   internally consistent. The caller then emits a loud WARN and falls back to
67    ///   `sequential_scan` (never a silent fallback).
68    ///
69    /// `scan_cancel` is an explicit PER-CALL cancellation token (issue #2346);
70    /// the sole caller ([`SSTableReader::iterate_all_partitions_cancellable`])
71    /// threads either the reader's own field (the pre-#2346 default) or a
72    /// caller-supplied token (the compaction path), so a shared/cached reader's
73    /// concurrent scans cancel independently.
74    pub(in crate::storage::sstable::reader) async fn iterate_all_partitions_via_full_index(
75        &self,
76        scan_cancel: &crate::storage::scan_cancel::ScanCancel,
77    ) -> Result<Option<Vec<(RowKey, ScanRow)>>> {
78        let Some(index_reader) = &self.index_reader else {
79            return Ok(None);
80        };
81        let entries = index_reader.get_partition_entries();
82
83        // Exclusive end of the last partition = the UNCOMPRESSED data-section length.
84        // Compressed reader: the authoritative `CompressionInfo.data_length`.
85        // Uncompressed reader: the raw Data.db file length minus the header (the raw
86        // and uncompressed domains coincide).
87        let data_section_end = match self.compression_info.as_deref() {
88            Some(ci) => ci.data_length,
89            None => self
90                .stats
91                .file_size
92                .saturating_sub(self.actual_header_size as u64),
93        };
94
95        if entries.is_empty() {
96            // Roborev job 1615 (MEDIUM): a zero-entry Index.db is NEVER a reachable
97            // "genuinely empty SSTable" here. `IndexReader::open`
98            // (index_reader/mod.rs) rejects a zero-byte Index.db as corruption
99            // BEFORE constructing the reader, and any NON-empty buffer that parses
100            // to zero entries necessarily failed on its FIRST entry, leaving
101            // unparsed trailing bytes — so `is_fully_parsed()` would be false there
102            // too (parse.rs: the entry loop only stops early on a parse error, which
103            // leaves a non-empty remainder). Neither Cassandra nor CQLite's
104            // `SSTableWriter` emits a zero-partition SSTable at all (a flush/compaction
105            // with no partitions writes no SSTable), so the former quiet
106            // `is_fully_parsed() && data_section_end == 0 => Ok(Some(vec![]))` success
107            // branch was DEAD CODE and has been removed. `entries.is_empty()` here
108            // therefore only ever means a corrupt-from-byte-zero / structurally
109            // unusable index: bail to the caller's loud WARN + sequential fallback
110            // (fail-safe), never fabricate a "complete empty" answer. No heuristics (#28).
111            return Ok(None);
112        }
113        if data_section_end == 0 {
114            // Entries present but the data section is empty: structurally
115            // inconsistent with a real BIG SSTable — not provably complete.
116            return Ok(None);
117        }
118
119        // Completeness Signal A (issue #2302, roborev job 1606): `IndexReader::open`
120        // accepts a truncated/partially-corrupt Index.db as a parsed PREFIX (it
121        // `break`s on the first unparseable entry). An index cut MID-ENTRY leaves
122        // unparsed trailing bytes, so `is_fully_parsed()` is false — the entry set is
123        // NOT a complete enumeration. Bail to the loud sequential-scan fallback
124        // rather than silently returning an under-enumerated "complete" set.
125        // (Boundary-aligned whole-entry drops leave no trailing bytes; those are
126        // caught below by the per-partition coverage check.)
127        if !index_reader.is_fully_parsed() {
128            return Ok(None);
129        }
130
131        // V5 parser over ALREADY-DECOMPRESSED partition bytes (never decompresses
132        // internally, unlike `parse_block_entries_with_schema`), so a compressed
133        // reader's decompressed slice is not double-decompressed. `read_shadowing =
134        // true` applies the same partition/range-tombstone shadowing + TTL expiry a
135        // user-facing SELECT scan uses (matching `sequential_scan`).
136        let parser = self.build_v5_parser(true);
137        let reader_schema = self.get_table_schema(None);
138        let schema = reader_schema.as_ref();
139        let mut results = Vec::new();
140        for i in 0..entries.len() {
141            // Cooperative cancellation (issue #2264): one real index-random-read +
142            // Data.db parse per partition — poll every entry so a cancelled Flight
143            // `do_get` abandons the walk promptly. Issue #2346: PER-CALL token.
144            scan_cancel.check()?;
145
146            // Roborev job 1610 (finding 1): `raw_key: None` never actually occurs
147            // in practice — `parse_big_index_entry` always sets `Some(raw_key)` —
148            // so this early bail is really about a PRESENT-but-ZERO-LENGTH key,
149            // which roborev correctly notes IS a legal Cassandra shape (a
150            // single-component TEXT/BLOB/etc. partition key whose value is the
151            // empty string serializes to zero bytes) — routing it into the normal
152            // index lookup, rather than bailing, was the suggested fix.
153            //
154            // Empirically verified (not assumed) before implementing that: the
155            // write surface does NOT reject an empty-string single-column TEXT
156            // partition key — `Mutation::decorated_key` succeeds (0-byte key,
157            // Murmur3 token computed over zero bytes), `SSTableWriter::write_partition`
158            // and `finish()` both succeed, and the resulting reader opens fine.
159            // BUT reading that partition back is unsafe on EITHER path: the shared
160            // structural row/partition scanner (`scan_partition_header`,
161            // `row_framing.rs`) explicitly rejects `key_len == 0` as "not a valid
162            // partition header" (issue #258 — needed to disambiguate a partition
163            // header's key-length byte from ordinary row-data bytes, since Data.db
164            // carries no other framing to tell them apart). A hand-built two-
165            // partition fixture (one empty-key, one normal) proved this is not a
166            // theoretical concern: `iterate_all_partitions` (bailing here to
167            // `sequential_scan`, since `sequential_scan` uses the SAME shared
168            // scanner) returned 3 corrupted rows for 2 written partitions —
169            // `sequential_scan` itself mis-parses this on-disk shape too, not just
170            // the index path.
171            //
172            // Given that, flowing an empty raw_key into `lookup_partition_with_index`
173            // + `partition_slice_fully_consumed` + `parser.parse_block` would risk
174            // the index path ALSO silently accepting corrupted bytes as a
175            // "complete" partition (worse than the current loud bail: a WRONG
176            // answer presented as success). The safe, evidence-based choice is to
177            // KEEP bailing here — never silently, always via the caller's loud WARN
178            // + `sequential_scan` fallback — until the underlying `key_len == 0`
179            // structural ambiguity in `scan_partition_header` is resolved (a
180            // deeper, format-level fix outside #2302's routing-layer scope).
181            //
182            // ADJUDICATED (roborev job 1615, finding 1 — DECLINED, behavior
183            // unchanged): empty raw partition keys are rejected fail-safe because a
184            // write/read round-trip of an empty PK is corrupt via BOTH the index
185            // and scan paths (verified empirically, see above). The structural fix
186            // for the empty-PK write/read asymmetry is tracked in issue #2325. Do
187            // NOT route empty keys into the walker until #2325 lands.
188            let partition_key = entries[i].raw_key.as_deref().unwrap_or(&[]);
189            if partition_key.is_empty() {
190                return Ok(None);
191            }
192
193            // Resolve through the shared probe so INDEX_PROBES / the B4 key cache /
194            // the observability counters all fire exactly as a point read's would.
195            let Some((data_offset, _size)) =
196                self.lookup_partition_with_index(partition_key).await?
197            else {
198                return Ok(None);
199            };
200
201            // Bound the partition: successor entry's offset, else the data-section
202            // end for the final partition. Offsets must ascend (Data.db physical
203            // order); a non-ascending pair means the index is inconsistent with the
204            // data section, so bail to the safe full scan.
205            let next_offset = if i + 1 < entries.len() {
206                entries[i + 1].data_offset
207            } else {
208                data_section_end
209            };
210            if next_offset <= data_offset {
211                return Ok(None);
212            }
213            let span = next_offset - data_offset;
214            let Ok(size) = u32::try_from(span) else {
215                return Ok(None);
216            };
217
218            // Read the partition's Data.db slice into the UNCOMPRESSED byte domain,
219            // then parse it with the NB-aware V5 block parser — the same producer
220            // `sequential_scan` uses.
221            let raw = if let Some(ci) = self.compression_info.as_deref() {
222                // Compressed: `data_offset` is an uncompressed-domain offset; map it
223                // to the covering compression chunk(s) and decompress.
224                self.read_compressed_offset_window(ci, data_offset, size)
225                    .await?
226            } else {
227                // Uncompressed: raw file offset = data_offset + header (0 for `nb`).
228                let absolute_offset = data_offset + self.actual_header_size as u64;
229                self.read_uncompressed_verified(&self.file, absolute_offset, size as usize)
230                    .await?
231            };
232
233            // Completeness + corruption Signal B (issue #2302, roborev jobs 1606 +
234            // 1609): physically decode exactly ONE partition from `raw` and require
235            // it consume the WHOLE slice. One structural check subsumes both:
236            //  - dropped trailing index entries (only the FINAL entry's extent is
237            //    NOT pinned by a successor offset — it comes from
238            //    `data_section_end`, so it silently spans any dropped tail);
239            //  - a truncated/corrupted partition body. `parser.parse_block` (the
240            //    shadowed decode below) SWALLOWS a row-parse failure internally
241            //    (it `tracing::debug!`s and moves on) and exposes no consumed-vs-
242            //    available signal, so a corrupt body whose header still parses was
243            //    silently accepted as "legitimately zero rows" — the exact
244            //    silent-acceptance class this issue exists to kill, one layer
245            //    deeper. `consumed == raw.len()` with zero rows afterward = a
246            //    genuinely empty/all-shadowed partition (proven, not guessed);
247            //    `consumed < raw.len()` — whether or not rows were already
248            //    produced before the failure — is a structural failure, never
249            //    accepted as complete. No heuristics (issue #28): every entry
250            //    bounds EXACTLY one partition by construction, so full byte
251            //    coverage is the ONE provable completeness criterion; there is no
252            //    "leftover, but not a header, so assume benign" carve-out anymore
253            //    — that assumption is precisely what let body corruption slip
254            //    through as "not a header either" before this fix.
255            if !self.partition_slice_fully_consumed(&parser, &raw, schema)? {
256                return Ok(None);
257            }
258
259            // `parsed.is_empty()` here is UNAMBIGUOUS: the check above already
260            // proved `raw` decodes to exactly one structurally complete partition,
261            // so zero rows means legitimately zero LIVE rows (all-shadowed /
262            // all-TTL-expired / all-tombstoned / a pure partition-delete) — never a
263            // swallowed parse failure.
264            let parsed = parser.parse_block(&raw, schema, self)?;
265            for (_table_id, row_key, value) in parsed {
266                if self.filter_tombstone(&value) {
267                    results.push((row_key, value));
268                }
269            }
270        }
271
272        // Token order matches `sequential_scan` (Data.db is already token-ordered, so
273        // this is effectively a no-op, but keep the ordering guarantee explicit).
274        sort_by_token_order(&mut results);
275        Ok(Some(results))
276    }
277
278    // The structural coverage oracle `partition_slice_fully_consumed` (its full
279    // `at_final_chunk = false` rationale, issue #2302 roborev jobs 1606/1609/1610)
280    // now lives on the sibling `full_index_stream` module (issue #2361) so the
281    // materialising walk above and the streaming walk share ONE implementation.
