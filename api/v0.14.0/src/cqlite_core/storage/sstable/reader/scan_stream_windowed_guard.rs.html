1//! Panic/early-exit drop-guard for the windowed streaming scan's raw-chunk feed
2//! loops (roborev finding, issue #1593; see also issue #1143 finding 2).
3//!
4//! Kept in a sibling file so the parent `scan_stream_windowed` driver stays under
5//! the campsite-rule size limit (epic #1116). Included via `#[path = ...] mod
6//! guard;` + a private re-export, so `use super::*` in the parent's test module
7//! resolves [`FeedFailureGuard`] directly.
8
9use std::sync::atomic::{AtomicBool, Ordering};
10
11/// Drop-guard that flips `io_failed` to `true` on ANY early exit — including a
12/// PANIC/unwind — of a raw-chunk feed loop, UNLESS explicitly
13/// [`disarm`](Self::disarm)ed on the clean-EOF path.
14///
15/// # Why this exists
16///
17/// A feed loop MOVES `raw_tx` in and drops it on return. The blocking parse half
18/// treats a `raw_tx` close with `io_failed == false` as a CLEAN EOF and runs its
19/// terminal (`at_final_chunk = true`) drain, which parses the trailing window AS
20/// IF it were a complete final partition. The normal read-error path sets
21/// `io_failed = true` before returning, so that is handled. But if the feed
22/// closure PANICS, `raw_tx` is dropped during unwind and the only other place
23/// that sets `io_failed = true` — the `Err(join_err)` join arm — runs LATER, only
24/// after the (already-closed) task is joined. The parse half would then observe a
25/// spurious CLEAN EOF, run the terminal drain, and emit a TRUNCATED trailing
26/// partition as a row before the scan surfaces its `Err`.
27///
28/// Arming this guard as a BODY-LOCAL of the feed closure fixes the ordering: body
29/// locals are dropped BEFORE a `move` closure's captured environment, so on a
30/// panic the guard's `Drop` flips `io_failed = true` BEFORE the captured `raw_tx`
31/// drops. The parse half's `io_failed.load` (sequenced after the `raw_tx`-close
32/// happens-before) therefore observes the failure and correctly SKIPS the terminal
33/// drain — no spurious trailing partition.
34///
35/// The clean-EOF path (and the consumer-ended-early break, which is likewise not
36/// an I/O failure) reaches [`disarm`](Self::disarm), so a normal finish leaves
37/// `io_failed == false` and the terminal drain runs EXACTLY as before — the happy
38/// path is byte-identical. `Drop` uses only `AtomicBool::store`, which never
39/// panics, honoring the no-panic-in-`Drop` rule.
40pub(super) struct FeedFailureGuard<'a> {
41    io_failed: &'a AtomicBool,
42    armed: bool,
43}
44
45impl<'a> FeedFailureGuard<'a> {
46    /// Arm a guard over `io_failed` (starts armed; fires on drop unless disarmed).
47    pub(super) fn armed(io_failed: &'a AtomicBool) -> Self {
48        Self {
49            io_failed,
50            armed: true,
51        }
52    }
53
54    /// Disarm on the clean-EOF (or consumer-ended-early) path so a normal finish
55    /// leaves `io_failed == false`.
56    pub(super) fn disarm(&mut self) {
57        self.armed = false;
58    }
59}
60
61impl Drop for FeedFailureGuard<'_> {
62    fn drop(&mut self) {
63        if self.armed {
64            // SeqCst matches the explicit stores in the feed loops so the parse
65            // half's `io_failed.load` observes it via the raw_tx-close
66            // happens-before. `store` never panics (no-panic-in-Drop).
67            self.io_failed.store(true, Ordering::SeqCst);
68        }
69    }
70}
