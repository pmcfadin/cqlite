# Design: corruption-verify-oracle (core)

## Context

The corruption-verify oracle proves CQLite's `verify_sstable` agrees with Cassandra `sstableverify` on a
corpus of deliberately-corrupted SSTable fixtures, one fixture per corruption class. Cassandra verifies the
**whole SSTable directory**, so the captured verdict is only sound if it is bound to the exact bytes of the
**entire** fixture directory under test — not just the one mutated component.

Fixtures fall into two provenance classes, recorded per-fixture as `verdict_byte_stable`:

- **Byte-stable (`yes`)**: regenerating from the `cassandra:5.0.2` container reproduces byte-identical
  fixture bytes. The committed hash-binding is a hard invariant of the tree.
- **Non-byte-reproducible (`no`)**: two BTI fixtures (`bti_partitions_footer_flip`, `bti_rows_truncation`)
  whose regenerated bytes legitimately differ run-to-run. Their binding cannot be validated against
  regenerated bytes; the generator **rebinds** the machine-computed hash atomically with a fresh verdict.

## Goals / Non-Goals

**Goals**
- Bind the captured verdict to a deterministic **full-directory** hash, closing the "non-mutated component
  drifts, bound hash unchanged" gap (acceptance #1).
- Keep the parity test **fatal** against the byte-reproducible tree and **fail-closed** on missing fixtures.
- Land a **minimal, green** PR — remove the machinery causing the two red PR checks.

**Non-Goals (→ #1373)**
- Deciding the CI tier for regeneration parity (nightly vs PR) — owned by #1361/#1367.
- The committed-vs-generated drift guard for the non-byte-reproducible fixtures — needs the nightly tier to
  be well-defined; belongs in the nightly lane.

## Decisions

### D1 — Full-directory hash is the binding of record
`fixture_dir_sha256()` (test) mirrors `fixture_dir_sha256()` (generator): a stable, order-independent hash
over every component file in the fixture directory. The manifest carries both
`verdict_captured_for_dir_sha256` (whole dir) and `verdict_captured_for_sha256` (mutated component). The
parity test validates the dir hash for byte-stable fixtures; a mismatch is a fatal test failure with a
"re-capture and update" message.

### D2 — Drop the PR-time committed-binding guard rather than patch it a 7th time
The PR-lane guard (two steps in `compression-corruption-parity.yml` + `validate-committed-dir-binding.py`
+ `extract-corruption-oracle.py` wiring) is **removed from this PR**. Rationale: it can only run against
regenerated bytes on a PR (binaries are gitignored), so it structurally false-fails the two
non-byte-reproducible BTI fixtures. No PR-lane patch resolves that; the correct home is the nightly
regeneration lane (#1373), where committed vs freshly-generated is a coherent comparison. The guard scripts
are preserved in this branch's git history and cited in #1373 as the reuse source.

### D3 — `sha2` is a dev-dependency
Full-dir hashing is needed only by the parity test, so `sha2 = "0.10"` is added under
`[dev-dependencies]` in `cqlite-core/Cargo.toml` — it does not enter the shipped dependency graph and does
not affect minimal-build or dependency-isolation surfaces.

## Risks / Trade-offs

- **Acceptance #2 not closed in this PR.** Mitigation: it is preserved, not dropped — #1373 lands it in the
  tier where it is well-defined, and #1373 is filed under epic #1360 with the reuse pointer.
- **Coverage gap between merge and #1373**: for the interval, the non-byte-reproducible fixtures' committed
  bindings are guarded only by the MODE-1 parity test (byte-stable tree) + the generator's atomic rebind,
  not a CI drift guard. Acceptable: #1236's original fail-closed parity claim is unaffected; this is
  hardening-of-hardening.

## Migration

None. Test-infra only; no committed bytes added or removed; no CQLite runtime surface changes.
