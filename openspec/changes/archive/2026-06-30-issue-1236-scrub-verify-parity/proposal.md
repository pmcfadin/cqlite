## Why

CQLite already ships a public SSTable **verify** surface — `cqlite verify <path> --mode quick|full
--out text|json` (`cqlite-cli/src/commands/verify.rs`) over
`cqlite_core::storage::sstable::verify::verify_sstable` — that walks an SSTable's components and reports
corruption as a `VerifyReport { findings: Vec<VerifyFinding> }`, where each finding carries a stable
`VerifyErrorClass` (12 variants: `DigestMismatch`, `ChunkDecompressionError`, `ChunkOffsetOutOfBounds`,
`CompressionInfoCorrupt`, `IndexEntryCorrupt`, `BtiRootPointerCorrupt`, `BtiTrieCorrupt`,
`StatisticsHeaderCorrupt`, `SummaryCorrupt`, `MissingComponent`, `UnexpectedEof`, `RowScanFailed`). This
landed under epic #970 / issues #998–#1001 / #1103 and is exercised by
`cqlite-core/tests/issue_1000_verifier.rs` against a reproducible 10-fixture corruption corpus
(`test-data/scripts/generate-corruption-corpus.sh` + `test-data/datasets/corruption/.../corruption-manifest.yml`).

What is **NOT** done — and what manifest scenario `cass.corruption_verify.component_corruption_detection`
records as `status: planned` / `ci.tier: manual_debug` / `fixtures: {}` — is the **parity claim**: there is
no gated test that asserts CQLite's detected-corruption verdict matches **Apache Cassandra's**
`nodetool verify` outcome on the *same corrupted bytes*, and the corpus is built from CQLite-clean
sources rather than Cassandra-written reference SSTables. So today the verifier is internally tested but
makes no public, evidence-backed claim of Cassandra parity.

This change closes that gap: it commissions **Cassandra-written** corrupted-component reference fixtures,
adds a **fail-closed parity test** that compares CQLite's per-component verdict against Cassandra's
captured `nodetool verify` verdict for each corruption class, and promotes the manifest scenario
`planned → mirrored` with real evidence (version pin, generation + comparison commands, failure
artifacts). It is the smallest change that converts the existing verify surface into a publicly-claimed
parity scenario.

- **Milestone:** maintenance / parity-program (epic #967). **Design-driven** — the verify *surface*
  exists, but the parity *layer* (oracle capture method, fixture commissioning convention, scenario
  evidence shape, error-class↔Cassandra-check mapping) has real latitude and no single byte-oracle, so it
  warrants an owner-approved spec (Seam 1). The owner confirmed this routing on 2026-06-29 over the
  manager's "skip OpenSpec" shorthand.
- Adds a new `sstable-verify-parity` capability.
- **No impact** on the no-heuristics mandate (verify is read-only/detect-only and already fails closed —
  no content-based type inference), no new public-binding surface (Python/Node unchanged), no change to
  the <128MB memory budget (verify streams components as it does today).

## What Changes

- **Commission Cassandra-written corrupted-component reference fixtures.** A clean source SSTable is
  written by **Apache Cassandra 5.0.2** (Docker flush), then one corruption per fixture is injected
  **reproducibly** (deterministic single-mutation tuples recorded in a committed manifest), one fixture
  per corruption class in scope. Following the established corpus convention (#970/#999), the corrupted
  `*.db` binaries are **gitignored and regenerated byte-for-byte** from committed clean sources + the
  mutation manifest — only the manifest, SHA-256 sums, text components, and a README are committed (this
  supersedes the issue's `git add -f` suggestion, matching how `generate-corruption-corpus.sh` already
  works).
- **Capture the Cassandra oracle.** For each fixture, the **actual** `nodetool verify` (extended) verdict
  on Cassandra 5.0.2 is captured (pass / throws `CorruptSSTableException` + which check) and committed as
  the golden, alongside the Cassandra version + git SHA. This is the parity source of truth.
- **Add a fail-closed parity test** (`sstable_parity_corruption_verify`) that runs CQLite's public verify
  surface on each Cassandra-written corrupted fixture and asserts: (a) the detected `VerifyErrorClass`
  set matches the expected class for that corrupted component, and (b) CQLite's pass/fail verdict agrees
  with Cassandra's captured verdict. The test is fixture-gated: skip-clean when binaries are absent, but
  **fail** when present-but-wrong (no silent 0-fixture pass).
- **Promote the manifest scenario `planned → mirrored`** with the lint-required evidence
  (`cassandra_version`, `cassandra_git_sha`, `storage_format_version`, `fixture_generation_command`,
  `comparison_command`, `reference_paths`, `failure_artifacts`) and a real CI workflow that invokes the
  comparison; regenerate the public parity report; lint green.
- **Doctrine touch:** none required beyond the manifest/report; the verify surface is already documented.

## Non-goals

- **No scrub / recovery surface.** Cassandra's `nodetool scrub` (rewrite a clean SSTable, `ScrubResult`
  good/bad/empty partition counts, out-of-order rewrite, skip-corrupted, TTL-overflow fix) is a large new
  write-path surface. The owner scoped #1236 to **verify-parity only** on 2026-06-29; scrub/recovery
  parity is deferred to a separate design-driven issue (filed as follow-up).
- **No new corruption error classes.** Cassandra's Verifier also flags **key/row out-of-order** and
  **negative/overflowed local deletion time**; CQLite's `VerifyErrorClass` has no equivalents. Adding them
  (and the matching fixtures) is out of scope and filed as a follow-up; this change asserts parity only
  for the structural / checksum classes CQLite already detects.
- **No consolidation of the two integrity APIs.** `verify::verify_sstable` is the public parity surface
  here; the older block-level `reader/integrity::perform_integrity_check` is left as-is (its
  overlap/dedup is a separate cleanup, filed as follow-up).
- No change to verify's quick/full mode semantics, exit codes, or output schema beyond what parity needs.

## Impact

- Affected specs: **new** capability `sstable-verify-parity`.
- Affected code/data: `test-data/cassandra-parity-manifest.yml` (scenario promotion), a new fixture
  commissioning script + committed manifest/SHA/text under `test-data/datasets/corruption/`, a new
  parity test target, the public parity report regeneration, and a CI lane that runs the comparison.
- Risk class: `p0_data_loss` (corruption detection is a P0 correctness claim) — hence fail-closed test +
  required-tier CI.
