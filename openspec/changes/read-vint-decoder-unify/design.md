# Design — read-vint-decoder-unify (issue #1638, Epic J / J4)

## Context

Cassandra encodes a VInt as `[leading-ones length prefix][0 separator][data bits]`
followed by continuation bytes in big-endian order (up to 9 bytes total). The
number of continuation bytes equals the count of leading 1-bits in the lead
byte. Unsigned fields use this format directly (`writeUnsignedVInt`); signed
deltas ZigZag-map first.

Today the read side decodes this four different ways. The write-side
`storage/serialization/vint.rs` is the single-implementation exemplar. J4 makes
the read side match: one bit-assembly, everything else a thin adapter.

## The single decoder

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum VIntError {
    /// The buffer ended before the full VInt declared by the lead byte's
    /// leading-ones count could be read (also covers empty input).
    Truncated,
}

#[inline]
pub fn decode_unsigned(input: &[u8]) -> Result<(u64, usize), VIntError> {
    let first = *input.first().ok_or(VIntError::Truncated)?;
    let extra = first.leading_ones() as usize; // 0..=8 for a u8
    let total = extra + 1;                      // 1..=9, == MAX_VINT_SIZE
    if input.len() < total {
        return Err(VIntError::Truncated);
    }
    if extra == 0 {
        return Ok((first as u64, 1)); // 0xxxxxxx single byte
    }
    // Load the `extra` continuation bytes as the low bits of a u64 via ONE
    // big-endian read (no per-byte index loop, no #[allow] lint suppression).
    let (_, rest) = input.split_at(1);
    let mut be = [0u8; 8];
    be[8 - extra..].copy_from_slice(&rest[..extra]);
    let tail = u64::from_be_bytes(be);
    let value = if extra == 8 {
        tail // 0xFF lead: no data bits in the first byte
    } else {
        let data_bits_first = 7 - extra;               // bits carried in byte 0
        let mask = (1u64 << data_bits_first) - 1;
        ((first as u64 & mask) << (extra * 8)) | tail
    };
    Ok((value, total))
}

#[inline]
pub fn decode_signed(input: &[u8]) -> Result<(i64, usize), VIntError> {
    let (u, n) = decode_unsigned(input)?;
    Ok((zigzag_decode(u), n))
}
```

The nom wrappers stay for their ~200 existing call sites:

```rust
pub fn parse_vuint(input: &[u8]) -> IResult<&[u8], u64> {
    match decode_unsigned(input) {
        Ok((v, n)) => Ok((&input[n..], v)),
        Err(_) => Err(eof(input)),
    }
}
```

`parse_vint` and `parse_unsigned_vint32` are the same shape (`parse_unsigned_vint32`
keeps its `leading_ones > 4` width pre-check, then delegates the assembly and
`u32::try_from`s the result). `parse_vint_length` / `parse_vint_length_signed`
are unchanged — they already delegate to `parse_vuint` / `parse_vint`.

## Why removing the `fixed → zigzag` fallback is behavior-preserving

`parse_vint` today is `parse_vint_fixed(input).or_else(|_| parse_zigzag_vint(input))`.
`parse_vint_fixed` **is** `zigzag_decode(unsigned-leading-ones-decode)` — i.e.
exactly `decode_signed`. It fails **only** on empty/truncated input. The
`parse_zigzag_vint` fallback (a) only handles a strict subset of lead bytes
(`< 0xE0`, `0xF0`, `0xFF`) and (b) applies its own bounds checks, so on every
buffer where `parse_vint_fixed` fails, the fallback also fails. Therefore for all
complete buffers `parse_vint == parse_vint_fixed == decode_signed`, and for
truncated buffers both return `Err`. Removing the fallback changes no observable
result. This is proven, not asserted:

- **Corpus differential**: a saved snapshot of the pre-refactor `parse_vuint`
  logic vs the new `decode_unsigned`, agreeing on value AND consumed length at
  every VInt across a generated byte space (all lead bytes × representative
  continuation patterns × truncation boundaries).
- **Round-trip**: proptest over all `u64` / `i64` — `serialization::vint`
  encode → new decode → identity.
- The I2 `_1624` framing/truncation regression tests and the
  `vint_length_corpus_audit_tests` (real 33-table corpus) stay green unchanged.

## Overflow / width safety

- `extra ∈ [0, 8]` (a `u8` has at most 8 leading ones) ⇒ `total ∈ [1, 9]`; no
  out-of-range width, matching `MAX_VINT_SIZE = 9`.
- `data_bits_first = 7 - extra ∈ [0, 6]` ⇒ `1u64 << data_bits_first` never
  overflows; `extra == 7` yields `mask == 0` (0xFE lead, correct: no data bits).
- `(first & mask) << (extra*8)`: `extra*8 ≤ 56` and `first & mask` occupies ≤ 6
  bits ⇒ ≤ 62 significant bits, no shift overflow. The `extra == 8` (0xFF) case
  is handled separately with all 8 continuation bytes.
- `parse_vint_length` retains the existing `MAX_VINT_LENGTH` (1GB) cap before the
  `usize` cast — no change.

## Deletions

- `parser/vint_fixed.rs` (module + its tests).
- `parse_zigzag_vint`, `parse_cassandra_vint_format`, `parse_custom_vint_format`,
  `detect_ascii_corruption` (all dead / fallback-only).
- `parse_vint_cassandra`, `encode_vint_cassandra` (0 callers; the latter
  depended on the deleted `encode_vint_fixed`).
- The `pub mod vint_fixed;` declaration and doc references in `parser/mod.rs`.
- Tests that exercised the deleted internals (`test_detect_ascii_corruption_patterns`,
  `test_parse_zigzag_vint_extended_consumes_exactly_nine_1624`) — the framing/
  truncation intent they guarded is preserved by the `parse_vint`-level
  `_1624` tests.

## Bench + gate

A `decode/vint_decode` criterion group in `benches/decode_bench.rs` decodes a
fixed table of representative VInt byte buffers (1..9-byte widths, signed and
unsigned) through `decode_unsigned` / `decode_signed`. It runs without the
`cli-helpers` / `bench-internals` features (pure public API, no fixture), so it
is always measured. `perf-gate.json` gains a `decode/vint_decode` entry; on first
landing there is no base baseline (the entry does not exist on `main`), which the
perf-regression workflow already handles by reporting "new" rather than erroring.
