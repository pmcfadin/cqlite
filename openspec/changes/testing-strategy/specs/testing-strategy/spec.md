# testing-strategy — delta for testing-strategy (issue #4259)

**Architecture note.** This capability defines the *shape* of CQLite's tests (matrix, anchor,
differential, randomized) and the *cost contract* of each CI tier. Mechanized requirements are enforced
by a Rust type, a runtime assertion, or a gate FAIL; review-enforced requirements are enforced by the
doctrine page plus `rust-reviewer` / roborev checklists and are marked **(review-enforced)**.

## ADDED Requirements

### Requirement: Every parity or differential suite declares its oracle class and that class's blind spot

Each test target that compares CQLite output against a reference SHALL state, in its module header,
exactly one oracle class — `cassandra-bytes`, `sstabledump-physical`, `query-semantics`,
`cqlite-differential`, or `cross-surface` — and the blind spot the doctrine page records for that
class. A `cqlite-differential` or CQLite-written/CQLite-read suite SHALL NOT be the sole oracle for an
on-disk framing or encoding property. **(review-enforced)**

#### Scenario: A new framing test cites only a CQLite round-trip
- **WHEN** a PR adds a test asserting an on-disk encoding property whose only oracle is CQLite writing
  then CQLite reading
- **THEN** review blocks the PR until a `cassandra-bytes` oracle (Cassandra-written fixture or pinned
  `cassandra-5.0.8` source) is added

#### Scenario: Header names the class
- **WHEN** a reviewer opens any suite added after this change
- **THEN** its module header names one oracle class and that class's blind spot

### Requirement: A new test is a matrix row unless it earns a named anchor

A test for behaviour already covered by a matrix SHALL be added as a row of that matrix. A new test
file SHALL be created only when it (a) asserts a second invariant beyond the primary comparison
(allocation budget, exact counter, digest, row count), (b) memorializes a specific past bug, or
(c) drives a sequence (paging, resume, multi-step compaction). The new file's header SHALL state which
of (a)/(b)/(c) applies. **(review-enforced)**

#### Scenario: Reverse-read coverage for BTI is added
- **WHEN** a contributor adds reverse-direction coverage for BTI point reads
- **THEN** it is added as rows of the point-vs-full matrix, not as a new `issue_*` file

#### Scenario: A regression for a specific bug
- **WHEN** a contributor memorializes a fixed bug
- **THEN** a named file is permitted and its header states reason (b) and links the issue

### Requirement: Matrix fixtures are built once per fixture-axis tuple and shared read-only across processes

Matrix tests SHALL obtain fixtures through a shared fixture cache keyed by the fixture-axis tuple
(format, compression, shape) plus a generator-version constant. The cache SHALL publish a fixture
atomically so concurrent nextest processes never observe a partial fixture, and matrix rows SHALL NOT
mutate a cached fixture.

#### Scenario: Two processes request the same fixture concurrently
- **WHEN** two nextest test processes request the same fixture-axis tuple at the same time
- **THEN** both receive the same complete fixture directory and the fixture is built at most twice,
  with exactly one published

#### Scenario: Generator version changes
- **WHEN** the fixture generator-version constant changes
- **THEN** the next request builds a new fixture under a new key and never reads the old one

#### Scenario: Fixture is reused across rows
- **WHEN** a matrix with N query-axis rows runs against one fixture-axis tuple
- **THEN** the fixture build runs once, and a test proves the second request is a cache hit

### Requirement: Query axes are covered pairwise, with named full-product pairs

Matrix query-axis rows SHALL be generated by an in-repo deterministic covering-array builder that covers
every pair of axis values in at least one row, prunes illegal combinations by predicate in the builder,
and supports declaring axis pairs that receive full product. Each matrix module header SHALL name its
full-product pairs. The initial named pairs are direction × format, direction × compression, and
clustering-slice × wide partition.

#### Scenario: Every pair is covered
- **WHEN** the builder is given any set of axes and values
- **THEN** its own tests verify every pair of values from distinct axes appears in at least one row

#### Scenario: Deterministic output
- **WHEN** the builder runs twice on the same input
- **THEN** it emits the same rows in the same order

#### Scenario: Illegal combination
- **WHEN** a pruning predicate rejects a combination
- **THEN** no emitted row contains it and every remaining legal pair is still covered

### Requirement: An empty or shrunken matrix fails

Every matrix SHALL assert a committed case floor (minimum row count) at run time, so an emptied or
accidentally pruned matrix FAILs instead of passing with zero rows.

#### Scenario: Matrix pruned below its floor
- **WHEN** a change reduces a matrix below its committed case floor
- **THEN** the test FAILs naming the matrix, the floor and the actual count

### Requirement: A differential case cannot be written without a declared expected outcome

The shared differential support SHALL require each case to declare one of `Served`,
`SupportedUnserved`, or `GatedFallback(FallbackReason)` at construction, with no default. The outcome
SHALL NOT be inferred from the result.

#### Scenario: Case omits its outcome
- **WHEN** a contributor constructs a differential case without an expected outcome
- **THEN** the code does not compile

#### Scenario: Declared fallback reason mismatches
- **WHEN** a case declares `GatedFallback(r)` and the engine reports a different `FallbackReason`
- **THEN** the case FAILs naming both reasons

### Requirement: A differential run proves the new path engaged on every probe

For a `Served` case, the differential runner SHALL read the access path after every new-path query and
FAIL if any query was not served by the targeted path, naming the table and key. A run whose `Served`
case engaged on zero probes SHALL FAIL.

#### Scenario: Point path silently falls back to a full scan
- **WHEN** a `Served` point-vs-full case's point query reports a non-targeted access path
- **THEN** the case FAILs naming the table and key, even though the rows match

#### Scenario: point-vs-full adopts the contract
- **WHEN** `point_vs_full_differential.rs` runs after this change
- **THEN** every case goes through the shared runner and every point probe is engagement-checked (#4255)

### Requirement: The new-path leg of a differential runs with cold process-global caches

Before the new-path leg, the differential runner SHALL invalidate process-global read caches
(including `GlobalKeyOffsetCache`) so the new path exercises its cold index and decompression path, and
SHALL NOT let an old-path run in the same process pre-warm state the new path reads.

#### Scenario: Old path ran first in the same process
- **WHEN** a case's discovery or old-path run touches the same generations before the new-path leg
- **THEN** the new-path leg's first probe records a key-offset cache MISS

### Requirement: Every differential suite has an end-to-end non-vacuousness meta-test

Each differential suite SHALL include one meta-test that injects a fault into the path under test
through a debug-only seam, runs the suite's real runner on a real fixture, and asserts the runner
reports a divergence. The seam SHALL be inert in release builds.

#### Scenario: Fault injected on the point path
- **WHEN** the meta-test enables the fault seam for the point read path and runs one real case
- **THEN** the runner returns a divergence error naming the perturbed column

#### Scenario: Release build ignores the seam
- **WHEN** the fault environment variable is set for a release-profile build
- **THEN** reads are unaffected and a test proves it

### Requirement: CI tiers are nextest profiles and the PR tier contains no randomness

Tests SHALL belong to exactly one tier — `pr`, `nightly` or `weekly` — expressed as nextest profiles.
Randomized (`burn_*`) test binaries SHALL be excluded from the `pr` profile. The randomized harness
SHALL refuse to draw a fresh seed unless the tier is `nightly` or `weekly`; in the `pr` tier it runs
only the committed fixed-seed array.

#### Scenario: A randomized test in the PR tier
- **WHEN** the gate runs the `pr` profile
- **THEN** no `burn_*` binary executes and no test draws a seed from the clock

#### Scenario: Fixed seeds in the PR tier
- **WHEN** a seed is appended to the committed fixed-seed array
- **THEN** the `pr` tier replays it deterministically

### Requirement: Each tier has an enforced time budget

The full gate SHALL print a `test-budget:` SUMMARY line reporting the tier's total test wall time, the
five slowest test binaries and the committed budget, and SHALL FAIL when a binary or the tier total
exceeds its committed budget. Budgets SHALL live in a committed file initialised from a measured
baseline plus headroom; raising a budget SHALL be a reviewed diff to that file, with no environment
override.

#### Scenario: A binary exceeds its budget
- **WHEN** a test binary's wall time exceeds its committed budget in the full gate
- **THEN** the gate FAILs naming the binary, its time, its budget and the remedies

#### Scenario: Budget line is always present
- **WHEN** the full gate completes
- **THEN** the SUMMARY contains a `test-budget:` line with measured values, never a bare zero

### Requirement: Randomized testing satisfies a determinism and triage contract

Any randomized test SHALL print its seed on failure, split data and query seeds, derive write
timestamps from the data seed, pin `now` per case, exclude TTL from replayed histories, and use a high
`gc_grace`. Nightly runs SHALL use CQLite self-consistency oracles; weekly runs SHALL replay a sample
through Cassandra 5.0. A randomized failure SHALL file an issue with the seed and shrunk repro and SHALL
NOT block a merge; the shrunk repro SHALL land as a committed regression test and its seed SHALL join
the fixed-seed array.

#### Scenario: Nightly burn failure
- **WHEN** a nightly randomized run diverges
- **THEN** an issue is filed containing the seed and a reproduction command, and no PR is blocked

#### Scenario: Replaying a reported seed
- **WHEN** a developer reruns the reported seed locally
- **THEN** the same divergence reproduces bit-for-bit

### Requirement: Test-binary consolidation is adopted only on measured benefit

Before any migration of existing `issue_*` test targets, a measurement SHALL consolidate a sample of at
least 20 targets into one binary on the gate box and record cold and warm build time, link time,
`target/` size and nextest wall time before and after. Migration SHALL proceed only if the extrapolated
saving is at least 10% of `core-tests` wall time or 20% of `target/debug/deps` size.

#### Scenario: Measurement below threshold
- **WHEN** the measured saving is below both thresholds
- **THEN** no migration issue is opened and the doctrine records the result

### Requirement: The strategy is documented once for agents and once for the public

A canonical agent doctrine page SHALL state the layers, contracts, tiers and budgets, and `CLAUDE.md`'s
Testing section SHALL link it rather than restate it. A public top-level "How CQLite Is Tested" docs
section SHALL present the strategy for adopters, including a known-blind-spots page that links every
open gap issue. Public claims SHALL be verified against the repository and SHALL respect the #1406
write claim boundary.

#### Scenario: A gap issue closes
- **WHEN** a gap issue linked from the known-blind-spots page is closed
- **THEN** the page is updated in the closing PR

#### Scenario: CLAUDE.md stays short
- **WHEN** the doctrine page is published
- **THEN** `CLAUDE.md`'s Testing section contains the hard rules and a link, and the blind-spot
  narratives live on the doctrine page
