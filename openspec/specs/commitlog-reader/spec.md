## Requirements
### Requirement: CommitLog descriptor parsing
The system SHALL parse a Cassandra CommitLog segment's `CommitLogDescriptor` header (segment id,
version, compression parameters) authoritatively from the header bytes, and SHALL reject any segment
whose version is not the Cassandra 5.0-era commitlog version via a typed `Error`, without attempting to
parse the remainder of the file.

#### Scenario: Valid Cassandra 5.0 segment header parses successfully
- **WHEN** `CommitLogReader::open` is given a real, well-formed Cassandra 5.0 CommitLog segment file
- **THEN** the descriptor is parsed and reports the correct segment id and version, matching the values
  Cassandra itself recorded when writing the segment

#### Scenario: Unsupported commitlog version is rejected, not guessed
- **WHEN** `CommitLogReader::open` is given a segment whose descriptor version is outside the supported
  Cassandra 5.0-era range
- **THEN** it returns a typed `Error` (e.g. `UnsupportedCommitLogVersion`) and does not attempt to
  decode the mutation stream

### Requirement: Mutation stream decoding matches ground truth
The system SHALL decode the mutation stream of a CommitLog segment into a sequence of mutations whose
table/partition/cell values match the mutations that were actually written to that segment.

#### Scenario: Decoded mutations match the inserted mutation set
- **WHEN** a real Cassandra 5.0 node has a known set of N mutations inserted via CQL and the resulting
  CommitLog segment is captured before discard
- **THEN** `CommitLogReader` decodes exactly N mutations whose table, partition key, and cell values
  match the original inserts (the insert-set-vs-decoded-set parity oracle)

### Requirement: Torn-tail truncation tolerance
The system SHALL tolerate a truncated or torn final section of a CommitLog segment: mutations that
decoded cleanly before the tear SHALL be returned, and the truncation SHALL be reported to the caller,
without panicking.

#### Scenario: Segment with a torn final sync section
- **WHEN** `CommitLogReader` reads a segment whose last sync-marker-delimited section is incomplete
  (simulating a crash mid-write)
- **THEN** it returns every mutation that decoded cleanly before the tear, surfaces that the segment was
  truncated, and does not panic or return a generic/opaque error

### Requirement: Malformed input never panics
The system SHALL return a typed `Error` — never panic, hang, or exhibit undefined behavior — when given
a corrupt or adversarially malformed CommitLog segment (bad CRC, corrupt header, truncated mid-record).

#### Scenario: Corrupt CRC is rejected cleanly
- **WHEN** a segment's per-record CRC does not match its payload
- **THEN** `CommitLogReader` returns a typed `Error` identifying the corruption, and does not panic

#### Scenario: Fuzzed arbitrary bytes never panic or hang
- **WHEN** the CommitLog frame parser is run against arbitrary fuzzer-generated byte sequences (via the
  `fuzz/` harness, matching the existing five-target safety bar)
- **THEN** it always returns (never panics, never hangs, never OOMs) — either successfully or with a
  typed `Error`

### Requirement: Public surface with end-to-end wiring evidence
The system SHALL expose CommitLog reading through a named public surface — a library API and a CLI
subcommand — each exercised by an end-to-end test reading a real segment file, not only by internal
unit tests.

#### Scenario: CLI subcommand reads a real segment end to end
- **WHEN** a user runs the CommitLog-reading CLI subcommand against a real Cassandra-produced segment
  file
- **THEN** the command succeeds and reports the decoded mutations (or a summary of them), proving the
  full call chain from CLI entry point through `CommitLogReader` to decoded output

### Requirement: Bounded memory via streaming decode
The system SHALL decode a CommitLog segment's mutation stream incrementally (one sync-section at a
time) and SHALL NOT materialize the entire segment's mutation set as a single in-memory collection
before returning any results to the caller.

#### Scenario: Reading a segment does not require whole-segment materialization
- **WHEN** `CommitLogReader` is used to iterate a segment's mutations
- **THEN** mutations are yielded incrementally as sync sections are decoded, and the reader's peak
  memory use does not scale with materializing the full mutation set as one collection up front

### Requirement: No-heuristics format detection
The system SHALL determine a segment's version and format exclusively from the authoritative
`CommitLogDescriptor` header fields, and SHALL NOT infer version, compression, or mutation framing from
file size, byte-pattern sniffing, or other non-authoritative heuristics.

#### Scenario: Ambiguous-looking payload bytes do not influence format detection
- **WHEN** a segment's mutation payload happens to contain byte sequences that resemble a different
  descriptor version or framing pattern
- **THEN** format/version detection is driven solely by the descriptor header fields already parsed,
  never by scanning or pattern-matching the payload bytes

### Requirement: Compressed segments fail closed, not silently
The system SHALL detect when a segment's descriptor indicates compression and SHALL return a clear,
typed "unsupported" error rather than attempting to decode compressed payload bytes as if uncompressed.

#### Scenario: Compressed segment is rejected with a clear error
- **WHEN** `CommitLogReader::open` is given a segment whose descriptor specifies a compressor class
- **THEN** it returns a typed `Error` indicating compressed segments are unsupported, and does not
  attempt to decode the (compressed) mutation stream as plain bytes
