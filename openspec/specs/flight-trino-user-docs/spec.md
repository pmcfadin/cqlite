## Requirements
### Requirement: A dedicated Flight/Trino page exists in the published user docs
The published documentation site SHALL include a user-facing page dedicated to the Arrow Flight server
(`cqlite-flight`) and the Trino connector (`cqlite-trino`), located under
`website/src/content/docs/user-docs/` with valid Starlight frontmatter (a `title`, a `description`, and a
`sidebar` `label` + `order`) so it renders as an entry in the site's "User Docs" navigation group.

#### Scenario: Page renders in the User Docs nav
- **WHEN** the website is built (`cd website && npm run build`)
- **THEN** a page sourced from `website/src/content/docs/user-docs/flight-trino.md` is produced
- **AND** it appears in the autogenerated "User Docs" sidebar group (its frontmatter provides `title`, `description`, and `sidebar.order`)

#### Scenario: Frontmatter is valid
- **WHEN** the site build parses the page's frontmatter
- **THEN** the build succeeds with no schema/frontmatter error (the page has a non-empty `title` and `description`)

### Requirement: The page explains the Flight server and its compaction-on-read model
The page SHALL describe what the Flight server is and its read model: it runs co-located with a Cassandra
node, performs an on-the-fly compaction merge of that node's SSTables on each read (leaving originals
untouched), reads only flushed SSTables (not memtable rows), is snapshot-aware, and produces output with
`SELECT` parity.

#### Scenario: Read model is documented
- **WHEN** a reader opens the page
- **THEN** it states that reads are served by an on-the-fly compaction merge of the node's SSTables with the originals unmodified
- **AND** it states that only flushed SSTables are visible (memtable rows require a `nodetool flush`)

### Requirement: The page documents running the published container
The page SHALL document running the server from its published container image
`ghcr.io/pmcfadin/cqlite-flight`, including that public images pull without authentication and a runnable
`docker run` example that mounts the Cassandra data directory read-only and points `--data-dir` at it and
exposes the Flight listener on `:8815`.

#### Scenario: Container run is documented
- **WHEN** a reader wants to start the server without building from source
- **THEN** the page shows a `docker pull`/`docker run` example against `ghcr.io/pmcfadin/cqlite-flight` with a read-only (`:ro`) data mount, `--data-dir`, and the `:8815` Flight port

### Requirement: The page documents the client ticket / predicate / projection API with a working example
The page SHALL document the Flight ticket contract (keyspace, table, DDL, and the optional snapshot,
token-range, projection `columns`, and `predicates` pushdowns), note the read-only RPC surface
(`GetFlightInfo`/`GetSchema`/`DoGet`), and include a runnable client example (PyArrow Flight) that
connects, fetches the schema, and streams a table.

#### Scenario: Client example is present and runnable-shaped
- **WHEN** a reader wants to query the server programmatically
- **THEN** the page shows a PyArrow Flight example that connects to `grpc://<host>:8815`, builds a JSON ticket (keyspace/table/ddl), and calls `do_get` to stream the table
- **AND** it documents the optional `columns` (projection) and `predicates` pushdown fields of the ticket

### Requirement: The page documents the Trino connector discovery, install, and read mode
The page SHALL document the Trino connector: that it discovers nodes and token ranges through the
Cassandra Sidecar and builds one split per token range pinned to a single replica (so each row is read
once cluster-wide), how the plugin is installed (assembled plugin directory from `./gradlew installPlugin`
or the published Maven artifact, dropped into Trino's plugin path), and the catalog `cqlite.read-mode`
choice (`snapshot` default vs `live`).

#### Scenario: Connector discovery + split model documented
- **WHEN** a reader wants to query Cassandra SSTables from Trino
- **THEN** the page states the connector discovers nodes/token-ranges via the Cassandra Sidecar and creates one split per token range pinned to one replica

#### Scenario: Install and catalog config documented
- **WHEN** a reader wants to install and configure the connector
- **THEN** the page shows assembling the plugin directory (`./gradlew installPlugin` or from the Maven artifact) and dropping it into Trino's plugin path
- **AND** it documents the `cqlite.read-mode` catalog property (`snapshot` default vs `live`) and its consistency tradeoff

### Requirement: The page is discoverable and links to authoritative sources
The page SHALL be reachable from at least one existing site page (not orphaned), and SHALL link to the
authoritative crate READMEs (`cqlite-flight/README.md`, `trino-connector/README.md`) for exhaustive
detail rather than duplicating their full flag/property reference. All internal links and anchors SHALL
resolve under the site's link validator.

#### Scenario: Reachable from an existing page
- **WHEN** the site is built
- **THEN** at least one existing page (e.g. `use-cases/sidecar-lakehouse.md`) links to the new Flight/Trino page

#### Scenario: Links validate
- **WHEN** `npm run build` runs `starlightLinksValidator`
- **THEN** the build passes with no broken internal link or anchor introduced by this change
