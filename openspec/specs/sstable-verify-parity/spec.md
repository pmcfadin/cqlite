## Requirements
### Requirement: Cassandra-written corrupted-component reference fixtures are commissioned reproducibly
The parity corpus SHALL include, for each in-scope corruption class, a reference SSTable whose **clean
source is written by Apache Cassandra 5.0.2** and into which exactly one corruption is injected by a
**deterministic, recorded** mutation. The corrupted and clean `*.db` binaries SHALL be gitignored and
regenerated byte-for-byte from committed clean-source recipes plus a committed mutation manifest; only
the mutation manifest, SHA-256 sums, text components, captured Cassandra verdicts, and a README SHALL be
committed (no force-committed binaries). The in-scope classes SHALL be the structural/checksum classes
CQLite's verifier already detects: `DigestMismatch`, Data.db chunk corruption
(`ChunkDecompressionError`/`ChunkOffsetOutOfBounds`), `CompressionInfoCorrupt`, `IndexEntryCorrupt`,
`BtiRootPointerCorrupt`, `BtiTrieCorrupt`, `StatisticsHeaderCorrupt`, `SummaryCorrupt`, and
`MissingComponent`.

#### Scenario: Each in-scope corruption class has a reproducible Cassandra-written fixture
- **WHEN** the fixture commissioning script is run against Cassandra 5.0.2
- **THEN** it produces one fixture per in-scope corruption class from a Cassandra-written clean source with a single recorded mutation applied
- **AND** it commits the mutation manifest, SHA-256 sums, text components, captured Cassandra verdicts, and README, while leaving the `*.db` binaries gitignored

#### Scenario: Corrupted binaries regenerate byte-for-byte without re-running live Cassandra
- **WHEN** the corpus is regenerated from the committed clean-source recipe and mutation manifest in a clean checkout
- **THEN** every corrupted `*.db` binary matches its committed SHA-256 sum
- **AND** regeneration does not require a live Cassandra instance

### Requirement: The Cassandra verify verdict is captured as the parity oracle
For each fixture, the corpus SHALL record the **actual** Apache Cassandra 5.0.2 `nodetool verify`
(extended) outcome — clean, or corrupt with the check that tripped — as the committed parity oracle,
together with the Cassandra version (`5.0.2`) and git SHA. Expected verdicts SHALL NOT be hand-encoded
from reading Cassandra source, and SHALL NOT be derived from a non-5.0.2 Cassandra build.

#### Scenario: Each fixture carries a captured 5.0.2 verdict
- **WHEN** a fixture's parity record is read
- **THEN** it contains the Cassandra 5.0.2 `nodetool verify` verdict actually observed on that fixture's bytes (clean or corrupt-with-check)
- **AND** it records `cassandra_version: 5.0.2` and the matching `cassandra_git_sha`

### Requirement: A fail-closed parity test asserts CQLite verify verdicts match Cassandra per fixture
A gated parity test SHALL run CQLite's **public** verify surface — `verify_sstable` (the call path
behind `cqlite verify --mode full`) — on each Cassandra-written corrupted fixture and assert both that
the reported `VerifyErrorClass` set contains the expected class for the corrupted component and that
CQLite's overall corrupt/clean verdict agrees with the fixture's captured Cassandra verdict. The test
SHALL be fixture-gated: it SHALL skip-clean when the fixture binaries are absent, FAIL when binaries are
present but a verdict or class mismatches, and treat zero-fixtures-evaluated-when-present as a failure.

#### Scenario: CQLite flags the same corruption class Cassandra does
- **WHEN** the parity test runs `verify_sstable(..., VerifyMode::Full, ...)` on a corrupted fixture whose `expected_error_class` is recorded
- **THEN** the returned `VerifyReport.findings` contain that `VerifyErrorClass`
- **AND** CQLite's corrupt verdict matches the fixture's captured Cassandra "corrupt" verdict

#### Scenario: A clean Cassandra-written baseline verifies clean in both
- **WHEN** the parity test runs `verify_sstable` on the uncorrupted Cassandra-written baseline
- **THEN** the `VerifyReport` reports zero findings
- **AND** that agrees with the fixture's captured Cassandra "clean" verdict

#### Scenario: Missing fixtures skip, present-but-wrong fails, zero-evaluated fails
- **WHEN** the fixture binaries are absent and `CQLITE_REQUIRE_FIXTURES` is unset
- **THEN** the parity test skips cleanly without asserting parity
- **WHEN** the fixture binaries are present but a CQLite verdict or class disagrees with the captured Cassandra verdict
- **THEN** the test fails
- **WHEN** the fixtures are present but the test evaluates zero of them
- **THEN** the test fails rather than reporting success

### Requirement: The parity manifest scenario is promoted to mirrored with verifiable evidence
The change SHALL promote the manifest scenario `cass.corruption_verify.component_corruption_detection` in
`test-data/cassandra-parity-manifest.yml` from `planned` to `status: mirrored` with the
fixture-backed evidence the parity lint requires — `cassandra_version`, `cassandra_git_sha`,
`storage_format_version`, `fixture_generation_command`, `comparison_command`, `reference_paths`, and
`failure_artifacts` — and its `ci.workflow` SHALL name a real workflow that actually invokes the
`comparison_command`. The public parity report SHALL be regenerated and the `cassandra-parity` lint SHALL
pass. The scenario text SHALL NOT claim verify parity for corruption classes that remain out of scope
(out-of-order, negative local-deletion-time, scrub/recovery).

#### Scenario: Lint accepts the promoted, fixture-backed scenario
- **WHEN** `cassandra-parity` lint runs after promotion
- **THEN** the scenario validates as `mirrored` with all required fixture-backed evidence fields present
- **AND** the named `ci.workflow` is a real workflow path that invokes the `comparison_command`

#### Scenario: The regenerated report reflects the mirrored scenario without overstating scope
- **WHEN** the public parity report is regenerated
- **THEN** the corruption-verify scenario appears as mirrored
- **AND** neither the scenario nor the report claims parity for out-of-order, negative-local-deletion-time, or scrub/recovery behavior
