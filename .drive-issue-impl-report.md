## 6. What could NOT be done as pure motion (all forced by the move; each is in a commit message)

1. **Node file count is 6, not the issue's 5.** The issue's own budget (350+330+350+160+200 =
   1390 of 1767 lines) omits the 342-line `open()` factory. Folded into `mod.rs` it would sit at
   ~790/800 — one edit from tripping the ratchet — so `open()` got `database/open.rs`, mirroring
   the python side's `database/open.rs`. mod.rs is 589L.
2. **Visibility widening**, mechanical and crate-internal: `ColumnInfo::from_core`,
   `ParquetExportOptions::to_core`, `value_to_json` → `pub(super)`; `ExecuteNativeTask`'s 5
   fields → `pub(super)` (constructed by `execute_native()` in the parent module);
   python `execute_dml` → `pub(super)`. Nothing new is reachable outside the crate.
3. **napi-derive ordering**: submodule declarations must sit AFTER `#[napi] struct Database` in
   node `mod.rs`, else `Did not find struct Database parsed before expand #[napi] for impl`.
   Commented in place.
4. **pyo3 name collision**: `#[pyfunction]` generates a hidden module named after the function,
   so python `mod.rs` declares `#[path = "open.rs"] mod open_fn;` — the file is
   `database/open.rs` as specified, but a literal `mod open;` + `pub use open::open;` defines
   `open` twice in the type namespace.
5. **`parse_single_table_schema`**: `sp` → `path` (the parameter name), the tail `match` returns
   `Ok(..)`/`Err(..)` instead of a value plus `return Err(..)` (clippy `needless_return` once it
   is a function tail). Error strings, the no-heuristics single-table rule and the three
   explanatory comments are verbatim.
6. `#[path]` for the moved legacy-json test file resolves relative to `database/`, not
   `database/json_value/` — verified against rustc, noted at the declaration.
7. Dropped: 4 `// -----` banner separator lines in python (redundant once each section is its own
   file) and the merged per-file `use` blocks. Verified by a multiset line diff old-vs-new: no
   other line of moved code changed. `unwrap()`/`expect()` counts are identical (node 6→6,
   python 3→3) — none introduced.
