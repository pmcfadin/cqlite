## BLOCKER 2 — record EXECUTION, not intent

All **eight** `bash -c` bodies (core-tests nextest, memory-budget, integration-tests,
write-tests, cli-tests, compaction-byte-parity, minimal-build, smoke) lost their parent-side
pre-records. Each body now calls the new exported recorder `_fm_observe_child <component>
<cargo-argv…>` on the line **immediately before** its own cargo command, from the same hoisted
package/feature variables the argv is built from.

- Interceptors (`cargo`/`env`) stay **unexported** (Phase B's rationale intact). Only
  `_fm_observe_child` + `_fm_describe_cargo` + `_fm_abbrev_features` + `_fm_sidecar` are exported,
  plus `AGENT_GATE_FM_DIR` (the child is told where to write; the parent still assigns it
  unconditionally to its own mktemp `LOG_DIR`, and `AGENT_GATE_FM_COMPONENT` is deliberately NOT
  exported — each body names itself as an argument). Guard B7 unchanged and green.
- **No second formatter**: the descriptor comes from the gate's own `_fm_describe_cargo`, so the
  guard's declared-vs-EXECUTED differential is still a comparison against the real one.
- Load-bearing detail found by measurement: three bodies run under `set -euo pipefail`, and
  `_fm_describe_cargo` contains `[ … ] && var=…` lists that legitimately evaluate false — under
  `set -e` the substitution shell EXITS there and every record is silently lost. The call is
  therefore `desc=$(set +e; _fm_describe_cargo "$@")`.
- New state: a body that dies before its first cargo now leaves an EMPTY sidecar, so
  `_fm_note_if_skipped` became `_fm_note_if_no_cargo_observed` and renders
  `no cargo invoked (component FAILed before its first cargo invocation)` — restricted to the
  `cargo` class, because an `indirect:` component that FAILs DID run cargo under its driver.

sidecar the rust blast-radius loop writes — **additive, never replacing**. One spelling only:
`_fm_indirect_desc` is now the single definition, used by both `_fm_annotate`'s `indirect:` arm and

## A PRE-EXISTING RED ON THIS BRANCH, found and fixed

`scripts/tests/test_agent_gate_cli_tests_enum.sh` extracted the cli-tests dispatch block with
`awk '/cli-tests\) run_component cli-tests bash -c/…'` — one line. **Phase B's variable hoist split
that arm** (`local ct_pkg=…` now sits between the label and `run_component`), so the extraction
returned NOTHING and 9 structural asserts became a cascade of false FAILs. This has been red since
Phase B and `tooling-tests` runs this script, so the closer's full gate would have FAILed. Fixed by
anchoring on the dispatch label (both shapes accepted) and by accepting either package spelling in
the two pass asserts, plus a new positive assert that the hoist itself is present. **Lesson for the
lane: `--lite` does not run `tooling-tests`, so a gate-shape refactor needs those scripts run by
hand.**

## Things I'd flag / disagree with

1. **Blocker 1 was widened on purpose** (rc-conditioning). The literal ask — "record it for the
   scoped python tier" — would have recorded a maturin invocation on a box with no cargo/rustc,
   where `--python-build-verify` returns 4 before ever calling maturin. Same defect class as
   blocker 2; I judged the ask's intent to require the narrower condition.
2. **`cli-tests` is NOT in section D's failing-shim loop.** Under the *passing* shim its Pass-1
   zero-tests guard already fires, so its baseline is itself a one-invocation short-circuit and the
   "strictly fewer" non-vacuity assert has no headroom. `C-cli-tests` (EXACT) is what measures it —
   and it measures precisely roborev's motivating example. `core-tests` took its place in D.
3. **Nothing mechanically prevents the next `bash -c` body from pre-recording in the parent** other
   than guard B9, which is a source grep over call sites. It is fail-closed for the eight known
   names; a NINTH body could be added with a parent-side record and only B9's `stray` half would
   catch it (it does catch it — any non-selftest `_fm_observe_cargo_argv ` call outside the block
   reds). I think that is proportionate, but it is a grep, not a proof.
