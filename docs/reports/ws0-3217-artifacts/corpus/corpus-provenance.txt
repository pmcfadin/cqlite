Deviations from #3100's recipe (all called out)
-----------------------------------------------
1. JDK 11.0.31 instead of JDK 17 (only JDK available here; Cassandra 5.0
   supports both; daemon and cassandra-stress both ran clean).
2. Root path /data/ws0 instead of /home/ubuntu/ws0 (this box's large volume).
3. cassandra.yaml IS patched here, so the data dir is /data/ws0/cassandra-data/data.
   #3100's corpus actually landed in the CASSANDRA_HOME-relative default
   (.../apache-cassandra-5.0.8/data/data). Location only -- no format/geometry effect.
4. gen-corpus.sh's final row-count step was changed from
   'SELECT count(*) FROM ws0.events' (which server-side-timeouts over 4M rows --
   already documented as failing in rerun.sh) to
   'sstablemetadata <Data.db> | awk /totalRows/'. Measurement-only change; the
   count was independently confirmed by fullscan.py 512 (3999890, exact agreement).
5. cql.py / measure-sstable.py / fullscan.py run under the venv interpreter
   /data/ws0/venv/bin/python (cassandra-driver 3.30.1); the system Python 3.12 is
   externally-managed and cqlsh is unusable on 3.12.
6. verify-claims.sh (#3026's bpftrace claim verification) was NOT run -- out of
   scope for #3217, which needs the corpus only.
