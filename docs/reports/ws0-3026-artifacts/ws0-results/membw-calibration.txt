  Analytic DRAM ground truth per working set (no IMC counters exist in this VM):
    512 MiB (4.9x the 105 MiB L3) -> every pass must miss L3, so DRAM bytes == bytes_touched
    32  MiB (< L3, > L2)          -> buffer stays L3-resident, DRAM bytes ~= one fill (32 MiB)

  PASS-COUNT SENSITIVITY (why `passes` must be large):
  membw_cal memsets the buffer before starting its own timer, but perf counts the

  amortizes as ~1/passes. Measured at 512 MiB:

CONCLUSION (unchanged from the original, now backed by retained output):
  `l2_lines_in.all x 64` equals DRAM traffic to within +1.1% ONLY when the working set
  exceeds L3 (512 MiB case). At 32 MiB it overstates DRAM traffic by ~342x (it measures
  L3->L2 refill, not DRAM). At 1 MiB it collapses to ~0 (0.7% of bytes touched) because
  the buffer never leaves L2. Any per-row traffic figure taken with this proxy is
  therefore valid as DRAM traffic only on a >L3 working set, and is an UPPER BOUND
  elsewhere.
