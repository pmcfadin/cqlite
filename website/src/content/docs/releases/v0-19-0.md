# CQLite v0.19.0 — the SSTable utility release

Where 0.18 shipped the first offline tools for damaged SSTables, 0.19 completes the set: **detect**
a problem, **diagnose** what the engine decided, **compare** two copies of a table, **recover** the
good data, and **export** it. It targets **stock Cassandra 5.0** with no server-side changes. Every
new verb is read-only on its input. Full detail, including every limit and breaking change, is in the
[CHANGELOG](https://github.com/pmcfadin/cqlite/blob/main/CHANGELOG.md); the verbs are documented in the
[SSTable Toolbox](/cqlite/user-docs/sstable-toolbox/) guide.

## Detect

- **`cqlite verify --mode audit`** checks that the components of an SSTable agree with each other,
  as a fixed eight-row `pass`/`fail`/`skip` checklist: index to data, summary samples, bloom filter
  false negatives, BTI trie bounds, `TOC.txt`, digest, compression coverage and `Statistics.db`
  (#4195). An audit that measured nothing exits 2 instead of passing. `sweep` runs it across a data
  directory.

## Diagnose

- **`cqlite find <table-dir> <key>`** tells you which generations hold a partition key and how each
  one answered, and with `--commitlog` which mutations are still unflushed (#4205).
- **`cqlite diagnose <table-dir>`** is a files-only health report: timestamps, droppable tombstones,
  token overlap, and with `--deep` histograms and a compaction reclaim prediction. The default tier
  never opens `Data.db` (#4204).
- **`cqlite explain <ks.table> <key>`** shows, cell by cell, which version won a reconciliation
  and why (#4193). Declared limit: it reports cell decisions only, not row-level marker facts (#4601).

## Compare

- **`cqlite diff <dir-a> <dir-b> --table <ks.table>`** compares two snapshots of one table's
  reconciled state and flags **resurrection risk**: a tombstone one side holds whose shadowed data the
  other side still has, before or past `gc_grace_seconds` (#4201). Read-only on both inputs. Declared
  limits: liveness-only rows report no risk (#4601), the result is capped at 32 MiB, and collections
  are compared per element.

## Recover

- **`salvage` and `rebuild` are now crash-safe.** Output is staged and published by rename, so a crash
  never leaves a component set Cassandra could mistake for complete (#4529). A failed `--manifest`
  write or a full disk while writing `Filter.db` now fails the run (#4527, #4528, #4549).
- Both still write **uncompressed** SSTables only.

## Export

- **`cqlite export --format vortex`** writes query results to the Vortex columnar format through the
  same Arrow layer as Parquet (#4237). Export only, behind the off-by-default `vortex` feature.

## Correctness fixes

Storage fixes that came out of the oracle work: an empty `Filter.db` no longer hides live keys
(#4572), a damaged `Summary.db` is an error rather than a panic (#4573), clustering columns of every
type decode by schema (#4279), rows kept alive only by a primary-key marker are returned and survive
compaction (#4524, #4545, #4581), equal-timestamp ties and `uuid`/`timeuuid` ordering match Cassandra
5.0.8 (#4530, #4531, #4534), and a read over an unreadable SSTable is an error instead of an empty
result (#4159).

## ⚠️ Breaking and behaviour changes

- A **truncated or corrupt `Statistics.db` now fails closed** everywhere (#4612): reads, `explain`,
  `diff` and `salvage` name the path; **compaction refuses a damaged input**, and a damaged
  overlapping SSTable disables purging; **`rebuild` stops on a damaged sibling `Statistics.db`**
  (move it aside to rebuild without it).
- A read over an unreadable SSTable returns an `Err`, not an empty result (#4159).
- `diff` caps its result at **32 MiB**.
- Parquet and Vortex export `TIMEUUID` as the Arrow UUID extension, not text.
- CQLite-written SSTables with `uuid`/`timeuuid` clustering columns were written in an order Cassandra
  rejects (#4539); re-write them.
- `explain` and `diff` JSON carry rule labels and a `conflict` cell status; `CellDecision` and
  `TombstoneRecord` gain a `cell_path` field.

## Get it

```bash
brew install pmcfadin/cqlite/cqlite      # CLI (macOS + Linux)
cargo add cqlite-core                     # Rust library
pip install cqlite-py                     # Python
npm install @cqlite/node                  # Node.js
```
