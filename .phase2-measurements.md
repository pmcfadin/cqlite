# #3630 phase 2 — measurements (all owed items, answered)

## M1 — task 1.1: `SELECT ... AS` alias support — **SUPPORTED (unquoted only)**

* `SELECT id AS __proto__` — **WORKS**. Column named `__proto__`, own data property, prototype intact.
  So the issue's claim "a minimal repro needs no fixture at all" is **TRUE**. Added as a second
  subject in the Node suite, never a substitute for the Cassandra-written fixture (which proves the
  DECODER can carry the name — a claim an alias on an ordinary column cannot make).
* `SELECT id AS "__proto__"` — **PARSE ERROR**: `Expected alias name after AS`. A quoted alias is
  unsupported. Orthogonal CQL-parser gap; recorded, not worked around, not in scope.

## M2 — the NULL-valued prototype-replacement mode — **REACHABLE, and this OVERTURNS my phase-1 conclusion**

Phase 1 concluded this needed a Rust-level unit test. That was **wrong twice over**: the Rust route
is impossible (`value_tests.rs` records that a real `ConvCtx` needs a live napi `Env`), and a JS
route exists. `TTL(col)`'s evaluation is not yet wired (#692) so it returns `Value::Null` — a genuine
null VALUE in the row's value map, which a CQL tombstone cannot supply.

Measured on UNFIXED code, `SELECT TTL(real_col) AS __proto__`:

```
Object.keys(row)                  -> []
Object.getPrototypeOf(row)===null -> TRUE      <-- the prototype WAS replaced
typeof row.hasOwnProperty         -> "undefined"
Object.prototype.toString.call(row) -> "[object Object]"   (identical either way; cannot detect this)
```

Both failure modes are therefore covered by real tests. The test declares its own expiry: if #692
lands and `TTL()` returns an integer, its `toBeNull()` assertion fails loudly and the remedy is
another null-valued route, never relaxing it.

## M3 — task 1.6 / design.md D3: `Value::Json` — **NOT REACHABLE from the public surface**

`Value::Json` is produced in exactly one place, `custom_scalar.rs`'s `"json"` arm, reached only via
`ComparatorType::Custom("json")`.

* **Measured**: a committed `.cql` schema declaring a column as `json` is **REJECTED** —
  `Column 'constructor' references undefined UDT 'json' in keyspace 'test_row_collision'`.
* **Cause, confirmed in source**: `json` is absent from `cql_parser.rs`'s type map (~line 1030-1053),
  whose `_` arm is *"assume it's a UDT if not a known primitive"*. The
  `ComparatorType::Json => CqlType::Custom("json")` mapping lives in `schema/parser.rs`, which reads
  Cassandra's **serialization header**, not `.cql` files — and Cassandra never writes a `JsonType`
  comparator, because `json` is not a Cassandra type.

**Conclusion: there is no route from a Cassandra-written SSTable to `json_to_napi`.** Per the spec's
own scenario, the null-prototype construction therefore ships with this measurement recorded and NO
public-surface wiring evidence. Deliberately NOT covered by a CQLite-written round-trip, which would
be invariant to a uniform error on both sides (#3042). The fix is still correct and still worth
making — it removes the channel before any future route opens one — but it is **uncovered, stated
plainly**.

## M4 — the EXTRAS path — **NOT REACHABLE from the binding surface; 5 routes tried**

The spec makes both `row_to_object` paths ONE requirement precisely because a fix reaching only one
leaves the other live. I could not reach the extras branch from Node:

| route | metadata columns | extras |
|---|---|---|
| `SELECT *` + full schema | all 5 | none |
| `SELECT id, "__proto__"` | `["id","col_1"]` — the quoted name DEGRADES to `col_N` | none |
| `SELECT "__proto__"` | `["col_0"]` | none |
| `SELECT COUNT(*)` | `["Count(*)"]`, value keyed identically | none |
| schemaless open | all 5, from `Statistics.db`'s authoritative header | none |
| partial schema (id, real_col only) | `["id","real_col"]` — values PROJECTED to declared columns | none |

**What this does and does not mean.** Both paths call ONE helper (`data_property`), so the MECHANISM
is shared and a divergence between them is structurally impossible today. But **a shared helper is
not coverage**: the extras branch's own `descriptors.push(...)` line is executed by no test I can
write, so if someone later inlines or special-cases that branch, nothing fails. Recorded as a
residual for the spec audit rather than papered over with a shared-mechanism argument.

**Adjacent finding, out of scope, worth filing**: an explicitly projected QUOTED column loses its
name — `SELECT id, "__proto__"` reports metadata `col_1` and keys the value `col_1`. Only `SELECT *`
preserves quoted column names. That is a real defect but it is not #3630's, and it is not a
prototype-pollution issue.
